## 一、問題

第一章斜面工作台已把第五段先遮住、要求玩家押值，再以真實 fixture 揭曉；但玩家押錯時，
現行 runtime 只顯示認證數字與提示。世界沒有先承接這張押記，也沒有在後文記得它。

本輪只處理一種可歸因失手：`consistent === true && predHit === false`。這代表前四段形狀足以
判讀，錯的是玩家對第五段的公開押值。器材造成的形狀不穩、混選配置、格式錯誤與未達前置
仍走既有診斷，不冒充同一種失敗。

## 二、裁決

1. 玩家第一次在 `A2-2/e1` 留下上述失手時，押記立即成為既有狀態中的 claim；不得扣信譽、
   不得原地要求改答案，也不得由伽利略先報正解。
2. 舞台殼把揭曉拆成兩段：先封存押線並播放 W1–W3；玩家親手收掉 W3 後，才讓工作台顯示
   實測線並播放 W4–W6b。物理計算與 claim 寫入仍由現行 `judge()` 一次完成。
3. 第一次之後的同型失手播放短反應；第一次後的第一筆成功 claim 播放 W8。兩者都從既有
   append-only claims 派生，不新增計數旗標。
4. 工作台保留一張可讀的押記紙：預測線與實測線以線型、標籤和文字三重區分；單筆與 2–3
   筆平均必須明說，不以顏色作唯一資訊。
5. `A3-1/n3` 後依既有紀錄互斥讀回：兩事皆有 ＞ 只有押值失手 ＞ 只有序幕搶答 ＞ 無讀回。
   序幕搶答從 choice／rep 事件派生；押值失手從 claims 派生。不得用當下 `rep`、`hadFailure`
   或新 flag 代替歷史事實。
6. `optional_probe` 案二封存，本輪不新增辯論按鈕、狀態或預留接口。

## 二之一、可知性四欄（ADR-016）

| 欄位 | 本岔口答案 |
|---|---|
| 當下誰知道什麼 | 玩家與伽利略只看過前四段與玩家封存的押值；第五段仍被蓋住。 |
| 現在最多能反駁到哪 | 伽利略可要求封存、追問讀法與提醒紙不替人緊張；掀開前不能宣布押值對錯。 |
| 還缺哪個證據 | 真實 fixture 的第五段刻痕，以及重押後玩家對前四段增量的重新判讀。 |
| 錯誤在哪一場揭曉 | 同一 `A2-2/e1` 的 W4 掀封時由刻痕揭曉；錯紙保留，`A3-1` 再由辛普里奧讀回。 |

這是「可當下判定就當下、尚待證據就延後」的短時程版本：等待只有一個揭曉拍，
不必為了形式把所有錯誤拖到後場。

## 三、允許的窄共用能力

為讓 canonical scenes 能描述 A3-1 條件節點，`Narrative.passRequire` 可加入唯讀布林組合：
`all`、`any`、`not`，以及精確匹配既有 `eventLog`／`lab.inference.claims` 的葉節點。

- 只讀，不寫 state；不接受函式名、路徑字串或任意運算式。
- event 僅比對白名單欄位 `t`、`at`、`pick`；claim 僅比對 `ok`、`consistent`、`predHit`。
- 未知 require key 必須 fail-closed；現行 `flag`、`flagAbsent`、`flags`、`evidence` 行為不變。
- 這項能力只服務資料驅動可見性，不得把物理判決或證據取得搬進 scenes。

舞台殼另可增加一個純表現事件：最後一條帶 `yieldToken` 的工作台台詞被玩家 ack 後，
`stage-ui` 發出同 token 的完成事件。它不得讀寫 Narrative、存檔或物理狀態；灰盒殼沒有訂閱者
時，judge 仍須可完成，不能卡死。

## 四、不變邊界

- 不改 `engine.js` fixture、12% 門檻、`judge()` 參數／結果、E3.a 取得條件或信譽公式。
- 不改 A2-2 `n2b`、`c1`、`qOdd`、`qCum`，也不改 A3-1 既有 n1–n3／n4。
- 不新增 evidence、flag、頂層欄位、schema、migration、時間回溯或多結局。
- 不把工作台台詞寫入物理引擎；不靠台詞文字 regex 判斷分支。
- 不為封存的 `optional_probe` 留死接口。

## 五、Design Gate 狀態與施工前置

Fable 已在劇本稿 v0.1.1 一字不改核准功能規格提出的 W5 平均版與 W7 中性句；
qOdd／W8 判讀為功能不同，不改 qOdd。文本事實邊界已閉合。

仍有一項必須納入 runtime 施工包的現行缺陷：合法路徑 `P0-2/q1.b → qB.b2 → nA4` 會被 sanitizer 誤判為
「信譽事件缺少依序的玩家操作」。未來施工包須把兩條合法因果鏈都列入白名單並補負向控制；

不是要求總監先解技術題。
