## 一、問題與目標

現行 `assets.json` 只讓 K1／K4 指向單一 SVG；取得特寫與旅人筆記又各自解析資產。
K1 已有固定摘要成品，K4 則有四條合法借條世界線。若直接把任一 K4 raster 設成
`card_K4`，其他三條世界線都會看到不存在的借條或被抹掉的借條，構成假證物。

本 CR 只授權建立一個唯讀 `resolveEvidenceVisual` 契約，讓**取得當下**與**筆記回看**
依同一份封存事實選到同一張完整圖，並提供圖外文字版與可鍵盤操作的放大閱讀。

## 二、AS-IS 事實

1. K1、K4 的 `card_K1`／`card_K4` 與 `evidenceVisual` 目前都是靜態 SVG mapping。
2. `showEvidenceFocus()` 從 `ASSETS.evidenceVisual[code]` 取圖；`renderEvidenceCards()`
   則優先取 `card_${code}`。兩入口沒有共用 resolver。
3. `collectNewEvidence(before, after)` 發出的 `bd:evidence` 只有 code、name、scene 與掛點，
   不含允許表現層選圖的唯讀投影；筆記的 `dataset.items` 也只有 code、name。
4. `engine4.sealModelComparison()` 在 K4 成功取得時，已把三列 stamps、兩格
   `loanDecision`、loans 與 `claimText` 封入 `modelLab.evidencePackage`。
5. sanitizer 要求 K4、逐格蓋章、借條與 `evidencePackage` 完全一致；schema1 遷移
   明文不合成 K4。故 K4 選圖不需新增狀態或遷移。

## 三、唯一狀態權威與選圖表

### 3.1 權威

K4 唯一選圖權威是**取得時封存後**的 `state.lab.modelLab.evidencePackage.stamps`，
不得改讀 DOM、當前工作台選項、`loans.length`、中文總結字串或資產檔名。只投影：

```js
{
  code: "K4",
  visualKey: "no_loans | planets_loan | comet_loan | both_loans | null"
}
```

`visualKey` 由 chapter-ui 在已驗證 state 上計算；stage-ui 只消費投影，不接觸引擎、
localStorage 或完整 state。投影進入兩個既有通道：新取得證據的 `bd:evidence.detail`，
以及筆記 `#evidenceList.dataset.items`。重播補發亦必須從當前已驗證 state 重算，
不得沿用失效記憶體佇列。

### 3.2 映射

只讀 `caseId === "planets"` 與 `caseId === "comet"` 的 `loanDecision`：

| Planets | Comet | `visualKey` | Art Locked 來源 |
|---|---|---|---|
| `no-loan` | `no-loan` | `no_loans` | K4 no_loans v03 |
| `loan` | `no-loan` | `planets_loan` | K4 planets_loan v03 |
| `no-loan` | `loan` | `comet_loan` | K4 comet_loan v03 |
| `loan` | `loan` | `both_loans` | K4 both_loans v04 |

K1 不讀狀態，固定解析至 K1 v02。
其投影 `visualKey` 恆為 `null`，且**不得**因此觸發 fallback 診斷；只有 K4 的非法／
缺失投影才屬 fail-closed 事件。

### 3.3 Fail closed

- 只有 `state.evidence.k4 === true`、`comparisonSealed === true`、package 存在，且兩格
  決定各自恰為 `loan`／`no-loan` 時，才能回傳 K4 raster。
- 缺格、重複 case、非法值、未封存或未知 `visualKey` 一律不得猜圖；退回現行已修正
  的中性 K4 SVG，並在圖外標示「此存檔的借條狀態無法安全還原」。不得默認 no_loans。
- 這個 fallback 是防呆，不是 legacy 故事：正常新檔與 sanitizer 通過的 K4 必須命中
  四變體之一；命中 fallback 應留可測診斷訊號，但不得阻斷玩家讀檔。

## 五、共同 resolver 與呈現契約

1. `resolveEvidenceVisual(code, visualKey)` 是取得特寫與筆記卡的唯一入口；兩邊不得
   各自維護 K4 switch，也不得從證據中文名稱反推 code。
2. resolver 只回傳已登錄 asset entry、alt、caption、可及文字版鍵與 fallback 狀態；
   不回傳任意 URL，不解析 state，不改狀態。
3. `ASSETS.evidenceVisual.K1/K4` 改為宣告 resolver 所需 mapping；既有其他章 static
   mapping 行為不變。K4 靜態 `card_K4` 不得再壓過狀態 resolver。
4. K4 新取得事件使用取得後 state 的投影；筆記每次開啟均使用當前已驗證 state 所產生
   的同一投影。四條路線在兩入口必須同圖。
5. 快取鍵包含 asset id／版本，不以固定 `card_K4` URL 共用四個世界線。

## 六、閱讀與無障礙

- 筆記縮圖可點擊；Enter／Space 亦可開啟全螢幕閱讀 dialog。Esc、關閉鈕與點擊遮罩
  關閉後，焦點回到原證據卡；dialog 開啟時焦點不逃出。
- 放大畫面顯示**整張 raster**，不得另加任何可見文字、章、借條或修補層。
- 圖外提供標題、caption 與可展開的「文字版」。K1 文字版列出兩句核准結論；K4
  文字版列出固定六格事實、**封存的**借條狀態與該世界線 `claimText`。文字版取自核准的
  deterministic 資料／既有 `claimText`，不靠 OCR 讀圖。
- `img alt` 簡述物件與比較目的，不塞完整逐字稿；讀屏可由標題、alt、caption、文字版
  取得等價資訊。縮圖不要求小字可讀，放大後全文必須可讀。
- 既有 `stage-ui.js`「表現層不碰引擎、不碰狀態、不碰存檔」鐵律維持；只准消費
  `bd:*` 事件與 DOM 上的唯讀投影。

## 八、契約與驗收

### 8.1 機械契約

1. 四組合法決定逐一命中正確 asset；對調任一格時只改至對應世界線。
2. K1 永遠命中 v02，不讀 K4 狀態。
3. 缺 package、缺格、重複 case、非法值、未封存各有負向測試，且不得命中任何 K4 raster。
4. 取得事件與筆記資料對同一 state 產生相同 `visualKey`；重播補發亦同。
5. 移除 resolver 或讓 `card_K4` 靜態優先後，負向契約必須轉紅。
6. 五張公開資產存在、可解碼、比例一致；衍生雜湊與 Art Lock ledger 可追溯。
7. stage builder 重建後 `stage-ui.js` 不落後；全套 `npm test` 維持綠燈。

### 8.2 人工驗收

- 桌機 1440×900 與手機 844×390：K1 與 K4 縮圖可辨、放大無裁字、無橫向溢出。
- 四個 K4 fixture 各走取得特寫→關閉→筆記回看；圖、借條與文字版三者一致。
- 鍵盤只用 Tab／Enter／Space／Esc 完成開啟、閱讀與關閉；焦點正確歸還。
- 讀屏抽驗：卡名、簡短 alt、caption、文字版不重複轟炸，也不遺漏借條世界線。
- DevTools 網路與 console 無 404、解碼錯誤或 fallback；再以一個故意破損投影確認
  fail-closed 中性圖與診斷成立。
- schema1 正常舊檔（從未取得 K4）開啟筆記時不顯示 K4 卡，也不觸發 fallback 診斷；
  「乾淨的沒有」與「已取得但投影破損」必須可區分。

## 九、存檔與回復
