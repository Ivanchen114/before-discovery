## 三、chapter registry：唯一章別權威

### 3.1 正本與 accessor

1. `greybox/data/series.json` 維持系列目錄正本，為每章新增 `runtime` 物件：

```json
  "saveEncoding": "letter-envelope",

```

2. 新增 `greybox/src/chapter-registry.js`，只讀 `series.json/series.js`，驗證 id、route 與 runtime
   metadata 唯一且完整，提供 `byId`、`byRoute`、`nextOf`、`isSupported`。它是 accessor，不得

   replay 必須同讀 registry，不能一邊從 1 開局、一邊仍寫死從 3 重播。registry 重構不得改任何舊值。
4. CH7 目錄資料：`id=ch7`、`route=ch07`、`number=07`、標題《一隻腿的證詞》、年代
   `1791–1800`；章問句採凍結台詞「那一踢的電，是青蛙自己的，還是我們帶來的？」；intro

6. 未知 route fail closed：不得悄悄把 `ch07` 或拼錯章號開成 ch1。真正未知 URL 可回目錄並
   顯示「此章尚未登錄」；已登錄但 runtime 物件缺失則阻止開始並留下診斷。

## 五、engine7 狀態與操作契約

### 5.1 最小狀態

```js

    traces: { baseline, bimetal, sameMetal, noMetal, electrometer, pile },
    archival1794, testedScope, boardComplete

  integrity: {

```

所有記錄以 append-only id 留存；重試增加 record，但同一具名 trace 只首次授予。不得提供刪除
或覆寫原紙 API。`activeWithholding` 只是 UI 可見性投影（`archival1794` 或具名 `traceId`），不得把

不清事故史。T3 的公開企圖亦另增 attempted-claim record，不覆寫 `exclusiveClaim` 或既有署名。

### 5.2 前四格自由配置

`e_matrix` 由玩家自行選執行順序與重複，不可固定播放。四張 fixture 只陳述單趟觀測：

### 5.4 判讀與信譽

- commitment 不含 `isCorrect`。只有 `recordMidVerdict`／`recordFinalVerdict` 按 contract 的
  supportedBy/refutedBy 判讀。
- 誠實押 M、A、not-yet、操作失敗與判讀錯誤全部 `repDelta=0`。
- ch7 初始信譽為 1。`SC7-R1` 只接受下列具名研究失信事件；每次皆 `1→0` 並立刻鎖定，修復走
  `rep → repLock → repairEnter → 玩家 withdraw → 對應修復 action → rep +1 → repairExit`，回到 1
  與事件原返回點。excuse／silence 均留在修復場，不能清鎖或前進。
- 失信 action 與扣分是同一個不可分割 transaction；若同一 `sourceId` 已在 `usedSourceIds`／eventLog
  出現，按鈕不再可見且 engine 必須拒絕重送。不得只防重複扣分、卻再次隱匿紙張。T2 以
  `ch7:withdraw-trace:<traceId>` 區分各格；不同 trace 可各觸發一次，同一 trace 終身一次。
- 任一 action 令信譽歸零後，UI 在同一次 `setState` 回傳玩家控制前就必須轉址；不是等到下一個
  narrative choice 才檢查。`repLocked=1` 時，除 SC7-R1 合法修復 action 外，所有 chapter／workbench
  action fail closed，因此 active withholding 不可能被拿去判讀、合帳或開 gate。

## 六、save、sanitizer 與 fail closed

1. ch7 使用 schema 1、`before-discovery:chapter7:v1` 與 letter envelope；不存在 legacy ch7
   migration，也不得把別章 payload 猜成 ch7。
2. `sanitizeImport7` 深驗：scene/node cursor、records 唯一與 append-only、各 trace 必有合法
   configuration/result、1794 紙揭曉時序、claim gate、public/repaired 因果、三個操作 dominance、
   board 由六格衍生、兩次 verdict 證源時序、ended 必須晚於正確 final＋s_scoped；另以 registry 的
   `initialRep=1` 重播完整信譽帳，驗證 integrity incident／active withholding／used source、rep lock、
   同因果修復與返回點互相一致。不得沿用共用 sanitizer 內寫死的 replay 初值 3。
3. 不合法狀態整包拒絕，不修補、不補故事、不自動補 trace；UI 保留本機舊檔並顯示原因。
4. registry 只負責選 sanitizer；sanitizer 仍是章內狀態權威，不能由 metadata 降低白名單。
