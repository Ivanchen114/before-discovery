## 一、這不是「缺一條法則」,是第三章繞過了資料層

先講結論,因為它和我原本的假設相反。

我把五章辯論的所有選項組抽出來對照,發現**第二章與第五章已經做對了**,而且做得很好:

**第二章 `fr.claim`(現行,無稻草人)**

| | 選項 |
|---|---|
| 正 | 這條規律寫到**低速、短程**的拋射:空氣影響還不明顯時,射程隨下落高度的平方根增加 |
| 誤 | 這條規律寫到**三里外的砲彈**:末段雖然變陡,射程仍隨平方根增加 |
| 誤 | 這條規律寫到**高空與星辰**:空氣變稀薄後,它們也會沿桌上的平方根關係運動 |

三個選項講**同一條規律**,只差在**適用範圍**。玩家不能靠直覺否掉任何一個,必須回去看砲術圖顯示的末段軌跡差異。

**第五章 `fr.claim`** 同理,而且 `same-thing`(兩本帳記的是同一件事,一本多自乘了一次)是**量綱上幾乎成立**的誘答,非常兇。

**第三章的四個 `concept` 步驟不是這樣**:

| 位置 | 正解 | 兩個錯項 | 問題 |
|---|---|---|---|
| p1 `concept` | 石頭鬆手前已和船一起走 | 石頭自己追桅杆 / 需要甲板風一直推 | 荒謬,不用證據就能否掉 |
| p2 `concept` | 運動 ≠ 運動在改變 | 少了船速欄就是假的 / 船加速時石頭變重 | 同上 |
| p3 `question` | 先確定同一時刻 | 先決定誰比較可靠 / 先選看起來平順的 | 同上 |
| p3 `concept` | 各自拿碼頭或桅杆當起點 | 兩張紙擺放角度不同 / 受了不同的力 | 同上 |

**根因**:第一、二、五章的辯論選項寫在 `data/debate*.json`,共用同一套資料結構,因此繼承了同一個寫法慣例。**第三章的卷宗辯論是獨立引擎,選項以 `if (choice !== "shared-motion")` 的形式硬編碼在 `src/engine3.js`**,沒有走那層資料,慣例也就沒有跟過去。

所以這不是品味問題,是**架構落差造成的品質落差**。

## 二、法則(建議入法源明文)

> **誘答項可否證性:每一個錯項都必須要求玩家動用一項具體證據才能排除。**
> 錯項若能僅憑常識、語感或荒謬程度否掉,它就不是誘答,是填充物。
>
> 具體寫法:錯項與正解應共用同一個主張骨架,只在**適用範圍、強度或所指對象**上不同(第二章 `fr.claim`、第三章 `p1.wind` 與 `p2.boundary` 為 canonical 範例)。

### 2-1 為什麼這條重要,而不只是「難度調校」

把台詞全部拿掉,一個決策點還剩下什麼,決定它是不是遊戲。

逆轉裁判拿掉台詞,「哪張證據和哪句證詞矛盾」仍然好玩。我們的 `p2` 三張紙分類(從岸標間距 `[0,0,0]` / `[1.5,1.5,1.5]` / 遞增 讀出分類)拿掉台詞也仍然好玩。**四個 `concept` 步拿掉台詞就只剩「挑那個不荒謬的」。**

而且位置最壞:`concept` 幾乎都是每一柱的**第二步**,玩家剛進入一柱、最需要被抓住的時候,先發一題白給的。

### 2-2 可機檢的判準(建議這樣落地)

不要靠人工評「這個錯項夠不夠兇」。改成資料契約:

> **每個錯項必須聲明 `refutedBy`——否掉它需要哪一張原紙、哪一個欄位,或哪一次實驗結果。**
> `refutedBy` 填不出來的錯項,依定義就是稻草人,不得上線。

這把品味判斷變成可掃描的欄位。建議由 `skill_guard.py` 新增一個 check(命名交 Sol,例如 `check-distractor`),掃描五章選項資料:

- 錯項缺 `refutedBy` → WARN(過渡期)→ 之後升 ERROR;
- 每一柱的**第一個**決策點,其錯項全部缺 `refutedBy` → ERROR(不得用白給題開場);
- 反向樣本:把第二章 `fr.claim` 的 `over` 選項換成「這條規律寫到魔法」,檢查必須轉紅。

## 三、法源歸屬(請注意,這裡不要放進 skill)

總監的原話是「把 skill 寫完整」。依 skill v3.1.0 §首段與 §6 的既有約束——「本 skill 是任務分類器與法源路由器,**不是第二份專案法典**」「柱數、卡片欄位與操作細節只維護在該法源,不複製進 skill」——**這條法則不能寫進 skill 正文**,否則就是再造一次已經清理掉的雙份真相。

正確配置:

| 內容 | 去處 |
|---|---|
| 法則本文、canonical 範例、`refutedBy` 欄位規格 | `02_設計/發現之前_工作台與辯論架構_一二章實證規格_v0.1.md` **§七新增小節** |
| 上位裁定(若總監認為需要 ADR 層級) | 新 GB-ADR 或併入既有辯論 ADR,交總監裁 |
| skill | **只加一行路由**:辯論／誘答項設計任務必讀上述法源。不抄內容 |
| 機檢 | `skill_guard.py` 新 check + 五章選項資料的 `refutedBy` 欄位 |
| 治理鏡像 | 法源改完後跑 `sync-mirror`(見 §六附帶事項) |

## 四、施工範圍(建議分兩批,第二批可延後)

### 批次 A|第三章四個 `concept` 步驟改寫(R2,建議本輪做)

只改**錯項文字與對應的 NPC 反駁**,不動正解、不動物理、不動柱數、不動存檔、不動判定邏輯。

示範(p1 `concept`,現行對手是「石頭自己追桅杆」):

> **改為**:石頭鬆手後保持原速,所以會落在桅腳**後面一點點**。
> `refutedBy`:`A1` 走穩三回的落點欄——三回都在桅腳附近,沒有系統性後偏。

方向完全正確,只有量錯。玩家不能靠直覺否掉,**必須回去翻自己手上的 A1**。一秒從填充物變成真誘答,而且沒有新增任何介面。

另三處請 Sol 依同一原則設計,並在 CR 回覆中列出各自的 `refutedBy`。

**備選方案**(若 Sol 認為改寫錯項不夠):把 `concept` 從「選正確說法」改成「**這個說法要用哪張紙支持**」,直接複用已經好用的證據綁定機制,連新介面都不用寫。兩案請 Sol 判斷後擇一,並說明理由。

### 批次 B|第三章辯論選項資料化(R3,可延後)

把 `engine3.js` 裡硬編碼的選項與判定表抽到 `data/` 層,與 `debate*.json` 對齊。這是根因修法——不做,下一個新章節的獨立引擎會再犯一次同樣的錯。

但它會動共用狀態語意,需要獨立 Design Gate 與存檔影響評估,**不建議和批次 A 綁在同一包**。

## 五、驗收條件

1. 第三章四個 `concept` 步驟的每個錯項都有具體 `refutedBy`,且該證據是玩家在該時點**確實持有**的(請以 node 實跑驗證,不要只看資料)。
2. 反向樣本:把任一錯項換回荒謬版本,`check-distractor` 必須轉紅。
3. 不新增禁詞;第三章禁詞 lint 維持 0 命中。
4. `npm test` 全綠,且**不得靠修改既有契約來過關**。
5. 存檔 schema 不變;既有 `scene + node` 游標全部保留(批次 A 只改文字)。
6. 法源、skill 路由行、治理鏡像三處同步,`validate` 不得因此新增 error。
