# ENGINE-CR-033｜對話選項寫入章別狀態

**日期**：2026-08-01
**狀態**：已實作；外部 Claude Opus 對抗審查完成，C2 已修復，完整自動回歸通過
**範圍**：`Narrative.choose` 的有限章別動作效果；第四章 K0 與歸檔狀態

## 一、問題

第四章有兩個只需要一次判斷的段落，被迫包成完整工作台：

- 玩家先在對話選「沒有拉力時沿切線直行」，進工作台後又回答同一題；
- 五張證據完成後，玩家在結尾逐張按「翻看／夾回」，但五次操作沒有新增推論。

若只把工作台拿掉、用普通 `effects.flag` 代替，K0 封存、錯答痕跡與章末歸檔就會從
引擎事實退化成劇情假話。因此需要一條窄的引擎能力：**對話選項可以呼叫既有的章別純函式，
成功或失敗結果仍寫進 `state.lab`，而不是由台詞宣稱發生。**

## 二、決策

在 choice option 的 `effects` 內允許：

```json
{
  "labAction": {
    "action": "sealTangentPrediction",
    "args": { "choice": "tangent" }
  }
}
```

`Narrative.choose` 必須沿既有 `labAction` 分派器執行；不得由 JSON 直接寫 `state.lab`。

- 動作回傳 `error`：整次選擇拒絕，保留原 state 與 cursor。
- 動作回傳 `ok:false` 但沒有 `error`：保留錯答 append-only 記錄，照 option 指定分支前進。
- 動作成功：保留引擎紀錄後前進。
- 沒有 `labAction` 的既有選項行為不變。
- 一個 option 本輪只准一個 `labAction`，避免把多步實驗藏進一句對話。

第四章另新增 `Engine4.archiveEvidenceSet`：它不是跳過五份證據，而是以**一次玩家歸檔決策**，
依固定 K1→K5 次序呼叫既有 `clipEvidence`，保留原本五筆 append-only 歸檔紀錄與章末守衛。

## 三、非目標

- 不把斷言成功、數據運算或多步實驗搬進對話選項。
- 不開放任意函式名稱、任意 state patch 或 UI 直接改資料。
- 不升 save schema，不移除舊 embed node。
- 不改第一至三章既有 choice 語意。

## 四、驗收

1. K0 三個對話選項都會留下 `sourceLab.attempts`；只有切線會封存 K0，且不授予證據。
2. 拿掉正解 option 的 `labAction` 後，後續 K1 前置守衛必須擋下，證明狀態不是由台詞假造。
3. 章末正解一次完成 K1–K5 歸檔，留下五筆依序紀錄；錯答不歸檔。
4. 既有沒有章別動作的選項測試全部維持。
5. 舊游標停在已退役 K0／archive embed 時，匯入淨化依狀態真相導回對話：未完成回選項，已完成才略過；不得再顯示退役 UI。
