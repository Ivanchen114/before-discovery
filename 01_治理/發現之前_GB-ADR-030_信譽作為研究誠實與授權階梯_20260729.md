## 一、問題

現行 runtime 有兩個相近但不同的量表：

- `state.rep`：全章共用的「信譽」，代表歷史人物是否相信旅人會照證據說話。
- 辯論內的「說服力」：代表這一場論證還能承受多少次失準。

施工前，第一、二章只有零散 `state.rep` 事件，且第一章曾把答對感官題、記得主線問句當成加分；第二章同一個越界選項可以反覆扣分。第三章只有結尾越界斷言會扣，第四、五章沒有章別觸發。第三章辯論雖有「說服力」，玩家仍會合理地感覺全域信譽只在第一章存在。

另一個問題是第三章的因果：旅人前段多在心裡觀察，到了實驗前才被指定安排卷宗。人物「為什麼願意把實驗權交給他」支付不足。

## 二、裁定

### 2.1 信譽量的是研究誠實，不是答題正確率

下列情況**不改變信譽**：

- 誠實提出一個尚未驗證的假說或問題。
- 計算錯誤、選錯原紙、實驗失敗。
- 誠實承認自己看不出一張不完整原紙還能支持什麼；這是證據判讀錯誤，由 NPC 追問與重選處理。只有把紙藏起來、刪掉，或明知它記了不利結果仍宣稱「沒有資料」，才是研究失信。
- 在尚未看見答案前做出錯誤預測。
- 被新資料推翻後正常修正。

下列情況可 **−1**：

- 把尚未取得證據的未來答案當成已證明事實。
- 隱瞞、刪除或補寫不利原紙。
- 把局部結果說成普遍結論。
- 明知資料沒有量到某件事，仍借權威宣稱已證明。

下列情況可 **+1**：

- 在他人逼問前主動承認資料還不能回答。
- 保留不利或不完整原紙，並標明它的限制。
- 把原先過大的斷言收窄到資料真正支持的範圍。
- 完成對方要求的邊界檢驗，因此取得下一級操作權。

### 2.2 每次變動必須回答「為什麼」

每筆現行 `rep`／`repDelta` 事件除數值外，必須附 `reason`。HUD 每次變動都顯示：

```text
信譽 −1｜把還沒有原紙支持的答案當成事實
信譽 +1｜主動把斷言收回到原紙能支持的範圍
```

通用說明只作舊存檔或未知外部事件的相容 fallback，不得替新事件省略原因。信譽說明改為：

> 猜錯與實驗失敗不扣；把未驗證答案說成事實、隱瞞資料或越過證據邊界才扣。主動補正並守住證據範圍可恢復。

### 2.3 信譽與說服力不得混用

- 信譽：跨場景的合作資格與研究誠實。
- 說服力：單場辯論的容錯。
- 同一次操作只有在同時傷害研究誠實與當場論證時，才可兩者都扣；必須分別說明原因。

本案不改第三章既有 `debate.rep` 儲存欄位，以免製造存檔遷移；玩家可見名稱仍固定為「說服力」。後續 schema 升版時再考慮將內部欄位改名。

### 2.4 規則跨章，數值不跨章繼承

五章使用同一套信譽語意，但每章的 `state.rep` 仍是當章人物對旅人的合作資格。相隔數年、數十年且換了一批人物後，新角色不會知道上一章的信譽帳；因此本案不建立系列共用分數，也不把跨章投影塞進既有存檔。若未來要做「旅人自己是否守住原則」的系列量表，應另立名稱、用途與 schema，不得偷用人物信任值。

## 三、五章施工矩陣

| 章 | 扣分觸發 | 加分觸發 | 明確不扣 |
|---|---|---|---|
| 第一章 | `P0-2/nA4`：把沒有證據的未來答案說成大家都知道的事；辯論中拿未來物理學換權威、偽稱量過垂直，各只在首次扣分 | `P0-2/nB3`：同意讓斷言接受證據檢查，且同一規矩也約束同行 | `P0-1` 感官題答對、`INT-1` 記得主線問句 |
| 第二章 | `B0-2/q1/a`：未看砲術圖就宣稱舊規律一定管得到飛行；辯論中把低速短程外推到遠砲、把未測高空寫成已證明，各只在首次扣分 | `B0-2/s1`：先讀對手的圖，也保留它真正能支持的範圍 | 預測錯、實驗失敗、一般錯答 |
| 第三章 | `C0-3/c1/all`：正確方向卻沒有此紙支持；終局兩種不同越界各只在首次扣分 | `C0-3/c1/bounded`：把話收回原紙範圍 | 選錯紙、實驗失敗、辯論說服力損失；舊終局 API 不再重複扣 |
| 第四章 | 虎克來源過度／抹除、機制過度／牛頓單獨完成；每一種不同越界只在首次扣分 | 旅人親手退出《原理》作者欄 | 九宮格預測錯、計算錯、封存操作失敗 |
| 第五章 | 拿前輩名聲替代可驗資料、抹去黏土坑、捏造短少去向或隱去不利帳目；每一種不同越界只在首次扣分 | 把兩本帳改寫成可驗問句；`J4` 保留未對平的去向 | 選錯帳、碰撞或黏土實驗失敗 |

五章皆有章別修復場：第一、二章 `SC-R1`、第三章 `SC3-R1`、第四章 `SC4-R1`、第五章 `SC5-R1`。信譽歸零時保存原游標；玩家必須親手撤回越界、辨認失信發生在哪一筆，或補做一筆可查紀錄，才回到原處。第三至五章的修復各有兩個仍在逃避責任的錯選項；選錯不回補、不離場，不能把修復壓成免費的「繼續」按鈕。

不要求每章固定「兩加兩扣」。觸發數量服從戲劇與證據經濟；最低要求是玩家能看見誘惑、後果與修復，且不得靠故意重複同一錯誤刷扣。

## 四、跨章施工設計

### 4.1 旅人知道答案，但不能拿答案換權威

在 `C0-3` 舊紙判讀加入一個真正有誘惑力的選項：

> 船若只是平穩往前，石頭會跟船一起走，不會落在後面。

這句物理方向正確，但舊紙沒有記「平穩」，因此此刻公開斷言要 `信譽 −1`。伽桑狄不是說物理錯，而是追問「這張紙哪裡寫了走穩」。

玩家仍可改選：

> 它只記下一次落在桅後；那一趟的船速沒記，不能拿來代表別的船況。

這是主動縮限，`信譽 +1`。

### 4.2 實驗權必須由剛才的行為換來

伽桑狄交出安排權的理由改為兩層：

1. 旅人沒有把自己知道的答案塞回舊紙。
2. 在明天上船的人裡，旅人唯一不欠船主人情。

旅人的理解則明說：

> 他不是因為我知道答案才把卷宗交給我。是因為我沒有先把答案寫進去。

因此「旅人後來做實驗」不再是系統指派，而是前一場研究誠實的可見後果。

### 4.3 同一錯誤不能變成扣分機

- 場景選項用旗標切換成同文案、無第二次 `rep` 的重試項。
- 引擎型越界把「是否已嘗試過這一種 choice」留在 append-only attempts；重選同一項仍有 NPC 回應，但不重複扣分。
- 不同越界若傷害的是不同研究誠實邊界，仍可各自承擔一次後果。

### 4.4 跨章修復不是免費按鈕

信譽歸零只會把玩家導入章別修復場，不直接回補。修復場保存 `returnScene + returnNode`；玩家須在錯選仍可失敗的操作中，完成一個可驗行動或明確撤回越界，才回復至 1。再入修復場不得覆寫返回點。

## 五、不變量

- 第三章仍不得出現「慣性、參考系、相對運動、加速座標、引力」等答案詞。
- 物理正解、證據取得條件與自由卷宗機制不變。
- 猜錯紙、分類失敗、預測失準、辯論答錯不扣全域信譽。
- **本轮信譽增量**不刪除或改名現行節點；`C0-2` 只插入兩個公開問答節點，另增各章修復場。這不等於宣稱第四章 v0.8 重構前後 id 未變；其既有 schema 1→2 變動由 19 組／205 舊游標遷移另案接住。
- **本轮信譽增量**不再升 save schema；新增的 `reason` 只進 event log。第四章沿用 v0.8 已完成的 schema 1→2。舊存檔可繼續讀取；第三章早期合法存檔中「已做過限縮、但尚無信譽事件」的精確舊形狀以窄相容條件放行，空殼偽旗標仍須拒絕。
- `state.rep` 與第三章辯論內部的 `debate.rep` 不合併；後者玩家可見名稱固定為「說服力」。
- `rep` 事件的 `at` 必須命中章別來源登錄，且增減方向、幅度與 `reason` 必須吻合；未知來源採 fail-closed。既有舊存檔來源要以明列的 legacy 規則相容，不得重新打開「任意來源皆可匯入」。
- 每一筆正向信譽必須能在同一事件帳找到來源操作：選項、證據取得或引擎行動。修復加分還必須證明同一輪已經「歸零鎖定 → `repairEnter` → 玩家完成修復操作」，不能只憑合法理由字串直接領取。
- 非修復正向來源只能兌領一次；多個前置操作須依 runtime 順序出現，不能反序，也不能讓同一次操作支付兩筆加分。修復來源可以跨輪再用，但每一輪只認該輪 `repairEnter` 之後的新修復操作。
- 信譽事件須與章別實際狀態相符：第四章退出作者欄的 `rep` 與 `lab` 必須是同一動作產生的相鄰事件，`lab` 只能有一筆，且其 `sequence` 必須逐值等於 `authorField.removedAt`；第五章 `J4` 加分必須依序對上唯一的 `J1 → J2 → J3 → debateInit → P2/P1/P3 擊破 → J4@debate.fr5 → debateWon`，並核對三份工作台證據、三柱、最後反撲與 `fr.resolved` 的現態。只翻狀態位元或補一段勝辯尾事件，不構成合法存檔。
- 匯入淨化是**非密碼式的一致性守門**：它拒絕 runtime 不可能產生的局部或互相矛盾狀態，不宣稱能阻止使用者同時重造整份彼此一致的 client-side 存檔。若未來要做防作弊或可信簽章，須另立伺服器／簽章架構，不能把那個威脅模型偷塞進本地 sanitizer。
- 第二章舊版 `B0-2/q1.a` 曾合法產生「有 choice／rep、但沒有 reason 與首次旗標」的存檔。匯入時只在該窄形狀成立時補回帶遷移標記的 `ch2BallisticsScopeBlurted` 旗標，避免續玩後重複扣分；遷移後再存再讀必須冪等，缺原 choice 的偽舊紀錄仍拒絕。
- `reason` 同時是玩家看見的說明與存檔驗證值。修改任何信譽理由時，必須同步 `src/sanitize.js` 的 `reasonRules` 與負向測試；這是現行無 schema bump 的刻意耦合。未來若拆成穩定 `reasonCode`＋可改文案，須另立存檔遷移。
- 正式 UI 的唯一狀態提交入口是 `chapter-ui.js` 的 `setState()`；每次操作在儲存與重畫前先執行 `redirectIfLocked()`。因此歸零當步即離開原工作台並進修復場，不能把繞過 `setState()` 的連續底層 API 呼叫描述成玩家可達行為。

## 六、驗收

1. 一至五章所有 `rep`／`repDelta` 皆有可讀理由；答對一般物理題、預測失準與實驗失敗不得改變全域信譽。
2. 第一章兩個舊的答題獎勵已歸零；第二、三、四、五章的同一越界重試不得重複扣分。
3. 五章皆有不靠測試人工指定 `rep=0`、能由不同失信行為自然扣至零的路徑；歸零後導入正確修復場，保存返回點。錯誤修復不得回補或離場，正確修復才回復至 1 並返回原游標。
4. 第三章黃金路徑能看見伽桑狄把卷宗權交給旅人的明確理由。
5. 第四章退出作者欄的加分只發生一次；錯誤九宮格預測不扣分。
6. 所有 rep 變動都能觸發附方向與理由的 HUD 回饋；第三章說服力仍是獨立量表。
7. 第三章禁詞 lint、五章資料鏡像、舊游標、全章走查、存檔與全套測試維持綠燈。
8. 負向控制：移除受保護的扣分、重複防護、修復路由或 HUD 理由時，契約測試必須轉紅。
9. 匯入負向控制：憑空注入一般 +1、五章修復 +1、錯誤增量、未知 `sourceId`、重複兌領、反序前置、借用上一輪修復操作、事件／章別狀態矛盾、只偽造第五章勝辯尾段、缺少或重複 `debateWon`、重複 J4 取得、第四章作者退出事件序號錯誤／缺失／重複／與加分事件不相鄰，必須拒絕；合法舊版答題獎勵仍須由原 choice 鏈證明，第二章 reasonless 舊越界須窄遷移首次旗標，第三章 `bounded` 的窄相容形狀維持可讀。
