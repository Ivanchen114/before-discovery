# 總監裁決:戲劇完整度四律・全面展開(2026-07-27,同日第三號)

**裁決**:A/B 展開原型(`spike_workshop/spike_ch3_c1r4_expansion_ab.html`)實玩後,總監裁:**採 B 展開版**。原話:「我個人是喜歡 B,這樣才有順暢感。」
**意義**:推翻「先原型後全面」的觀望條款(設計原則 K 節紀律③已由本裁決結案)——展開為**全系列標準**,不是關鍵場限定。原則 63–66(三拍展開律/認知停頓/角色反應權/轉場不得不)自本日起為**新章硬約束**,既有章走展開批次。

## 一、判準(避免「寫豐滿一點」變成空話)

- 展開的目的是**場面完整**,不是字數。判準仍是原則 K 節引言那兩句:精簡而完整者不動(「下面是發生過的事。上面是你準備拿它說的話。」);資訊完整而場面不完整者展開(「這一筆只能寫未分類。」)。
- 展開**不得**:新增未取得的證據、讓 NPC 代玩家診斷(原則 61 高於本節)、增加玩家必須點擊才能通過的判斷數(拍數增加=閱讀,不等於操作增加)。
- 每一場展開後自問三題:誰先發現異常?誰回應了誰?玩家在哪一拍以為成功了?

## 三、工程紀律(節點暴增的三個地雷)

1. **存檔相容**:新增節點=節點 id 增加。既有存檔停在舊 id 上必須能安全遷移(既有 `loadSave` 四分類+版本 schema 沿用);每批次跑存檔往返測試。
2. **演出節奏**:展開後每場文字量增加,**逐字機速度與 ack 機制須實測**——原則 8「演出永遠等玩家讀完」不得因拍數變多改成自動連播。手機橫屏(844×390)一次可見行數要重測。
3. **金路徑回歸**:每批次跑該章黃金路徑+錯誤路徑;禁止「既有測試仍綠」代替新場面驗收——展開屬表現層,**新增契約僅限「節點連續性」與「存檔遷移」**,不為文字加 lint(避免把戲劇綁死)。

## 四、Sol 分工

Sol 對抗審重點(交接時附本檔):①展開是否偷渡新證據或代玩家診斷②角色反應是否符合各自聲線與職務(水手不看紙、艾蒂安對數字敏感、馬蒂厄只認紙上有沒有)③認知停頓是否真的停在「以為成功」而非提前洩答④手機橫屏與逐字機節奏。生圖不受本裁決影響。
