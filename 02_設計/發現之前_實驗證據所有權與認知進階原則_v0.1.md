## 一、不可退讓的核心

### 1. 原始結果不等於證據

跑完實驗只代表「有了紀錄」。只有玩家完成下列三件事，系統才可授予證據：

1. 選出要引用的紀錄；
2. 說明這些紀錄比較了什麼、控制了什麼；
3. 選出資料真正支持、且沒有超出邊界的主張。

因此禁止：跑滿次數就自動取得證據、NPC 代替玩家完成歸納、系統把正確結論寫在按鈕上。

### 2. 標準實驗循環

每個核心實驗依序經過：

> 問題 → 器材踏查 → 預測 → 取得原始紀錄 → 選資料 → 選概念／提出斷言 → 取得證據 → 帶進質詢

可依劇情省略非必要步驟，但不可省略「玩家提出斷言」。如果某章只剩操作與自動頒證，視為玩法回歸缺陷。

### 3. 器材踏查不是尋物遊戲

- 踏查的目的，是讓玩家知道每件器材控制哪個實驗條件；必要件不得藏在像素角落。
- 固定且唯一的骨架直接安裝並說明責任，不製造假選擇。
- 有替代件且會改變讀值時，才讓玩家選擇、比較與承擔代價。
- 踏查完成後，實驗室只呈現真正有意義的選項；已解釋的固定件標示「已固定｜無須更換」。

## 二、跨章認知進階

章節升級不是把數字和欄位越堆越多，而是提高玩家對「什麼算證據」的要求。

| 章節層級 | 玩家主要工作 | 完章應掌握的判讀 |
|---|---|---|
| 第一章：規律 | 從重複量測辨認數列並押下一筆 | 資料是否穩定、預測是否命中 |
| 第二章：比較 | 控制裝置與變因，選成對資料比較 | 只改一件事時，結果是否隨它改變 |
| 第三章：模型 | 從多種船況與觀察位置挑選來源，限定主張 | 同一事件可有不同描述；證據能排除什麼、不能證明什麼 |
| 後續章節 | 模型競爭、精度、異常、可辨識性 | 以最少額外假設解釋最多觀察，並保留未知 |

第三章因此不追求比前章更多的無意義數字，而要求玩家辨認：停船基準、穩速紀錄、加減速反例、船上／岸上兩份同步紀錄，各自能支持哪一層主張。

## 三、時代盲點與誘答設計（v0.1.4）

**總監裁決（2026-07-26）：概念收，值得成為《發現之前》的招牌。但不是每章一題的配額。**

> **每章都要讓玩家為自己的主張範圍負責，但不必每章都騙玩家一次。**

「誘答」只是表現方式；核心是**玩家親自站進那個時代看似合理的盲點，再用自己的紀錄走出來**。

### 3.1 原則

> 當一個時代性的錯誤推論**能由玩家現有資料自然導出**，也**能由同一份資料診斷與修正**時，應優先讓玩家**先提交主張**，再親自撤回、縮窄或補做實驗。
> **不得靠虛構資料、明顯錯句或 NPC 權威製造陷阱。**

為什麼值得做：盲點是那個時代真的絆倒過人的地方，玩家踩到會發現**自己剛剛就是那個時代的人**。遊戲叫《發現之前》——發現之前的人不是笨，是站在一個看起來很有道理的位置上。玩家沒親自站過那個位置，就沒真的體驗過「之前」。

### 3.2 六條底線

| # | 底線 | 說明 |
|---|---|---|
| 1 | **作答前，診斷錯誤所需的資料必須已經可見** | 原紙要寫齊條件（船名、桅高、操作者、划槳方式…）。玩家不是靠運氣避開，是靠細心讀 |
| 2 | **誘答要真的合理** | 不得只靠「任何、一定、完全、全都、絕對」替錯項插旗。若主題正是適用範圍，所有選項都要同樣明確地交代範圍，不能只有錯項使用極端量詞 |
| 3 | **玩家先承諾，之後才揭露質疑** | 質疑早於承諾＝提示。順序不可反 |
| 4 | **NPC 可以指向欄位追問，不能替玩家說出完整診斷** | 「操作者一樣嗎？槳法呢？」可以；「你同時改了多個變因」**必須由玩家自己選出來** |
| 5 | **失敗只打掉主張** | 原紙、數據與進度全部保留 |
| 6 | **玩家必須親自選擇**縮窄主張、撤回，或回去補實驗 | 系統不代為降級 |

**補充判準（用於判斷底線 1 是否達成）**：**陷阱的反駁必須在玩家自己的紀錄裡可被指出。** 只能由 NPC 宣布＝靠權威教學＝玩家記得結論、不記得憑據。

**史實邊界（分兩層，不可混用）**：
- **核心盲點**要有當代思想或史料依據。
- **具體玩家錯誤**可以是符合當時器材、知識與方法的**教學重建**，但**章末史實頁必須說明**（沿用第六節）。

### 3.3 資料誠實：誘惑只能由模型自然產生

**不得先決定要誘惑玩家，再反向調整 fixture 製造趨勢。** 所有讀值先由物理正確、史實可接受且可重現的條件生成；誘答只能利用這些真資料中自然存在的相關、缺欄或範圍空隙。

| 資料形狀 | 設計判斷 |
|---|---|
| 為了讓錯項看起來合理，任意調數字造出趨勢 | ❌ 教學目的凌駕模型，禁止 |
| 資料一攤開就反向或自我否定 | △ 不是錯誤物理，但沒有形成值得玩家承諾的盲點 |
| **物理模型自然產生看似支持的相關，且同一份紀錄保留可診斷的其他條件** | ✅ 可以成為誘答 |
| 趨勢與單一變因完美成比例 | 不自動等於因果證明；但遊戲若要用「比例不吻合」反駁，就不得生成完美比例。必須承認資料中真正存在的相關，再由玩家指出控制或範圍不足 |

**自檢順序**：

1. 先列出每趟實際改變的條件，再由模型算結果；不可先寫理想錯項再配數字。
2. 把生成表與預定反駁並排；反駁只能使用作答前已在原紙上的欄位。
3. 台詞說有幾個條件同時改變，fixture 就必須真的讓那些條件改變。
4. 若資料確實呈現相關，NPC 與系統不得把「相關存在」也說成錯；只能否定超出資料的因果或全稱主張。

### 3.5 重用規則（取代 v0.1.1 的「不得重複」）

v0.1.1 寫「第五章起不得重複任何種類」——**算術上不可行**，二十四章一定會重逢某些推論錯誤。改為：

> **相鄰兩章不使用同型主誘答。** 日後重用同一型時，**必須改變玩家動作、證據載體或修正方式**至少一項。

判準與原則 58 同源：形式可以重複，**要求必須升級**。ch1 的混淆（NPC 即時診斷）→ ch3 的混淆（玩家提交並在辯論中辯護）就是合格的重用。

### 3.6 出貨檢核（誘答專用）

- [ ] 診斷所需資料在作答前已可見。
- [ ] 錯項不靠「任何／一定／完全／全都／絕對」這類詞單獨暴露；範圍題的所有選項具有同等清楚的範圍標示。
- [ ] 質疑出現在玩家承諾**之後**。
- [ ] NPC 只指向欄位，完整診斷由玩家選出。
- [ ] fixture 先由模型與條件生成，沒有為了誘答反向調數字；預定反駁與資料真相一致。
- [ ] 負向自動測試：玩家做出該錯誤推論時被擋，**資料未被刪除**。
- [ ] 錯誤主張留下可回看的撤回／縮窄痕跡；存檔往返後仍成立。
- [ ] 無提示試玩能確認玩家是因為相信推論而選誘答，不是因為看不懂文字。
- [ ] 手機與桌機作答時，診斷所需欄位能同時看見。
- [ ] 該盲點在章末史實頁有揭露；教學重建者另加說明。
- [ ] 主誘答型別與相鄰章不同。

### 3.7 證據判斷可否證契約（v0.1.4）

凡玩家是在判斷「哪一句受這批紀錄支持、否證或仍不能裁決」，設計 contract 必須
標為 `kind: evidence_judgment`。純關係、態度、角色扮演、導航與操作方式選擇不
強迫套用。

最低要求：

1. 決策本身與每個選項都不得預選。
2. 可接受主張至少有一個 `supportedBy`，指出來源、可見欄位與成立條件。
3. 每個錯項至少有一個 `refutedBy`，指出玩家必須翻哪張紙、讀哪一欄才能否掉。
4. `refutedBy.relation` 只使用 `contradicts`、`confounded`、
   `out_of_scope`、`insufficient` 四類。若只是資料不足，必須標成
   `insufficient` 並說明缺少的對照或範圍，不得硬寫成物理上相反。
5. 被引用的來源與欄位必須在作答前已取得、可見且能回查；提交後才出現的資訊
   不能當成公平反駁。
6. 玩家先提交，系統與 NPC 才能揭露質疑；失敗只打掉主張，原紙與操作痕跡保留。
7. 經 Design Gate 確認為科學判斷的 decision 要另列在 `decisionRegistry`；
   施工者不得只把 kind 改成 `narrative` 來逃避檢查。

最小結構例：

```json
{
  "id": "ch3.p1.concept",
  "kind": "evidence_judgment",
  "preselected": false,
  "options": [
    {
      "id": "shared-motion",
      "isCorrect": true,
      "supportedBy": [
        {
          "sourceId": "A1",
          "field": "landingOffset",
          "condition": "near_zero"
        }
      ]
    },
    {
      "id": "small-lag",
      "isCorrect": false,
      "refutedBy": [
        {
          "sourceId": "A1",
          "field": "landingOffset",
          "relation": "contradicts",
          "condition": "no_systematic_lag"
        }
      ]
    }
  ]
}
```

`condition` 必須對應該章已核准的模型、容差與量綱；跨章法源不替各章發明數值門檻。
若題型允許多個可辯護答案，不能為了符合單選 schema 強迫只留一個正解，應先把
題目改為範圍判斷或明示多選。

**機械層可以保證**：欄位存在、source／field 可解析、作答前可見、先承諾後揭露、
錯項不缺 `refutedBy`、已登記的 decision 不被降型逃檢。

**機械層不能保證**：錯項真的像當代人會相信、指定欄位在物理與史實上真的足以
反駁、文字是否靠荒謬或極端量詞洩答。這三項仍須物理／史實審查、陌生玩家試玩與
對抗審；不得把 presence check 冒充誘答已可信。

### 3.8 認知錯誤雙層回饋（v0.1.6）

玩家提交錯誤的資料組、判讀或主張時，不得只回傳「不成立」「超出範圍」或內部
錯誤碼。回饋分成兩層：

1. **介面短診斷**：保留一句可掃讀的結果，例如「所選原紙的條件欄不一致」。
2. **人物質詢**：由當場實際負責該欄的科學家或操作人員，接住玩家剛提出的話；
   回應必須直接引用所選原紙、可見欄位或封存預測，指出「這批紙少了什麼、混入
   什麼，或主張越過哪一條邊界」。

人物質詢仍受 §3.2 底線 4 約束：可以把玩家指回欄位，不能替玩家念出完整正解。
質詢後回到同一決策，原紙、錯誤主張與操作痕跡都保留；玩家必須親自重選、縮窄
或補做。

下列情況**只使用介面提示，不啟動人物對話**：未選資料、空白欄位、無效數字、
步驟順序錯誤、尚未完成前置工作、重複按下已完成操作。這些是操作狀態，不是值得
人物出場質詢的科學主張。

出貨檢核：

- [ ] 認知錯誤先留下玩家實際選的主張，再由人物回應。
- [ ] 人物至少指出一張已見原紙或一個可見欄位，不只說「再想想」。
- [ ] 人物沒有直接報出正確選項全文或替玩家自動縮窄。
- [ ] 同一次失敗只觸發一次質詢；重繪與讀檔不重播。
- [ ] 純操作錯誤沒有被戲劇化成冗長對話。

| 取得紀錄 | 設計航次 → 看動畫 → 生成觀察者原紙 → 簽名收卷 | 動畫、原紙與卷宗必須使用同一份資料；資料不自動成為證據 |

## 五、視覺與回饋

1. **世界圖負責情境**：器材的位置、規模、使用方式與歷史氛圍由場景圖／物件圖呈現。
2. **程式圖負責物理**：讀值、落點、軌跡、同步標記與可切換參考物使用 HTML／SVG，避免把答案畫死。
3. **每種實驗有不同可見狀態**：停船、穩速、加速、減速、船艙滴水、拋接、船上紙帶、岸上紙帶不得只共用一個靜態圖示。
4. **紀錄與證據分色分階段**：原始紀錄是中性墨色；玩家斷言成立後才出現金色證據脈動與證據卡。
5. **證據可追溯**：旅人筆記的證據卡必須能展開來源紀錄、玩家選的主張與適用邊界。
6. **失敗要說人話**：回饋指出「少了哪組資料」「混入哪種船況」「這個主張超過資料能說的範圍」，不顯示內部代碼。

### 5.1 全章證據解鎖與配圖契約

本節適用於任何章的實驗、觀測、史料、作圖、計算、對帳、封存、署名或出版
證據，不以是否採用左右頁工作台或柱式辯論為前提。

1. `state.evidence[code]` 從未取得轉為已取得，是 canonical acquisition event；
   台詞關鍵字只可作舊資料 fallback，不能成為新章主契約。
2. 有取得台詞時的結構化 `item.evidence`，與沒有取得台詞時直接發出的
   `bd:evidence`，必須匯入同一個 `playEvidenceGain()`，每次狀態轉移只播放一次。
3. 解鎖儀式至少同時提供：證據圖、`◆ 新證據已收入旅人筆記`、非單靠顏色的金色
   標記／脈動及可關閉的雙音 chime；不以放大正文字級當獎勵。
4. 每章 `scenes*.json.evidenceNames` 宣告的每個 code，都必須有
   `assets.evidenceVisual[code]`；每個映射至少含可解析圖像、alt 與 caption。
   取得特寫與旅人筆記共用同一映射，不得另造兩份真相。
5. alt／caption 說明玩家看見什麼及其證據邊界。歷史重建圖明示「重建／意象」，
   不冒充原書頁或原報告掃描；可驗算數字、軌跡與方程使用確定性 SVG／HTML，
   生成圖只承擔器物、材質、空間與情緒。
6. 每份 runtime 圖像映射都要指向可追查的來源母版／生成 ledger；缺 runtime 檔、
   alt、caption 或來源母版，任一項皆視為未完成。
7. 全章契約測試由所有 `evidenceNames` 即時盤點，不維護手寫舊章 allowlist；同時
   驗結構化取得、無台詞取得、一次性播放、映射、runtime 檔與母版。
8. 進度只列已取得證據；未來不做答案清單，只顯示當下目標與取得條件。

## 六、歷史誠實邊界

- 玩家參與史料空隙中的組裝、測量與判讀，不取代真實科學家。
- 教學代理、合理重建與虛構串接必須在章末史實頁揭露。
- 不得偽造精確歷史讀值並冒充原始史料；fixture 是可重現的遊戲模型，文件需明示其身分。
- 一個反對意見失效，不等於整套宇宙論已被證明。
