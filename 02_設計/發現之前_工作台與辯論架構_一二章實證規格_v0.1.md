# 〇、一句話：一二章 pattern

**工作台＝一本攤開的實驗簿：左頁是裝置，右頁是紀錄與斷言。玩家在左頁下拉選單裡組裝，右頁一次一筆累積資料，勾選資料才能提出斷言，帶著斷言上辯論台。**

這句只描述第一、二章已驗證的介面 pattern；跨章真正不可省略的責任在下一節。

# 一、跨章只保留三項認知責任

```
① 留下可追查紀錄
② 玩家親自解讀並提出有限主張
③ 以可見證據公開支付，成功與失敗都有可讀後果
```

章別可以用實驗、觀測、史料對讀、作圖、對帳、封存或出版支付，不要求左右頁、
`<select>`、一次一筆或柱式辯論。每個公開追問都必須有玩家可見、可指名的證據，
但追問數量由命題與劇情決定。fixture 的數值計算可由引擎完成；選什麼資料、
如何解讀與主張到哪裡仍由玩家完成。

第一、二章把三項責任展開成「器材踏查 → 左右頁工作台 → 勾選紀錄與斷言卡 →
柱式辯論」。以下 §二～八記錄這個 pattern，供確實採用相同工作台語法的任務參考，
不是新章的預設外形。

# 二、器材踏查（`:1140`、`:1254–1295`）

| 規則 | ch2 實證 |

| **踏查的目的是「知道每個部位控制什麼」，不是找東西** | `:1140`「踏查已說明每個部位控制什麼；現在真正要選的是各部位的做法。」 |

# 三、工作台版面：左頁裝置／右頁實驗簿（`:1236`、`:1305`）

| 元件 | 規格 | ch2 行號 |

| 標題列 | `I　裝置與校準` ＋ **狀態標籤**（「尚未組好」／「可以放球」） | `:1239–1240` |
| **大圖持續可見** | 裝置母圖 ＋ figcaption 說明零件會影響什麼 | `:1241–1243` |

| 部位說明側欄 | 見第二節 | `:1246–1253` |
| 校準列 | ○/✓ ＋ 名稱 ＋「校準・1 天」／「已校準」 | `:1296–1303` |

**⭐ 選「哪一個」用 `<select>`；做「執行／封存／翻頁／簽名／送印」用按鈕。**

一二章是**兩者並用**（`:1277–1291`）：`<select>` 選零件 → 按鈕「裝上零件」執行。

- **一個變因＝一個下拉**（必要時加一個確認按鈕）。
- **不得用一排按鈕代表一個變因的互斥選項**——那會讓「一次只改一項」看不出來，也會把版面撐爛。
- **動作按鈕留著是對的。** 第四章有 88 個 `ship3Btn`，多數是封存、跑、翻年、接線、送印——**那些不該改成下拉**。照字面把按鈕全改掉是誤讀本條。

理由（總監 20260726 裁決）：一二章是下拉，玩家的手感建立在那上面。
（註：20260726 上午曾裁決改按鈕，同日下午改回下拉；晚間依第四章實查補上「變因／動作」的分辨。**本檔以此為定案。**）

### 斷言卡的文案契約（`:1320`、`:1323`）

- 未取得：**寫出取得條件**，例如「選一組可用數據＋概念後取得」「完成銅球／木球比較後取得」。
- 已取得：**寫出斷言內容＋引用的紀錄編號**，例如「高度 ×4，射程約 ×2（引用 #3）」。
- 全部取得：`◆ 完整證據已收入旅人筆記`（`:1324`）。

> **⭐ 總監要的「拿到斷言或證據要有圖示表示」＝這張卡。** ch2 已實作；ch3 目前沒有等價元件。

### 3-2b 證據解鎖與配圖（跨章契約已移出）

全章通用的證據狀態、一次性解鎖、`evidenceVisual`、caption、母版與全量測試，
唯一法源為《實驗證據所有權與認知進階原則 v0.1.5》§5.1。本檔只保留「斷言卡
如何在一二章右頁呈現」的介面樣本，不再另抄跨章契約。

### 3-2c 目的卡（每相位／每輪開頭）

**每個實驗相位開頭必須回答「為什麼做這個」**：`這一輪要回答＿＿` 一句白話 ＋ 科學家一句 in-world 台詞。ch2 的任務卡（`:1310–1313`）與 ch4 的 `orbit4Mission` 目的欄（RUNTIME-CR-019）是兩個實作樣本。

- **目的優先接玩家自己留下的問題**（例：ch4 vectors 引用玩家在 ch3 末頁親手寫的「月亮為什麼沒有沿直線離開？」）——玩家自己的問題就是最強的動機，不需另造。
- 玩家操作的若是**模型而非實物**（紙上模型、帳本），目的卡必須講明（例：「月亮搬不進工作室；搬得進來的是規則」），否則玩家會問「為什麼可以操控月球」。

### ⚠ 邊界：進度可見 ≠ 未來清單

**已取得的證據全列（✓）；未來的證據不得演成打勾清單**——只亮「這一輪追的那一張」（○＋取得條件）。既有契約測試明文禁止把未來證據做成 checklist（進度感來自筆記變厚，不是點亮代碼清單）。**若要五張全列，須先由總監修改該治理測試。**

# 五、執行實驗：一次決策，不等於一次滑鼠點擊（`:1341–1364`）

> **⭐ 適用範圍（20260726 依第四章實查補訂）**：本節只管**玩家親手操作的實驗**（放球、撞車、放石頭）。
> **模擬與計算可以一次跑完**——玩家不可能親手把行星軌道跑三次，手動按三次只是無決策的苦工。
> 此時玩家的「一次一筆」動作改為**封存預測：一次封一項，不可逆**（第四章在 `vectors`／`scale`／`planets`／`comet`／`models` 各一次，比一二章更嚴格）。

| 規則 | 實作判準 |
|---|---|
| **玩家每次操作都要有新決策或新觀察** | 若三回之間沒有任何可改條件，按一次執行固定三回，避免無決策重按 |
| **重複資料不得被平均值吃掉** | 三回仍各留編號、原始值、條件與異常；UI 可包成一組，但可展開逐張查看 |
| 每回有新預測或新調整時仍分開操作 | ch1／ch2 單次放球若下一回可改高度、材質或預測，維持一次一筆 |
| 時間成本依真實回數計算 | 一鍵三回仍花三回的天數；省的是重複點擊，不是劇中時間 |
| 放棄一組要明講**紀錄保留** | 「放棄這組（紀錄保留）」（`:1364`） |
| 結果訊息說清楚可用／不可用與偏差 | `:1359–1361` |

> **⭐ 總監更新裁決（20260730，取代 20260726 的「要三回就按三次」）：**
> 「做幾回」仍不是玩家可任意調整的實驗變因；但沒有新決策的三次重按也不是玩法。
> 因此以**一次決策執行一個預先承諾的重複系列**，保留每回原紙，斷言門檻仍檢查
> 至少三筆同條件資料。第三章詳見 CH3-CR-027。

# 六、斷言：重點在選對數據，不在選對句子

**總監裁決（20260726）：斷言選項只留現階段正確的那一句，不給三選一。**

理由：**玩家已經知道這一輪的目的**（右頁任務卡寫著），所以難度不該放在「猜哪句話對」，而該放在：

```
設計實驗 → 得到需要的數據 → 勾選正確的數據 → 斷言成立
```

因此判定與提示落在**數據**上，不在句子上。錯誤要能分辨：

| 玩家的錯 | 提示（在斷言區下方，不彈窗） |
|---|---|
| 勾選筆數不足 | 「這句話要能重現。目前只勾了 N 筆，至少要三筆同樣做法的紀錄。」 |
| 勾到變因不同的紀錄 | 「這幾筆的〔某欄〕不一樣。混在一起，就分不出是哪一項造成的。」 |
| 勾到條件不乾淨的紀錄 | 「其中有一筆是徒手放的。手可能多推一下，這筆不能替『走穩』作證。」 |
| 該輪要求的對照缺一半 | 「還缺停泊那一組。只有平駛，沒有東西可以比。」 |

> 此處與《實驗證據所有權與認知進階原則 v0.1.5》§三「誘答」**不衝突**：
> **誘答放在「這句話寫在多寬的範圍上」（辯論台的 scope 步），不放在「這句話對不對」（工作台的斷言步）。** 工作台是取得證據，辯論台才考範圍。

### 6-1 斷言成立必須有人接住

斷言成功不是資料庫寫入提示。畫面必須依序支付：

1. 玩家角色把「引用哪組資料＋有限斷言」說出口；
2. 最相關 NPC 指名核對條件、範圍或缺口；
3. 證據圖與收入筆記提示出現。

NPC 不得只說「很好」「成立」；若刪掉所選資料，回應就應失去意義。這也是檢查回應是否真的針對玩家工作的最小測試。

### 6-2 完成後可重播，但不能重做狀態

- 工作台應提供「重播這組紀錄」；旅人筆記應列出已完成資料組並可再次重播。
- 重播只讀既有原始資料，不得再呼叫產生資料、增加天數、解鎖證據、改信譽或寫事件帳的 action。
- 重播畫面標明「既有紀錄」，與真正的新實驗分開。
- 從工作台或旅人筆記啟動重播，必須定位到動畫本身；不得只重新渲染就把玩家捲到工作台頂端。
- 旅人筆記同時保留證據圖、資料組摘要與逐回原始紀錄；只有證據圖、沒有原始數據，不算完整筆記。

### 6-3 斷言後必須離台、對話、再入

當一項斷言成立並開啟下一個實驗階段時，不得只在同一張工作台上插播幾句對白就直接更換任務卡。畫面必須依序支付：

1. 收起工作台，回到人物與場景可見的對話舞台；
2. 完成 §6-1 的斷言簽收，並由人物的動機或眼前矛盾提出下一個問題；
3. 若下一步是「研究策略」（先查什麼、怎麼排除變因、主張限到哪裡），在對話舞台上讓玩家選；若是器材參數（鼓點、放手法、觀察位置），保留在工作台；
4. 對話全部讀完後，才顯示一個文意明確的再入按鈕（例如「進入船艙實驗」），由玩家親手進入下一階段。

「自動捲到下一區」、「工作台不消失但上面出現對白」、「對話還沒讀完就可按再入」都不算過關。若實驗全數完成，就把玩家帶往辯論或下一場；沒有新證據、新邊界或教學價值的「選做補強」不得擋在主線出口前。

**機械契約**：斷言成功路徑必須可驗出「工作台隱藏」、「對話佇列」、「再入 token／按鈕」三者同時存在；刪掉任一層，測試必須轉紅。

# 七、辯論台：柱數由劇情決定，每個追問都有可見的證據支付

`debate.json` 既有結構（章節通用）：

```
chapter.pillars[P] = { title, statements[], playerCorrect, breakReply }
chapter.fr        = { open, explore, scholar, assertion, trap/claim, closeReply }
```

| 規則 | ch1／ch2 實證 |
|---|---|
| **柱數不寫死**；依劇情可為二、三、四柱或其他數量 | ch1／ch2 現況各三柱，但三不是跨章契約 |
| **每柱由玩家指名一項或一組證據回答** | `statements[].weakTo:{evidence}`；若追問分段，可逐段追加另一組紙 |
| **玩家必須把論證說出口**（`playerCorrect` 是一整句台詞） | 按鈕不得直接跳 NPC 下一句 |
| 說服力歸零不刪資料 | 破掉的支柱保留、原紙保留 |
| 失敗可回工作台補證據 | ch3 `C3-F` 迴路 |

> **⭐ 總監原話：「拿到斷言或是證據要有圖示表示，然後辯論才可以選來對抗。」**
> → **證據卡是工作台與辯論台之間唯一的介面。** 工作台產出的斷言卡（§3-2）要能在辯論台被選來出示。

### 7-1 證據必須攤開，不能只剩答案按鈕（20260729 試玩裁決）

- 問「哪組紙能證明」時，**所有目前已取得、可在本輪引用的證據包都要同時攤開**；不能只顯示三個被設計者挑好的文字答案。
- 每張證據卡至少標明：
  1. 所含原紙編號或資料組；
  2. 船況／實驗條件；
  3. 觀察位置與參考物；
  4. 本組改了什麼、固定了什麼；
  5. 最多能支持到哪個範圍。
- 進入後續判讀題時，畫面必須持續顯示「**現在判讀的紙**」及其條件。不得只寫「這張紙」「再看那張」，卻讓資料離開畫面。
- 錯選仍要讓玩家把該證據說出口，再由 NPC 指出「它回答的是另一個問題」；系統不得直接標紅正解。
- 原紙很多時，可以先組成可追溯的證據包，但卡上必須列出所含原紙；玩家仍可回卷宗查看每張原紙。

### 7-2 柱數與資料結構

- `pillars[]`／`pillarOrder[]` 必須資料驅動；呈現層不得把 `repeat(3, …)` 或 `p1→p2→p3` 當成跨章假設。
- 每增加一柱，都必須另有：對手主張、玩家可選證據、追問、正確論證、錯誤後果與回工作台缺口。只多一格進度條不算新增一柱。
- 在既有章節新增第四柱或更多柱時，除了資料定義，也必須同步檢查該章引擎的預設值、正規化／補欄、存檔 sanitizer 與 schema 遷移；UI 顯示為資料驅動，不代表底層狀態已自動支援新柱。
- 柱數增加是戲劇需求，不是難度裝飾。若第四柱只重問前三柱已支付的資料，應合併而非硬加。

科學／證據判斷的選項可否證契約不在本檔另抄；統一依
`發現之前_實驗證據所有權與認知進階原則_v0.1.md` §3.7 的
`evidence_judgment`、`supportedBy`、`refutedBy` 與作答前可見性執行。

### 7-3 必要點擊必須支付新的認知工作（20260731 試玩裁決）

每個必按動作至少完成下列一項：**選證據、做新推論、限制主張、親自轉換資料**。
玩家若已在實驗簿完成同一筆分類，辯論沒有新增反例、干擾變因或適用範圍時，
不得再把它做成計分題。

提問在施工前必須標記功能：

- `optional_probe`：可選的「問到底」，用來拆穿隱藏前提；
- `inference`：答案會改變後續證據選擇或主張邊界；
- `bridge`：只承接劇情，不得做成計分選項。

「問到底」不是每章必備的同名按鈕；只有在玩家真的需要拆前提時才出現。章別可以
用不同介面完成同一功能。

### 7-4 證據卡採漸進揭露（20260731 試玩裁決）

所有可用證據仍須同時攤開，但卡面第一層只顯示**圖、短標題、情境／觀察位置、
一句支持範圍**。固定變因、改變變因、資料缺口與原紙編號放進同卡的
「查看條件與原紙」展開區。不得把「全部可追查」誤寫成「全部細節同時佔滿畫面」。

### 7-5 章別備忘依認知任務改寫

第一、二章可沿用三柱辯論備忘；第三章必須說明共同前行、變速邊界與雙參考原點；
第五章依兩輪帳目改寫。第四章是出版校樣，不得為介面對稱套用三柱備忘。
章別不必共用文字或位置，但高負荷操作前與操作中都必須能重新叫出當章規則。

### ⭐ 終局形式不限於三追問（20260726 依第四章實查補訂）

「三支柱」假設了**房間裡有一個對手**。第四章沒有對手——它的對手是「同一條律必須同時吻合五組互相獨立的資料」，所以它的終局是**出版校樣**：五段證明各自接回來源、四項信用各自歸戶、機制欄留白。

> **終局的形式可以是「對手三追問」、「出版校樣五段接回」或其他。共同的硬要求只有一條：**
> **每一項證據都必須被玩家指名用途，而且指錯要有可讀後果。**

第四章完全滿足（接錯線＝壞校樣，錯稿保留）。**把第四章改成三柱辯論反而是降級**，因為它會把「跨獨立資料集核帳」壓回「說服一個人」。

# 八、反向設計：先定證據，再定變因

**設計順序必須反過來寫**（總監 20260726）：

```
1. 這一柱的追問是什麼？
2. 要回答它，需要哪一項證據？
3. 那項證據需要哪些紀錄（幾筆、什麼條件、要跟什麼對照）？
4. 那些紀錄需要玩家決定哪幾個變因？   ← 只有這一層才變成下拉選單
5. 其餘變因一律「已固定｜無須更換」＋說明為什麼
```

**第 5 步是控制難度的旋鈕。** 變因太多不是「自由」，是把設計責任丟給玩家。第一、二章的難度剛好，正因為每一輪只開放 2–4 個真正影響那筆證據的變因。
