實作入口：`greybox/src/stage/09-notebook.part.js`、`greybox/src/chapter-ui.js`

## 一、系統目的

旅人筆記不是「已拿到幾張卡」的清單，而是玩家在歷史探究中留下的可追溯工作面。它必須同時回答：玩家做過什麼、看見什麼、如何判讀、哪些內容已取得正式證據資格。

本系統固定分成四層：

1. **研究紀錄**：裝置設定、原始讀值、錯紙、封存預測、校樣、退件與未完成嘗試。
2. **玩家判讀**：玩家選過的來源、比較、有限定的斷言、撤回與重做痕跡。
3. **正式證據**：章別引擎通過取得閘門後寫入 `state.evidence` 的耐久成果。
4. **歷史參考**：史料、刊本與明示身分的重建圖；可供閱讀，不自動替玩家授證。

核心關係是：**研究紀錄不等於證據；玩家完成判讀後，只有通過章別取得閘門的成果才升格。**

## 二、單一真相與副作用邊界

- 研究紀錄必須由章別 state 重建，不得依賴當下工作台 DOM。
- 開啟、關閉、翻頁、展開舊紙與閱讀筆記皆為唯讀；不得增加原紙、改寫判讀、授予證據、改信譽或推進游標。
- 正式證據只讀取既有 evidence 清單；`bd:notebook-snapshot` 不得寫入 `state.evidence`。
- 舊存檔只有成果旗標、卻缺少操作紀錄時，須明示「未留存」，不得倒推出一套假歷程。
- 錯誤、撤回、中止、退件與被取代的紀錄不得消失；重做只能新增版本。
- 玩家可見文字使用人類可讀標籤，不得直接露出 `steel-only`、`time-not-squared` 等內部代碼。
- 正式證據圖不是另一份答案資料庫。底圖只提供物件、紙張與時代質感；路徑、讀值、封存值、殘差、判讀與裁決由當局 state 投影成 HTML／SVG。重做後應換成新投影，舊版本仍留在研究紀錄。
- 資產欄位責任固定如下：`projectionOnly: true` 表示任何結果與答案都只能由 state 投影；`neutralBase: true` 只允許讀圖器顯示已驗收的空白／非答案中性底圖，不得因此顯示預製路徑、數字、判讀或裁決。兩者同時成立時，畫面是「中性底圖＋本局 state 投影」，不是固定成品圖。
- 暫扣、污染與修復是同一份證據投影的處置狀態；取得提示、筆記縮圖、放大讀圖器與研究紀錄必須共用同一個可見性判斷，不得有任一入口繞過。

## 三、揭曉邊界的通用判準

旅人筆記不得成為繞過「先承諾、後揭曉」的旁路。只要某個欄位的存在或內容取決於玩家是否已承諾、是否已實測、是否已修復完整性，它即使存在 state 內，也不等於可以在筆記顯示。

1. **封存中**：只顯示玩家已承諾的預測與封存狀態，不顯示實測值、殘差或裁決。
2. **已揭曉**：只有章別引擎的可見性條件成立後，才顯示結果；有 `visible*` 函式時必須共用，不另抄判斷式。
3. **完整性暫扣**：原紙被暫扣、污染或等待修復時，顯示「已離開桌面／待修復」，不得藉 state 洩出原文。
4. **已修復**：原紙恢復可見，但事故、離台與修復歷史仍須保留。
5. **懸空引用**：找不到引用的輪次或裝置時，明示「本裝置未留存該輪紀錄」，不得靜默省略或拼接別輪資料。

## 四、正式章別投影對照

正式章別由 registry 機械列舉；新增章別若沒有非空、可讀且唯讀的 notebook handler，常駐測試必須失敗。

正式證據數量由每章認知義務決定，不追求卡數一致。研究紀錄可以多於辯論會用到的證據；第一章一張證據可拆成數個可引用子斷言，也不構成其他章必須照抄卡數的理由。

## 五、版本、舊紙與收合

- 被新版本取代的預測、主張、證明或校樣，一律保留並標示「舊版」「作廢」或「已被取代」。
- 同一類歷史超過三筆時，最新一筆直接可讀，其餘預設收合在 `<details>`；收合不得刪資料。
- 每筆至少顯示來源／輪次、條件、可見結果、目前判讀狀態；可取得時再顯示時間、版本、順序與失敗理由。
- 重播只讀既有紀錄且明示「不新增實驗」；沒有可靠重播路徑時只提供原紙，不偽造動畫。

## 六、介面與無障礙契約

- 左頁依序顯示「正式證據」「歷史參考」「研究紀錄（快照）」；完整劇情紀錄留在右頁。歷史參考不進 `state.evidence`，也不出現在辯論選牌。
- 同一證據含多張原紙時，讀圖器須逐張呈現，不得只顯示第一張；每張各有可讀替代文字，整組另有短圖說與文字版。若同組同時含中性底圖與烤入答案的舊圖，`neutralBase` 必須逐張標記：只顯示安全底圖，本局結果改由 HTML／SVG 投影，不得因同組有一張安全圖就放行其餘舊圖。
- 狀態投影縮圖第一層只放最少判讀線索；小字、完整數值與來源移到讀圖器 HTML 文字版，避免 844×390 把 SVG 小字縮到不可讀。
- 章別 handler 必須有穩定邊界，供行為契約抽取；缺資料仍須 `handled=true` 並顯示「未留存」，不可掉回空白 DOM 快照。
- 筆記內 `button` 與 `summary` 的最小觸控高度為 44px。
- 不以拖曳作唯一操作；鍵盤、觸控與讀屏都能打開正式證據、研究紀錄與舊版本。
- 844×390 橫屏可閱讀標題、目前狀態與首筆紀錄；長內容允許分頁或捲動，不可把橫向卡片推出可達範圍。
- 歷史參考在圖說與資產資料中標明原典、後世刊本或「依原典重建」，不得冒充玩家取得的原紙。
- 史料身分須同時出現在縮圖標題、圖說、替代文字與放大讀圖器標題；無可靠原件時只能標「依原典重建／教學重建」，生成底圖不得偽造可讀古文、數字或幾何答案。
- 第四章 K4 的四張有限變體均須從封存的 `evidencePackage` 決定，不讀當前 DOM 或重新推測借條狀態；每張的縮圖標題、圖說、替代文字與放大讀圖器都要明示「現代教學比較／固定簡化模型」，因精確殘差與週期差是現代重算，不是十七世紀原表。2026-08-14 白話封版 raster 已把未借狀態寫成「原結果保留」、兩借總結寫成「原先兩格對不上」；舊 Art-Lock 圖只留追溯，不得回接 runtime。
- 第四章 K5 的取得後圖固定使用六段證明鏈：「原有前進→持續改向→同一把尺→事前預測→三種天空→球殼定理」。圖說與文字版另列 Hooke、Halley、Flamsteed、Newton 的工作分工及「仍未回答引力如何隔空作用」的邊界；必須標為證明鏈教學圖，不冒充《Principia》原頁。

## 七、新章接入與常駐測試

每章在可試玩前必須回答：

1. 哪些 state 欄位是原始研究紀錄、玩家判讀與正式證據？
2. 哪個引擎轉移是正式證據的唯一取得點？
3. 哪些值在合法揭曉前須遮蔽，章別可見性函式是什麼？
4. 舊存檔缺歷程時如何誠實顯示「未留存」？
5. 被取代、暫扣與修復歷史如何追加而不覆寫？
6. 玩家可見錯誤碼如何翻成自然中文？
7. handler、證據放大與重播是否全部唯讀？
8. 每張正式證據的底圖與 state 投影如何分工？暫扣時四個可見入口是否一起關閉？
9. 歷史參考的原典、年代、版本、來源路徑與重建身分是否完整？

常駐測試不得只搜尋字串，必須：

- 依 registry 遍歷全部正式章別，實際執行 handler，檢查有工作時輸出非空。
- 對未揭曉／已揭曉、暫扣／已修復狀態比較實際渲染 DOM。
- 同一 state 連續開啟至少三次，深比較前後 state 完全相同。
- 用反向控制證明 handler 缺漏、永遠空白、提前揭曉或寫回 state 時測試會轉紅。
- 靜態契約只作輔助；不能以「檔案裡有某段字」代替玩家實際看得到。

缺任一項，不得只用漂亮證據圖宣稱旅人筆記完成。

## 八、驗收分層與未驗

- 自動驗收：章別投影、可見性、唯讀、資料完整性、反向控制與 CSS 觸控尺寸。
- 瀏覽器驗收：桌機與 844×390、焦點、展開收合、長資料、console。
- 真人驗收：是否找得到舊紙、是否理解「研究紀錄不等於正式證據」、讀屏順序與長局節奏。
- 測試全綠、commit、push、deploy、production smoke 是不同事實，必須分開回報。
