## 三、主岔口：A2-2/e1 第五段押值失手存活（v0.3.1，時序與載體依 Sol B-1/B-2 修正）

- **核心認知**：現行機制已是「押第五段」——`runExperiment()` 一次產生五段讀值存入 run，畫面只遮住第五段；玩家選 1–3 筆既有 run、輸入預測，`judge()` 揭露所選 run 的第五段。**球早就滾完了，答案一直在遮板下面**——押的是既成事實的揭曉，這比臨場滾球更符合本作母題：紀錄先於判讀存在，世界不等你。岔口＝把 `consistent && !predHit`（形狀站得住、押值失手）從冷處理升級成失敗弧線；器材混亂、選紙錯誤照原診斷迴路，不進此枝。
- **載體與定位**：六拍是**工作台演出稿**（既有 `sayIntoDialogue()`／`sayWorkbenchCorrection()` 序列），不是 scenes 節點；數字全用**原始刻度**（如緩坡 12/36/60/84/108），**不硬編**——UI 由既有 `claim.prediction`／`claim.observedFifth`／`claim.runIds` 畫押線與實測線。
- **錯法（自由輸入，不設計錯項）**：照抄第四段原值（勻速直覺）、只延伸最後一次差額、任意押值——predDev 統一判，世界一視同仁。
- **六拍**：
  1. **commit**——前四段原始讀值在紙帶上，第五欄封著。伽利略：「第五段在板子下面。它已經滾完了——先說它停在哪，再掀。」玩家選 run、輸入押值（現行機制零變更）。
  2. **world_action**——玩家的押值化為**押線**，覆在被遮的第五欄上（可移除的預測透明紙／蠟紙）。伽利略不評數字：「線畫在你說的地方。」
  3. **apparent_support（輕）**——押線在紙帶上看起來像前四段的合理延伸——掀板前，眼睛替它背書。旅人 OS 一句（劇本打磨）。伽利略手停在遮板上，不掀：「確定？」（四律 64 認知停頓）
  4. **reality_pushback**——掀開封存的第五欄。實測刻痕與押線錯開，兩線並列在同一張紙上。伽利略不說「錯了」——紙上兩條線自己說（裁決二數據反駁純形；`predHit=false` 現行判定）。
  5. **player_repair**——「押線不撕。旁邊，重押。」玩家回看四段差額、修改延伸方法、重押（現行重試迴路）。不扣 rep（F2；對照表確認 ch1 押錯本就無信譽事件）。
  6. **readback**——**押記紙可攜**（押線與實測線同紙，claims 保證其存在，舊存檔相容）。A3-1 大講堂：辛普里奧以書脊壓住講台上那張押記紙——「押錯的也帶來了？貴工作室的紙，比人誠實。」（確切文句劇本打磨；低成本案＝本版預設）
- **匯流**：修復拍後回現行 qOdd 判讀段（qOdd 自身維持 F1 一拍糾正，不動）。
- **保留痕跡**：押記紙（演出層）＋claims 既有紀錄；不新增證據卡、不新增 flag、不動 schema。
- **保護面（不可動）**：`judge()` 數值介面（規律假說引擎不開，未來另立 `hypothesis` 封套 R3 案）；GB-ADR-007/010/011；E4 駁回契約；A2-3 換球鉤；P2 柱不放讀回。
- **成本**：工作台演出稿 6–10 拍（需含**單筆與 2–3 筆平均**兩種畫面語意）＋A3-1 條件句＋UI 押線演出（Sol 施工規格定形式）；engine 零變更。
- **待總監劇本階段順裁**：讀回是否升級 P3 後玩家主動 `optional_probe`（中成本）——兩案並陳於劇本稿。
- **驗收問題**：「你押了多少？」「掀開之後你看到什麼——誰告訴你押錯了？」「後來講堂上有誰提起那張紙？」

## 四、讀回強化候選乙：P0-2 搶答延壽
