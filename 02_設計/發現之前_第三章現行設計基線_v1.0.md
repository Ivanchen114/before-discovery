# 《發現之前》第三章現行設計基線 v1.0

**章名**：《船艙裡的靜止》
**版本**：v1.0
**日期**：2026-08-04
**狀態**：CURRENT
**施工正本**：`greybox/data/scenes3.json`、`greybox/src/engine3.js`

## 一、章的核心問題

玩家不是替伽桑狄完成五張任務卡，而是在一份「看似互相打架」的航船卷宗裡，逐步補出漏掉的船況、觀察位置與共同時間。外層是破案；內層也必須維持因果：**上一輪留下的缺口或某人的反駁，逼出下一輪實驗。**

本章要讓玩家親手取得的不是一句現代術語，而是以下有限主張：

1. 船近似穩速時，桅頂落物仍落在桅腳附近。
2. 船況改變時，落點與紙上軌跡會改變；不能把不同船況混成同一結論。
3. 封閉船艙裡的局部滴水或落石，不能可靠分辨船是停著還是近似穩速。
4. 岸紙與船紙可以同時為真；兩張紙使用不同起點，必須先對齊同一拍再逐拍換算。

## 三、五輪因果鏈

1. **先讀舊紙**：玩家先判斷紙上到底記了什麼，抵抗「我知道未來答案」的誘惑。越界只傷信譽，不把物理錯答當失信。
2. **穩速基線**：舊紙缺船況，玩家補記放手方式、鉛直基準、觀察者與重複次數，取得 G1。
3. **船況反例**：艦長的舊落後紀錄不能被刪。玩家以墨水瓶／鬆木板類比先押加減速方向，再讓預測紙與落點紙並排，取得 G3。
4. **封閉船艙**：進船艙後是新一輪器材踏查。玩家選擇全輪固定使用「滴水」或「丟石頭」，停泊與近似穩速各做三次；不靠岸上船位資訊作弊，取得 G2。
5. **雙紙換算與公開複驗**：兩張紙先產生真正的矛盾感，不准刪掉任一張。玩家逐步確認同一航程、同一事件／同一拍、兩個零點，選換算方向並逐拍改寫，最後封存公開採信標準取得 G4、G5。

## 四、第三柱的玩家代理權

第三柱不得只讓玩家選一個答案名稱後由系統自動算完。現行順序固定為：

`同一航程 → 同一事件與同一拍 → 兩個零點 → 對齊共同拍 → 封存換算方向 → 每一拍逐點換算 → 檢查兩紙是否相容 → 限定結論`。

錯誤換算留在紙上，以直線、彎曲或錯位的可見結果回饋；玩家改的是下一步，不是抹掉曾做過的判斷。概念類比是「兩把尺：一把零點留在碼頭，一把零點跟著桅杆走」，但類比不能代替實際逐拍操作。

## 五、斷言與辯論

- 工作台先攤開可成立的斷言，再讓玩家挑原紙、讀差異、決定哪一組資料支持哪句；不先把「問題」當成題幹餵答案。
- `enterDossierDebate` 前須完成來源、範圍與必要操作；動畫／收卷接縫不可被直達按鈕繞過。
- 「問到底」產生可用洞見，證據配對錯誤降低論證對位；研究誠實越界才改信譽。
- 論證對位歸零只複盤錯配並保留原紙與已破支柱，不重做無關實驗。

## 六、歷史與敘事邊界

- 不讓角色提前說出「參考系」「慣性系」等現代總結；玩家先做出關係，命名可留到後設筆記。
- 局部不可分辨只限封閉、近似穩速的條件，不擴張成「任何實驗都測不到運動」。
- 風只可說本次散布內未見系統主因，不宣稱完全無影響。
- 初次艦長落後紀錄是真資料，只能重新分類，不能改寫落點。

## 七、裁決鏈與驗收

現行依 `GB-ADR-026`、`GB-ADR-028`、`GB-ADR-029`（未被取代部分）、`GB-ADR-031`、`GB-ADR-034`、`GB-ADR-035`、`GB-ADR-037`、`GB-ADR-040`、`GB-ADR-041`。

自動驗收包含資料鏡像、active 可達、legacy cursor 遷移、船艙器材承諾、第三柱逐拍換算、斷言來源與結論詞彙護欄。真人另驗「上一輪是否真的逼出下一輪」、錯圖是否看得懂、船艙是否像新一輪調查，以及 844×390 橫屏手感。
