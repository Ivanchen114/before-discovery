# 二、一個物理事實，決定了「船速」該怎麼放

`Δ(τ) = δv·τ − ½aτ²`。**式子裡沒有 `v_r`。**

所以船速**不改變落點**。這件事有兩種處理方式，差別很大：

- **錯的做法（v1 犯過）**：把它做成會動的旋鈕，玩家以為它重要，其實什麼都沒變 → 假變因。
  （v1 更糟：我原本把三回散布的抖動加在船速上，而 Δ 不含 v，所以三回落在同一點，散布是假的。已修。）
- **對的做法（v2）**：船速的後果放在**斷言的適用範圍**。只在一種船速下跑過走穩，A1 只能寫「在這個船速下」；三種船速都跑過還是落在桅腳，範圍就正當地變寬。

→ **船速是真變因，但它的後果在 §5「選適用範圍」那一步，不在落點。** v2 已加「走穩・已試過的船速」追蹤器（○/✓ 慢槳・半槳・滿槳），並在判讀提示裡說明範圍能寫多寬。

**這一點請 Sol 特別裁**：這是把總監要的變因保留下來、又不製造假因果的唯一誠實路徑。若你有更好的接法，請提。

# 三、v2 的六個決定（全部是命令或有代價的選擇）

| 決定 | 選項 | 為什麼它是真決定 | 後果落在哪 |
|---|---|---|---|
| **用哪一艘船**（跨趟・**已依丁-4 更正**） | 小艇 7 m／艦長那艘 12 m／隔壁大船 18 m<br>（自由換，無天數代價） | 換船換掉的**不只是桅高**：船的輕重不同，同一句「加槳」產生的加速度就不同 | 全力加槳下 a＝**1.34／1.10／0.97**（船越重加速越小），偏移 **0.96／1.35／1.78 m**。<br>**單調遞增（誘惑活著），但偏移比 1 : 1.40 : 1.84 ≠ 桅高比 1 : 1.71 : 2.57（因果不成立）**。不吻合的原因寫在岸標紙上：大船間距拉開得比較慢 |
| **船怎麼開** | 繫著不動／走穩／解纜起步／收槳 | 給舵手的命令 | 主變因：Δ 的符號（中／後／前） |
| **下幾支槳** | 慢槳 1.5／半槳 3.0／滿槳 4.5 m/s | 給槳手的命令 | **斷言的適用範圍**（見 §二）；不改 Δ |
| **加減槳的力道** | 輕一點 0.5／全力 1.1 m/s² | 可以下令的程度（總監指出） | Δ 的大小 |
| **誰放手** | 馬蒂厄抽門閂／水手用手放 | 關於人的決定 | 乾淨度：門閂散布 0.01–0.08 m；手放 0.79–0.83 m，走穩時**方向還不一致** |
| **鼓打多快** | 慢 0.70／中 0.50／快 0.35 s | 你自己的測量程序 | **兩頭都有代價**（見下） |

**鼓拍的真取捨**（v2 新增，這是 v1 沒有的）：

| 鼓 | 讀數誤差 | 落下期間拍數 | 代價 |
|---|---|---|---|
| 慢 0.70 s | ±0.02 m | **2 拍** | 拍數不足，**兩張紙無法逐拍配對**（直接卡住 A4／A5） |
| 中 0.50 s | ±0.04 m | 3 拍 | 甜蜜點 |
| 快 0.35 s | ±0.12 m | 4 拍 | 艾蒂安來不及點，間距趨勢難看清 |

**一個刻意的保證**：讀數誤差用**交替**序列（`[0,+1,−1,+0.5,−0.5,…]×err`），不是單向漂移——所以它**不會偽造出單向的間距趨勢**，玩家不會因為打快而把走穩誤判成變快。這一條沿用 GB-ADR-002 的教訓（零均值抖動 vs 系統性偏移，兩者不可混用）。

**所有抖動都來自固定表，沒有 RNG**（設計原則 13）。同一組命令永遠得到同一結果。

# 五、資料契約（模擬 → 卷宗）

模擬跑完一趟後應交出：

```
design   : { ship, state, oar, force, release, beat }
conditions : { shipName, mastH, crew, oarLabel, forceLabel, releaseLabel, beatLabel }
             // ↑ 丁-4 必要：原紙抬頭要寫齊條件，混淆才「看得見」，
             //   槳手質疑時是指著玩家自己的卷宗，不是 NPC 宣布答案
shorePaper : [ { n, t, Xread } ]        // 岸標紙：每拍船位（含讀數誤差）
gaps       : [ ... ]                    // 相鄰間距，供分類船況
landings   : [ Δ1, Δ2, Δ3 ], spread     // 三回落點與散布
shipPaper  : [ { n, t, xRelMast, y } ]  // 船上紙：逐拍相對桅杆（原紙，未做轉換）
flags      : {
  cleanRelease : release==="latch",
  classifiable : 有岸標紀錄 && 落下拍數 ≥ 3,
  pairable     : 落下拍數 ≥ 3,          // A4／A5 的前置
  scopeSpeeds  : Set(已在走穩下試過的槳檔),
  scopeShips   : Set(已實際做過紀錄的船)   // 丁-4：決定辯論 scope 步出現哪些選項，
                                          // 也是「答三艘卻只做過一艘」的判定依據
}
```

對應現行斷言：
- **A1** ← state=steady && cleanRelease && classifiable && 三回 && spread 小；**適用範圍寬度由 `scopeSpeeds` 決定**
- **A3** ← state=accel && cleanRelease && classifiable（且已有 A1）
- **S1** ← release=hand，且走穩時 `landings` 方向不一致
- **S4** ← 三種 state 齊備
- **A4／A5** ← 只在碼頭第三柱，用 `shipPaper`＋`shorePaper` 現場完成；`pairable=false` 時應在實驗台就先給質疑釘
- **A2**（船艙）← 本切片未涵蓋，維持現行封存盲測

# 八、邊界（誠實聲明）

- **無空氣阻力、無風、不模擬縱搖**的理想模型。用來看**形狀與方向**，不是史料重建。
- 因此**這個模擬不能用來「證明風沒有影響」**——它根本沒有風。風的排除仍由封閉船艙（A2）承擔，且結論只到「甲板風不是共同前行的必要原因」。
- 三回差異來自固定抖動表，不是真實隨機誤差的模型。
- 切片位於 `spike_workshop/`，依該資料夾慣例：**失敗即整包刪除，不留相容性負債**。
