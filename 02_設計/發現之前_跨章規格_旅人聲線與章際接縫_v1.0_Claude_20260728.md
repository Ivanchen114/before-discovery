## 一、旅人雙聲域規格

### 1.1 兩個聲域

| | **說出口**(NPC 聽得到) | **心聲 / OS**(只有玩家看得到) |
|---|---|---|
| 用詞 | 現代白話,但**內容克制** | 現代白話,**語氣放開** |
| 句子 | **一律完整句**。他是現代人,不是古人 | 可短、可碎、可自嘲 |
| 允許 | 「我看過拋出去的東西,畫出什麼樣的弧。」 | 「三十年欸。我連一根白頭髮都沒賺到。」 |
| 語助詞 | 少用 | 欸、勒、吧、啦 可用 |
| 荒謬感 | 不可 | 可以(「風也覺得那頁比較有意思吧」) |
| 未來知識 | **不得暴露來源**。可以說「我見過」「我在別的地方看過」,不可以說「課本上」「四百年後」 | 可以直說(「課本上那個瞬間,本人完全狀況外」) |
| 答案詞 | 禁(見第四節) | **一樣禁**。心聲不是洩題的後門 |

### 1.2 66-bis 語言溫差律(手冊既有,重申)

**古人可以短,旅人不行。**牛頓可以只說「嗯。」,維達爾船長可以只說「書。」——那是他們的權利。旅人一句話講一半、靠讀者補完,是主筆偷懶。
**精簡不等於留白,只有讀者接得住的省略才叫留白。**

### 1.3 說話人標籤 —— ADR-011（2026-07-30）取代舊方案

資料層保留兩種聲域：

- `旅人(你)`：NPC 聽得到的公開發言。
- `旅人・心聲`：只有玩家看得到，NPC 不得回應。
- 裸 `旅人`：canonical scenes 禁用；僅允許舊動態接口在相容層正規化成公開發言。

**玩家可見名牌不再顯示技術說明。**兩種聲域一律只顯示 `旅人（你）`；
不得再附加「說出口」或「其他角色聽不見」。

區分聲域的責任改由表現與無障礙語意承擔：

- 公開發言：正常對話框、旅人發言側亮起；讀屏為「旅人說」。
- 心聲：虛線框、斜體聲部、所有肖像壓暗；讀屏為「旅人心裡想」。
- 不得只靠顏色區分；資料層聲域不可因可見名牌相同而合併。

章別數量屬即時診斷，不再寫成永久條文；每次交付由工具重撈靜態與動態兩層。

### 1.4 ⚠ 第五章的旅人參與是獨立缺口

第五章劇情層目前只有極少旅人公開發言。修法不是補一批心聲，而是讓旅人在人物衝突中
提出問題、承擔選擇並得到回應。數量由當次 runtime 報告實撈，不在本條固定。

## 二、「他不會老」的鏈 —— 五章對照

這條線在系列裡是**有人說破**才成立的。實撈:

### 2.1 ch3 斷鏈 —— 但這不是漏寫,是結構決定的

第三章是**唯一一章,現場沒有任何人以前見過旅人**。伽桑狄、維達爾船長、馬蒂厄、艾蒂安全是 1640 年當天第一次遇到他。**沒有人有資格說「你沒老」。**

所以 ch3 不該硬塞一句「你沒老」。它的正確處理是**把「沒有人認識我」本身演出來**——這是全系列唯一一次旅人完全匿名。v0.9 展開稿的處理:`CE-1` 讓伽桑狄問「你認識他?」→「見過」→「在哪裡?」→「比薩。還有帕多瓦」→ **伽桑狄自己算年份,看他一眼,沒有再問**。說破的權力交給玩家自己去算。

**規格**:此後任何一章展開,「不會老」這條線的處理必須落在下列三種之一,不得漏掉:
1. **有人當面說破**(ch1/ch2/ch4 模式)
2. **有人算出來但不問**(ch3 模式,僅限現場無舊識的章)
3. **明示放棄本章不處理**,並在展開稿寫明理由

### 2.2 ch5 待處理

1740 年西雷莊園,距倫敦 53 年。杜夏特萊與旅人是初識——**同 ch3 情況**。第五章展開時依 ch3 模式辦理。

### 3.2 ⚠ 稿與 runtime 的分家(施工前必查)

第四章台詞稿 v0.8 的 `D0-1` 寫的是「石頭離開桅杆,**還帶著原來的前進**」,而 runtime `scenes4.json D0-1/n2` 寫的是「石頭離開桅杆,**仍把原來的前進帶在身上**」。**稿≠runtime**。

### 4.1 跨章通則

1. **ch1 沒有量到垂直落下的數值。**`scenes.json:1989` 明載「斜面沒有直接量到垂直落下」,且 ch1 的高潮就是玩家被逼承認沒量過。**任何一章不得把「一秒落下 4.9 公尺」歸給第一章。**(A-1 事故本體)
2. **旅人 OS 對現實世界的事實斷言(「課本上寫…」「現在還有人…」)一律視為事實聲明,寫稿時必須查證。**(伽桑狄事故本體)

## 五、誘答鍵規格(2026-07-28 新立)

來源:總監在 D3-1 指出「把規則微調一點,讓預測更漂亮」——**什麼規則??**

**三條硬規則:**

1. **要點名。**按鈕必須寫出「改的是**哪一條**、改成**什麼**」。「微調一點」「讓它更漂亮」這類寫法一律不合格。
   - ✗「把規則微調一點,讓預測更漂亮」
   - ✓「把『四分之一』改成別的倍數,讓火星從 1.87 對成 1.88」
2. **要有餌。**誘答只能在玩家**真的有動機**的時候才亮。D3-1 原版的鍵在**預測還不存在時**就亮著(1.87 要等火星判讀答完才出現),那是一個沒有餌的陷阱——玩家不會按,按了也不知道自己錯在哪。
3. **一鍵一罪。**不同的作弊要分開:
   - **封存前**=逃避承諾(把話說鬆,讓自己不會錯)
   - **拆包後**=事後配答案(改數字去湊已知結果)
   兩者混成同一顆鍵,兩個教訓都教不成。

## 七、每章展開的開工 SOP

1. 讀本檔。
2. **實撈該章 runtime**(`scenes*.json` + 對應 `engine*.js`),列出場數/節點/每節點字數、旅人台詞數、說話人標籤分佈。
3. 撈**上一章末場**與**本章首場**逐字,填接縫表。
4. 列本章的史實斷言 → 查證 → 寫成查證表。
5. 寫展開稿(標 〔新〕/〔改〕)。
6. 跑 §6 八項機械檢查。
7. 交總監讀 → 交 Sol 對抗審 → 才進 runtime。
