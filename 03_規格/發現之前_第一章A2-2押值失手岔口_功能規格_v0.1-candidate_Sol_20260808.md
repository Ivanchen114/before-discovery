## 1. AS-IS 實查

1. `engine.js/judge()` 已回傳 `claim.prediction`、`observedFifth`、`predHit`、`consistent`、
   `predDev`、`runIds`；`ok = predHit && consistent`。不需要新物理能力。
2. `Narrative.labAction("judge")` 會把失敗記入 claims，並設廣義 `hadFailure`；後者混合形狀不穩、
   預測失手等原因，不能作本岔口身分。
3. 工作台會立即渲染 claim 表與 `judgeMsg`，所以若只追加 W1–W6，第五段會在 W3「確定？」前
   先露出；必須規範呈現時序。
4. `passRequire` 現只懂 `flag`／`flagAbsent`／`flags`／`evidence`，不能直接表達兩個歷史事實的
   AND／NOT。A3-1 不能靠 scenes 現況完成互斥三句。
5. 序幕兩條搶答路徑分別是 `P0-2/q1.a` 與 `P0-2/qB.b2`，最後都走 `P0-2/nA4`。
6. A2-2 `qOdd` 是所有路徑都要完成的「逐段增量」判讀；W8 只在失手修復後收紙。兩者功能
   不同，故本包**不改 qOdd prompt**。相似的「並排／不擦」是有意義的物件連續性，不是重複題。
7. 現行 sanitizer 對 `P0-2/nA4` 只接受先選 `P0-2/q1.a`；合法的
   `P0-2/q1.b → P0-2/qB.b2 → nA4` 存檔會被拒絕為「信譽事件缺少依序的玩家操作」。全套測試
   仍是綠燈，表示這是**未覆蓋、且與本讀回重疊的既有缺陷**，不是本功能造成的新紅燈。

## 2. 狀態真相與派生投影

### 2.1 不新增狀態

本功能不得新增 flag、failure counter、paper object、evidence 或頂層欄位。以下值只在讀取時
由既有 append-only 記錄計算：

```text
isPredictionMiss(claim) = claim.consistent === true && claim.predHit === false

claims       = state.lab.inference.claims
firstOkIndex = index of first claim with claim.ok === true; if none, claims.length

// A2-2/e1 未成功以前的同型失手；一旦已有 ok，玩家即可離開 e1。
arcMisses   = claims before firstOkIndex that satisfy isPredictionMiss
firstMiss   = arcMisses[0] || null
repairClaim = first ok claim after firstMiss

// A3 可以讀回任一斜面階段真正留下的同型錯紙。
hasMiss  = claims.some(isPredictionMiss)
hasBlurt = eventLog has choice(P0-2/q1, a)
        OR eventLog has choice(P0-2/qB, b2)
        OR eventLog has rep(at=P0-2/nA4)   // legacy-compatible fallback
```

`hasBlurt` 不得由 `state.rep < 3` 推測；同一信譽值可由不同事件造成。`hasMiss` 不得由
`hadFailure` 推測；形狀不穩也會設該旗標。

### 2.2 單次 judge 分類

| 分類 | 條件 | 行為 |
|---|---|---|
| invalid | `labAction` 回 error 或 rejected、沒有 claim | 現行拒絕／診斷；不演 W1–W8 |
| shape-failure | `consistent=false` | 現行診斷；不演 W1–W8 |
| clean-success | `claim.ok=true` 且歷史無 firstMiss | 現行成功；不演 W8 |
| first-miss | 新 claim 是第一個 arcMiss，且當下游標為 `A2-2/e1` | W1–W6b |
| repeat-miss | firstMiss 已存在、repairClaim 尚無、當下又產生 arcMiss | W7 短反應 |
| repaired | 新 claim 是 firstMiss 之後第一個 `ok=true` | W8，僅一次 |
| post-repair | repairClaim 已存在後的所有 judge | 現行回饋；不重播 W7/W8 |
| later-miss | 第一次 `ok=true` 後才出現的同型失手 | 現行回饋；A3 可讀回，但不假裝 W1 弧線發生過 |

A3-1 的 `hasMiss` 可讀到任何第一章斜面 claim 的同型失手；讀回只說「押錯的紙」，不謊稱它
必然發生在第一個 embed。完整 W1–W6b 只屬已核准的 `A2-2/e1`。

## 3. A2-2/e1 呈現狀態機

### 3.1 首次失手：commit 與 reveal 分離

玩家按現行 `labJudge` 後：

1. 仍以現行 args 呼叫 `N.labAction(state, "judge", {runIds, prediction})`。
2. 若不是 first-miss，走 §2.2 對應路徑。
3. 若是 first-miss，立即 `setState(result.state)`，讓 claim、eventLog、`hadFailure` 與自動存檔成為
   世界事實；但此刻**不呼叫** `renderLabTables()`，也不把 observed 值寫入 `judgeMsg`。
4. `judgeMsg` 只顯示中性句「押線已封存；第五欄仍蓋著。」；押記紙只畫 prediction 虛線。
5. 以既有對話框播放 W1、W2、W3；W3 是帶唯一 `yieldToken` 的末句。
6. 玩家用既有 ack 收掉 W3 後，舞台殼回送同 token。chapter UI 才渲染 claim 表、加入 observed
   實線與差值文字，接著播放 W4、W5、W6、W6b。
7. 重新整理若發生在 3–6 之間：claim 已保存；重載直接呈現已揭曉押記，不重播台詞、不卡等待。
   玩家不能藉重載抹掉失手。

灰盒 `chapter.html` 沒有 stage typewriter／ack 訂閱者時，不等待 token：直接完成保存與渲染，
並在文字 log／`judgeMsg` 留下完整數值。灰盒只少演出節拍，不得有不同物理或存檔結果。

### 3.2 對話序列接口

`sayIntoDialogue(lines, cls, sceneId, options)` 可接受可選 `options.yieldToken`，只掛在最後一條
`bd:line`。舞台 typewriter：

- 只有該句實際播完且玩家清除最後 ack 時才 dispatch `bd:dialogue-yielded`。
- detail 只含不透明 token；不含 state，不執行 callback 字串。
- fast-forward、鍵盤、點擊、reduced-motion 都必須走同一 ack；不得固定秒數自動完成。
- token 一次性；不匹配、過期或重複事件一律忽略。
- `stage-ui` 維持純表現層，不匯入 Narrative、不寫 localStorage。

### 3.3 W5 單筆／平均語意

- `runIds.length === 1`：使用劇本單筆版。
- `runIds.length === 2 || 3`：劇本原句不能直接使用。`consistent` 只判前四段平均形狀，並未
  排除單趟異常；「這不是哪一趟量壞了」超出引擎事實。候選替代句為：

  > （把蠟紙壓平）把 N 趟平均起來，押線還是沒有碰上第五段。至少這張平均紙，現在不肯替我們作證。

  N 必須動態帶入 2／3。此句須由 Fable 核准或換稿；不得對兩筆資料說「三趟」。
- 其他數量由現行引擎拒絕，不能進 W5。

### 3.4 W7 重複失手的真值守衛

劇本原句不能由現行狀態完整證成：

> 好消息：錯得不一樣了。（指差距）在縮小。你的讀法，對了一半。

`predDev` 可能持平或變大；即使變小，也只證明數值差距變小，不能證明玩家採用了什麼讀法，
更不能判定「對了一半」。以下替代句已由 Fable 在劇本稿 v0.1.1 一字不改核准：

> （把新蠟紙覆上去。掀開。他把兩次押記並排）紙又答了一次。先別急著第三次——告訴我，這一押跟上一押差在哪裡。

這句即使玩家重押同一數字也成立；「沒有差」仍是可回答的觀察。若 Fable 尚未核准，施工不得
以原句覆蓋 repeat-miss，也不得讓系統捏造改善或替玩家命名方法。

### 3.5 W8 修復

firstMiss 後第一筆 `claim.ok === true` 才播 W8。W8 只說錯紙與成立紙一起留存，不額外授證、
加信譽或改 gate。之後再成功不得重播。修復 claim 可以是同工作階段內另一組合法配置；文本
不得聲稱兩張紙只差 prediction。

## 4. 押記紙 UI 契約

### 4.1 資料來源

只讀 claim 的 `prediction`、`observedFifth`、`runIds.length`、`predDev`、`ok`，以及既有 config。
禁止從文字解析數字、禁止重算 fixture、禁止把 UI 值寫回 state。

### 4.2 顯示

工作台在首次 `hasMiss` 後顯示「第五段押記紙」：

- prediction：虛線＋「你先押的線」；observed：實線＋「第五段實測刻痕」。
- 明文列出「你押 X／實測 Y／相差 Z，實測較高或較低」。
- `runIds.length > 1` 時標為「N 趟平均」，不得裝成單趟刻痕。
- repaired 後保留第一次失手與第一張成立紙；錯紙不得被成功紙取代或隱藏。
- 色彩只能輔助；線型、位置、標籤與文字是必要通道。
- 動畫只做蠟紙覆上／掀開；`prefers-reduced-motion` 取消移動但不取消 W1–W6內容。

可用 HTML＋SVG／CSS，不生成點陣圖。SVG `aria-hidden=true` 時，旁邊必須有完整可見文字；若
SVG 本身可聚焦，需有等價 title／description。`judgeMsg` 的 live region 不得在 W3 前朗讀 Y。

## 5. A3-1 scenes 拓撲

### 5.1 require 的有限語法

保留現行四種 leaf，新增：

```json
{ "event": { "t": "choice", "at": "P0-2/q1", "pick": "a" } }
{ "claim": { "consistent": true, "predHit": false } }
{ "all": [ REQUIRE, REQUIRE ] }
{ "any": [ REQUIRE, REQUIRE ] }
{ "not": REQUIRE }
```

規則：物件只能有一個 operator；array 不得為空；巢狀深度上限 8；未知 key、非布林 claim 值、
event 非白名單欄位皆回 false。這是 canonical scene 的可信資料語法，不接受玩家存檔提供 require。

### 5.2 三句互斥鏈

把 `A3-1/n3.next` 改為 `n3c`。所有條件節點採**同一條 sequential next 鏈**；可見節點播完後，
後續不符條件的節點由既有 `skipInvisible` 跳過：

```text
n3
 ↓
n3c [hasMiss AND hasBlurt] → n3a
 ↓ invisible／播完後續跳過
n3a [hasMiss AND NOT hasBlurt] → n3b
 ↓ invisible／播完後續跳過
n3b [hasBlurt AND NOT hasMiss] → n4
```

精確 `next`：`n3→n3c→n3a→n3b→n4`。不得把 n3c 的 `next` 直接寫成 n4，否則 n3c 不可見時
會跳過 A／B；也不得讓三節點條件重疊，否則可能連播。

hasBlurt 的 event require 是 `q1.a`、`qB.b2` 或 `nA4` rep fallback 的 OR。hasMiss 是 claim leaf。
台詞逐字採 Fable 稿版 C／A／B；不可同場連播兩句。三節點皆為 `type:line`、speaker `辛普里奧`。

### 5.3 舊游標

- 舊存檔停在 `A3-1/n4`：照舊從 n4 繼續，不倒退補播。
- 舊存檔停在 `A3-1/n3`：玩家播放 n3 後，按既有歷史進入一條讀回。
- 新增節點上的新存檔可由同一 schema 3 讀回；移除本功能時，回復方案須把 n3a/b/c 游標導到 n4，
  不能讓玩家落在不存在節點。
- 有 miss claim 的 legacy save 可顯示版 A/C；沒有既有紀錄不得補造錯紙。

### 5.4 qB.b2 sanitizer 相容修復

`reasonRules.ch1["P0-2/nA4"]` 不得移除因果驗證。為表達兩條合法 ordered path，新增 sanitizer
內部規則欄位（不是存檔欄位）：

```js
requiresBeforeAny: [
  [{ t:"choice", at:"P0-2/q1", pick:"a" }],
  [
    { t:"choice", at:"P0-2/q1", pick:"b" },
    { t:"choice", at:"P0-2/qB", pick:"b2" }
  ]
]
```

驗證器在 rep event 以前，分別用既有 `findRepTrace` 檢查每條候選的順序；至少一條完整成立才
通過。既有 `requiresBefore` 語意與其他章規則不變；同一 reason rule 不得同時配置
`requiresBefore` 與 `requiresBeforeAny`，避免優先序模糊。空 alternatives、空 path 或未知 event
形狀一律 fail-closed。

## 8. 測試矩陣

### 8.1 引擎／Narrative

- first-miss：claim 落地、rep 不變、E3.a 未成立、`hadFailure=1`。
- first-miss → repeat miss：重押同值、差距變小、持平與變大都只能使用核准後的中性 W7；
  不得由數值推測玩家採用了哪種讀法。
- first-miss → ok：repairClaim 唯一；第二次 ok 不再觸發 W8。
- shape-failure、rejected、clean-success 不觸發 consequence classifier。
- require 四組：none、miss only、blurt only、both；各只到 n4 前一條讀回。
- qB.b2 路也算 blurt；rep fallback 可讀 legacy；相同 rep 無事件不算。
- unknown require、空 all/any、過深巢狀 fail-closed；六章現有 require fixtures 全數不變。

### 8.2 資料與相容

- `scenes.json === scenes.js` 深等；n3c/n3a/n3b 都可達且 next 完整。
- schema 3 sanitizer 接受合法新增游標；捏造 claim／event 仍 fail-closed。
- `q1.a→nA4` 與 `q1.b→qB.b2→nA4` 都可匯入；缺 q1.b、只有 qB.b2、或憑空 nA4 rep 都拒絕。
- legacy cursor n4 不補播；legacy n3 正確派生；無 claim 不捏造。
- 反向控制：刪掉 miss claim 但留 `hadFailure`，A3 讀回必須消失。

### 8.3 舞台與無障礙

- first-miss 點 judge 後 claim 已保存，但 W3 ack 前 DOM／ARIA 查不到 observed Y。
- ack 一次後恰好揭曉一次；重複／錯 token 不動作。
- 刷新於 W1–W3：失手仍在、直接可見、不重播、不死鎖。
- 單筆、2 筆、3 筆分別顯示正確語意；數值從 claim 讀，不硬編。
- prediction 虛線／observed 實線＋標籤＋差值文字；只移除顏色仍可判讀。
