# 《發現之前》第一章功能規格書 v0.1.2

**版本**：v0.1.2
**日期**：2026-08-03
**狀態**：CURRENT
**正本**：`greybox/data/scenes.json`、`greybox/src/engine.js`
**取代**：v0.1.1 作為現行施工入口；舊 R-ID 仍供追溯

## 一、章目標

玩家從「快慢是物體的渴望」走到可檢查的斜面紀錄：分段增量近似 1:3:5:7:9，累加後為 1:4:9:16:25。關鍵關係必須由玩家判讀，不再由 NPC 在選擇前自動宣告。

## 二、斜面工作台現行流程

1. 踏查水鐘、斜槽與球；配置會真正影響可重複性與資料形狀。
2. 每一組先完成前四段，遮住第五段；玩家依前四段封存第五段預測。
3. 引擎揭曉**真實第五段實測值**，並把押記與刻痕並排。比較值不得由同一預測公式回算，避免恆真循環認證。
4. `A2-2/qOdd` 由玩家判斷各段增量。誘答「1、4、9、16、25」是真實累加值但放錯欄位；錯答必須回到增量／累加的差異，不得用書面語域洩題。
5. 玩家先選 1:3:5:7:9，再把增量累加為 1:4:9:16:25，才取得平方關係。

## 三、斷言與證據

- 認證、換球、換傾角依當前階段分段開放；引擎守衛不得只靠 UI 隱藏。
- 換球比較只接受同裝置 revision、均 `accepted=true` 的一銅一木紀錄；未受理紙留在紀錄簿但不可引用。
- 普通配置失敗、預測錯誤與關係誤判不扣信譽；明知未量仍宣稱已證明才屬失信。
- 結論詞彙 lint 仍掃 text、hint、options，白名單路徑須可證明在玩家取得之後。

## 四、信譽修復

`SC-R1` 不再只檢查「多了一筆 run」。玩家必須在修復場進場後完成新 run、對該 run 做 `judge`，再提出一個由該紀錄真正支持的有限主張，才可恢復信譽並回原游標。刪除 `judge` 或引用髒紀錄的匯入必須 fail-closed。

## 五、辯論與名稱

內部沿用 `persuasion`，玩家可見名稱依 `GB-ADR-041` 為「論證對位」。配錯證據使論證對位下降；歸零後複盤錯配並保留已破支柱，不進無關實驗。信譽歸零才進 `SC-R1`。

## 六、存檔與驗收

- `scenes.js` 必須由 JSON 重生且深度相等。
- 四段舊存檔可還原，不捏造第五段；新第五段必須來自實際 fixture。
- 54 種配置仍由核心引擎真判定，不因修門檻改成固定答案。
- 自動測試外，真人須確認：先看到問題與依據、再預測、猜錯紙留下、奇數與平方的跳躍確實由玩家完成。
