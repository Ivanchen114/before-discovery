# 《發現之前》第三章功能規格書 v0.2

**版本**：v0.2
**日期**：2026-08-03
**狀態**：CURRENT
**設計基線**：`02_設計/發現之前_第三章現行設計基線_v1.0.md`
**正本**：`greybox/data/scenes3.json`、`greybox/src/engine3.js`

## 一、資料與相容

- `scenes3.json` 是敘事唯一施工正本；`scenes3.js` 只由建置產生。
- 現行 10 主線＋1 修復場；legacyOnly 節點與舊 API 只為存檔遷移，不得重新接回新主線。
- 所有工作台動作經 narrative `labAction` 呼叫 Engine3；UI 不得直接改 `state.lab`／dossier。
- 匯入須重算 fixture、來源資格、事件順序與第三柱逐拍狀態，不信任存檔自稱完成。

## 二、卷宗狀態

現行工作區至少包含：實驗草稿、已歸檔 records、來源選擇、提出範圍、成立斷言、船艙器材承諾、盲測結果、辯論三柱，以及第三柱的 premise／alignment／transformed beats／final boundary。狀態必須可序列化往返，讀檔後恢復同一操作位置。

## 三、實驗與斷言 API

- `setDossierDraft`、`runDossierExperiment`／`runDossierSeries`、`fileDossierRecord`：先設計、執行、歸檔，三者不可合成一鍵。
- `commitDossierCabinInstrument`、`runDossierCabinSeries`、`runDossierBlind`、`judgeDossierBlind`：固定滴水或落石後完成停泊／近似穩速比較；器材承諾須寫進存檔，不只留 DOM 變數。
- `selectDossierSource`／`setDossierSourceGroup`：來源預設空白；未歸檔、條件不合或缺必要對照者不可引用。
- `setDossierProposedScope`／`setDossierScope`：玩家在取得斷言前先決定資料能說到哪；越界原狀拒絕，不能由系統改成正解。

## 四、辯論與第三柱

- `enterDossierDebate` 必須檢查工作台完成與故事接縫；「去辯論」按鈕不可繞過收卷／雙視角確認。
- `selectDossierPillar`、`answerDossierDebate`：論證對位只處理證據—主張錯配；已破支柱與已取得原紙在重入時保留。
- `setDossierP3Premise`：玩家逐一確認同一航程、同一事件／拍與兩個零點。
- `alignDossierPapers`：只有共同拍可對齊；兩張紙都保留。
- `transformDossierPaperBeat`：每次只換算一拍並留下可見結果；不得選一次後自動完成全紙。
- `setDossierFinalBoundary`：只有完成換算後才能提出有限結論；錯誤邊界不授予 G4／G5。

## 五、結論護欄

第三章禁詞規則必掃首次取得前的 text、hint、options。探針句由測試端獨立書寫，不得讀 `rules[].term` 生成，避免規則錯字與自我檢驗一起通過。角色可提出待駁假說，但須有可達的玩家互動 `refutedBy`。

## 六、驗收

常駐測試至少鎖定：JSON／JS 深等、194 active 可達、29 legacy 遷移、船艙器材寫入存檔、重播不刪紀錄、斷言來源／範圍、第三柱 premise→align→逐拍 transform→boundary、辯論不可旁路、結論詞彙反向控制。瀏覽器另驗錯圖、捲動、鍵盤與 844×390。
