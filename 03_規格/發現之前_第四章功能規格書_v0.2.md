## 一、資料、狀態與遷移

- `scenes4.json` 為正本、`scenes4.js` 為生成鏡像；UI 不得自行補節點或證據。
- 現行 12 主線＋1 修復場，307 active＋19 legacy；schema 1→2 的 19 組／205 舊游標須全部可遷移或有明確 fail-closed 理由。
- `initialState` 內的 transition、tangent／orbit、scale、planets、ledger／loans、proof／press、archive 狀態必須序列化往返。K1 新局的 `orbitLab.paperTrials[]` 與 `paperTrialActiveId` 也屬正本狀態，不得只存在 DOM。
- 每個引擎拒絕都回傳原 `state`；缺證據歸檔不得局部寫入。

## 二、K1 切線與軌道

1. K0 切線改在對話舞台完成：先顯示已觀察短圓弧，再由玩家選出並畫下無作用切線；`sealTangentPrediction` 仍由選項寫入引擎，錯選留痕，不另開大型工作台。
2. 新局先在對話中共同固定「每一小步都加上一支朝此刻地心的箭」，精簡板只讓玩家改「月亮原本跑多快」與「朝地心的箭頭有多長」。此處尚未以天空資料證實是重力，玩家可見名稱不得提前寫成「重力大小」。
3. `runOrbitPaperTrial` 依固定算法續畫紙上小步，append-only 保存設定、實際路徑、分類與操作次序；相同組合不得重跑洗版。介面必須明說這是紙上模型輸出，不是天文觀測。
4. `assertK1` 必須同時引用 K0 切線紙與三張玩家已跑過的試紙。四張試紙只在同一張資料表出現一次，首欄提供勾選，不得在表格下方重抄成卡片或 radio。UI 先問「在朝地心箭頭長度相同時，原本速度會怎麼影響軌道？」，讓玩家選兩張箭頭長度相同、原本速度不同且分別留在／偏離原半徑窄帶的紙；再問「在原本速度相同時，朝地心箭頭長度又會怎麼影響軌道？」，固定離帶紙的速度，接上一張箭頭長度不同且回到窄帶的紙。三張中因此仍有兩張快慢、箭頭長度皆不同而同樣留在近圓窄帶，第三張只改其中一項且不再近圓；玩家再親自把兩次比較合起來，選出「原有前進保留，朝地心的箭頭長度必須和原本速度相配」才授 K1。K0 切線紙須在介面明列為已引用來源，不占三紙名額。
5. 第一問與第二問各自有確認動作、短診斷及旅人—牛頓回應。第一問成立後，旅人指出「箭頭相同、速度不同」及一張留帶／一張離帶，牛頓只收窄到速度確實改變路徑；玩家親手收掉這段對話後，第二問才出現。第二問成立後，旅人指出「速度相同、箭頭不同」及路徑回到窄帶，牛頓才邀請把兩次比較合起來；第二個 yield token 收到前不得開放綜合斷言。重選第一問、試紙失效、切換 embed 或重開遊戲，皆須清除兩個等待 token、第二問與結論的 UI 草稿，但不得刪除任何試跑紀錄。
6. sanitizer 逐張重算試跑路徑、核對 `runOrbitPaperTrial` 操作事件與成功 claim 的三紙選集；偽造座標、少選、重選同紙、先寫 claim 或新舊紀錄混用皆 fail closed。
7. 舊存檔若已有 `ruleSeal`、`manualBeats`、`manualAttempts` 或 `ruleRuns`，仍顯示舊版三拍／續畫板並依舊 audit 走完；新 `paperTrials` 不得和這批欄位混寫。`sealOrbitRule`、`nudgeOrbitAim`、`commitOrbitBeat`、`continueOrbitRule` 僅為這條相容路徑保留。

## 三、K2 地表與月球比較紙

- `sealScalePrediction`：僅保留舊 schema2 存檔與既有 action log 相容；新局 UI 不顯示、不自動呼叫，K2 新流程也不以它作前置閘門。
- 新局主線不再進入 `D1-2/e1` 的 `scale` 大工作台。玩家在對話中依序完成幾何段落、約 3600 倍與 `60×60` 三次判讀；每次選項直接呼叫章別 action，最後一判成立才取得 K2。舊 embed 只保留讀檔相容。
- `convertMoonTime`：新局的第一個可見判斷。玩家先判斷切線弧長與「切線端點到實際端點的正矢」何者代表向內偏折；正解由 `earthRadiusKm=6371`、`moonDistanceEarthRadii=60`、`moonPeriodDays=27.3` 真實重算一秒正矢約 1.36 mm，不讀固定 60 秒答案，也不要求先猜量級。若舊存檔帶有封紙，仍可在第一次幾何判讀時依舊規則開封，但不得影響新局可達性。
- `judgeScaleRatio`：並排地表一秒約 4.9 m 與月球一秒約 1.36 mm，使用由 fixture 重算的約 3613 倍設定量級容差；不可硬吃剛好 3600。
- `judgeScaleRelation`：最後才讓玩家把月距約 60R 與偏折量級約 3600 配成 `60×60`，完成後才命名距離平方；K2 成立後六十秒約 4.88 m 只作事後放大顯影。
- K2 完成後先以正文寫清楚可見關係：同樣一秒裡，距離放大約六十倍，向內落下的距離縮成約六十平方分之一；此段不以「力」「加速度」或普遍定律替玩家補上尚未成立的理論。
- 地心量距缺口使用純對話 choice：球形中心、四面對稱、落下方向三項皆無 `effects`，各自進入專屬牛頓回應後匯流。對稱只可支持合成方向朝中心，不能宣稱已證明大小等效；三路最後都由旅人提交有限主張，不扣信譽、不重授 K2。
- 玩家可見錯因由單一 error-code 表產生，按鈕 fallback 不得再硬寫第二份相同文案。
- schema2 舊存檔中唯一可信的 1.4 mm／4.9 m／0% 顯示精度組合可正規化為 1.36 mm／4.9 m／0.4%；不得補造 action、證據或完成旗標。

## 四、K3 雙押行星

- 舊 `predictPlanet` 會在同一次動作內封存又揭曉，現行引擎不得匯出、敘事層不得派送、canonical scene 不得重新掛回；只保留 `sealPlanetPrediction` 各自封存火星與木星。
- `revealPlanetPredictions` 的必要條件是兩張都已寫下並封好。不得在同一次呼叫內替未封好的紙自動預測、封好、打開資料。
- 兩張一起打開後，`judgePlanetComparison` 讓玩家並讀事前猜測、資料揭開前的理論計算與觀測；只有「理論在看見觀測前先留下兩筆預測」可取得 K3。判讀前 UI 不得先說出這項鑑別邏輯；事前猜錯不阻擋，猜對也不能取代理論預測。成功後由 `D3-1/n38` 哈雷具名簽收，K3 的視聽授證只在該行觸發。
- `judgePlanetComparison` 是資料打開後的證據解讀，不是研究策略選擇。現行 runtime 不提供「已知距離預測週期／已知週期反推距離」分岔；日後若新增，策略先在對話舞台決定，操作板只負責寫下預測、封好、打開資料與留痕。
- 舊 `assertK3` 不得繞過揭曉後判讀；新局使用 `blind-v1`，已取得 K3 的合法舊檔以 `legacy-v2` 保留。

## 五、K4 模型比較

玩家可見介面先直說：左邊記拉力說，右邊記漩渦說；兩套說法都要看月亮、行星、彗星同一批資料。若看完結果才添新假設，就把補充紙留在原結果旁。工作台可以把兩本實體冊頁稱為「拉力帳／漩渦帳」，把補充紙稱為「借條」；這三個詞是物件名稱，不得再衍生「過帳／聽證／整桌帳作廢」等操作暗語。

- `setModelProtocol`：玩家先鎖定「同一力學規則不變，各天體使用觀測初值」。把三種天體硬改成同起點／同速度，或逐案重調定律，均留痕但不鎖定協定。
- `sealModelPrediction`：拉力帳與漩渦帳在任一列結果出現前各自封存預測；缺協定或任一預測紙時，`beginLedgerRow` 必須原狀拒絕。
- `beginLedgerRow`／`stampLedgerCell`：新局固定依 Moon→Planets→Comet 開列；任何時刻只能有一個當前列，當前列完成兩格判斷與人物回應後才可進下一列。逐列讀可重算結果並判斷「對得上／只有說法／對不上」，不得一次攤開六格答案。無數值來源的方向判讀不得偽造百分比。
- `addModelLoan`／`declineModelLoan`：原始「對不上」不得被改寫；加借條時另留 `patchedOutcome`，且必須顯示這是事後調整或新增假設，`independentlyTested=false`。兩張都不借仍可封存。
- `sealModelComparison`：未完成列、未處置借條或非法補充原狀拒絕。正確結案只支持「同一規則跨資料的表現」，不得擴張為已說明引力為什麼能隔著空間拉動物體。
- 已開始比較的舊檔以 `ledger-v1` 續玩；新局仍使用內部版本值 `hearing-v1`，不得倒填舊檔未做的操作。
- K4 的 0.36%、0.32%、6.4 年、11.86 年與 45.8% 為本章固定簡化模型的現代教學重算；UI、縮圖、圖說、替代文字與放大閱讀器均須近端標示「現代教學比較／固定簡化模型」，不得稱作十七世紀原始對帳表。2026-08-14 四張白話封版 raster 已清除「失配保留」：未借狀態寫「原結果保留」，兩借總結寫「原先兩格對不上」。舊圖保留追溯但不得回接。

## 六、K5 證明鏈與出版

- `assembleKnownProofSources` 一次整理玩家已取得的五份來源（原有前進、持續改向、同一把尺、事前預測、三種天空），不得把每張再做成一次例行考題；缺任一來源原狀拒絕並列出缺項。
- `judgeShellBalance` 是新的物理判讀：玩家必須指出近側較近但對應面積較小、遠側較遠但對應面積較大，成對細錐中的作用恰能抵消。錯選留 trace，不得顯示球殼頁或提前完成球心等效。
- `placeShellPage` 只能在 `judgeShellBalance` 成功後執行，玩家親手把球殼定理頁放入第六格。舊 `revealShellPage` runtime action 已退役；合法舊檔只由 `shellInsightVersion: "legacy-revealed"` 的讀檔相容路徑承接，不捏造玩家判讀或放頁。
- `acknowledgeCreditDispute` 只能在球殼頁入槽後執行，留下單筆 append-only trace 與同序敘事事件；人物對話確認完成前，工作台須保持不可操作，且不得開放 `setHookeScope`。合法舊檔若已跨過 Hooke 範圍判讀，以 `creditDisputeVersion: "legacy-past-scope"` 續接，不反向補寫新操作。
- `setHookeScope` 保留一次真正有爭點的範圍判斷；`assignCreditPlan` 以一個完整方案同時分配 Hooke（問題方向與平方反比猜想）、Halley（1684 追問與出版推動）、Flamsteed（帶日期觀測）、Newton（數學證明、球體處理與跨天體整合），取代四次輪流填名。遊戲的封存預測不算成 Halley 的歷史功勞。
- 取得後 K5 使用 `ch04_card_K5_scoped_proof_raster_v03.webp`：六段為「原有前進→持續改向→同一把尺→事前預測→三種天空→球殼定理」，並標明是證明鏈教學圖、不是《Principia》原頁；歷史紙面校樣的逐字稿完整烘焙入圖，替代文字與讀圖器仍須完整列出四人分工與「仍未說明引力如何隔空作用」的邊界。
- `removeTravelerFromAuthorField` 同時寫入 proof 與信譽事件，兩者須相鄰且理由一致。
- `submitProof`／`deferPress` 才推進出版窗口；`submitPartialProof` 留下可見後果。
- `archiveEvidenceSet` 只在完整 proof 與 K1–K5 全部成立後一次歸檔；缺任一證據回同一 state 與明確 missing 清單。

## 七、介面與可及性

互動依認知工作分三級。第一道門檻只判斷是否離開對話：反覆改變條件且結果不同、錯誤留可診斷產物、存在可續玩的中間狀態、或玩家決定操作順序／協定，任一成立才升為操作板。第二道門檻才判斷是否使用完整工作台：還必須同時攤開多來源、跨兩次以上判斷反覆回查條件後才能提主張，或組裝需署名、送印、對外負責的公開產物；單一「封好預測—打開資料」循環中同批翻開、可一次判讀的有限卡組不單獨滿足多來源條件。前述訊號相互重疊時不得重複計分。第四章因此以 K0／K2 對話判讀、K1／K3 精簡板、K4／K5 完整桌面為現行分工。K1 的四張試跑紙共用一張首欄勾選表；兩問共享同一張離帶紙，第一問與第二問各有獨立確認、`aria-live` 短診斷與人物對話 yield token。人物回應期間工作台不可操作，收掉第一段才開第二問，收掉第二段才開綜合斷言；這是兩次不同的控制比較，不得退化成一次勾三張，也不得把相同資料重抄成另一組選項。K2 raster 只提供紙張與已知短圓弧氣氛，切線、實際短彎路、兩端點與端點短差由 runtime SVG 分階段顯示；所有畫面維持米白紙面，不以灰底製造層級。按鈕 44 px、鍵盤焦點、錯誤 `aria-live`、低高度捲動與說明預設收合皆屬驗收。

`D-INT-1` 使用 `sceneTreatment: time-passage`：進場後書房與焦點圖退到近黑，對話框、繼續操作及 `1665 → 1679` 的 HTML 年份錨點保留；玩家親手翻到 `D2-1` 時才淡入 1679 的背景。此短幕不開 `sceneFx` 蒙太奇、不自動換句、不修改劇情或存檔；減少動態模式直接切換明暗。

## 八、驗收
