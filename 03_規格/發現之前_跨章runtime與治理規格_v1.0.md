# 《發現之前》跨章 runtime 與治理規格 v1.0

**版本**：v1.0
**日期**：2026-08-03
**狀態**：CURRENT
**裁決者／專案作者**：臺北市立松山高中物理教師 陳育詮

## 一、用途與正本

本文件不重述五章全部台詞；它定義跨章共同邊界，並把現行章規格、runtime 與決策記錄接成同一條可查鏈。

- 敘事正本：`greybox/data/scenes.json`、`scenes2.json` 至 `scenes5.json`。
- 行為正本：`greybox/src/engine.js`、`engine2.js` 至 `engine5.js` 與共用 narrative／sanitize 層。
- `scenes*.js` 是生成鏡像，不得手改後反蓋 JSON。
- 現行規格清單：`03_規格/current-specs.json`。
- GB-ADR 唯一流水帳：`greybox/decisions.md`；跨章治理另用 GOV-ADR 命名空間。

## 二、跨章不變量

1. 玩家先做可檢查的操作或判斷，角色才可覆述結論；提示不得先花掉玩家要取得的答案。
2. 原始結果不自動等於證據。至少須經來源選擇、關係判讀、有限主張或資料轉換之一。
3. 預測必須先回答「押什麼、憑什麼」並封存；揭曉後保留錯紙，不替玩家擦掉。
4. 失敗是資料，不是刪檔。改設定後舊結果留存但失去當輪證據資格，必須重新封存預測。
5. 選項若不影響狀態、回饋、資料或後續台詞，不得偽裝成互動。
6. 時間跳躍須由物件、人物反應或未解問題承接，不以裸年份代替戲。
7. AI／生成圖必標示「教學重建」；數字可烤入完整重建圖，但不得冒充史料掃描或提前畫出未揭曉答案。
8. 每條護欄同時需要「正向路徑存在」與「負向旁路不存在」的契約；負向探針須由測試獨立書寫，不得從被檢驗欄位複製，且要跨 canonical data、派送層、引擎 API 與匯入淨化檢查實際可重接的入口。

時間轉場另分兩級：跨章、換地點、換同行者或需要多個史實里程碑者使用 `sceneFx: montage`，每拍由玩家手動推進；同一敘事場內只以數句話掠過多年者使用 `sceneTreatment: time-passage`，世界退到近黑但保留對話、繼續操作與 HTML 年份錨點。兩者皆不得固定計時自動前進，同一場景不得並用；短幕折疊不寫入存檔，也不得從音樂 mood 反推視覺狀態。

## 三、資源與名詞

- `state.rep` 的玩家可見名稱為「信譽」，依 `GOV-ADR-001` 衡量研究誠實與操作授權。
- 內部 `persuasion` 的玩家可見名稱為「論證對位」，依 `GB-ADR-041` 衡量證據是否咬住當前主張。
- 兩者不合併、不共用修復動詞；普通算錯、選錯資料或預測失準不扣信譽。
- 內部欄位不因顯示名改動；存檔 schema 變更須另立遷移裁決。

## 五、跨章 ADR 語意落點

本表只承接真正跨章的責任；章別裁決必須落在對應章規格的同名表，不能靠一張全號碼索引假裝完成。`03_規格/current-specs.json` 明列每筆 active／partially-superseded ADR 必須出現在哪些 CURRENT 文件，治理測試逐檔驗證。

| ADR | 本文件承接的現行語意 |
|---|---|
| GB-ADR-005 | CURRENT、HISTORICAL 與 AUDIT ONLY 必須由索引唯一分流，檔名、H1 與登錄版號一致。 |
| GB-ADR-014 | 行動裝置以橫屏與全螢幕能力偵測為主，iPhone 無能力時才顯示加入主畫面指引。 |
| GB-ADR-015 | `stage-ui.js` 只能由 stage 分檔建置生成，來源與 bundle 漂移必須使測試轉紅。 |
| GB-ADR-016 | 直向裝置的轉向提示不可破壞既有進度，轉橫後須回到同一遊戲狀態。 |
| GB-ADR-017 | 證據取得、角色指圖與筆記重播共用穩定資產映射，圖像不得與台詞所指證據錯位。 |
| GB-ADR-025 | 系列章名與分頁標題由章別 registry 提供，不得在缺資料時靜默偽裝成第一章。 |
| GB-ADR-027 | 證據圖以穩定 evidence code 接線，正文改字不得使取得圖與實際證據分離。 |
| GB-ADR-028 | 章尾以史實回聲、未解問題、下一章出口接棒，不把裸年份或系統通知當成敘事交接。 |
| GB-ADR-037 | 玩家先做資料判讀與有限主張，結論詞彙護欄掃台詞、提示與選項且使用獨立探針。 |
| GB-ADR-041 | 玩家只看見「論證對位」，內部仍保存 `persuasion`，並與研究誠實的信譽狀態分離。 |
| GB-ADR-044 | 六章共同探究以關係側視與紙面正視分工；少量已揭曉短註可進圖，互動資料與答案仍由程式呈現。 |
| GB-ADR-049 | 重大年代／人物交棒使用逐拍 montage；同場數句掠年使用保留對話的近黑短幕折疊，兩者皆由資料驅動且不自動前進。 |

## 六、驗收層級

1. 靜態與契約測試：資料鏡像、可達性、狀態不變量、負向控制。
2. 瀏覽器驗收：桌機與 844×390 橫屏、鍵盤、焦點、重播落點、讀屏文字。
3. 真人通關：因果是否順、玩家是否知道為何操作、是否真的感到自己做出判斷。
4. commit／push／release／production smoke 是另外四個事實；不得以 `npm test` 全綠代替。
