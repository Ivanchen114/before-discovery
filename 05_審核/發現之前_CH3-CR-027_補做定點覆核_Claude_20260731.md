## 一、逐條對 CR-027 §四 驗收條件

### ✅ 1|同條件按一次得到三張不同編號原紙,借船成本只算一次

`engine3.js:2106 runDossierSeries()`:

```js
var count = mission === "dual" ? 1 :
  (mission === "explore" ? 3 : Math.max(0, 3 - priorCount));
...
for (var i = 0; i < count; i += 1) {
  var row = buildDossierRecord(draft, d.nextRecordId, priorCount + i + 1);
  row.borrowDays = i === 0 && borrowedNow ? dossierVessel(draft.vesselId).borrowDays : 0;
  rows.push(dossierAppendFiledRecord(s, d, row));
}
```

三張各自 `buildDossierRecord` 帶獨立 `d.nextRecordId`,**沒有任何平均或合併**。`row.borrowDays` 只在 `i === 0` 掛借船成本——**借船只算一次,這條寫得很精確**。

### ✅ 2|舊存檔已有一／兩張時只補足到三張

`Math.max(0, 3 - priorCount)`,`priorCount` 由 `dossierTrialFingerprint` 比對同條件既有紀錄計得。已有 2 張 → `count = 1`。已滿三張 → `count = 0` → `err("dossier-series-complete")`,**不會做成 4–5 張**。

### ✅ 3|船艙停泊與平駛各按一次,各得三張

`engine3.js:2221 runDossierCabinSeries()`:`var existing = d.blind.records.filter(item => item.stage === stage).length; var count = Math.max(0, 3 - existing);`——**逐 stage 獨立計數**,停泊與平駛互不相干,各自補到三張。

### ✅ 4|雙視角按一次只得一個同步事件

`count = mission === "dual" ? 1`。同一筆 record 內含 `papers.shore` 與 `papers.ship` 兩個視角(見 `chapter-ui.js:3510-3513` 的雙圖渲染),**不是兩個事件**。

### ✅ 5|斷言勾選以資料組為單位,展開後三張原紙逐張可讀

`chapter-ui.js:3507-3513`:`details`／`summary`「查看 〈ID〉 的原紙」內含 `ship3DossierPaperPlot` 逐張繪製岸紙與船紙。組內可展開,**沒有把三回壓成不可追溯的數字**。

### ✅ 6|A1／A3／A2 斷言成功都有「旅人說出 → NPC 核紙 → 證據圖」

`ship3SayAssertionBeat` 五組(A1／A3／A2／S1／S4)皆為「旅人句 + 負責該欄位的 NPC 句」,並掛 `sayIntoDialogue`。**我上輪已對這五組做過逐句改寫審查**,現行版本採用改寫稿(艾蒂安補船位、馬蒂厄壓蠟「歪的沒關係」、船長「那就寫『不知道』」)。§2.3 要求「不得使用可套用任何章節的泛稱讚」——現行五組全部指名具體欄位,守住。

### ✅ 7|船艙與雙視角開始前各有一個可錯的設計選擇,錯誤不產生資料

- **船艙**:`engine3.js:2226` `if (!d.designCommitments.cabinWind && !d.blind.records.length) return err("cabin-wind-plan-required")`。三選一中只有 `close-cabin` 通過,錯案推 `cabinWindAttempts` 但不生資料。**這一項在 CR-029 又被強化過,我上一輪已實測。**
