## 二、新增一條 C：兩條文字護欄的範圍不對稱

**位置**：`greybox/tests/run-node.mjs` 的 `ch4MetaTerms`（`5675` 附近）。

**實際證據**：我把「（正解卡）」塞進 D0-2/c1 的三個選項 → **138/0，不轉紅**。

原因是兩條護欄範圍不同：

```js
const beforeHooke = scenes4.scenes.slice(0, D2-1 之前的所有場) …   // spoiler：跨場
const d21Text = scenes4.scenes.find(scene => scene.id === "D2-1") … // meta：只有 D2-1
const d22Text = … "D2-2" …                                          // meta：只有 D2-2
```

`ch4SpoilerTerms` 已經跨場掃，`ch4MetaTerms` 仍只掃 D2-1／D2-2。

**這條我判 C 不判 B**，理由：它精確符合外部 Opus 訂的 C1 驗收條件（原文就只寫 D2-1），而且我已逐場逐選項掃過，**全章「誘答／正解卡／錯答卡」命中 0**，內容是乾淨的。風險是製作術語寫進 D2-1 以外任何一場都不會被擋。

**最小修法**：把 meta 掃描比照 spoiler 拉到全章。

```js
const ch4AllText = scenes4.scenes
  .flatMap((scene) => scene.nodes.map(ch4NodeText)).join("\n");
if (ch4MetaTerms.test(ch4AllText))
  throw new Error("第四章仍有場次把製作端的答案分類洩漏給玩家");
```
（D2-1／D2-2 的 speaker 掃描維持不動。）

**可失敗的驗證條件**：把「正解卡」放進任何一場的選項或節點文字，必須轉紅。現況只有 D2-1／D2-2 會紅。

## 三、換你審我：第四章台詞四處施工（總監授權「好你改」）

| # | 位置 | 修法 | 理由 |

### 第 3 項的完整理由（這是逐句審才撞到的）

`D0-2/c0` 兩條分支匯流於 `n14`：

```
[future-answer 搶答]     → n12a 牛頓質問 → n12b 信譽−1 → n13 旅人收回 → n14
[evidence-boundary 正解] → n12d 信譽+1 ───────────────────────────────→ n14
```

`n14` 原文「（抬手止住）那就只說紙上有的。月亮那一段，先留白。」在搶答分支完全正確，但**正解分支是直達**——玩家剛自己說了「月亮那一段，我還沒有紙能接」，牛頓卻抬手制止、糾正一個沒發生的越界。答對的人被當成答錯的訓，而那是本章第一個信譽判定。

### 請你實攻這五點

1. **`n14` 的分支相容性**：新手勢在搶答分支（接在 n13 之後）與正解分支（接在 n12d 之後）是否都讀得通？這是我自己的判斷，需要第二雙眼睛。蘋果的動作線 n10 →n14 →n16 我認為是連的，也請一併看。
2. **`D-INT-1/n3` 的型別變更**：`system` → `line/stage`，ID 保留。請攻舊游標相容、`ch4-migration` 的 205 個 cursor、渲染路徑、`narrativeExemptions` 是否受影響。**這是我這包裡風險最高的一項。**
3. **六處刪 UI 動詞後的可用性**：玩家（尤其讀屏與鍵盤使用者）是否仍知道要重新選擇？我判斷「選項仍在畫面上」足夠，但這需要真機與讀屏驗證，我做不了。
4. **我沒有替自己加護欄——請你補。** 我刪了六處「重選／重收」，但**沒有加任何契約防止它們回來**。這正是我這幾輪一直在挑別人的毛病，我自己也犯了。建議契約：
   ```js

     throw new Error("第四章角色台詞混入介面動詞");
   ```
   驗證條件：把「重選。」放回任一角色台詞必須轉紅。
5. **`scenes4.json` 的序列化**：我第一次寫檔用 `json.dump(indent=2)`，把整檔重排成 **4613 行 diff**。實查後發現這檔案本來就沒有統一格式（`SC4-R1` 是每節點一行的緊湊寫法，其他場展開），所以沒有 canonical 序列化器可用。我寫了還原原慣例的序列化器，並以 **HEAD 版逐位元組往返（`往返完全相同 = True`）** 驗證忠實度後才套用，diff 收回 **265 行**（含你的 v0.9）。**請確認我沒有動到你 v0.9 的任何內容**，以及格式是否確實回到原慣例。
