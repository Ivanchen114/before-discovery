## 二、B-1｜動畫閘門旁有兩顆按鈕可以直接跳過動畫與對白

**位置**：
- `greybox/src/chapter-ui.js:3849-3857`（`mission.id === "explore"` 分支的「把卷宗帶上碼頭」）
- `greybox/src/chapter-ui.js:3798-3800`（工作台頂端分頁鈕「去碼頭辯論」）

**實際證據**：

`renderShipDossierLab` 在 3848 行呼叫 `renderShipDossierLastSeries(work, d)`，**緊接著** 3849 行進入 explore 分支，兩者渲染到**同一個 `work` 容器**（3828 行 `work = apparatusPage`）。雙視角完成後 `missionAfter === "explore"`，所以兩段同時渲染：

```js
renderShipDossierLastSeries(work, d);        // 3848：內含「看完動畫，收好兩張紙」(3595)
if (mission.id === "explore") {              // 3849：沒有檢查 ship3PendingMissionBridge
  ship3El("h3", "卷宗已齊", work);
  var debateButton = ship3Btn(work, "把卷宗帶上碼頭", function () {
    doShip("enterDossierDebate", {}, "…");   // 3855：直呼，無閘門
  }, "shipAction primary");
```

`ship3PendingMissionBridge` 全域只有 5 個出現點（`1540` 宣告、`1875` 設定、`3592`／`3596`／`3597` 消費），**explore 分支與分頁鈕都沒有檢查它**。引擎層對 bridge 零概念（`grep -c "PendingMissionBridge\|dual-complete" src/engine3.js` = **0**），而 `enterDossierDebate` 的唯一前置是：

```js
if (!dossierExperimentalAssertion(d) && !d.records.length && !d.blind.ran)
  return err(state0, "dossier-record-required");
```

雙視角剛留下一筆 record，`d.records.length > 0` 即成立，**引擎立刻放行**。

**玩家實際會看到的後果**：按完「執行雙視角紀錄」後，畫面同時出現「看完動畫，收好兩張紙」與「把卷宗帶上碼頭」（另加頂端「去碼頭辯論」）。按下後兩者任一，會**直接進入碼頭辯論**，跳過：岸紙／船紙動畫、收卷確認、`ch3-dual-complete` 舞台閘門、以及 `ship3SayMissionBridge(dual→explore)` 的人物對白。這正是總監要求 5 與審查包 C 面「是否仍有任何路徑能在看動畫前搶播最終對話」所指的那條路徑。

**為什麼測試沒抓到**：`run-node.mjs:2471-2477` 的契約只檢查 `seriesReplayUi` 內**存在**「看完動畫，收好兩張紙」與 `ship3OpenIntermission("ch3-dual-complete"`，不檢查同畫面**是否另有繞道**。存在性契約擋不住並存的旁路。

**最小修法**：把 explore 分支與分頁鈕都掛上同一個守衛。

```js
if (mission.id === "explore" && !ship3PendingMissionBridge) {   // 3849
```
```js
ship3Btn(tabs, "去碼頭辯論", …, "shipAction debate",
  !canDebate || !!d.pendingRecord || !!ship3PendingMissionBridge);   // 3798-3800
```

**可失敗的驗證條件**：新增契約——在 `renderShipDossierLab` 的來源切片中，`mission.id === "explore"` 分支與 `shipAction debate` 的 disabled 運算式都必須引用 `ship3PendingMissionBridge`；拿掉任一個守衛必須轉紅。

## 三、B-2｜Sol 自己列的反向控制第 2 條是空變異，且缺口是硬卡死

**位置**：`greybox/src/chapter-ui.js:1820`；契約在 `greybox/tests/run-node.mjs:2478-2489`、`2496-2498`。

**實際證據**：我把監聽器的事件名改掉（等同「移除接線」）：

```js
document.addEventListener("bd:workbench-intermission-choice", …)
→ document.addEventListener("bd:DISABLED-choice", …)
```

結果 **138 通過／0 失敗——完全沒有轉紅**（其餘四組各自 137/1，見 §五）。

原因是契約檢查錯了對象：

```js
!stageUi2.includes('new CustomEvent("bd:workbench-intermission-choice"')   // 2486：檢查「派送端」stage-ui.js
```

字串 `bd:workbench-intermission-choice` 在 `chapter-ui.js` 只出現 **1 次**（就是這個監聽器），而契約從未對 `chapter-ui.js` 斷言它。`assertionIntermissionUi` 切片（`ship3StartAssertionIntermission` → `doShip`）雖然涵蓋這段程式，但只檢查 `detail.token !== "ch3-cabin-wind"` 與 `"ch3-after-wind-choice", "▸ 進入船艙實驗"` 兩個**函式體內容**，監聽的事件名可以隨便改。

**玩家實際會看到的後果**：這不是「少一段演出」，是**硬卡死**。A3 斷言成立後開啟 `ch3-cabin-wind` 接縫時：

- `body.embarkGate #panelWrap { display: none !important; }`（`stage.html:553`）→ 工作台整個移出 DOM 流；
- `$("btnEmbark").hidden = choices.length > 0`（`05-events.part.js:159`）→ 轉場鈕隱藏；
- 畫面上唯一可操作的就是三顆風選項按鈕。

接線一斷，三顆按鈕全部無反應，玩家**沒有任何出口**，只能重整（重整後靠工作台的 `renderShipDossierDesignDecision` fallback 才救得回來）。一個打字錯誤就能造成這個結果，而測試維持全綠。

**最小修法**：在既有契約補一行。

```js
if (!assertionIntermissionUi.includes(
      'document.addEventListener("bd:workbench-intermission-choice"') || …)
  throw new Error("排除甲板風的研究決定沒有接線，選項會變成死按鈕");
```

**可失敗的驗證條件**：把監聽器事件名改成任何其他字串，該契約必須轉紅（我已確認現況不會）。
