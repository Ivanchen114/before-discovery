## 二、B 級(2 條)

### B-1|風的重複支付**只做了三分之一**——玩家會被問兩次同一件事

**位置**:`chapter-ui.js:4336` `} else if (!db.p1.wind) {`

Sol 自己在上一輪指出這個接縫,並提出三段解法:

> 1. 新流程在實驗設計時用 G 完成一次風的範圍承諾;
> 2. **辯論直接引用玩家先前的選擇,不再重問;**
> 3. **舊存檔若沒有這筆承諾,才顯示 `p1/wind` 作為相容 fallback。**

**第 1 步做了。第 2、3 步沒做。**

**可重現證據**(node 實跑):

```
已在設計階段公開承諾 cabinWind = "close-cabin"
  db.p1.wind = false → UI 條件 !db.p1.wind = true
  → 辯論仍會再問一次「這組紙隔開了甲板風;你最多能把結論寫到哪裡?」
```

`engine3.js` 只在 `wind` 步自身(2648/2659)設 `db.p1.wind`,**沒有任何路徑讓 `cabinWind` 承諾滿足它**;`chapter-ui.js:4336` 的分支也沒有檢查 `designCommitments.cabinWind`。

**因果問題**:玩家在設計階段已經公開說過「這組只回答沒有甲板風時,停泊和平駛還像不像」,辯論再問一次「你最多能把結論寫到哪裡」——**同一筆主張範圍付兩次**。這正是 CR-028 想解決的「重複小考」,在新流程裡又長回來一個。而且 `choice_per_scene` 從 0.36 升到 0.45,有一部分是靠這個重複買來的。

**測試沒抓到**:`tests/run-node.mjs:2551` 只鎖了錯案會留 attempt、不生成證據,**沒有任何契約斷言「已承諾者不得再被問」**。

**直接修法**:`chapter-ui.js:4336` 改為

```js
} else if (!db.p1.wind && !(d.designCommitments &&
           d.designCommitments.cabinWind === "close-cabin")) {
```

並在 engine 的 cabin 步,若 `cabinWind === "close-cabin"` 則一併設 `db.p1.wind = true`、`db.pillars.p1 = true`,`lastReply` 改為**引用**玩家先前那句(例:「你上船前就說了只回答沒有甲板風的情況。那句我收。」)。舊存檔 `cabinWind` 為 null → 原路徑照舊。

**會失敗的驗證條件**:新增契約——`cabinWind === "close-cabin"` 的狀態走完 `p1/cabin` 後,`p1` 必須完成且**不得出現 `wind` 步**;`cabinWind === null` 的舊存檔仍須出現 `wind` 步。反向:拿掉守衛,契約轉紅。
