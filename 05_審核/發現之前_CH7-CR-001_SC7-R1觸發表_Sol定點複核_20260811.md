## 一、裁定

### A-1｜補件的 `rep 1→0` 沒有 runtime 權威

補件明定 ch7 初值 1，但現行 `narrative.js` 的 `initialStateBase()` 與 `sanitize.js` 的
`sanitizeReputationLifecycle()` 都從 3 開始；原 CR 的 registry metadata 亦沒有 `initialRep`。若照原稿
施工，T1／T2／T3 各扣 1 後只會到 2，不會鎖定或進 SC7-R1，整張觸發表實際不可達。

**吸收**：CH7-CR-001 已把 `initialRep` 納入 registry：ch1–ch6 保持 3，ch7 明定 1；initial state 與
sanitizer replay 必須同讀 registry，並加反向測試「ch7 從 3 開局必紅」。

### A-2｜「同事件不重複扣」不足以防第二次藏紙

若同一 T1／T2 action 第二次仍能改 visibility、只是 `applyRepOnce` 不再扣分，玩家會得到
「證據已藏、rep 仍為 1、沒有 repair lock」的非法世界線。這不是防刷分問題，是證據可見性與信譽
因果斷裂。

**吸收**：同一 source action 終身只可執行一次；UI 隱藏控制、engine 亦拒絕重送。事故史與
used source append-only，修復只清 active withholding。鎖定後所有非修復工作台 action fail closed。

### A-3｜T3「已送出」與凍結修復場不相容

補件寫「回覆送去傳抄」，但凍結稿同時要求：

1. §4.3 的 M 路不送出回覆；
2. SC7-R1/n1 桌上真的有被收起紙張留下的空位；
3. withdraw 是把紙放回去；
4. silence 是「先把回覆送出去」；
5. n2 是 Galvani 把紙放回桌上。

將 T3 解讀成「已公開」會讓上述至少四個玩家可見句子失去字面所指，也把 M 路從「當場可反駁」
偷改成另一條失敗前進線。

**建議收口**：T3 改為 pre-dispatch 的失信企圖——旅人抽走兩張反證、把原稿遞向門邊，Galvani
當場不接；attempted claim 留痕但 `public=false`。建議結果拍：

> 旅人把回覆遞向門邊，卻把四年前那張紙和今天親手填的那格抽離附件。桌上立刻空了兩處。Galvani 沒有接。

此句屬補件新文，不改凍結正文。Fable 已於 2026-08-11 逐字確認；A-3 關閉，日後 scenes7
必須採此句，不得恢復「回覆送去傳抄」。

### B-1｜`hidden` 不應成為原紙／trace 的可變事實

補件的意圖「紙離桌、record 不刪」正確，但若直接寫 `matrix.traces[x].hidden=true`，原始 trace
同時承擔證據事實與 UI 可見性，sanitize 與重播較容易把「曾發生」誤讀成「目前可見」。

**吸收**：CR 改用獨立 `integrity.activeWithholding` 做短暫投影；trace／record 永不改寫，事故與修復
均另增 record。這是實作表達修正，不改玩家所見的「紙離開桌面」。
