## A-1｜第四章「軌道與出版備忘」已無任何可觸及路徑（玩家無法取得關鍵規則）

**位置**
- `greybox/src/stage/05-events.part.js:106–109`（與生成檔 `src/stage-ui.js:626–629` 同步）
- `greybox/stage.html:1936`、`stage.html:1953`

**實際行為（逐項驗證）**
1. 進入任一實驗視圖時：`(view==="lab"||"ship"||"orbit") && !labIntroSeen` → 先把 `labIntroSeen = true`，然後 `if (CHAPTER_ID !== "ch4") setTimeout(showLabIntro, 0);`。**ch4 因此永不自動顯示**，且旗標已被設為 true，後面 `else if (!labIntroSeen) { … showLabIntro(); }`（`05-events.part.js:153`）也不會再觸發。
2. 程式註解寫「第四章的長備忘改為 **? 查閱**」。但全 `src/` 只有一個入口：`$("btnLabHelp")`（`07-intro-inputs.part.js:211`）。

4. 第四章 orbit 視圖渲染進 **`<div id="controls"></div>`**（`stage.html:1985`，`#controls.orbitLab`），`#lab` 全程不顯示。

→ **結論：ch4 既不自動給備忘，也沒有任何可按的「?」。** 該註解描述的機制並不存在。

**為什麼是 A 級**
消失的六條含載重規則：**「出版沒有倒數——閱讀、重排與預覽不耗窗口；只有送樣或明列理由延後，才讓排程往前走」**、「公平比較模型：同一條定律與參數全程鎖住」、「錯路就是資料」。而 HUD 常駐「校樣窗口：1/3」。玩家在沒有這條規則的情況下，理性反應是**趕快送樣、少讀少試**——恰好摧毀本章「先封存再揭曉、錯路可讀」的核心體驗。這是「玩家無法理解任務」，不是美觀問題。

**可直接施工的修法（三選一，建議①）**
1. **在 orbit 抬頭放一顆「?」**：於 `orbitHead` 產生按鈕（`ship3El` 既有 helper），`aria-label="重看軌道與出版備忘"`、`min-height:30px`，`onclick` 呼叫既有 `showLabIntro()`。與 `btnLabHelp` 共用同一張卡，零新內容。
2. 把 `btnLabHelp` 從 `#lab` 內移到與視圖無關的容器（如 HUD 或 `#panelWrap` 上緣），保留單一實作。
3. 最低成本：在 `press-opening` 相位首次出現時，於 `orbitPressStatus` 固定加一行「閱讀與重排不會消耗窗口；只有送樣或延後才前進。」（但仍建議補①，否則其餘五條仍不可見。）

**必須補的測試**（現有 112 項抓不到此類缺失）
`run-node.mjs` 加一條契約：`stage.html` 於 orbit 視圖存在可觸及的備忘入口（按鈕 id 存在且不在 `#lab` 子樹內），且 `showLabIntro` 至少有一個 ch4 可達的呼叫點。

## A-2｜1665「對不上」的史實措辭把單一說法寫成定論（憲章四）

**位置**：`greybox/data/scenes4.json` → `D1-3 / n5h`（system）

**實際文字**
> 「史實註：牛頓晚年的相關備忘錄記載，他早期曾比較月球所需的作用與地表重力；採用的地球尺度不夠可靠，結果不足以支撐公開宣布。本場把這次失配具象化，不把 1665 年演成理論完成的一刻。」

**為什麼是問題**
「他早期曾做過這個比較」有備忘錄支持，沒問題；末句「**不把 1665 年演成理論完成的一刻**」也守得很好。問題在中段把**一種**因果說成事實：
- **牛頓本人**的備忘錄說這次比較「**answer pretty nearly**（相當接近）」——並未說失敗。
- 「**因為採用 60 英里／緯度而失望、算不合**」主要來自 18 世紀 Whiston／Pemberton 的轉述。
- 牛頓在《原理》序言給的延遲理由是**另一個**：他轉去研究月球運動的不等性與多體問題，所以把出版推後。
- 現代敘述另指出，讓月球檢驗真正站得住的還包括**球體可視為質量集中於中心**的證明（約 1685 年完成），以及較精確的地球測量（通常歸功於 Picard 1669–70 年的子午線弧測量）。

戲劇上把「對不上」演出來完全可以（`historyTag` 本來就允許重建）；**但史實註是玩家唯一學到邊界的地方，不能只給一種說法**。這正是憲章四要防的「虛假歷史因果」。

**修法：把 `n5h` 換成（同長度、不動戲）**
> 「史實註：牛頓晚年的備忘錄記載他早期比較過月球所需的作用與地表重力，並自稱『相當接近』；十八世紀另有轉述說他因為採用的地球尺度不佳而失望。他在《原理》序言則把延遲出版歸給轉往研究月球運動的不等性。本場採『尺度不可靠、結果不足以宣布』這一種重建，把失配具象化，不把 1665 年演成理論完成的一刻。」

**建議同步**：`historyTag` 由 `modern-model` 改為 `later-recollection+reconstruction`（`D0-2` 已有此標籤先例），並在章末史實頁把此條列為「合理重建」而非「史實」。

**為什麼是問題**
`unstable` 是 `commitDeflection` 的**逐拍**判定（`engine4.js:272–275`：偏角 >15°、或量 1.25–2.2 倍、或 <0.75 倍），此刻玩家只畫了一拍，**畫面上還沒有「圈」**，說「每一圈都在換半徑」與眼前現象不符（那是整輪 `outer-band`／`inner-band` 的症狀）。而且 `unstable` 是**最常觸發**的 catch-all，卻是四句裡唯一不告訴玩家「它做了什麼」的一句。引擎其實已經連 `angleDeg` 與 `magnitudeRatio` 都回傳了（`engine4.js:278–279`），資訊白白丟掉。

# 四題回答

**1. 玩家現在是否真的有「和牛頓一起想」的感覺？**
有，而且是這輪最大的實質進步。關鍵不在標題改名，而在牛頓開始對**你這一次畫出來的東西**說話——尤其「你連自己寫的規則會做什麼都沒料到」這種只有在場的人才說得出口的句子。他現在像個有標準的人，不是關卡導覽。仍有一個縫：A-1 讓他變成唯一的資訊來源，玩家卻連整章規則都查不到，這會在 `press-opening` 那段把「同行」變回「被催稿」。

**2. 1665 的失敗是否成為故事，而不只是教學說明？**
是。它有三個要素：他自己先試過、他拒絕把數字湊到好看、他開出一個條件才肯回頭。而且是**玩家替他做決定**，不是旁白告知。唯一削弱它的是 B-4——他開的條件後來沒有任何人兌現，抽屜自己開了。補一拍「有人重新量了地球」，這場戲的因果就閉合。

**3. 哪一個階段仍最像工作坊或表單？**
`models`（雙模型反驗）。它仍是「先設定公平標準 → 鎖定 → 兩個模型各跑一次 → 讀殘差與補丁數」的表格比較，靠的是 `orbitModelGrid` 的數字欄位，人味最少；`proof`（印刷台）反而因為哈雷在旁邊逼人而活著。若要再修一輪，`models` 該讓**佛蘭斯蒂德的書信在比較過程中插話**（他已經有「若要用我的數字改變結論，也請留下是哪一夜改變了你」這種好句子），而不是只在開場給一段。

**4. 如果這輪只能再修三件事，你會選哪三件？**
1. **A-1**：把備忘變回可觸及（orbit 抬頭加「?」），並補契約測試。這是唯一會讓玩家做出錯誤行為的缺陷。
2. **A-2**：改寫 1665 史實註，並列牛頓自述「相當接近」與 18 世紀轉述。憲章四不可交易，且只是一句話。
3. **B-1**：修 `unstable` 那句。它是最常出現的失敗回饋，現在既描述錯現象、又浪費了引擎已算好的診斷資訊——改完，玩家「自己看懂哪裡錯」的比例會明顯上升。

（B-4 緊接在後；若三件之外還有餘裕，它是性價比最高的第四件。）
