### 誤報機制(精確定位)

`narrative_guard.py:325 _contains_gold_phrase` 有兩條規則。我把它們分離,對**全五章**跑統計:

```
規則1(不是…是…)命中:  13
規則2(A，不是B)獨有命中: 5
```

規則二的 5 條全列如下,**我逐句判:3 真 2 誤**——

| 出處 | 句 | 判 |
|---|---|---|
| ch2 B0-2/nb2 | 是畫給瞄準用的,不是畫給真相用的 | ✅ 真(VP 對 VP) |
| **ch4 D1-2/n4** | **這個 4.9,不是我量的** | ❌ **誤**(NP 對 VP) |
| ch4 D1-2/n7 | 是我估的,不是你量的 | ✅ 真 |
| **ch4 D2-1/n32** | 它永遠是一條帶子,不是一條線 | ✅ 真 |
| ch4 D4-2/n16 | 寫清楚,不是寫大方 | ✅ 真 |

**根因**:規則二 `[^。！？!?]{1,30}[，,；;]\s*不是[^。！？!?]{1,30}` 只看「逗號 + 不是」,不看逗號前是**謂語**還是**主題**。真對仗兩半平行(寫清楚/寫大方、一條帶子/一條線);誤報的前半是主題名詞組(「這個 4.9」),後半才是謂語。

**驗證我的分類正確**:「這個 4.9 **不**是我量的」(去逗號)→ 不命中;加回逗號 → 命中。**觸發它的是標點,不是語意。**

## 定點 2|contract 完整性:**足夠,一項建議**

63 三拍要求「同場、不同節點、依序、發現與回應講者不同」——**這正好擋住我最可能犯的錯**:把三拍併成一句結果句(ch3 病灶原型)。64 要求 pause 在 evidence 之前,擋住「先給證據再補停頓」。

**會被錯擋的合理場景我想到一個**:三拍中的「回應」由**同一角色**做出——例如牛頓自己發現、自己反駁自己(ch4 D1-2 n18-n19 牛頓連問兩句就是這型)。contract 強制「發現與回應講者不同」會擋掉這種**自我詰問**。

**修法**:允許 contract 標 `self_interrogation: true` 時豁免講者不同的檢查,但**必須人工填**——即成本可見。**這是 C 級,不是 B**,因為現況是「保守擋下+人可改 contract」,不是靜默放行。

## 定點 4|Markdown 排除:**通過,但密度指標可被條列污染(B-1 的實測)**

- ⚠ 我一度以為「動能」漏報,**查表後是我錯**:ch5 禁詞表只禁「焦耳/動能=½mv²(現代式)/能量守恆定律」,單獨「動能」不在表內。**FORBIDDEN_PATTERNS 是忠實照跨章規格 §四抄的,五章逐條核對無誤。**

**但發現一個真問題(升 B):**

```
兩句台詞               → nodes/beats=2  nodes/scene=2.0
同樣兩句 + 四條設計條列 → nodes/beats=6  nodes/scene=6.0
```

**設計條列被計入 beats。**條列沒有變成講者(Sol 說的沒錯),但它們**灌水了 nodes/scene 與 chars/node**——而這兩個正是 NAR-08 壓縮率偵測的**唯一指標**,也正是揪出 ch5(3.6 nodes/scene)的那把尺。

**因果風險**:一份被壓縮的展開稿,只要設計註記寫成條列(**我寫稿的習慣就是這樣**),密度就會被稀釋到看起來正常。這會讓四律守門在**最需要它的場合**(草稿階段)失效。runtime JSON 路徑不受影響。

**修法**:draft parser 的條列項若不含講者標記,**計入 parser 統計但排除於 beats 密度分母**;或至少分開印 `dialogue_beats` 與 `total_lines`。
**會失敗的驗證條件**:上述兩份 fixture 的 `nodes/scene` 必須都是 2.0。
