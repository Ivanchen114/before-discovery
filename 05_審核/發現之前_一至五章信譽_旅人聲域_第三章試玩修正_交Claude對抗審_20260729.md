## 一、這次不是逐張截圖打補丁

總監連續指出的表面症狀不同：

1. 第三章前段旅人像旁觀者，後面卻突然取得實驗權。
2. 「旅人說出口」與「旅人心聲」在畫面、讀屏與資料上容易混淆。
3. 第三章辯論攤開全部證據後，玩家不知道「現在問哪張紙」；選到新開放的證據時，還可能出現玩家沒說話、NPC 卻回錯對象。
4. 信譽像第一章限定功能，且少數舊觸發把答對當成加分、同一錯誤可反覆扣分。
5. runtime、劇本正本與 skill 檢查器各自修一點，會再製造三套真相。

本輪把它們收斂成四個跨章契約：

| 契約 | 玩家可見結果 | 機械守門 |
|---|---|---|
| 信譽＝研究誠實與授權，不是答題分數 | 猜錯、預測錯、實驗失敗不扣；越過來源才扣 | 五章觸發矩陣、每筆理由、同錯首次制、五章修復路由 |
| 聲域＝說出口與心聲是不同事件 | 名牌、框線、肖像亮暗、字體與讀屏都能辨認 | canonical speaker taxonomy、舊接口正規化、五章鏡像與反向變異 |
| 辯論＝題目、原紙與發言綁在同一資料源 | 所有可用紙攤開，但「這一題看哪張」不會猜 | shared evidence catalog、source fail-closed、逐卡玩家發言與 NPC 回應 |
| 正本、生成物、runtime、測試一起交付 | 不以 runtime 綠燈掩蓋劇本或生成物落後 | 五章 JSON／JS 深等、stage parts／生成檔深等、第三／四章劇本錨點同步 |

## 二、五章信譽實作矩陣

上位裁定：`01_治理/發現之前_GB-ADR-030_信譽作為研究誠實與授權階梯_20260729.md`。

| 章 | −1：越過哪條邊界 | +1：完成哪個研究行動 | 首次制／中性行為 |
|---|---|---|---|
| 第一章 | `P0-2/nA4` 把沒有證據的未來答案說成大家都知道的事 | `P0-2/nB3` 同意讓斷言接受證據檢查，且同行也受同一規矩約束 | 移除 `P0-1` 感官題與 `INT-1` 主線記憶的答題獎勵 |
| 第二章 | `B0-2/q1/a` 未讀砲術圖就宣稱舊規律一定管得到飛行 | `B0-2/s1` 先讀對手的圖，也保留它真正支持的範圍 | 同句第二次走 `a-again`，NPC 仍回應但不再扣；預測與實驗失敗中性 |
| 第三章 | 舊紙上搶先宣布「平穩船必然如何」；終局宣稱量到地球、或把走穩結果擴成變速結果 | 把話收回「只記一次、船速未記」的原紙範圍 | 舊紙與兩種終局越界皆以 choice 分別首次扣；舊 `setBoundary` 不再重複改全域信譽 |
| 第四章 | 虎克整套完成／虎克被抹除；作用機制已證明／牛頓一人完成 | 旅人親手退出《原理》作者欄 | 四種不同來源錯誤各首次扣；重選同一項不再扣；九宮格預測錯與計算錯中性 |
| 第五章 | `E1-1/q1/authority` 用前輩名聲替代可驗資料 | 把兩本帳改寫成可驗問句；`J4` 保留未對平的去向 | `authority-again` 不重複扣；選錯帳、碰撞與黏土失敗中性 |

每筆變動都有 `reason`；HUD 每次顯示方向與理由。第三章辯論的「說服力」仍是單場容錯，不與 `state.rep` 合併。

規則跨章一致，數值不跨章繼承：每章 `state.rep` 表示當章人物是否願意把研究工作交給旅人。換了年代與人物後，新角色不會自動知道上一章的信譽帳；本輪沒有偷建系列共用分數或跨章存檔投影。

## 三、第三章旅人授權與聲域

### 3.1 旅人不是突然被系統指定

第三章正本與 runtime 現在同時具備：

1. `C0-2`：旅人先提議把「船怎麼走」也記下來。
2. 維達爾船長只給條件式回應：先真的記出那一欄，再談配紙。
3. `C0-3`：玩家面對「我知道正確方向，但這張紙沒有支持」的信譽誘惑。
4. 伽桑狄以兩個理由交權：旅人守住原紙空白；旅人不欠船主人情。
5. 旅人心聲確認：取得卷宗不是因為知道答案，而是沒有先把答案寫進去。

`04_劇本/第三章台詞稿_v0.9_展開版_Claude_20260728.md` 已與 runtime 同步，不再只修遊戲資料。

### 3.2 說出口／心聲雙重提示

五章 canonical speaker 只允許：

- `旅人(你)`：真的說出口。
- `旅人・心聲`：其他角色聽不見。

精確裸名 `旅人` 為零。舞台呈現：

- 說出口：名牌顯示「旅人（你・說出口）」；旅人側亮起。
- 心聲：名牌顯示「旅人・心聲（其他角色聽不見）」；虛線框、斜體現代字、所有肖像壓暗。
- 讀屏使用同一組聲域提示。
- 舊接口若送入裸 `旅人`，在事件邊界正規化為 `旅人(你)`。

canonical 的說出口／心聲／裸名數：

| ch1 | ch2 | ch3 | ch4 | ch5 |
|---|---|---|---|---|
| 17／4／0 | 13／4／0 | 19／45／0 | 38／30／0 | 1／0／0 |

第五章旅人密度低是另一個劇本展開議題；本包沒有拿「改 speaker 標籤」冒充已補足第五章戲份。

## 四、第三章試玩修正與 Claude A／B／C 回覆

### 4.1 已完成的總監試玩項

- 舊紙取得時已有專圖；圖上不偷渡可讀署名、年代、船速或新落點。
- 解纜起步圖仍表現共同前行，但相對偏移只留在船內可讀尺度，不再讓石頭視覺上飛出船。
- `C0-1` 的三十年翻頁改走三板時間蒙太奇：1609 問題留下 → 1632 《對話》船頁 → 1640 馬賽交棒。
- 辯論問題改為白話：
  - 「這些原紙能支持哪一句斷言？」
  - 「勾選能支持同一個說法的原紙，再選你要提出的斷言。」
- 所有已取得、仍有效的原紙都攤開；每張標明船況／條件、觀察位置、變因與可支持範圍。
- 選題時同步顯示「現在判讀的紙」。
- 同號鼓點的逐拍數值表已移除，保留兩張圖與玩家實際對鼓點、扣桅杆位置的判讀動作。

### 4.2 Claude A-1：玩家空白發言、NPC 回錯紙

已把 `getDossierEvidenceCatalog()` 設為共同來源。所有 owned packet 都由 catalog 生成：

- 非空 `lastPlayerLine`，且明說玩家遞出的實際紙名。
- NPC 回應引用同一張紙，不再固定回「舊紙和船艙紙」。
- 合法雙紙仍進正解路徑。

測試逐一遍歷 catalog，不只抽 A1；拔掉生成邏輯會紅。

### 4.3 Claude B-1：原紙綁定不得 fallback 猜測

`ship3DossierPacketSourceIds()` 只接受實際保存的 `assertionSources`／`claimSelections` 與該題正式來源。來源空白、偽 ID、不同 stage 都回空集合；UI 明示：

> 這一題的原紙尚未綁定，請先在卷宗選紙。

已用 VM 實跑 helper，避免只檢查字串形成假綠。

### 4.4 Claude C-1：柱數不固定，但 schema 也不會自己長

法源已改為「柱數服從劇情，可三柱或四柱」。同時明列：新增第四柱必須同步 engine defaults、欄位正規化／補欄、sanitizer 與必要的 schema migration；不能因呈現層使用陣列，就宣稱整個狀態模型已自動支援。
