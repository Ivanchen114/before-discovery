### B-1|五章裡有三章的修復場**在正常遊玩中到不了**;第五章的還是本輪新蓋的

**位置**:`data/scenes.json`、`scenes2.json`、`scenes5.json` 的扣分點總量 vs `src/narrative.js:65` 起始 `rep: 3`。

**可重現證據**(逐章列舉所有 −1 來源,含引擎層,皆按首次制計):

| 第二章 | `B0-2/q1/a` ×1 | 0 | −1 | **2** | ❗`SC-R1` 不可達 |
| 第三章 | `C0-3/c1/all` ×1 | 終局 overclaim / other ×2 | −3 | 0 | ✅ 可達 |

補充查證:
- `applyRep` 是 `state.rep` 的**唯一寫入點**(`narrative.js:104/106`),夾制 `REP_MIN=0`。無其他旁路。
- ch1 `P0-2` 是線性 DAG,`nA4` 之後**無法再經過 nA4**(我跑了場景內可達性),所以不能靠迴圈刷到 0。


## C 級(4 條,不阻擋)

### C-1|`applyRep` 有四個呼叫點沒傳 `reason`,是留給下一個人的陷阱

**位置**:`src/narrative.js:283 / 427 / 511 / 547`

```js
applyRep(state, opt.penalty.rep, "debate.pressChoice");        // 283,無第四參數
applyRep(state, t.penalty.rep, "debate.fr2." + t.id);          // 427
applyRep(state, claim.penalty.rep, "debate.fr5." + claim.id);  // 511
applyRep(state, t.penalty.rep, "debate.trap");                 // 547
```

`applyRep(state, delta, sourceId, reason)` 的第四參數缺席時,`if (reason) event.reason = reason;` 直接略過,產生**無理由的 rep 事件**——正是 §二-2 禁止的。

**目前不可達**:我掃了五章資料,`"penalty"` 物件 **0 個**,遑論 `penalty.rep ≠ 0`。所以今天 §六-1 是真的成立的,這四行是死路徑。

**風險在未來**:下一個人在辯論選項加一條 `penalty: {rep: -1}`,會靜默拿到無理由事件,而**沒有任何測試會紅**——我在 /tmp 副本上拔掉全部 `reason` 欄時是 12 紅,但那是資料層;引擎層這四條不在守備範圍。

**修法**:`applyRep` 把 `reason` 改成必填(缺就 throw,或寫入 `reason: "(未填)"` 並讓契約測試斷言事件流裡不得出現該字串)。四行補上理由字串。

### C-3|誠實模型不對稱:「高估資料」扣分,「低估資料」免費

**位置**:`C0-3/c1/fake`——「船速、鼓點和岸標都沒記,這張紙不能算數。」`rep = []`。

GB-ADR-030 §二-1 的 −1 清單處理的全是**往上越界**(把未證明說成已證明、局部說成普遍、借權威)。**沒有一條處理往下越界**:把一份不完整但有效的紀錄說成毫無價值。

而這張紙不是路人甲——它是 p2 辯論裡旅人自己要拿出來用的「我的舊紙」。玩家在 C0-3 說它「不能算數」,兩場之後又要靠它贏。伽桑狄的 `f2`「條件沒寫全,這張紙能說的就少;但它記下的落點還是真的」在**台詞層**糾正了,但**機械層零後果**。遊戲教出來的規則會是:誇大要付一分,抹殺免費。

**這不必然是缺陷**——可能是刻意的中性設計(丟棄資料至少是誠實的保守)。但 §二沒有寫,所以看不出是裁定還是遺漏。

**修法**:二擇一。或補一條 −1(建議名稱:「把不完整的紀錄說成沒有價值,等於刪掉不利原紙」——這其實貼近 §二-1 既有的「隱瞞、刪除不利原紙」);或在 §二-1 明記「低估資料」刻意不扣,並寫出理由。
