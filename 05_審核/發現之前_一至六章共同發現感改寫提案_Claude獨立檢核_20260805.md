## 一、總裁決

# 有條件放行

九項候選裡 **6 項採用或修改後採用、2 項修改後採用但需先補救提案自身的缺陷、1 項退回重新定位**。

放行的理由是提案的方向與總監校正後的原則一致，而且它**撤回舊版過度規格化這件事做得徹底**——2.3 節主動撤回第三章 `INT-C2` 與第五章 `E2-2` 兩個原候選，並在第五章寫下「不能因答案稍後才被旅人說進場面，便判成 NPC 或系統代做」。我實讀 `INT-C2/x2-x5` 與 `E2-2/x8-x11` 後確認這兩個撤回是對的。

有條件的理由是三件事，**每一件都是提案自身的問題，不是它診斷對象的問題**：

**條件一｜CH4-CD-01 必須重新定位，不能照現狀執行。** 提案的「候選發現順序」12 步裡有 **11 步已經存在於總監親自定案的對白**中（`05_審核/…三方潤飾與意見彙整_20260804.md` 開頭明載「總監已定案本場戲的結構、互動設計與玩家判斷點；本輪任務範圍限定為口語潤飾」）。提案雖在「相關既有文件」列出該檔，內容卻是平行重寫而非承接。這一項的正確動作是「把總監定案版落進 `scenes4.json` 並與 GB-ADR-039／040 對帳」，不是「重新設計發現順序」。詳見第四節。

**條件二｜CH1-CD-01 的候選 `n2` 會違反 GB-ADR-040 ①。** 現行 `n2` 含「別猜總長；先看每一段比上一段多走多少，**再押第五段**」，這正是 ADR-040 ①「預測只外推第五段，揭曉時把押記和真實刻痕並排」的落地句。候選 `n2` 刪掉「再押第五段」，只留「第五段蓋住」。而 `engine.js:118 judge(state0, runIds, prediction)` 與 `:124 predDev` 證明第五段**必須**有押記，工作台會要一個對白已不再交代的東西。

**條件三｜CH2-CD-01 的「現況」描述失真，候選反而是淨損失。** 提案說候選要新增「但這只是預測；船上的紀錄，我們一筆也沒有」——**這句在 runtime 的 `B1-2/na1` 裡已經逐字存在**。候選實際做的是刪掉伽利略的物理說明並移給旅人，同時把現行的句號改成分號（P1 回歸）。

### 4.2 為什麼是案 A

**史實理由**：牛頓自己的說法是 1665–66 年的比較「answer pretty nearly」。我算過他當年實際會拿到什麼：

```
1665 年英格蘭常用值：緯度一度 = 60 英里 → 地球半徑 3438 英里（真值 3959）
偏小係數 0.868 → 月球一秒偏折算成 1.178 mm（而非 1.356）
比值 = 4900 ÷ 1.178 ≈ 4161 ｜ √4161 = 64.5 ｜ 與 3600 差 16%
```

16% 的幅度支持案 B 的戲劇可行性（大到看得出不是 60²，小到會寫「pretty nearly」）。但**史學上對「地球半徑錯值到底延遲了他多久」有爭論**，能穩穩站住的只有「他當時算出來只是接近」這件事本身。**案 A 只要在場內明示「接近不是正中」並留下尺度債，就已經誠實地承載了史料能支持的全部內容**；案 B 要多承載一個史學上仍有爭議的因果（錯值造成延遲），反而在史實嚴謹度上不是純增益。

**工程理由**：案 B 的代價我逐項列在下面（第 4.3 節），核心是它會**動到 GB-ADR-039 的既有裁決**。ADR-039 明文：「沿用既有 K2 引擎 action 與 schema，**不新增存檔欄位**」，並且「最後在疊合台由玩家決定兩個 60 應相加或相乘，**完成後才明說兩條獨立路徑各自得到 1/3600，並命名距離平方關係**」。案 B 要讓「1665 只成立方法與近似關係、後期再正式對上」，就必須：把 K2 的證據取得時機拆成兩段、新增階段狀態、遷移舊存檔——**全部是 ADR-039 明文排除的那一類改動**。要做就得先廢止或修訂 ADR-039，這不是一次對白 CR 能承載的。

**體驗理由（這是我與 codex 在 `彙整` 文件裡的既有分歧）**：現在這版的高潮是兩人沉默、玩家親手把「60」挪過去、旅人只說「六十……」。案 B 會讓高潮出現兩次（互相稀釋）或第一幕沒有高潮（玩家算完兩張紙換來「差不多但不對」）。**後者正是總監自己實機在 K2 卡住時的體驗**（施工總清單第六節記錄的原話：「這裡只是盲猜嗎？我不知道要幹嘛」）。

### 4.3 案 A 的前置條件：必須確認 UI 揭曉時機的法源歸屬

提案的「現行核心問題 6」說 `chapter-ui.js` 會在外層對話前顯示「偏折依時間平方縮小」「各自得到 1／3600」「支持距離平方關係」。我逐行確認：

```
chapter-ui.js:6786  "✓ 藍紙完成：時間縮短 60 倍，偏折依時間平方縮小，得到約 1.36 毫米。"
chapter-ui.js:6837  "✓ 兩張紙對齊：一條從時間平方換算，一條從距離平方建模，各自得到 1／3600。"
chapter-ui.js:6845  "兩個 3600 不是同一步重算：一個來自時間換尺，一個來自兩張一秒紙的比較。
                     它們在這裡對上，才支持距離平方關係。"
```

**但提案漏了三件事，而這三件事會改變修法：**

1. **這些訊息是玩家完成操作後的成功回饋，不是事前指示。** `:6837`／`:6845` 都在 `matchedOverlay` 裡（玩家對齊兩張紙之後才出現），`:6786` 的 `✓` 前綴也是完成訊息。所以它們不是「搶先揭曉」，而是「即時確認」。
2. **這個揭曉時機是 GB-ADR-039 明文授權的**：「完成後才明說兩條獨立路徑各自得到 `1/3600`，並命名距離平方關係」。要延後或刪除，等於修訂 ADR-039。
3. **`:6845` 那句是施工總清單第六節 K2 重新設計的成果**——它存在的目的就是解決總監實機卡關的「兩個 3600 分不出來」。刪掉它會重新製造那個問題。

**所以真正的問題不是「UI 搶先揭曉」，而是「`n10`／`n11` 與玩家在 K2 已完成的事重複」。** 節點序證實了這點：`D1-2` 是 `…q3 → e1(EMBED orbit/scale, until=k2) → n9 → n10 → n11 → n12…`。玩家在 `e1` 裡完成疊合並看到「支持距離平方關係」，出來後牛頓 `n10` 又下指令「再按距離平方把地表那個數縮小」，旅人 `n11` 又覆述同一關係。

**這個診斷讓修法變得便宜得多**：不必碰 UI、不必修 ADR-039，只需把 `n10` 改成 GB-ADR-040 ④ 要求的讀回句、把 `n11` 從覆述改為推進到下一個未決。**兩處純對白，且是既有 ADR 的合規修正。**

### 4.4 案 A 的施工形狀（建議）

1. 以總監定案對白為正本，落進 `scenes4.json`（`D1-1`／`D1-2`）。
2. `n10` 依 GB-ADR-040 ④ 改為讀回句；`n11` 改為推進而非覆述。
3. 結尾加約六句：牛頓自己指出「接近不是正中」，指認嫌疑犯（地球大小的測量），記為尺度債。**這是我在 `彙整` 文件裡提的輕量版，成本約六句台詞、零程式改動**，並讓旅人現有的「數字吻合，但還不是最後的證明」有具體所指。
4. 保留 `n12` 的「在『支持』兩字下劃線，沒有把它改成『證明』」——提案第 10 步的認識論收束已在此。
5. UI 三處訊息**不動**（ADR-039 授權且是 K2 卡關修法的成果）。
6. 對白裡的「拖」字改為中性動詞（見第五節誤傷檢查）。
