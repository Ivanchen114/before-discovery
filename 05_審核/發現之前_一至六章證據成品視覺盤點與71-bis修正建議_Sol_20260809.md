# 《發現之前》一至六章證據成品視覺盤點與 71-bis 修正建議

## 一、總裁決

**應修，但不應把全系列套成同一張羊皮紙模板。**

本輪第四章 K4 成功的原因，不是「生成圖比 SVG 高級」，而是畫面終於同時具備：

1. 一眼可辨的物質載體；
2. 世界內的製作者與字跡；
3. 玩家實際做過的操作痕跡；
4. 與 runtime 一致的數字、印章、借條與主張邊界；
5. 取得後像一件已完成的證物，而不是等待 UI 填字的空背景。

所以改版單位應是「證據成品」，不是「把 SVG 全換成生成圖」。固定內容可以做完整
raster；玩家狀態會改變內容時，真實世界線優先於美術整齊，必須使用完整的動態製圖
或受控變體，不能把某一條預設路線烘焙成所有玩家都看見的假證物。

### P0 事實錯誤：CH6 T4

現行 `engine6.js` 為四個來源各提供兩種合法 band，但 band 並不相同：chips 與 air 是
`soon／no-endpoint`，封條裂或完整由玩家選擇決定；cannon 與 water 是
`soon／within-shift`，兩者都是有限預測，因此封條終態恆裂，但原預測帶的位置仍隨
玩家選擇不同。有限預測未兌現才令封蠟 `cracked`；未設終點則應保持 `intact` 並記為
`insufficient`。目前 `ch06_card_T4_prediction_bands_v01.svg` 卻固定畫四個叉與四張裂封，
會把玩家沒有下過的有限預測畫進證物。

因此 T4 不是直接生一張漂亮圖即可。若卡面只畫封條裂否，chips×air 只有四種組合；
但 T4 的證物承諾是「裂封仍可追查原預測」，cannon／water 即使同樣裂封，也必須保留
玩家押的是 `soon` 或 `within-shift`。卡面忠實呈現封條態與原預測帶時，四來源的 band
選擇仍形成 2⁴＝十六種完整世界線，超過有限變體上限。應改為**完整的程式製圖成品**，
不能為了湊四張而刪掉證物最重要的原預測；也不得使用生成底圖加可見文字疊層冒充
完整證物。

## 三、71-bis 候選條文：取得後證據成品

### 3.1 先分類載體，再選技術

1. **固定摘要卡**：內容恆定、所有玩家相同。使用單張完整 raster；核准文字、數字、
   印章與邊界句可烘焙入圖。
2. **有限變體卡**：內容只依不超過四種枚舉狀態改變。製作完整扁平 raster 變體集，
   runtime 依 canonical state 選整張；各版共用固定區，只允許核准差異區改變。
3. **玩家狀態卡**：含自由輸入、連續值、任意紀錄集合，或超過四種組合。使用完整的
   deterministic HTML／Canvas／SVG 製圖；畫面仍必須像世界內的完成紙件，不能退回
   通用資訊面板，也不能用生成圖偷偷固定一條世界線。

「單圖原則」約束玩家最後看見的成品不可像拼貼 UI，不等於所有證據都必須預先生圖。
四張是以 CH4 K4 既有變體包為錨的工作上限：生成、逐字驗收、並排漂移檢查與資產包
成本都隨張數線性增加；超過四張時必須回頭簡化卡面，或改用完整動態製圖，不能把上限
當成自然定律，也不能為守上限刪掉證物必要內容。

### 3.2 字體依作者，不依年代裝飾

| 文字作者／聲部 | 視覺語言 |
|---|---|
| 旅人筆記、玩家親筆、玩家貼上的借條 | 楷書手寫感 |
| 世界內文獻、科學家帳頁、預刻印章 | 明體／宋體刻本感；西文與數字用相應時代筆跡 |
| 系統、現代導覽、無障礙替代資訊 | 黑體，置於圖外 UI |

同一卡可以同時有兩種字跡，因為那表示不同作者。CH4 K4 的帳冊與印章屬世界側；
「借條只有玩家自己貼得上」，借條應用旅人／玩家的楷書聲部。古意由紙、墨、壓痕、
間距與器物取得，不靠奇幻書法。正式出貨仍不得把專有的標楷體檔嵌入遊戲；楷體聲部
須另選可隨遊戲出貨的授權字型子集。K4 借條是「同一卡兩種字跡＝兩位作者」的標準
判例，不是字體不一致。

### 3.3 逐字稿、事實與驗收

- 生圖前先鎖定逐字稿與 runtime state table；每一個數字、單位、印章與結論都是事實
  主張，不能把舊 SVG 當可信上游。
- 固定 raster 的文字生成失敗時整張淘汰重做，不在成品上以 SVG／HTML 補字。
- 上一條在**取得後證據成品**範圍內修訂 GB-ADR-044 的「OCR 未過便改無字圖加程式
  疊字」備援；探究進行中的關係鏡頭、焦點圖與非成品式 UI 不受影響。
- 變體以核准基底為來源；並排驗收固定區語意與構圖，差異只出現在允許區。
- 玩家狀態卡必須用目前存檔重建，讀檔、重播與舊存檔不得捏造未發生痕跡。
- 圖外保留 alt、caption、逐字文字版與來源展開；證據圖不是唯一可及來源。
- 證據提供點擊放大／全螢幕。縮圖只要求標題與物質載體可辨，放大後才要求全文可讀。
- 驗收至少包含：runtime 對照、逐字／OCR 對照、視覺作者聲部、桌機／手機放大、讀屏
  替代文字、變體或存檔往返。

## 四、Skill 修正建議

Skill 應補，但只補**路由與失敗條件**，不複製上面整份美術法。建議在
`before-discovery-dev` 的 art／history 段加入：

> 取得後證據圖在 prompt 或施工前，先讀「實驗證據所有權與認知進階原則」的證據
> 成品分類（該法源 71-bis 節生效後），判定 fixed summary／finite variant／player state；不得假設「所有精確文字
> 數字一律疊 SVG」，也不得假設「完整 raster 一律優先」。先由 canonical runtime
> 列出固定欄與狀態欄，再決定 raster、變體集或 deterministic 動態製圖。字體依作者
> 聲部，不依「看起來古」選擇。交付須分列 runtime fact check、逐字稿、放大閱讀、
> alt／caption、變體／存檔往返與來源 ledger；任一圖固定了不存在的玩家狀態即 BLOCKED。

本案 Design Gate 的必要交付包含：先將 71-bis 正式納入「實驗證據所有權與認知進階
原則」，並明文限縮 GB-ADR-044 在取得後成品的舊備援；之後 Skill 才能引用該節，不能
保留空指針。

本案已於 2026-08-09 通過 Design Gate。Skill 維護包須以局部 patch 保留既有未提交
內容、同步治理鏡像並完成獨立 CONFORMANCE；activation 仍是另案。安裝中的舊 Skill
仍保留「精確數字一律使用 SVG／HTML」的過時硬規則，在新版啟用前不可用它否決固定
摘要 raster。

1. 修 CH6 T4 的世界線錯誤，完成 CH4 K1／K4 現行包。
