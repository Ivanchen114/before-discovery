## 三、Sol 額外抓到的「第一章」誤標：屬實，而且現在還在線上

**這一條我差點誤判為不成立。** 我先用檔案層搜尋：`51c977d` 的 `chapter2.html`／`chapter3.html` 裡「第一章」出現次數 **0**，兩檔到現在的 diff 也只有 CSS 與快取鍵。看起來沒有這個 bug。

實查執行期才確認**是真的**：

```js
function chapterMeta(id) {
  return SERIES_CHAPTERS.find((ch) => ch.id === id) || {
    id: id || "ch1", route: "ch01", number: "01",
    label: "第一章",                      // ← fallback 寫死
    title: SCENES.title || "重物的渴望",
```

`SERIES_CHAPTERS` 來自 `SERIES.chapters`，由 `series.js` 提供。**`51c977d` 的 `chapter2.html` 與 `chapter3.html` 沒有載入 `series.js`**（grep 計數 0；現況已補上，計數 1）。查表落空 → 走 fallback → 執行期把章名蓋成「第一章」，靜態 `<title>` 寫對也會被覆蓋。

**玩家後果**：直接開第二／三章獨立頁時，畫面上的章名與標題顯示「第一章：重物的渴望」。**此刻線上仍是 `51c977d`，這個錯誤還在。**

**我的方法錯誤，記在這裡**：靜態 grep 證明不了執行期行為。這是我這幾輪同一類錯誤的又一次變體（假設形狀／範圍而未實查），這次是靠追 fallback 分支攔下的。

## 四、C 級兩條

**C-1｜`chapterMeta` 的 fallback 會靜默偽裝成第一章。** 位置：`src/chapter-ui.js:39-47`。查不到章別時不報錯，而是回傳一個**看起來完全合法的第一章**。這次是漏載 `series.js`，下次可能是章別 ID 打錯或 series 資料缺一列——症狀都會是「顯示成第一章」，而且測試不會紅。修法：fallback 保留（避免整頁壞掉），但把 `label` 改成可辨識的佔位（例如 `"（章別未載入）"`），或在 `console.warn` 留一行。**可失敗的驗證條件**：把任一章頁的 `series.js` 拿掉，該頁的章名不得顯示成任何真實章名。

**C-2｜這個 bug 沒有常駐契約。** 現行修法是「補載 `series.js`」，但沒有測試防止哪天又有人漏載。建議加一條：每個 `chapter*.html` 都必須引用 `series.js`，且 `chapterMeta(該頁 CHAPTER_ID)` 不得回傳 fallback 物件。**可失敗的驗證條件**：從任一章頁移除 `series.js` 引用，測試必須轉紅（現況不會）。
