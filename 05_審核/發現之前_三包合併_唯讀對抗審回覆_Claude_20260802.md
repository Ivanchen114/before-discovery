## 二、B-1｜第三章洩題契約只綁一個節點，而現行內容在別處已經命中（已發佈）

**位置**：`greybox/tests/run-node.mjs:2438-2442`；內容在 `greybox/data/scenes3.json` 的 `C0-3/c1`。

**實際證據**——契約長這樣：

```js
const xcard = byId(s3, "C0-1", "xcard")?.text || "";
const revealedSteadyResult = /落(?:在|到)?(?:桅(?:杆)?(?:腳|下|底)|原處)|(?:跟|隨)(?:著)?船(?:一起)?(?:走|前進)|不(?:會)?落(?:在)?後|沒有落後/.test(xcard);
```

**regex 是對的，範圍是錯的**——它只讀 `C0-1/xcard` 一個節點的 `text`。契約名字叫「不提前洩題」，實際只守一格。

**反向控制（副本基線 139/0）**：

| 變異 | 結果 |
|---|---|
| 把「石頭會跟船一起走，不會落在後面」加進 **`C0-1/xcard`** | 138/1 ✅ 命中「C0-1 合理重建卡提前揭露落石結果」 |
| 同一句加進 **`C0-3/c1` 的 `fake` 選項** | **139/0 ❌ 不轉紅** |
| 同一句加進 **`C0-2/n1` 的節點文字** | **139/0 ❌ 不轉紅** |

**而現行內容已經命中**。我對第一次實驗（`C1-1`）之前的全部 active 文字跑同一條 regex，**4 處命中**，全在 `C0-3/c1`：

```
[all]       船若只是平穩往前，石頭會跟船一起走，不會落在後面。
[all_again] （同上，require 互斥，首次 rep−1 後不重複扣分）
```

「跟船一起走」正是包裡 A-1 自己列的禁詞。

**玩家實際會看到的後果**：第一次上船之前，玩家必須讀完四個選項，其中兩個把本章要靠實驗掙來的穩速結果直接寫出來。之後真的量出「落在桅腳」時，那一拍的重量已經先被花掉。

**為什麼我判 B 不判 A**：`xcard` 是**系統權威語氣直接陳述結果**；`all` 是**玩家提出、立刻被扣分否定的過度宣稱**。語氣不同，嚴重度不同。但第四章的先例是同一個問題的更嚴標準——`D0-2/c0` 的過度宣稱原本寫「月亮一直往下掉，卻永遠錯過地面」，被判 B 後改成「地球一定也在拉月亮」，**保留主張、拿掉結果意象**。第三章沒有比照。

**最小修法**（兩段都要）：

1. 契約改成邊界檢查：

```js
const beforeFirstRun = s3.scenes
  .slice(0, s3.scenes.findIndex((sc) => sc.id === "C1-1"))
  .flatMap((sc) => sc.nodes.filter((n) => !n.legacyOnly).flatMap((n) => [
    String(n.text || ""), ...(n.options || []).map((o) => String(o.text || ""))
  ])).join("\n");
if (revealedSteadyRegex.test(beforeFirstRun))
  throw new Error("第一次實驗前已提前交付穩速落點");
```

2. `all`／`all_again` 改成宣稱**範圍過大**而非**說出結果**，例如：

> 這張紙已經夠說明船平穩前進時會怎樣了。

**可失敗的驗證條件**：把「跟船一起走」放進 `C1-1` 之前任一節點**或選項**必須轉紅（現況只有 `xcard` 會紅）；改完後基線必須回到全綠——**現在直接套上契約會立刻紅，因為內容真的有**。

**與第四章的關係**：這與我上一輪抓到、Sol 已用 `ch4NodeText` 修成全章掃描的第四章 B-1 **是同一類**。第三章沒有比照辦理。建議把「文字護欄一律掃 `node.text` + `options[].text` + 明確場次邊界」訂成跨章通則，不要每章各修一次。

## 三、B-2｜升 A 的判準沒有一致套用

**位置**：第三章包 §一。

包把 `C0-1/xcard` 與 `C0-3` 重試句從報告的 C／B 升為 **A=2**，判準是「第一次實驗前交付完整正解」。但同一份包沒有把 `C0-3/c1` 的 `all`／`all_again` 納入同一把尺——那兩個選項在**同一場、同一個節點**、同樣在第一次實驗前，同樣寫出穩速結果。

**因果問題**：判準只套在被三方報告點名的位置，沒有套成邊界，於是「升 A」看起來像是對特定條目加重，而不是建立標準。下一位審查者無法從這份包推出「什麼算洩題」。

**最小修法**：把判準寫成可機檢的一句話並登記成跨章規則——

> 一章之內，在該章第一個玩家實驗之前，任何 active 的節點文字或選項文字都不得出現該實驗的結果句或其同義句；被扣分的過度宣稱選項亦同，只能宣稱範圍過大，不得寫出結果。

**可失敗的驗證條件**：這條規則同時能解釋「為什麼 xcard 要升 A」與「為什麼 `all` 要改」。若總監判「被懲罰的過度宣稱不算洩題」，那**原本的 xcard 也不該升 A**——兩者必須用同一把尺。這條 B 的重點不是哪個答案對，是**現在兩處用了不同的尺**。

## 五、C 級三條

**C-1｜交付包的 SHA 表缺 commit 對應。** 見 §一。共用工作樹上純 SHA 很快失效，收件人依包內指示會停工。修法：SHA 表加一欄「對應 commit」；未進 commit 的中間態明標「working state, not committed」。

**C-3｜第三章洩題 regex 值得升級為跨章共用。** 現在第一、二、四章各有自己的護欄寫法，第三章這條又是第三種。建議抽成共用函式（比照 `ch4NodeText`），一處維護。
