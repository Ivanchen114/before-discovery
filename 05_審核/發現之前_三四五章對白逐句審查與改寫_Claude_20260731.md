## 二、第四章

### 2-1 場景劇本:健康,而且是三章裡最穩的

`D0-2` 的入場考、`D2-1` 的鬆繩木球滾到十四年前那張紙旁邊、`D3-1` 哈雷把封蠟推到**旅人面前而不是牛頓面前**、`D4-1` 結尾「還有比彗星難算的?」「**人名。**」——這些是完成度很高的戲。

## 四、共同病灶與法源建議

三章一起看,只有一條共同病灶,而它**只出現在 runtime 注入層,不在 scenes JSON**:

> **把設計理由拆給兩個人講,不叫對話。**

CR-027 的五段轉場全是「NPC 講缺口 + 旅人講做法」。scenes JSON 裡由劇本流程產出的段落沒有這個問題——差別在於**前者是為了填補流程而生,後者是為了演一件事而生**。

建議入法源(依 skill v3.4.7 首段,**不寫進 skill 正文**,skill 只加路由):

**入 `02_設計/發現之前_互動敘事與歷史科學探究規範_v0.1_20260730.md`——轉場對白五條驗收:**

1. 轉場由人的動機推動,不由邏輯缺口推動。
2. 每段轉場至少一個實體動作或實物。
3. 用得上角色既有的過去,就要用。
4. **旅人不念實驗規程**;規程由負責的 NPC 下,或由玩家選。
5. 不要每次都乾淨讓步。

其中第 4 條可機檢:掃轉場字串,旅人句若含「沿用／安排／記錄／再做一組」等規程詞彙即 WARN。

**入 `02_設計/發現之前_工作台與辯論架構_一二章實證規格_v0.1.md`——證據簽收儀式**(總監指定「斷言成功要有對話」):

> 每次斷言成立,必須由**負責該欄位的角色**出面,且包含一個實體動作(封蠟、寫字、推紙)。NPC 不得複誦玩家剛說過的內容,必須補上玩家沒說的一件事。
