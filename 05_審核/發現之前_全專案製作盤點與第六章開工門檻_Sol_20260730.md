## 二、專案已具備什麼

### 2.1 設計核心

本作已有清楚而可延伸的自定義類型：

> **歷史情境科學探究遊戲**  
> history-of-science inquiry game

核心不是在古代背景回答物理題，而是讓玩家在當時可取得的器材、語言、原紙、
信用與公開程序內，完成：

> 問題／承諾 → 操作 → 原始紀錄 → 選資料 → 有限斷言 → 公開支付／修正

跨章已具備：

- 玩家參與證據但不偷走歷史人物成果；
- 雙重刪除測試；
- 合作交棒與權限升級；
- 原始紀錄、證據、主張三層分離；
- 誘答的 `supportedBy`／`refutedBy` 與證據邊界；
- 旅人公開發言、心聲與 NPC 可聽範圍；
- 可變終局；不把三柱、工作台或左右頁當全系列固定外形；
- 「去掉說明性台詞，機制仍承重；台詞放回後增加人物與歷史」雙軌測試。

### 2.2 五章內容

| 章 | 現有認知工作 | 後續章不可退回 |
|---|---|---|
| ch1 | 量測、單變因、預測、誠實邊界 | NPC 不替玩家診斷 |
| ch2 | 控制條件、成對比較、模型適用範圍 | 結論必須綁實作資料 |
| ch3 | 選來源、參考系、限定斷言 | 隱藏資料不能替代原紙 |
| ch4 | 紙上建模、跨尺度核帳、來源與署名 | 解釋現象不等於知道機制 |
| ch5 | 兩本帳重算同一批資料、保留未知去向 | 不為了閉帳偷偷換資料或補結論 |

第五章到 H1 的正確交棒是「全帳尚未對平」，不是「已經證明短少都變成熱」。
目前 ch5 runtime 沒有可靠演出小說稿的「指腹一點溫」；H1 開場不得假裝玩家一定
看過這條線索。直接選 ch6 的玩家，也須在開場 20–40 秒內獨立理解年代、人物與案件。

## 三、第六章 runtime 前的 A 級門檻

### A-1｜先正式立案 H1

總監需裁一句：

> 第六章採 H1《熱從哪裡來？》為工作案；章名暫定，案件資格通過後再正式定名。

這不要求現在承諾完成日期，也不等於公開 24 章 roadmap。

### A-2｜H1 史實與物理 dossier 尚未完成

現有總表只有 Rumford 1798 原始論文的起始錨點。寫劇本前至少補：

- 一份可逐項核對的原始文獻；
- 一份以上現代科學史研究；
- 鑽炮、鈍鑽、水、工時、溫度與重複條件的 fact ledger；
- 熱質說當時能提出的合理回應；
- 史實／合理重建／虛構串接／傳說分類；
- 可說與禁止說的邊界。

本章最多先支持：

> 持續機械作用能持續產熱，有限庫存式的簡單熱質流出模型受到重大壓力。

本章不得提前宣稱：

- Rumford 一次實驗單場殺死熱質說；
- 熱已被證明「就是運動」；
- 總能量守恆已建立；
- 功與熱已有固定定量兌換率（留給 H2）。

### A-3｜五章仍有兩條玩家代理權紅線

1. ch5 J3 只驗三種速度與同質量，`depth=[99,1,99]` 仍可取得平方關係證據；
2. ch3 在玩家選紙與 scope 前，UI 已顯示完整 canonical assertion。

兩項不阻擋 H1 史料與紙上設計，但在 ch6 觸碰共用 runtime 前應各立 CR、補反向
測試並經 Claude 定點覆核。

### A-4｜共用 runtime 對未知章節不是 fail closed

目前：

- `narrative.js` 與 `stage-ui.js` 只接受 ch1–ch5，未知章節會退回 ch1；
- chapter UI 的 sanitizer 分派只到 ch5，其他章會走第一章 sanitizer；
- 未登錄 `until`／gate 會被當成已完成，可能越過證據門檻；
- `labAction`、render、狀態摘要與 engine evidence → `state.evidence` 投影皆逐章寫死；
- 書信封套尚未完整涵蓋 ch5，缺 save key 時又會退回 ch1 key；
- schema、save key、repair scene、engine／data 注入與 stage 文案分散在多處；
- mechanics guard 的 canonical adapter 只登錄 ch1–ch5；
- 全章測試發現仍手列章節／證據，新增 ch6 可能未被自動納入。

ch6 runtime 前應先建立單一 **chapter runtime registry**，至少登錄：

- chapter id／route／label；
- scenes、engine、debate、histfacts、assets；
- sanitizer、schema version、save key、migration；
- gate evaluator、interaction action、render adapter、status projection；
- engine evidence → canonical `state.evidence` adapter；
- 書信 envelope codec 與跨章路由；
- repair scene、chapter end、previous／next；
- mechanics guard canonical target；
- 由 registry 枚舉的 scenes／sanitizer／save round-trip／evidence／asset 測試。

單一 registry 是推薦解法；真正的 A 級驗收條件是：未知章節、未知 gate、缺
sanitizer／save key／action／render／evidence adapter 時全部明確轉紅，不得退回
第一章或默認完成。

### A-5｜先建立可回復的五章基線

目前 `git status` 有 **285** 個變更路徑：73 個 tracked changes、212 個 untracked。
其中混有正式成果、審查稿、runtime、美術、spike 與待裁法源。

這不代表要立即清空，更不能：

- `git reset --hard`；
- 整批刪除未追蹤檔；
- `git add -A` 後做一顆巨大 commit；
- 把來源不明檔案直接移入 archive。

正確流程是先依所有權與狀態分類：

1. 可提交正式成果；
2. 尚在進行的 WIP；
3. 應封存的 superseded 稿；
4. 可再生的生成物；
5. 來源不明、待 Claude／總監確認。

ch6 前製可在此期間進行；ch6 共用 runtime 施工前必須有 scoped、可回退的五章基線。

## 五、已修正的新章流程

盤點時發現舊流程互相卡死：

- candidate skill 原要求新章 `write` 前先有完整 chapter spec；
- 系列聖經則要求小說稿凍結後才建立章規格。

本輪 candidate 已拆成兩層：

1. **chapter brief**：案件資格、機制骨架、物理／禁宣稱邊界；通過後才可寫小說稿；
2. **implementation chapter spec**：小說稿凍結後建立，含 fixture、state、schema、
   save、UI 與測試；通過後才可進 runtime／正式美術。

router 現在也會核對新章支援檔的 front matter：文件角色、`chN`、brief 的
`design-gate-passed`、spec 的 `frozen`，以及 provenance sidecar 的
`review-ready|verified`；錯章、錯角色、未凍結、同一檔案兼任多角都會 exit 2。
這只防止 `package.json` 等任意檔冒充 gate 文件，不能獨立證明簽核真實性或史料品質。

兩層都不能取代史實 provenance。Design Gate 時只人工審 mechanics contract；
canonical scenes JSON 尚未存在前不得冒稱機械 PASS。
