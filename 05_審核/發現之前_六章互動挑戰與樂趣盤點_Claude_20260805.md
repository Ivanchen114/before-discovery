**審查者**：Claude (Anthropic) ｜ **日期**：2026-08-05
**維度**：互動機制本身的挑戰性與趣味性（不是劇本邏輯，不是介面可用性）
**方法**：讀 `engine.js`–`engine6.js` 的 action／判定邏輯 ＋ `chapter-ui.js` 對應渲染，並用 Node 實跑量測「玩家到底能不能失敗、失敗率多少、失敗後看到什麼」。**所有分數都附可覆核的量測值，不用印象打分。**

## 二、逐章優點盤點（不要在後續修改中誤傷）

### 第一章

**① 器材選擇是真的有後果，而且後果可診斷。** 實測 54 種配置只有 13 種能讓 `consistent` 成立。三種計時器的成功率天差地遠：

```
水鐘: 6/18    脈搏: 0/18    音格: 7/18
```

**選脈搏永遠不會成功**，而且 `A2-2/c1` 伽利略已經先說了「這幾次的點散成一團,什麼規律都讀不出來;實驗常常就是這樣失敗」——失敗被納入敘事，不是懲罰。加上 `PATTERNS.dayCost[timer]` 的天數成本，選錯器材有實質代價。**這是全案最乾淨的「工具選擇＝實驗設計」教學。**

**② 第五段是真測量。** `judge()` 的 `target = 兩趟 fifthReading 的平均`，不是 `9 × avg[0]`。實測：音格的 `9×首段` 與真值完全相同（108 vs 108，maxDev 0.0%），但水鐘會差（114.3 vs 108，maxDev 5.6%）。**所以「用奇數律外推」在低噪器材上精確、在中噪器材上仍在 ±12% 內、在高噪器材上連 `consistent` 都過不了。** 三段式難度，設計得很精細。

**③ 失敗留痕。** 押錯的蠟封不擦掉，`qOdd` 明說「把押記和第五段刻痕並排，沒有擦掉」。

### 第二章 —— 全案最佳，請整章視為範本

**① 零件指紋診斷迴路，這是全案最好的單一機制。**

```js
_PARTS: release  → latchRelease（乾淨）｜handRelease [speedDrift]
        edge     → polishedEdge（乾淨）｜roughEdge [directionScatter]
        rangeBed → rakedSand（乾淨）｜eyeBoard [coarseRead]｜fineSandPlumb（乾淨）
_FIXTURE 條件集: clean, directionScatter, speedDrift, coarseRead
```

12 種組合裡**只有 2 種是全乾淨**。關鍵是：**每個壞零件注入的是一種特定形狀的雜訊，而不是通用的「失敗」**。用手放（`handRelease`）→ 出手速度飄；用粗桌沿（`roughEdge`）→ 落點方向散；用目視板（`eyeBoard`）→ 讀數粒度變粗。

**玩家看到沙痕的散布形狀，就能反推是哪一個零件在騙他。** 失敗不是牆，是線索。這是「有挑戰又好玩」的教科書級答案，而且它同時教了實驗方法學（系統誤差 vs 隨機誤差有不同指紋）。

**② 預測有真實的可否證性。** `_judgeRaw` 用雙門檻：形狀誤差 ≤12% **且** 預測誤差 ≤12%，而 `pErr` 是對**真實 readings[25]** 的比較（不是對推導值）。兩個門檻獨立，所以「形狀對但預測偏」和「預測碰巧中但形狀亂」都會被擋。

**③ `assertLaw(state, seriesId, conceptId)` 區分「不存在的概念」與「存在但錯的概念」**，回不同錯誤碼（`unknown-law-concept` vs `concept-mismatch`）。這讓 UI 能給針對性駁回，而不是一句通用錯誤。

**④ 錯答用物理現象回應。** `B2-2` 選錯彎折起點 → 「（把直尺貼上墨線起段）尺不會客氣。你再看。（尺與墨線之間,漏進一線光）」——**用一線光當駁回**，不用文字說教。

### 第三章 —— 設計空間全案最大

**① 玩家設計實驗，而不是從選單挑一個。** dossier draft 12 欄：

```
location(2) × stage(4) × release(3) × speedRecord(3) × positionRecord(4) × repeats(3)
× sameStone(2) × sameHeight(2) × speedBand(3) × forceBand(2) × beatBand(3) × vesselId(3)
≈ 186,000 種設計
```

而且 8 條斷言（A1/A2/A3/A6/S1/S4/A4/A5）各有自己的 `claimSelections`（引用哪幾筆紀錄）與 `proposedScopes`（範圍寫到哪裡）。**玩家不只是做實驗，還要決定每一筆結論引用哪些紀錄、範圍收到哪裡。** 這是六章裡唯一真正的「研究設計」關卡。

**② 借船有機會成本。** `borrowedVessels` 限制、`designCommitments` 記錄承諾——設計選擇不可自由回頭。

**③ 壞紙全部留著並可被後續引用**（我在別輪已驗過 `x19`「少了一欄的這張，也不撕。留著。」）。

### 第四章

**① K1 的落筆機制是全案第二好的觸覺互動。**

```js
ORBIT_AIM_OFFSETS = [0.47, -0.41, 0.53];   // rad，刻意不是 6° 的整數倍
```

程式註解寫明「三拍刻意從不同側、不同幅度偏離正確方向，避免玩家不看圖只背『每拍固定按三次逆時針』也能過關」。**這是明確為了防止盲按而設計的**——玩家必須每一拍重新看圖判斷當下地心在哪。而且第一拍成功不代表第二拍能沿用，`commitOrbitBeat` 會判 `matchedPreviousEarth`（指向上一拍的位置）為錯。

**② 27 種規則配置只有 3 種可行，而且不是「中間那格」。** UI 明說「三組速度／箭長配對都可能形成近圓，不只有中間那格」——**多解**，避免了「猜中間值」這條捷徑。

**③ 幽靈紙。** 錯拍收進 `manualAttempts`，`resetOrbitBeats` 回傳幽靈紙張數。失敗有可見的累積。

### 第五章

**① `assertJ1` 的六道閘門是全案最嚴格的單一斷言。**

```js
≥6 筆紀錄 → 鋼頭≥3 且油灰頭≥3 → 質量全部 4/4 → 速度帶單一
→ 動量前後閉合 → concept === "both-close"
```

**玩家必須主動湊出一組受控對照集**，不是跑完就過。而 `masses: "4/8"` 在取得 j2 前是鎖住的（`masses-locked`），所以難度是分階段解鎖的。

**② 「同一批數字算兩次」的概念本身極優雅。** 杜夏特萊阻止玩家重做資料，改用第二本帳重算——這個機制把「換一種記帳方式」變成一個操作，而不是一段講解。

**③ 4／8 砝碼追一筆**：先封存預測、再換質量比、看「一半」是否仍成立。真封存、真可錯。

### 第六章

**① 封條「裂而不消失」是全案最好的證據倫理機制。**

```js
state.finiteSources.sealState[source] = expected === "not-fulfilled" ? "cracked" : "intact";
```

曲線越過預測帶**不會自動裂封**，只有玩家提交判讀才轉態。而且判讀依該來源封存的 band 決定合法答案（`no-endpoint` → 只收 `insufficient`）。**判斷權真的在玩家手上，而且「未決」是一個可以走到的合法結局。**

**② 水箱台的等溫準備是真機制。** `readWaterTemperature` 兩支都要親手讀 → `equilibrateWaterBox` 靜置對齊 → `|water − cannon| ≤ 0.5` 才能封存起點；改水溫會把 `equilibrated` 重設。

**③ 四人分欄署名。** 史坦格只簽操作、凱斯勒簽反例與保留、朗福德簽自己的解讀、旅人簽邊界與債務。`setJointColumn` 要求 `args.text === JOINT_VALUES[column]`，放錯欄直接拒絕。

## 三、逐章弱點盤點

### 第一章（4/4）

**W1-1｜找到「音格」之後，挑戰歸零。** 實測音格的 `maxDev = 0.0%`——完全無噪。所以玩家一旦發現音格，後續所有配置都是確定性的，`9×首段` 就是精確答案。**難度曲線在中段斷崖式歸零。**

### 第二章（5/5）

**W2-1｜12 種組合的探索沒有被鼓勵。** 只有 2 組全乾淨，但遊戲沒有任何機制讓玩家想去試那 10 組壞的。指紋診斷這麼好的設計，玩家可能一次選對就再也不會看到。

### 第三章（5/4）

**W3-1｜186,000 種設計空間，但通關只需要少數幾組。** 巨大的設計空間缺少「不同設計各有不同代價／不同能支持的結論」的正回饋，容易退化成「找到一組可行解就走」。

### 第四章（3/3）

**W4-1｜K2 已經退化成三個連續單選填空。** 三步各是一個有唯一正解的下拉／按鈕：
1. 弧長 vs 正矢（2 選 1）
2. 倍率 60／360／3600／36000（4 選 1）
3. 相加／相乘／先不連（3 選 1）

**沒有任何一步需要組裝、測量或多次嘗試。** 而且第 2 步的四個選項只有一個是 60 的平方，一個懂平方的玩家零思考通過；不懂的玩家隨機猜有 25% 命中率且沒有代價。**這是全案「照著填空就會過」最明顯的一站。**

**W4-2｜K4 對帳桌是 allowlist 蓋章。** `placeAuditEvidence` 的 allowed 是 `{chips:["T1"], air:["T3"], cannon:["T4"], water:["T4"], condition:["T2"]}`——每格恰好一個正解。三種章（對上了／講得通／對不上）看起來是判斷，實際是查表。

**W4-3｜K3 的預測帶過寬。** 火星 1.5／1.9／2.3 年、木星 5／8／12 年，各三選一。真值 1.88 與 11.86，所以正解顯然。**封存機制是對的，但被押的東西不難。**

### 第五章（3/3）

**W5-1｜操作總量太少。** draft 5 欄 72 種配置，但整章只有 `runCollision` 與 `runClay` 兩個「跑」動作。相較第二章的組裝→校準→三高度→換球，第五章的手感薄。

**W5-2｜判斷全是單一正解。** `setJudgment` 四個 key 各 3 選項，但每個都只有一個合法值（`j1` 必須 `both-close`）。三選一 × 4 次。

**W5-3｜沒有器材選擇的後果。** `speed`（low/mid/high）、`clayHeight`（h1/h4/h9）、`ballMass`（light/heavy）都可自由選，但它們**不會像第一、二章那樣製造壞資料**——只會影響數值，不會影響「能不能成立」。所以沒有「選錯器材」這個挑戰維度。

### 第六章（3/2）

**W6-1｜招牌機制是點六次同一顆按鈕。** 這是全案最不好玩的機制，詳見第五節。

**W6-2｜四座工作台的推論是二選一，而且本章修辭洩答。** 碎屑／摩擦／乾式／密合四台各給「1 正解 + 1 明顯過度宣稱」：

| 台 | 正解 | 唯一誤答 |
|---|---|---|
| 碎屑 | 碎屑並沒有顯著較低的熱容量 | 碎屑**一定**製造了更多熱 |
| 乾式 | 只主張已觀察時段內持續升溫 | 主張**永遠**都會以同斜率升溫 |
| 密合 | 空氣不是升溫的必要來源 | 密合證明空氣仍從縫裡進來 |

**五個判斷的正解全部是兩者中較謹慎的那個**，而整章的教學重點就是「不要說超過你的紙」。玩到第三台，玩家學會的是「挑語氣小的」這條不必碰物理的規則。

**W6-3｜11 站太多，而每站的操作太淺。** 站數是六章最多，但多數站是「按 2–4 顆按鈕 → 選一個推論」。廣度換掉了深度。

## 四、弱點章節的機制重新設計提案

全部遵守：零拖曳、不代做關鍵判斷、不犧牲物理與史實。標註工程量。

### 提案 A｜第六章長時段：把「點六次」換成「配額下的三選一」

**現況問題**：`runContinuousSegment` 只接受 `record-next`，溫度硬編 `[31,47,65,83,96,100]` 只吃 `segments.length`。三方定案認定這是本章的「新動詞」（管理一個不會自己停下來的持續過程），實際是六次點擊。

**重新設計：用「馬班配額」把連續過程變成資源管理。**

- `continuousRun` 新增 `shiftBudget: 8`（八個半小時的馬班額度，對應 `H0-2` 已建立的「借到明晚」期限）與 `drift`、`waterLevel` 兩個狀態。
- 每段開始前，畫面顯示三支溫度計、水位刻線、馬速指示；其中**一項會依 `segments.length` 用決定性規則出現異常**（不用 RNG，維持純函式；例如第 2 段馬速漂移、第 4 段水位下降）。
- 三個動作各有配額成本：**續鑽（1 格）／校準（1 格，清除漂移）／修漏（1 格，補回水位）**。
- 玩家必須在 8 格配額內取得 **6 格乾淨讀數**。若在有漂移時續鑽，該格 `temperature` 記 `null`、`gaps:["horse-pace-drift"]`，仍消耗配額 —— **壞紙保留在原紙、不可剪掉，但配額用掉了**。
- 配額用盡而乾淨格不足 6：長紙不完整，`judgeFiniteSource` 仍可進行，但缺格的那一段在後續判讀時**不能用來否證任何來源**（對應史坦格「我只能簽『煮開』，不能簽這段升溫一路怎麼來」）。

**為什麼這樣既有挑戰又好玩**：①失敗有代價但不致命（配額，不是血條）；②三個動作**互相排他**，玩家必須讀儀器再決定，不能盲按；③已經寫好但目前不可觸發的三段壞紙台詞（`H2-3/w1`／`w2`／`w3`）全部有了路徑；④它把史坦格建立的「借到明晚」從敘事期限變成機械期限，同時解決我在別輪指出的「`days` 從未被讀取」。

**工程量**：`engine6.js` 約 +45 行（兩個狀態欄位、決定性擾動表、三個動作的配額扣減與後果）、`chapter-ui.js` 約 +25 行（配額顯示、儀器異常標示、三顆按鈕）。**需新增 schema 欄位 → 須開 CR。** 這是本提案唯一需要動結構的一項。

### 提案 B｜第四章 K2：把三個單選換成「兩張紙各自量出來再疊合」

**現況問題**：三步各一個唯一正解的下拉。第 2 步（60／360／3600／36000）尤其是純填空。

**重新設計：讓玩家自己從幾何圖讀出量級，而不是從四個數字裡挑。**

- 第 1 步（弧長 vs 正矢）**保留**——這一步是好的，它對應史實上真正的陷阱，而且 `engine4.js` 已有 `arc-is-not-sag` 的後果。
- 第 2 步改成**刻度尺讀值**：畫面給一把對數刻度尺（純 SVG，非拖曳），刻度上有 `×10 / ×100 / ×1000 / ×10000` 四個可聚焦的刻痕，以及兩個已知端點（4.9 m 與 1.36 mm）。玩家用方向鍵在刻痕間移動一支游標，Enter 落點。落錯時**不給答案**，只把 1.36 mm 那一端按玩家選的倍率投影出去，讓他看到投影點與 4.9 m 差多遠（例如選 ×60 會落在 8.2 cm，離 4.9 m 明顯很遠）。
- 第 3 步（相加／相乘）改成**兩個 60 的實物並排**：一張寫「月距＝60 個地球半徑」、一張寫「量級＝約 3600」。玩家在兩張紙之間選一個運算符卡（＋／×），選完後系統只顯示「60＋60＝120」或「60×60＝3600」與量級紙並排，**由玩家自己按下「這兩張對上了」或「還對不上」**。選 ＋ 之後畫面留下一張 120 的幽靈紙，不消失。

**為什麼更有挑戰又好玩**：①第 2 步從「四選一」變成「在連續尺度上定位」，錯誤有可見的空間後果（投影點差多遠），這與第一章「點散成一團」同一種回饋語言；②第 3 步把判斷從「選正確運算」變成「自己確認兩張紙是否對上」，玩家仍可選錯並看到 120 的幽靈紙；③零拖曳（方向鍵＋Enter，沿用 K1 已有的轉鍵語彙）。

**工程量**：`engine4.js` 現有 `judgeScaleRatio(state0, choice)` 收數字，**可直接沿用**（游標刻痕值就是 choice）；`judgeScaleRelation` 也可沿用。主要是 `chapter-ui.js` 約 +60 行（對數尺 SVG、游標鍵盤處理、幽靈紙渲染）。**不需改 schema、不需開 CR。**

### 提案 C｜第五章：給器材選擇真實後果，把「72 種配置」變成挑戰

**現況問題**：draft 5 欄可自由選，但選擇不影響「能不能成立」，只影響數值。所以第五章缺了第一、二章最強的那個維度。

**重新設計：讓兩個 draft 欄位變成資料品質的來源，沿用第二章的「指紋」手法。**

- `speed`：`high` 時碰撞讀值出現**單一方向的系統偏移**（撞擊過猛，油灰頭有回彈殘留）；`low` 時**讀值粒度變粗**（速度太慢，坑深差異落在可讀範圍以下）。只有 `mid` 給乾淨資料。
- `clayHeight`：`h1` 與 `h9` 各引入一種可辨識的偏差（太淺→坑深飽和，太深→側壁崩塌），`h4` 乾淨。
- 兩者都**不亮紅燈**：`runCollision`／`runClay` 照跑、照記錄，但 `assertJ1` 的「動量閉合」檢查會因偏移而失敗，錯誤碼指向**偏差的形狀**（`momentum-drift-one-way` / `depth-below-resolution`）而不是通用失敗。
- 杜夏特萊的既有角色功能（守資料邊界）剛好可以承接：她會指出「這一批的短少全部偏同一邊——是你的撞法，不是物理」。

**為什麼更有挑戰又好玩**：①把第五章從「跑完就過」變成「先找出可用的撞法」，而這正是第二章最好玩的那個迴路；②`assertJ1` 已有的六道閘門立刻變得有意義——目前那六道閘門檢查的是「你有沒有湊齊對照組」，加上這個之後還檢查「你的對照組是不是用可用的器材做的」；③完全不需要新概念，只是把第二章證明有效的設計移植過來。

**工程量**：`engine5.js` 約 +30 行（`_FIXTURE` 增加三個條件集、`runCollision`／`runClay` 依 draft 選 fixture、兩個新錯誤碼）、`chapter-ui.js` 約 +15 行（錯誤文案）。**`_FIXTURE` 是引擎內常數，不是存檔欄位 → 不需改 schema。**

### 提案 D｜第六章四座工作台：補第三個「收得太窄」的選項（跨站小改）

## 五、全六章最好玩與最不好玩的機制

### 最好玩：第二章的「零件指紋診斷」

```
handRelease → speedDrift        （出手速度飄）
roughEdge   → directionScatter  （落點方向散）
eyeBoard    → coarseRead        （讀數粒度粗）
其餘        → clean
```

**理由（三點，都可覆核）：**

1. **失敗是線索而不是牆。** 12 組裡只有 2 組乾淨，但每一種失敗都有**唯一對應的視覺形狀**。玩家看沙痕的散布方式，就能反推是哪一個零件在騙他。這讓「重試」變成推理而不是重複勞動——這是「想再試一次」的鉤子的正確來源。
2. **它同時教了一件真的科學方法。** 系統誤差與隨機誤差有不同指紋，這不是包裝在台詞裡的知識，是玩家必須用來過關的工具。物理準確度與趣味在同一個機制裡，沒有互相犧牲。
3. **它與駁回設計咬合。** `B2-2` 選錯彎折起點時，回饋是「（把直尺貼上墨線起段）尺不會客氣。你再看。（尺與墨線之間,漏進一線光）」——**用一線光當駁回**。整章的錯誤回饋都是物理現象，不是文字說教。

### 最不好玩：第六章的「長時段連續鑽削」

```js
if (args.action !== "record-next") return fail(state0, "unknown-run-action");
var temperatures = [31, 47, 65, 83, 96, 100];
var row = addRecord(state, "continuous-segment", {
  temperature: temperatures[index], horsePace: "steady", pressure: "fixed", leak: "none" });
```

**理由（三點）：**

1. **它是點六次同一顆按鈕，沒有任何決策。** 溫度只吃 `segments.length`，`horsePace`／`pressure`／`leak` 是字面常數。無論玩家做什麼，序列都是 31→47→65→83→96→100。
2. **它偏偏是本章被定案為「新動詞」的那個機制。** 三方定案寫「管理一個不會自己停下來的持續過程——前五章量的都是離散試次，本章第一次量連續累積量」。全章的結構重量壓在這一站，而它是六章裡互動最薄的一站。
3. **它讓三段已經寫好的台詞永遠不可觸發**（`H2-3/w1`「紙帶卻在第二段少了水位，第三段換馬沒有記鼓點……兩個不能補寫的洞」等），而史坦格「別為了追溫度，把一張壞紙追到底」預設了一個會產生壞紙的機制——那個機制不存在。

**補充說明**：這一站曾經有三個動作（`continue`／`calibrate`／`repair-leak`），但三者效果完全相同；上一輪施工的處理是**移除假選擇、只留一顆按鈕**。那是誠實的處理（不再騙玩家），但把問題從「假挑戰」變成「無挑戰」。**提案 A 就是要把它變成真挑戰。**

## 六、給三方交叉檢視的判斷依據摘要

我的評分邏輯是三個可覆核的問題，不是主觀感受：

**Q1｜玩家能失敗嗎？失敗率多少？** 用 Node 窮舉配置空間量測。
- ch1: 54 配置 / 13 成功（24%）
- ch2: 12 組合 / 2 全乾淨（17%）
- ch4-K1: 27 配置 / 3 可行（11%，據程式註解）
- ch4-K2: 每步 1 正解（第 2 步隨機命中率 25%）
- ch5: 72 配置，但器材選擇不影響成敗（0 個「選錯器材」的失敗路徑）
- ch6 長跑: 0 種失敗路徑

**Q2｜失敗告訴玩家什麼？** 分三級：
- **有指紋**（能反推原因）：ch2 的四個 fixture 條件集、ch1 的散布形狀
- **有留痕但無指紋**（知道錯了，不知道為何）：ch4 的幽靈紙、ch6 的壞紙
- **無失敗可留**：ch6 長跑、ch4-K2 第 2 步（選錯只是重選）

**Q3｜玩家的決定會不會改變別的東西？**
- ch3 最強（設計承諾不可回頭、借船有機會成本）
- ch1／ch2 次之（器材選擇決定資料品質）
- ch5／ch6 最弱（選項多但互不影響）

**三個問題全部得分高的是第二章；全部得分低的是第六章長跑。** 這就是我把 ch2 列為最好玩、ch6 長跑列為最不好玩的依據。
