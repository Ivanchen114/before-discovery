## 一、總裁決

**有條件放行，但九項候選全部只能「修改後採用」，目前文件不可直接交施工。**

原提案的核心判準仍成立：平等不等於均分台詞，而是雙方工作會改變對方的判斷與下一步。然而提案在三類地方高估了修法：

1. 把「換說話者」誤當成「把認知步驟還給玩家」。第二章 `B1-2` 最明顯；玩家若仍只選地點，旅人自動說理由，代理權並未增加。
2. 把 stage 寫成角色「量過、算過、核過」卻沒有 runtime 行為或資料依據。第一章 `A2-2` 的伽利略核水量、六章 `H1-1` 四人一起扶紙，都有表演式合作風險。
3. AS-IS 已落後現況。`A2-2/n2`、`B2-3/p1` 已含提案想加入的內容；第四章 K2 已讓玩家親手完成 `60 ↔ 3600` 配對，`n10/n11` 不是搶答。若照提案原文施工，反而會覆蓋已改善的鋪陳或重做既有功能。
4. 第四章 K2 的畫面雖有兩張紙，數值來源卻不獨立。`engine4.js:6` 把地表一秒落距與月球六十秒偏折都直接設為 `4.9`，再於 `1191` 用後者除以 3600；而且結果只留一位小數，Node 直跑實得 `1.4mm`，與 UI／ADR 宣稱的 `1.36mm` 不同。這是同一個數值自我吻合，不是週期與軌道幾何算出的第二份來源。

現行 `cd greybox && npm test` 為 **157 通過、0 失敗**；這只證明現行契約。下列裁決另以逐節點與 action 路徑核對，不拿綠燈代替合作感驗收。

1. **問題是否存在**：存在。玩家把潛熱卡放進自己模型的未決欄後，承擔只在心聲，其他人聽不到。
2. **是否增加共同發現**：改為公開承認有效；但候選長句重複剛選的判斷及凱斯勒下一句。
3. **發現權分配**：玩家親手把反例留在自己一側並公開認債；凱斯勒負責指出這一回合對手真的輸了。

5. **是否重複 embed**：是，候選重述玩家剛放卡的資訊；應只公開承擔，不再講完整判決。
6. **邊界**：不得補上現代潛熱解釋，也不得說炮紙因此失效。
7. **聲線**：候選旅人自然但過完整；短句更像當場承認。

## 五、第四章案 A／案 B 裁決

### 裁決：採案 A，但撤回「D1-2 整段需要結構重寫」的前提

#### 1. 現行認知順序

`D1-1/c1` 先讓玩家封存切線；`ok2`（`scenes4.json:548-552`）隨即從「月亮沿直線」跳到「到了月亮那麼遠還剩多少」。中間沒有把同一時刻的切線端點與實際軌道端點並排，也沒有讓玩家看到兩端差距指向地球、因而可作為向內偏折量。這是真缺口。

場景沒有預設完美圓：`D1-1/w1` 會反駁把圓先塞入答案；因此只需在 `ok2` 後補一個視覺／白話橋，不需重寫切線預測。

#### 2. `60 秒` 是否只在發現後顯影

**沒有。** `D1-2/n7`（`scenes4.json:642-646`）直接給「月亮六十秒偏了那麼一點」，embed hint（`695-703`）也要求「先猜 60 秒換成 1 秒後會剩多少」。UI 的藍紙（`chapter-ui.js:6748-6791`）更明載「月球 60 秒偏折約 4.9 公尺」，先做 `sealScalePrediction`，再用 `convertMoonTime` 換成一秒。

這不是在選項層直接把「距離平方」答案塞給玩家，因為玩家仍須完成時間換尺、倍率比較與關係選擇；但它**預先給了一個尚未由本場來源鏈說明的 60 秒起點**。更重要的是，這個起點並非獨立算得：`engine4.js:6` 直接令 `moonSixtySecondSagM=4.9`，恰與 `surfaceOneSecondFallM=4.9` 相同，`convertMoonTime()` 再於 `1191` 除以 3600。該行 `round(...,1)` 使 Node 直跑結果成為 `1.4mm`，而 `chapter-ui.js` 的說明與 GB-ADR-039 又宣稱 `1.36mm`；`judgeScaleRatio` 仍硬編碼只接受 3600。全檔 K2 路徑沒有月球週期、正矢、`2π/T` 或對應幾何計算；玩家看到的「兩張紙碰上」是程式先把答案抄到另一張紙後再拆開。

這形成兩個必須分開處理的問題：

- **數值來源造假**：即使保留 60→1 的 UI 順序，也必須修；否則共同發現只是表演。
- **發現時序**：若設計原則已定為「共同的一秒先完成公平比較，60 秒只在事後放大毫米級偏折」，現況仍違反該原則。修數值來源不會自動把 60 秒移到後面。

因此修法不能只改 `n7` 一句。至少要同步改：

- `D1-2/n7`、`c0` 與 embed hint；
- `chapter-ui.js` K2 scale phase 的藍紙標題、預測問題與步驟順序；
- `engine4.js` 的 `sealScalePrediction/convertMoonTime` 是否仍保留，或改為先算一秒弓高、關係成立後再觸發顯影；
- GB-ADR-039 的藍紙定義與對應契約測試。

若總監不把「60 秒只可事後出現」列硬要求，可保留現有 K2 順序，但仍要用軌道幾何真正算出六十秒偏折，再換成一秒。若列硬要求，仍屬 **K2 次序 CR**，但可重用現有 schema 與多數 action，不是 D1-1～D1-2 全段重寫。

#### 3. 數字與來源

- 現行數值不是獨立計算：`engine4.js:6,1191` 把地表 `4.9` 複製為月球六十秒 `4.9`，再除以 3600。
- Node 直跑 `convertMoonTime(...,"divide-3600")` 回傳 `{moonOneSecondSagMm:1.4}`；現行 UI 用狀態值顯示時會成為 `1.40mm`，但固定說明又寫 `1.36mm`，倍率選項仍只接受 3600。這三者目前互相矛盾。
- 若採顯示值 `60R`、`27.3日`、地球半徑 `6371km`，正矢給月球一秒約 `1.356mm`、六十秒約 `4.882m`；錯除一次 60 約 `81.4mm`。
- 若採現代平均月距 `384400km` 與恆星月 `27.321661日`，則一秒約 `1.362mm`、六十秒約 `4.902m`，錯除一次 60 仍約 `81.7mm`。因此 `81.7→81.4` 不是必然修正，取決於 teaching fixture；規格必須先選定並公開來源。
- 無論採哪組，`4.9m/約1.36mm` 只能寫「約3600」，不可寫等號。
- 現行 `D1-2/n1`（`scenes4.json:600-604`）已明標「合理重建」「沒有存世的1665年計算紙」「現代教學整理值」。
- `n3-n6` 也把牛頓地表估算與比薩斜面比例分紙，明說 4.9m 不是旅人第一章直接量得。

案 A 仍須在人物場面補一句「接近，不是正中；地球大小的尺度仍欠重測」，不能只把史實債藏在 system 頁首。

#### 4. `60R ↔ 3600` 是否由玩家觸發

**已由玩家觸發，提案原診斷應撤回。**

- UI 先由玩家用 `judgeScaleRatio` 選出約 3600（`chapter-ui.js:6793-6815`）。
- 再由玩家用 `judgeScaleRelation` 選 `60×60`（`6817-6838`）。
- engine 只有在倍率與關係皆正確後才授予 K2，來源記為 `player-scale-judgments`（`engine4.js:1201-1262`）。
- `D1-2/n10/n11` 位於 `e1 until orbit:k2` 之後（`scenes4.json:695-724`）；`n10` 是 recap，`n11` 才由旅人公開有限概括，不是 NPC 在玩家操作前搶答。

因此 GB-ADR-039 所裁的藍紙／金紙／疊合台已實作核心代理權。若只為共同發現感，不需要另加「拖 60R 紙籤」新 action；選擇與確認已是有效玩家工作。可以把物理紙感做得更強，但那是 UX 改良，不是認知權修復。

#### 5. 案 A 是否足以避免史實誤導

**足以，但有三個硬條件：**

1. 場內保留目前的「合理重建／非存世 1665 計算紙」標示，不准改成史實重演語氣。
2. 月球紙由獨立的月距、週期與正矢生成，不得再把地表 `4.9` 複製為月球 fixture。
3. 人物收尾明示「約合、非精準證明」及地球尺度債；`支持` 不改成 `證明`。

在這兩條下，案 A 比案 B 更合適：它保留一次完整認知高潮，也不需要把 K2 證據拆成兩個年代。案 B 的史實純度較高，但會重複同一發現並增加遷移風險，收益不足。

#### 6. 真實工程量重估

**P0：修獨立數值來源，約 0.5–1 人日。**

- `engine4.js` 增加月距、地球半徑、週期與正矢計算；移除抄寫式 `moonSixtySecondSagM:4.9`，並把月球一秒值保留到至少兩位小數，不能再 round 成 `1.4`。
- 更新 UI 數值文案、錯除一次 60 的退件值與對應測試。若採現代平均月距＋恆星月，81.7mm 可維持；若採 60R＋27.3日，改為81.4mm。
- 保留現有 action、schema、gate 與 K2 evidence；新增「改動地表4.9不會同步改變月球幾何值」的反向測試，證明兩份來源真的分開。

**縮小案 A，不強制改 60 秒順序，連同 D1-1 橋與史實債：約 1–2 人日。**

- `scenes4.json`：補／重用 D1-1 一個偏折橋；D1-2 加尺度債 recap。
- 保留現有 K2 actions、gate、schema、evidence。
- 更新 node-count／文案契約（若重用節點可避免計數變更）、CH4 CR、分支與 205 舊 cursor 回歸。

**案 A＋硬性「1 秒先、60 秒後」：小至中型，約 2–3 人日。**

- 可沿用現有 `scalePrediction/conversionAttempts/moonOneSecondSagMm` 欄位及判倍率／判關係 action；把藍紙改成由週期＋月距求一秒弓高，疊合後才顯示六十秒放大尺。
- 仍須改 `n7/c0/e1 hint`、K2 UI 文案與 `convertMoonTime` 的可見語義，並 supersede GB-ADR-039，因 ADR-039 明文裁定「藍紙只處理60秒到1秒」與81.7退件。不能宣稱舊 ADR 逐字仍成立。
- 不預期 schema migration，但必須做 K2 mutation、evidence grant、205 legacy cursor 及 full-walk 測試。

**案 B：大型，約 7–12 人日。**

- 另拆後期重算場景、K2 method/final evidence、gate/action/state；高機率 schema 及 migration；重測 D2 以後所有 K2 依賴。

本報告不選案 B。
