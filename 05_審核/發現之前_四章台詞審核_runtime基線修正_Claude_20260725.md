## 二、②可選微調（一致性／輕度編劇腔）

- **「筆記重重寫下」×2**：ch1 `A1-5/n12`(system)、ch2 `B1-3/s1`(system)。全作其餘一律「筆記：「…」」（ch1 A1-4/n5、A1-6/n6），此二處多了小說副詞「重重」。建議統一為「筆記：「…」」。
- **ch3「前行」名詞化 motif**：`C0-2/n3b` 伽桑狄「不會突然丟掉**這份前行**」、`C2-4/n2` 旅人「不等於把**已有的前行**歸零」。翻譯腔，建議改動詞說法（「不再往前／本來就在走」）。⚠**同概念也在 `C2-4/q1` 正解選項**「…鬆手不會清除石頭與**共有的前行**」——該選項是判定分支、其精確性有功能（區別於兩個誇大錯項），**建議保留或極輕動，且須先過判定測試**；若動 motif 請全章一致。
- **ch3 `publicDemo.steps[stable-window].reply` / 艾蒂安**：「鼓點和岸標都留著，**任何人都能重新判斷這段船速**。」艾蒂安聲線＝短、只說自己做的事；此句概化像稽核員。建議：「鼓點和岸標我都留著。你們自己照著查一次。」（注意此台詞在 `publicDemo.steps`，非場景節點）
- **ch4 `D2-1/n7` 牛頓**：「差在「多少」。方向說得再好，也**不能替數量作證**。」牛頓＝數字導向、不用比喻，「替數量作證」是法庭腔。建議：「差在「多少」。方向對了，**數量還沒算出來**。」
- **ch4 `D2-1/n9` 旅人・心聲**：「他怕兩件事：**證明還沒閉合**，名字卻先被寫死。」替牛頓解說動機＋抽象。建議：「他怕的是：**還沒算完**，名字就被刻死了。」
- **ch4 章末旅人心聲（主旨／續集）**：`DE-1/n12`「一本書可以有一個作者……不只一雙手。」、`DE-2/n6`「知道力怎麼改變一顆物體……守住哪一本帳。」屬「心聲替章旨下標題」通則；可收短或改成旅人寫在筆記上的具體問句，但屬語感取捨、非缺陷（亦可留）。
- **系統／hint game-speak（極輕）**：如「三柱皆破」「錯誤出示」「判讀成功步」略書面；玩家可見但非對白，低優先。

## 五、給 Sol 的做法（施工流程）

1. **canonical 是 JSON**：所有改動改 `scenes*.json`，再自動生成 `.js`；不手改 `.js`。
2. **逐句對抗審**：以本報告 ①② 為清單，逐條回 runtime 確認節點與逐字後再改；③ 不動。
3. **判定敏感先過測試**：ch3 `C2-4/q1` 的「bounded」正解選項若要動，先確認判定不以該字串比對、`npm test` 全綠；不確定就不動、回報。
4. **凍結章走 CR**：ch1／ch2／ch3 改動以變更紀錄登記各章檔頭（先文件後程式）。**ch4 未凍結**，走一般增補，但仍需 `scenes4.json`／對話審稿本／runtime 三源同步。
5. **只改語感、不動語義**：物理判定、證據配對、章名與命名禁令一律不變。
6. **回寫 `.md`**：改完後同步更新對應小說稿／劇本，避免「JSON 改了、`.md` 沒改」的反向漂移。
