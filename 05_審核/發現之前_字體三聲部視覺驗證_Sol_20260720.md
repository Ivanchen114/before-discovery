# 《發現之前》字體三聲部視覺驗證（Sol，2026-07-20）

## 結論

**方向通過，實作有條件通過；暫不宣告「三聲部完成」。**

- 黑體＝現代／系統、明體＝歷史世界、楷體＝玩家留下的字，這套分工清楚且可跨章沿用。
- P0-0 黑體切到 1590 明體，作為無聲的穿越剪接成立。
- 明體的正文參數適合長篇對話；楷體目前仍依賴系統字型，跨平台不穩，且檯上便條的敘事身份尚未完全對齊「玩家親筆」。

## B 級修正

### B-1｜「明體首現於 1590」與實際順序不一致

標題畫面在 P0-0 之前已大量使用 `--font-dialogue`（遊戲名、模式名、按鈕、書信碼標題）。因此玩家看到的順序是：

> 標題明體（封面）→ P0-0 黑體（現代）→ 1590 明體（歷史世界）

這個三拍本身並不壞，甚至像「封面打開後先掉進現代，再落入歷史」。問題是文件與測試宣稱「整個遊戲第一個明體字在 1590」，而現有測試只檢查 P0-0 三個 selector，沒有驗證時間順序。

**建議採封面例外，不改標題美術：**把原則、註解與測試名稱改為「P0-0 現代敘事全黑體；落地 1590 時恢復世界明體」。不要再寫「整個遊戲首次」。若總監堅持嚴格首次，才把標題卡改成黑體／標誌圖，並預載明體，避免落地第一句發生字型閃換。

### B-2｜楷體沒有隨遊戲出貨，第三聲部不可保證存在

`--font-hand` 目前依賴 `Kaiti TC / DFKai-SB / BiauKai / TW-Kai / KaiTi`。本次檢查的 macOS 環境未在系統字型清單找到宣告的中文字型檔；Windows 端也取決於繁中字型功能是否安裝。回退到底時會變成一般 `serif`，視覺上等於與世界明體合流。

**建議：**目前標記為 provisional；RC 前子集化一套 OFL 楷／手寫字型隨遊戲出貨，或至少做 macOS＋Windows 真機截圖後再決定。不要只憑 CSS 字型名稱宣告完成。

### B-3｜檯上便條的字體像玩家，文案卻像系統

`friendlyLabGoal()` 現在寫「從四段數字……」「只換球……」，是任務系統對玩家下指令；套楷體後卻被解讀為玩家親筆，與「只有你的字是手寫的」略衝突。

**建議二選一：**

- 保留楷體，把四條便條改成第一人稱，例如「我要從四段數字找出規律……」「我只換球的大小……」。
- 保留現文，改回明體／墨色批註，承認它是遊戲給的任務卡。

我建議前者，既保留玩法提示，也讓字體語義成立。

## C 級觀察

1. 靜態粗體檔被映射到 600–700；表頭與小標用 600 會直接取 700 字面，局部可能略黑，但不影響正文。若實機看見表頭比內容搶眼，再把非關鍵小標改 500 或改用色彩，不必新增字重。
2. `font-display: swap` 在首次載入時可能先顯示 fallback 再換字。現在標題畫面預先使用明體，反而提前完成載入；若日後採「1590 嚴格首現」，應加字型 preload。
3. 楷體只適合短句與玩家輸入，不宜擴到整本旅人筆記介面、證據說明或長篇旁白，否則會從聲部變成裝飾噪音。

## 視覺裁定

- **明體濃度：通過。** 400 正文＋大字級＋1.55 行高合理；不建議整體加粗。
- **楷體三處：概念量恰好，但兩處需收尾。** 回顧作答通過；`旅人筆記`短句通過；實驗便條先改成第一人稱。字型檔本身仍待跨平台固定。
- **黑體→明體穿越：買單。** 但精確名稱應是「現代段到歷史段的切換」，不是「全遊戲第一次看見明體」。
- **額外古字／標題字：本輪不做。** 先守住三聲部，不加第四種口音。
