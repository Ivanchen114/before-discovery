## 必攻六條路徑

### 1. 第五段是否仍可偷看或恭真

- 在封存前從 DOM、UI model、讀值表、無障礙文字與存檔匯出面查找第五值。
- 把隱藏第五值改到超出舊公式容差，舊 `9 × first` 預測必須失敗。
- 確認 UI 揭曉的實測值來自 run 的第五段，不是另一個重算公式。

### 2. 四段舊存檔

- 刪掉新 run 的第五讀值，往返 serialize／sanitize／load 後應還原同值。
- 不同配置、patternIndex 與 seq 不得串值；無法還原時應拒絕，不得靜默猜一個值。

### 3. 信譽修復偽造

- 只做 run、只偽造 embedDone、只塞 ok claim、刪掉進場後 judge 事件，四種都不得領回信譽。
- 第二輪修復不得借用第一輪的 run／claim／judge。
- 舊版沒有 `gate` 的合法存檔仍要依明示相容規則可讀，不能全部誤殺。

### 4. 平方律是否仍由 NPC 代做

- 分別走 qOdd 與 qCum 的兩個錯項，應看到當前讀法的錯圖反饋，不得洩漏下一題正解。
- 確認未選中 qOdd 前不會出現完整平方序列；未選中 qCum 前不會由 NPC 說出時間平方。

### 5. 第二章橋接是真的角色拍，不是系統通知換名

- 檢查 B2-3 `s1→p1→n4`、`e3→s3→p2→n6` 與 B3-1 `n3_os→pF1→s1`。
- 前後人物必須回應玩家實際剛說的資料關係；不得把尚未出航的船桅紙寫成已驗證證據。

### 6. 跨章 lint 是否只有表面字串測試

- 把每個受管詞分別放進節點 text、hint 與 option text，三層均必須轉紅。

- 攻擊詞彙邊界的合理性：第五章的「活力」當帳名可提前，但「短少」與「速度的平方」不可提前當結論；不要用全文禁詞破壞史實語境。
