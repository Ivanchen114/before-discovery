## 一、驗證① 「第五段預測」是循環認證 —— ✅ **成立**

### 程式證據

`data/patterns.json` 的 `base` **每個傾角只有四個值**：

```json
"base": { "緩": [12, 36, 60, 84], "中": [14, 42, 70, 98], "陡": [22, 66, 110, 154] }
```

`computeReadings`（`engine.js:41-50`）以 `b.map(...)` 產生讀值 → **永遠只有 4 段**。
`avgDeltas`（`:98-102`）也只 map `[0,1,2,3]`。

而 `judge`（`:111-137`）：

```js
var avg = avgDeltas(sel.runs);
var target = 9 * avg[0];                              // ← 第五段的「答案」由第一段推導
var predDev = Math.abs(prediction - target) / target;
var predHit = predDev <= TOL;
var devs = ODD.map(function (k, i) { return Math.abs(avg[i+1]/avg[0] - k)/k; });
var consistent = devs.every(function (d) { return d <= TOL; });
```

**沒有第五段的實測值存在。** `target` 是用玩家正要發現的那條定律（1:3:5:7:9）從同一批資料算出來的。

### Node 實測

```
 run#1 readings = 12.1 , 36.3 , 59.75 , 84.35  ← 共 4 段
 run#2 readings = 11.9 , 35.7 , 60.25 , 83.65  ← 共 4 段
 run#3 readings = 12.05 , 36.25 , 60.3 , 83.7  ← 共 4 段
 avg[0] = 12.0167   9×avg[0] = 108.1500
 押「9×第一段」 → predHit = true  predDev = 0.000000%
 readings.length = 4 → 沒有第五段
```

### ⚠ 比 codex 說的更強：`predHit` 是**恆真**，不只是循環

`predDev = |9·avg[0] − 9·avg[0]| / (9·avg[0]) = 0`，**與配置無關、與資料乾不乾淨無關**。

我掃過全部 54 種器材配置（3 球 × 2 槽面 × 3 傾角 × 3 計時）、各跑三筆、一律押 `9×avg[0]`：

| 結果 | 數量 |
|---|---|
| `predHit === consistent` | 12 |
| `predHit ≠ consistent` | **42** |

那 42 種全部是 **`predHit = true` 而 `consistent = false`**——也就是說，**紀錄髒到形狀完全不成立時，預測照樣「命中」**。

**所以真正的門檻只有 `consistent`（前四段是否 1:3:5:7），而 `predHit` 對任何會算 9×第一段的玩家而言是免費通過。**

容差還很寬：

```
 押  87% ×(9·avg0) → predHit=false
 押  88% ×(9·avg0) → predHit=true
 押 112% ×(9·avg0) → predHit=false
```

——連乘法都可以估到個位數。

### 為什麼這是問題（對照設計意圖）

- 規格 §11 驗收準則③ 是「**預測制**＋lint」；R-JUD-03/04 稱之為「**預測式指認**」。
- `chapter-ui.js:660` 給玩家的輸入標籤寫著「**押第五段**」。

**「押」這個字承諾了一個揭曉，而揭曉不存在。** 玩家寫下一個數字，系統拿同一批資料算出同一個數字，然後說「命中」。這在體感上是「你猜對了自然」，實際上是「你會乘法」。

對照同專案：第四章 `D3-1` 的行星預測我批評過「封存與開獎在同一函式內完成」；**第一章的問題在同一類，但更根本——這裡連要開的獎都沒有生成。**

### 🔧 建議（P1-A）：讓第五段成為真的實測

**主案**：`patterns.json` 每個樣式陣列補第 5 個元素，`computeReadings` 產生 5 段，但**只把前 4 段交給玩家看**：

```js
function computeReadings(config, patternIndex) {
  ... // 現行邏輯，改為產生 5 段
}
function runExperiment(state0, config) {
  ...
  var full = computeReadings(config, patternIndex);
  var run = {
    ...,
    readings: full.slice(0, 4),      // 玩家看得到的
    hiddenFifth: full[4]             // 封存，judge 時才揭曉
  };
}
```

`judge` 改為：
```js
var target = sel.runs.reduce(function (a, r) { return a + r.hiddenFifth; }, 0) / sel.runs.length;
```
並在回傳裡帶出 `revealed: target`，UI 揭曉「你押 108，量到 106.4」。

**效果**：
- 有真的揭曉，「押」這個字兌現
- 誤差樣式（timer／surface／ball）也會落在第五段上，`predHit` 不再恆真
- `consistent`（你看懂了前四段嗎）與 `predHit`（自然真的照這條走嗎）變成**兩件獨立的事**

**理想值**：`base` 本來就是 `[1,3,5,7]` 的倍數（緩 12×、中 14×、陡 22×），所以第五段的理想值 = 緩 108／中 126／陡 198。三個樣式表（timer／surface／ball）各需補第 5 個元素。

**過渡方案（P1-A′，一行）**：若暫時不動 fixture，至少把 `target` 改成不由玩家這幾筆導出——
```js
var target = 9 * PATTERNS.base[sel.runs[0].config.incline][0];
```
髒配置的 `avg[0]` 偏掉時 `predDev` 就不再是 0。**這修掉「恆真」，但仍然沒有揭曉。** 建議只當過渡。

### 🔧 建議（P1-B）：要求一筆基線之後、且通過認證的紀錄

```js
if (until.repairRun) {
  var base = parseInt(state.flags.scr1_baseline || "0", 10);
  if (state.lab.series) { /* 第二章維持 */ ... }
  /* R-REP-03「並出示紀錄」：需有一筆在基線之後產生、且經 judge 認證成立的主張 */
  return (state.lab.inference.claims || []).some(function (c) {
    return c.ok && c.runIds.every(function (id) { return id > base; });
  });
}
```

**防卡關**：失敗時不要沉默——`chapter-ui.js:678-681` 已經有現成的診斷函式（會針對「陡坡＋水鐘」給出「若每次都往同一邊歪，多測幾次救得了嗎？」），直接複用即可。玩家可以無限重做，不扣任何東西。

**順帶**：把 SC-R1 的 hint 從「完成任意一次實驗」改成「做一次**認證得過**的實驗，把紀錄帶回」，四處文案才會一致。

### 🟡 C6｜`assertE3` 沒有錯誤概念可選——但比第五章好，比第二章差

`assertE3(state, type, claimIds)` 的 `type` 由兩顆具名按鈕決定（`labAssertB`／`labAssertC`），兩句都是真命題，唯一的失敗來源是選錯 claim 配對。**所以有真的映射判斷，但沒有概念誘答。**

同專案的三種水準：

| 章 | 斷言介面 | 概念誘答 |
|---|---|---|
| **第二章** | 選來源 `<select>` ＋ **選概念 `<select>`** ＋ `concept-mismatch` | ✅ 有 |
| **第一章** | 勾兩筆 claim ＋ 兩顆具名按鈕 | ⚠ 無（但映射會被擋） |

**建議（P2-D）**：把兩顆按鈕換成一個概念下拉，加入誘答——
> ✓「只換球重，量到的規律沒有改變。」
> ✓「換了傾角，規律的形式仍然不變。」
> ✗「球越重，規律越準。」
> ✗「傾角越陡，前四段越接近 1:3:5:7。」

引擎只需把 `type` 的合法值從 `{b,c}` 擴到含誘答並回 `concept-mismatch`（現行 `invalidType` 分支已經有不改 state 的正確行為，直接沿用）。

## 六、對交辦問題的直接回答

> **codex 的兩個發現是否屬實？**

**兩個都屬實，我用 Node 重現了。**

1. **「第五段預測」循環認證** —— 屬實，且**比 codex 描述的更嚴重**：`predDev` 恆為 0，`predHit` 對任何會算 `9×第一段` 的玩家是**無條件通過**。54 種配置的掃描顯示，有 42 種是「紀錄髒到形狀完全不成立、預測照樣命中」。真正的門檻只有 `consistent`，而它也是同一批資料算的。
2. **`repairRun` 不檢查可判讀性** —— 屬實。最髒配置（木球／原木／陡／脈搏）跑一筆，`maxDev = 60.3%`、`claim.ok = false`，但 `runs.length > base` 成立，出口開啟；玩家甚至不必按 judge。而規格 R-REP-03 明文要求「並**出示紀錄**」，UI 與筆記也都寫「乾淨的」「可檢查的」——**四處文案與程式不一致。**

**我要補充的一點**：這兩個洞都在**把關層**，不在物理層。第一章的 `computeReadings` 是全系列做得最紮實的確定性模型之一（器材選擇真的決定成敗，54 選 12），`assertE3` 的變因守衛也找不到捷徑。**所以這是「兩道門沒關」，不是「整個實驗台是假的」**——修法明確、成本低。
