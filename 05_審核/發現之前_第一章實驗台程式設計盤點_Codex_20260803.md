## 一、總裁決

第一章不是「沒有玩法」，而是玩法品質高度集中在斜面工作台與三支柱辯論；高塔、綁縛悖論、紙張／水缸對照多屬低顆粒敘事互動。這個分工本身符合第一章規格，但現行程式有三個會傷到玩家認知主體性的實質缺陷：

1. **斜面第五段沒有真的被量出來**：玩家輸入的預測，是拿已顯示的第一段乘 9 後直接認證，沒有「先承諾、再揭曉一筆新結果」。核心迴圈因此是公式驗算，不是預測實驗。
2. **信譽修復守衛過弱**：任意新增一筆 run 就可解鎖；即使用木球、原木槽、陡坡、脈搏得到明顯失真的數列，且完全不判讀，也可被敘事稱作「乾淨的實驗」並修復信譽。
3. **高塔見證人是半套假選擇**：助手分支有後續台詞；學生與無人分支除玩家選項文字外，後續逐字同軌。這直接違反規格 R-TWR-04 與「旗標寫入後必須被消費」。

另有兩個 P1 體驗落差：換球／換坡動畫各自正規化到整條軌道，無法直觀看出跨 run 的絕對差異；既有紀錄沒有可見重播入口，`compareRuns()` 雖存在，第一章 UI 卻沒有使用。玩家最後多半是在表格裡比配置字串，而不是看物理運動。

**建議裁決**：可形成性試玩，但不宜把第一章工作台視為已完成。P0 應先修第五段揭曉與修復守衛；P1 再補跨 run 共尺比較、重播、見證人後果與玩家限界主張。

## 三、設計分工是否落地

現行法源把責任分成三層：

1. **系統產生可追溯資料**；
2. **玩家親自解讀並提出有限主張**；
3. **NPC 對玩家實際選的資料與主張作具體回應**。

落地狀況如下：

| 層次 | 現況 | 判定 |
|---|---|---|
| 產生資料 | 斜面 run、配置指紋、天數、讀值、錯誤 claim 均會留存 | 強 |
| 親自解讀 | 玩家選 run、填第五段、選兩筆 claim 做 b/c；但第五段沒有新結果，b/c 又只由引擎判 `diffDims` | 中偏弱 |
| 有限主張 | 正確配對後，系統自動代旅人說完整長句；工作台也只顯示「成立／不成立」 | 弱 |
| NPC 針對回應 | 辯論破柱回應具體；斜面 b/c 後的劇情有回應，但沒有引用玩家實際選的 run 或差異 | 中 |
| 可見後果 | 辯論破柱 FX 清楚；斜面失敗診斷有用；高塔見證人與紙／水操作後果較弱 | 中 |

核心落差不是「引擎替玩家算數」；系統當然可以算。問題是它同時替玩家完成了**最重要的轉換與主張措辭**，而玩家只剩選 ID。

## 五、逐站詳細盤點

## 5.1 高塔演示：有控制變因判讀，沒有完整的見證策略

### 現行做對的事

- 規格明定高塔是低顆粒敘事互動，不應錯誤要求它變成完整數值模擬。
- `A1-3/q1` 的鉛球＋木球錯誤路徑不是單純紅燈；它留下混雜紀錄，要求玩家判讀「材質與重量同時改變，原因待查」。這是第一章很好的研究設計教學。
- 錯答後仍回到三個平行選項，沒有用排除法偷偷教答案。
- 塔上固定結果「近乎同時、重者早一線」會被辛普里奧反吃，結果不是獎勵動畫，而是新的敘事困境。

### 實測問題：見證人三選只消費一條

Node 由 `A1-3/q1` 走到 `A1-6/n1`：

- `w=assistant`：20 行 transcript，A1-5 多出助手作證與辛普里奧反吃兩句。
- `w=student`：18 行。
- `w=none`：18 行。
- 後兩者除了玩家在 q3 選的文字外，A1-4／A1-5 後續逐字一致。

規格 R-TWR-04 明訂 `student / assistant / none` 都應影響 A1-5 插入台詞與 P1 的 E1 特殊回應。現況只做到 assistant，故 `student` 與 `none` 是假分支。

### 為何影響遊戲性

q3 表面上問「誰替這筆證據背書」，這本來可以是第一章對「資料品質不等於公共可信度」的首次操作。但學生、無人沒有差別，玩家學到的反而是：見證選擇只是風味文字。

### 建議

**P1-A｜不改物理結果，只補可見後果。**

- student：A1-5 開場已有全城傳言；辛普里奧可攻擊「學生只聽見兩聲，沒看放手是否齊」；P1 特殊回應承認公開流傳但質疑量法。
- assistant：保留現行「對方的人也作證，反被吸收」。
- none：A1-5 先要求「誰能證明同時放手」，E1 仍保留但公共效力較低；不要扣信譽，因紀錄仍是真的。

驗收：三條路徑的 transcript 與 P1/E1 特殊回應至少各有一個獨有、且能回扣玩家選擇的句子；不需要數值 buff/debuff。

**P2-A｜讓放手方式成為可見固定件，而不是新下拉。**

現行塔上只播放固定放手。可在畫面中明示「手背抵齊、同時放手」是伽利略固定的程序，避免玩家誤以為自己少做了一個操作；不要新增沒有後果的放手按鈕。

## 5.2 綁縛悖論：分支可讀，但第二拍是單選按頁

### 現行做對的事

- 玩家第一步可選「小石拖慢大石」或「綁起來更重所以更快」，兩條都是從假設出發的合理推論。
- 遊戲不把首選標成錯答；它先承認合理，再從另一角度逼出矛盾。
- 兩條路徑都留下清楚、對稱的敘事後果，這比選正確結論好。

### 問題

第二拍 `qA2` 與 `qB2` 都只有一個選項。玩家不是親手把兩張推論組成矛盾，而是按唯一按鈕，接收伽利略的結論。探索模式甚至在 `m1` 直接完成判定；學者模式雖多問一次，仍只有一個答案。

這不算錯誤判定，也不是繞過資料；但它使「悖論」更像互動小說分岔，而不是玩家完成的推理物件。

### 建議

**P2-B｜改成兩張可拖曳後果卡，不增加物理引擎。**

1. 玩家先選首張：「慢石拖累」或「總重增加」。
2. 桌面保留首張卡。
3. 玩家從另外兩張敘述中挑出能由同一前提推出、卻與首張衝突的一張。
4. 兩張卡疊合後，矛盾線才亮起；錯卡留在桌上並由伽利略問「這句用了哪個前提？」

低成本替代：保留 JSON 拓樸，只把唯一選項改為「翻另一面」的情境按鈕，且在 m1 前顯示兩張並列原句；至少讓玩家看見自己剛建出的矛盾，而不是只聽 NPC 摘要。

## 5.3 斜面工作台：資料狀態完整，但核心預測是循環認證

### 現行做對的事

1. 四維配置指紋完整：球、槽面、傾角、計時器。
2. 同配置重做依序使用三組確定樣式；可重現、可測試、可存檔。
3. 1–3 筆 run 必須配置完全相同，混選會被守衛拒絕且不留下假 claim。
4. claim 成敗會保留 `predHit` 與 `consistent`，UI 能分辨「預測沒接上」和「前四段不規整」。
5. 失敗後第二、三次提示會逐步區分隨機擾動、系統偏差、坡度太陡與計時器精度；這是目前最有教學價值的回饋。
6. 動畫每段固定 800ms，位置按累積位移更新，因此單一 run 內能看見等時段越走越遠。

### P0-1：第五段根本沒有新觀測

`judge()` 的 target 是：

```text
target = 9 × 前四段平均中的第一段
```

引擎只儲存四段讀值，沒有生成第五段。玩家輸入預測後，系統不是放球取得第五段，而是把預測和上述公式比對。換言之：

- 「預測」與「驗證資料」來自同一批已顯示數字；
- 玩家若知道規則，只需看第一段乘 9，不必觀察第五段；
- 動畫也只播四段，成功後沒有第五段出現的驚喜或失敗殘影。

這違反本作最強的迴圈「先承諾、再揭曉」。它同時造成先前鋪陳中的「第五段」語義錯置：玩家以為在預測一個即將量出的數字，實際是在接受程式的公式口試。

### Node 實測：三筆 run／6 天完成 E3 全套

以下各做一次、預測填 `9 × 第一段`：

| run | 配置 | 四段讀值 | 預測 | 結果 |
|---|---|---|---:|---|
| 1 | 銅大／打磨／緩／水鐘 | 12.7 / 36.15 / 60.15 / 84.35 | 114.3 | 成立 |
| 2 | 銅小／打磨／緩／水鐘 | 13 / 36.75 / 59.65 / 85.05 | 117 | 成立 |
| 3 | 銅大／打磨／中／水鐘 | 15.4 / 42.3 / 70.3 / 98.7 | 138.6 | 成立 |

run 1+2 可成立 E3.b，run 1+3 可成立 E3.c；總耗時 6 天。這條路徑合法、不是 bug，但證明「多次實驗」不是必需策略。若設計意圖是一次一筆、每次有新決策，這可以接受；若故事聲稱規律已經過反覆驗證，就需調整台詞而非暗加重複次數。

### 配置矩陣結果

枚舉 54 組：

- 單筆可成立：10 組。
- 同配置三筆平均可成立：12 組。
- 原木槽：18 組中 0 組可成立，即使平均三筆也全部失敗。
- 打磨＋水鐘：18 組中 4 組單筆可成立。
- 打磨＋音格：18 組中 6 組單筆可成立。
- 打磨＋脈搏：0 組單筆成立；只有緩坡的銅大／銅小在三筆平均後成立。

這個分布能教「儀器精度與系統誤差」，但原木其實不是風險較高的選項，而是**永久死選項**。若玩家不知道這是刻意的系統偏差，只會以為運氣不好而重做。

### P1-1：跨 run 動畫沒有共尺

`stage/11-fx.part.js` 對每筆 run 都以自身四段總和當 `total`，再把 `total` 映射為整條視覺軌道。結果：

- 同一 run 內的 1/3/5/7 形狀清楚；
- 不同坡度或不同球的總距離都會各自填滿整條軌道；
- 玩家無法用動畫直接比較「中坡比緩坡整體更快」或「大／小球幾乎相同」。

數字標籤仍正確，所以不是物理算錯；問題是最需要視覺比較的 E3.b/c，只能靠表格。

### P1-2：沒有既有 run 重播，也沒有可見 compare 工具

- `compareRuns()` 會記錄兩筆 run 相異的維度，`narrative.labAction("compare")` 也有入口。
- 第一章 UI 沒有 compare 按鈕；玩家只在 claim 表中勾兩筆，讓 `assertE3()` 自動算差異。
- `bd:run` 動畫只在新 run 產生時觸發；第一章紀錄列只有 checkbox，沒有「重播這筆紀錄」。
- 這不符合 v0.1.7 §6-2「工作台與筆記都可重播既有資料，且不得改狀態」。

### 建議

**P0-1a｜生成並封存真正的第五段。**

最小資料改法：run 建立時即生成五段原始值，但在預測前只公開前四段；`judge()` 提交後揭露 `run.readings[4]`，並用它判斷預測。第五段必須在 run 當下決定，不能在 judge 時臨時重抽或由預測推回。

狀態建議：

```text
run.readings = [d1,d2,d3,d4,d5]
run.revealedSegments = 4
claim.observedFifth = d5
claim.prediction = 玩家值
```

若要兼容舊存檔，可保留四段舊 run，但標 `legacyNoFifth:true`，只能用於既有 E3 證據，不可再新增 claim；不要用公式補造歷史第五段。

驗收：提交前 state 已有但 UI 不可見 d5；提交後同一筆 d5 被揭露；改預測不會改 d5；重載後 d5 不變。

**P1-1a｜b/c 進入共享尺度比較模式。**

- 選兩筆成立 claim 後顯示雙軌重播；共用同一距離比例與同一時間節拍。
- 球不同：兩顆同時播放，顯示位置差隨時間是否擴大。
- 坡不同：軌道角度不同，但距離刻度共尺；另以正規化小圖顯示「形狀」相同。
- 不要只顯示 `diffDims = [球]` 或 `[傾角]`；那是守衛，不是頓悟。

**P1-2a｜接上 compare 與無副作用重播。**

- 每個 run 列增加「重播」；只讀既有 run，不增加天數、不寫 event、不改 evidence。
- 選兩 run 後顯示「只改了：球／傾角」與「還同時改了：…」。
- 重播應聚焦動畫，不只捲回工作台頂端。

**P1-3｜讓玩家說有限主張。**

assert b/c 成功後，不要立刻只顯示「成立」。先讓玩家選範圍：

- b：`在同槽面、同傾角、同計時下，換銅球大小沒有改變規律形狀`。
- 誘答可把範圍擴成「所有材質、所有介質都與重量無關」。
- c：`在已測的兩個傾角下，規律形狀相同`。
- 誘答可寫成「已直接量到垂直落下」。

NPC 必須引用玩家選的兩筆配置作回應。這才完整落實「系統算，玩家判斷」。

**P2-1｜把永久死選項說成可診斷的工具，而非可成功路線。**

原木可以保留，但 UI 應預告「粗糙槽面是用來觀察固定偏差，不適合拿來認證規律」；若目標是自由探索，也可讓原木在極少數慢速高精度條件下接近通過，避免整維選項永遠是陷阱。

## 5.4 換球、換坡：守衛正確，頓悟被表格化

### 現行程式正確性

`assertE3()` 對 b/c 的守衛嚴格：

- 必須選兩筆已成立 claim；
- b 只能差「球」，且必須是銅大／銅小；
- c 只能差「傾角」；
- 多差一維就拒絕。

這能阻止假控制變因，狀態機沒有偷放行。

### 互動問題

玩家實際做的是：

1. 從長表格勾兩筆 claim；
2. 按「檢查重量」或「檢查傾角」；
3. 系統算配置差異；
4. 系統授予 b/c。

引擎有 `compareRuns()`，但 UI 沒有讓玩家先看見比較結果；動畫也無共尺。這使「只改一件事」成為資料庫守衛，而不是玩家可感知的物理實驗。

### 建議

- 採 5.3 的雙軌共尺重播與 compare 卡。
- assert 前讓玩家先指出「哪個變因改了、哪些必須相同」；錯選時高亮兩筆配置真正不同之處，不要只回「變因不符」。
- b/c 成功後離開工作台回到人物場景，讓伽利略逐筆指向玩家所選紀錄再說結論；符合 v0.1.7 的離台契約。

## 5.5 紙張／水缸：符合低顆粒定位，但「做完清單再答題」

### 現行做對的事

- 紙張三操作順序自由，只有全做完才開結論；能避免玩家沒看結果就搶答。
- 天平結果直接保住「重量未變」，結論仍由玩家選「形狀／重量」。
- 水缸要求同一對球先在空氣、再在水中比較，結論由玩家選「介質／球」。
- 錯答不會消失，而是由角色指出可回看的具體事實。

### 問題

1. 所有結果都是固定 line；玩家的操作順序不改變觀察或人物反應。
2. 紙張要依序打滿三個 flag，水缸打滿兩個 flag，本質是 checklist。
3. 水缸沒有先封存「差距會縮小、相同或拉大」；看到固定答案後才問「變的是什麼」，比較像閱讀理解。
4. 成功後沒有把兩組結果視覺疊合；玩家靠文字「一線／差距拉開」理解。

### 建議

**P2-C｜保留低顆粒，不新增數值引擎，但增加承諾與視覺結果。**

- 紙：先把「攤平／揉團」兩張形狀卡放到「較慢／較快」預測位，再實際放手；天平是用來排除重量，不需要當第三個平行 checklist 動作。
- 水：入水前先封存「差距縮小／不變／拉大」；播放同一對球在空氣與水中的並排短動畫，落點殘影保留。
- 結論仍由玩家選，但選項應限制在證據邊界：「這兩次差異不能只歸因重量」而非直接宣告真空中必同落。

驗收：刪掉 NPC 的結論句，玩家仍能從兩張殘影與自己封存的預測看出形狀／介質改變了結果。

## 5.6 三支柱辯論：戲劇回饋強，但探索模式存在「免費掃描＋系統代說」

### 現行做對的事

1. 每柱有三句不同型態的證詞，畫面順序被打散，避免固定按中間。
2. 玩家必須選一張已持有證據與一句具體證詞配對；未持有證據會被引擎拒絕。
3. 配錯會留下 transcript、mistake 與對位後果；第一柱首錯免扣，符合教規則不教答案。
4. 正確配對後對手具體回應，並有支柱破裂聲畫效果。
5. 最後反撲要求誠實承認「沒有直接量過垂直」，是全章最有力的證據邊界操作。

### 實測捷徑一：完全不追問也能直破三柱

Node 初始化辯論並持有證據後，直接執行：

```text
E4 → P1/p1s2
E2 → P2/p2s2
E3.b → P3/s2
```

三次均 `outcome=correct`，`idx` 由 0→3，對位維持 5，press 次數為 0。這表示「問到底」不是必要推理步，而是可跳過的輔助層。

這不一定是 bug：熟手本來可以直接出示證據。但 UI 備忘把「先偵察，再開火」寫成主要玩法，程式契約卻沒有要求玩家真的辨識前提。

### 實測捷徑二：探索模式可免費掃完三句

同一支柱三句都可依序 `debatePress()`：

- 對位保持 5；
- 每句出現 `insight`；
- 有 `weakTo` 的句子在 UI 顯示「此句有隙」。

因此探索模式的穩定策略是按完三句，看哪句被標有隙，再用證據摘要配對。這是可接受的無障礙鷹架，但它不是「自己找出弱點」。若學者模式不顯 gap badge，兩模式的差異才成立；不要把探索模式的行為誤當核心推理已被驗證。

### 代理判斷：正確長論證由程式自動說完

`debatePresent()` 一旦證據 ID 與 target 命中 `weakTo`，就直接把 `pillarDef(pid).playerCorrect` 以旅人身分寫進 transcript。玩家完成的是「證據卡→句子」配對，沒有選擇論證範圍，也無法說出比較保守或越界的版本。

這部分符合舊規格「playerCorrect 是整句台詞，按鈕不可直接跳 NPC」，但不完全符合較新的責任分工「玩家親自解讀並提出有限主張」。不是狀態 bug，而是規格世代落差。

### 建議

**P1-D｜正確配對後增加一個範圍選擇，不重做三柱引擎。**

例 P1：

- 有限：`高塔與紙／水對照顯示，眼前的先後不能只歸因重量。`
- 越界：`所有物體在任何地方都同時落地。`

系統仍可代為整理完整句，但必須反映玩家選的 scope。錯誤 scope 留痕，不要把正確版自動補上。

**P2-D｜保留探索鷹架，學者模式要求指出前提類型。**

- 探索：保留免費追問與 gap badge。
- 學者：追問後，玩家先標「感官原因偷換／權威替代證據／目的論不可量」之一，再開證據配對；不能只靠卡摘要。

**P2-E｜證據摘要避免直接寫成對答案。**

摘要應說「這張紙記了什麼」，不要說「它推翻哪一句」。目前大方向已如此，後續新增卡片仍需守住。

## 5.7 信譽修復：守衛與玩家可見文案互相矛盾

### 現況

`friendlyLabGoal()` 與 `judgeAskText()` 都稱修復目標為「重新做一次乾淨的實驗」「像第一次那樣，押第五段」。但 `untilMet(repairRun)` 對第一章只檢查：

```text
目前 run 數 > 進入修復場時的 run 數
```

它不檢查：

- 球、槽面、坡度、計時器是否適合；
- run 是否規整；
- 是否填第五段；
- 是否產生 claim；
- 玩家是否承認紀錄能或不能支持主張。

### Node 重現

在 `SC-R1/e1`：

```text
配置：木球／原木／陡坡／脈搏
讀值：33.5 / 48 / 126 / 93
claim 數：0
E3：a=false, b=false, c=false
embedReady：true
embedComplete：成功進入 SC-R1/n3
```

這不是只有措辭不精準；玩家能用一筆明顯壞資料、不解讀、不押第五段，完成「用證據道歉」。研究誠信機制因此變成新增資料列即可洗白。

### 與舊規格的關係

第一章功能規格 R-REP-03 的舊文字是「完成任一次斜面實驗並出示紀錄」，所以程式沒有偏離舊守衛；偏離的是後來 UI 已改成「乾淨」與整體四層機制的研究誠信語義。這是**規格版本衝突**，不是單純 coder 疏失。

### 建議

**P0-2｜總監先選修復的意義，再改單一守衛。建議採「誠實分類原紙」而非強迫成功。**

推薦流程：

1. 玩家做一筆新 run；
2. 必須親選：`這筆可支持規律`／`這筆受干擾，只能證明此次讀值`；
3. 引擎依 run 形狀檢查分類是否誠實；
4. 誠實分類即可修復，不要求一定成功。

理由：道歉的核心是交出可檢查原紙並縮限主張，不是保證實驗漂亮。若硬性要求成功 claim，玩家可能為了修復被迫重刷熟練配置，變成懲罰性 grind。

最低成本修法：若維持現有 R-REP-03，就把 UI 的「乾淨」「押第五段」改回「做一筆新紀錄，並說清楚它能證明到哪裡」，且新增一個分類 choice；不能只改字而繼續自動放行。

驗收：壞 run 後 `embedReady=false`，直到玩家正確分類；好 run 也不能只執行，仍需完成分類。舊存檔 baseline 不得被偽造的單一 `rep` 值補歷史。

## 七、優先實作順序

### P0｜試玩前先修

1. **真正的第五段封存與揭露**：先承諾，再顯示既定第五段；舊四段 run 不得事後補造。
2. **修復守衛改成「新原紙＋誠實分類」**：任意 run 不再自動通關；不要用「成功實驗」取代研究誠信。

### P1｜直接提升物理參與感

4. **接上 compareRuns 與無副作用 replay**：每筆紀錄可重播、兩筆可見差異維度。
5. **高塔三種見證人都有可見後果**：只改文本與辯論特殊回應即可。
6. **assert／破柱後由玩家選主張範圍**：系統可整理句子，但不能替玩家決定是否越界。

### P2｜降低點讀與清單感

10. 探索保留 gap 鷹架；學者模式加入前提分類，不只做證據 ID 配對。

### P3｜清理與契約補強

12. 測試新增「玩家可見因果」而非只驗 evidence flag：第五段提交前後、共尺重播、見證人 transcript、修復分類、無副作用 replay。

## 八、建議驗收測試

### 8.1 第五段

- run 時即封存 d5；judge 前 UI 與 narrative view 不得讀到。
- 同一 run 以不同 prediction 提交，observed d5 完全相同。
- 重載存檔後 d5 不變。
- 成功／失敗動畫都顯示預測旗與實際第五段的距離。

### 8.2 換球／換坡

- 選兩筆多改一維，畫面高亮真正差異，不只回 error 字串。
- 合法 b/c 對會顯示雙軌共尺動畫。
- replay 不增加 `days`、runSeq、evidence、eventLog 或信譽。

### 8.3 高塔見證人

- student／assistant／none 三路在 A1-5 與 P1/E1 各有獨有反應。
- 三路物理結果相同，不以數值獎懲暗示某個見證人比較「正確」。

### 8.4 修復

- 新 run 尚未分類：ready=false。
- 壞 run 誠實標「受干擾」：ready=true。
- 壞 run 假標「支持規律」：ready=false，錯誤分類留痕。
- 好 run 也必須分類，不能只按 run 自動洗白。

### 8.5 辯論

- 正確證據配對後仍需玩家選 scope。
- 有限 scope 才破柱；越界 scope 不自動改成正確句。
- 探索／學者的 gap 鷹架差異有自動測試，避免日後無意漂移。

## 九、最值得保留的設計

1. **塔上結果被對手反吃**：實驗結果直接改變人物關係，不是單純授證。
2. **鉛球＋木球混雜紙不丟棄**：失敗紀錄仍有資訊，且原因由玩家判讀。
3. **斜面失敗拆成兩道門**：`consistent` 與 `predHit` 的回饋比單一紅燈好得多。
4. **b/c 嚴格單變因守衛**：程式沒有因劇情急著授證而放寬配置差異。
5. **辯論首錯免扣與特殊不足回應**：錯誤是可讀事件，不是純懲罰。
6. **最後反撲的誠實邊界**：玩家必須承認沒量到垂直，這是第一章最完整的研究倫理操作。

## 十、結論

第一章的底層狀態機相當可靠：資料不會無故消失、錯誤 claim 會留下、b/c 的單變因守衛嚴格、辯論配錯有後果。真正的問題不是「程式不正確」，而是**狀態正確不等於玩家真的完成了判斷**。

目前最重要的三個修復順序是：

1. 把第五段從公式認證改為真正的新觀測；
2. 把修復場從「新增一列資料」改為「提交並誠實界定一筆原紙」；
3. 讓換球／換坡的物理差異出現在共尺動畫與玩家主張裡，而不是只存在 `diffDims` 與證據旗標。

做到這三項，第一章才會從「可靠的教學狀態機」升級成「玩家親手發現規律的遊戲」。
