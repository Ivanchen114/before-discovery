## 二、A 級——Design Gate 前必修

### A-1｜加入 electrometer 了，但排他主張仍沒有完成範圍修正

**位置**：brief 35、39、53–54 行；contract 30、135–174 行。
**實際證據**：工作台已分成 `frog_response` 與 non-animal detector 的兩類觀測，岔口仍寫「**收縮**只可能來自金屬／只可能來自動物」；`animal-only` 卻由 electrometer／pile 的「無組織電效應」反駁。
**因果問題**：反證句與被反證句仍不是同一命題。伏打堆能否掉「所有持續電效應都需要生命組織」，不直接否掉「這次蛙腿收縮的來源只有動物」。A-2 只吸收了儀器橋，沒有吸收主張邊界。
**直接修法**：brief、四欄與 contract 統一使用兩句有範圍的承諾：

- M：`這批蛙腿配置已證明，每次收縮所需的電效應都只能由金屬接觸提供。`
- A：`這批配置已證明，任何可持續的電效應都必須有生命組織在場。`

M 由 1794 無金屬收縮反例縮窄；A 由 1796 electrometer＋1799/1800 pile 縮窄。不要再用同一個「收縮只可能來自動物」標籤代替 A。
**失敗條件**：若 `animal-only` 的顯示句仍含「收縮」，而 `refutedBy` 只含非蛙儀器，主張契約失敗。

### A-2｜實驗前署名不是 evidence judgment

**位置**：contract 112–177 行。
**實際證據**：`em1-exclusive-claim` 發生在矩陣未完成、反例尚未揭曉時，卻標為 `evidence_judgment`，並以後來才出現的 `GRID_NO_METAL`／`GRID_ELECTROMETER`／`GRID_PILE` 判定對錯；連 `GRID_STATE` locator 也在 commitment 之後的 `t_grid`。
**因果問題**：證據判斷契約要求 `supportedBy/refutedBy` 在作答前已取得且可見。這一拍的設計目的恰好相反——它是先押假說、後受世界檢驗。等 binder 生效，DEC-06 應該把這些晚證據判紅；現在只是因 BIND-01 提前失敗而尚未檢到。把「暫不排他」標 `isCorrect: true` 也會把承諾重新做成考卷。
**直接修法**：

- `em1-exclusive-claim.kind` 改為 `experiment_commitment`；
- 三個選項移除 `isCorrect`、`supportedBy`、`refutedBy`；
- 後果讀回以具名 commitment id 綁到後段反例，不在承諾當下評分；
- 真正的 `evidence_judgment` 只保留在所有相關格已取得後的 `em1-config-verdict`。

**失敗條件**：把後段 evidence locator 移到更晚節點後，若 commitment 仍能通過 DEC-06，負向控制失敗。

### A-3｜最終判讀把診斷塞進資料，且 `contradicts` 用錯

**位置**：contract 179–213、219–237 行。
**實際證據**：`always-both-sources` 由 `GRID_BIMETAL.configNote = prepared_leg_primarily_detector_in_bimetal_loop` 反駁，relation 標 `contradicts`。
**因果問題**：雙金屬格的原始可見事實只能是接法與收縮反應，不能自行宣布蛙腿「主要是偵測器」；那正是玩家要做的因果判讀。現有資料也未直接證明「兩來源總是同時存在」為假，只能說**不足以支持這個全稱**。目前 contract 同時踩到系統代診斷與錯誤反證關係。
**直接修法**：

- `configNote` 只保留材料、接點、閉路、樣本與觀測，不寫角色結論；
- `always-both-sources.refutedBy.relation` 改為 `insufficient`，來源指向沒有同時分離量測兩來源的可見欄位；
- 正向選項改成證據真正撐得住的句子，例如：`現有資料要求把不同配置分開記，尚不足以給所有配置同一個來源比例。`
- 章末較高層的「角色不同」可作限縮後的整合語，不冒充單格直接讀值。

**失敗條件**：刪掉 NPC／system 的 `configNote` 診斷後，玩家若再也無法由原始欄位完成判讀，表示資料設計仍未承重。

## 五、Locator／工具債判定

`check-mechanics` 現行 binder 只接受 runtime node 的**頂層 JSON field**，並要求 locator 所在 node 實際 grant 同一 evidence id。contract 現把六個來源全部指向 `EM7-2/t_grid`，field 使用 `grid.bimetal.observation` 等 dotted path；guard 不會把它解析成巢狀欄位，未來將報 DEC-05。

Design Gate 前需二選一並寫進 contract：

1. **建議案**：同一座工作台保留，但每階段完成後回到一個具名 trace node（如 `t_bimetal`、`t_no_metal`、`t_electrometer`、`t_pile`），各自以頂層可見欄位＋evidence grant 留痕；不是拆成六座 embed。
2. **高成本案**：為 engine7 建 chapter-specific mechanics adapter，能讀工作台內部的矩陣 state。若選此案，列入 implementation CR 與負向測試，不得假裝 scenes-json binder 已能驗。

這一項若不在本輪選型，至少把 `_status` 改成 `BLOCKED_LOCATOR_DESIGN`，不能稱 implementation-ready。
