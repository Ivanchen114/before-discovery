# 三、問題 C｜對沖語不對稱（**未登記，我認為比 A 嚴重**）

看四個選項的**開頭**：

| | 現行開頭 |
|---|---|
| 正解・窄 | 「我**先只說**其中一艘……」 |
| 正解・寬 | 「我**只把**這句話寫到實際做過的船……」 |
| 錯・混淆 | 「桅杆越高，石頭落得越後……」（無保留陳述句） |
| 錯・過度推廣 | 「任何船解纜起步……」（無保留陳述句） |

**兩個正解都以自我限制開頭，兩個錯項都是無保留的斷言。玩家只憑語氣就能挑對，完全不必看資料。**

這是**結構層**的洩答，不是詞彙層：把「任何／一定」換成別的詞，這個 tell 還在。修法必須讓四句**語域齊平**——四句都明講自己寫在什麼範圍上，差別只剩「那個範圍有沒有做到」。

# 四、替換句（四句一起換，不可只換錯項）

`engine3.js:1567–1572` `playerLines.p2.scope`：

```js
scope: {
  "one-tested-vessel":
    "這句話只寫在做過的那一艘：這批人、這套操法，解纜起步時落點偏到桅後。",
  "tested-vessels-only":
    "這句話寫到卷宗上的每一艘：船和人都換過，解纜起步的落點還是偏到桅後。",
  "height-causes-offset":
    "這句話寫在桅高上：小艇偏得最少，大船偏得最多——偏多少，是桅高決定的。",
  "all-vessels":
    "這句話寫在所有船上：偏到桅後是起步這件事造成的，跟哪一艘船無關。"
}
```

**四句同一個句型**「這句話寫在＿＿上」，語域齊平，tell 消失。

**兩個錯項為什麼變得真的有誘惑力**：

- `height-causes-offset` 現在**引用玩家資料裡真實存在的單調趨勢**（小艇偏最少、大船偏最多——這是 fixture 真的會產生的）。它不是憑空亂說，是看了紙才說的話。誘惑活著。
- `all-vessels` 拿掉「任何／一定」之後，變成**物理上幾乎正確**的一句話。這正是它難的地方，也是它值得存在的理由：**它教的是「說得對，不等於已經證明」。** 玩家會為一句正確的話被駁倒，而理由是他沒做到那麼多船。這一課比抓錯物理更難忘。

# 六、底線 4 還缺一步——建議用零新節點的做法

底線 4 要求「**『同時改了多個變因』必須由玩家自己選出來**」。改完 5-1 之後，槳手只問不答，但**現行流程裡玩家仍然沒有任何地方說出那句診斷**——失敗即回圈，重選一次正解就過了。

三種補法，我建議第三種：

| 做法 | 成本 | 評價 |
|---|---|---|
| 甲：失敗後插一個「你要改哪裡？」choice 節點 | 新增節點與狀態 | 最明確，但 Sol 說不重建機制，這算加機制 |
| 乙：把診斷留到 `C3-F` 複盤 | 中 | 診斷離錯誤太遠，玩家已經忘記自己選了什麼 |
| **丙：曾經 `confounded` 失敗過的玩家，正解選項改用「含診斷」版本**（建議） | **零新節點**，只在取字時看一個既有旗標 | 玩家親口說出診斷，且是在他自己選的那句話裡 |

丙的實作：`d.debate.attempts` 已經在記 `reason`（`engine3.js:1405–1407`），直接判斷有無 `reason === "confounded"` 即可，不必新增欄位。

```js
var hadConfounded = (db.attempts || []).some(function (a) {
  return a.reason === "confounded";
});
```

取字時替換這兩句：

```js
// tested-vessels-only（曾混淆過）
"這三趟不只桅高不一樣，人和操法也不同——偏多少歸不到桅高。我只寫落在哪一邊。"

// one-tested-vessel（曾混淆過）
"我把每一趟改動的條件都算了一遍，才發現不只桅高。這句話縮到一艘船上。"
```

沒失敗過的玩家維持第四節的原句——**不獎勵也不懲罰，只是說話的人知道的事不一樣。**
