# 〇、總判斷

**以 v0.6 為主幹，吸收 v0.5 的五項，並先解決兩個問題。**

v0.6 在「玩家到底在設計什麼」這件事上做得比我好——它把控制變因變成**介面動作**（複製只改一項）、把「說到剛好」變成**每次斷言都要做的判斷**（適用範圍三選一）、把失敗變成**留在卷宗上的物件**（質疑釘）。這三件是我 v0.5 沒有的深度。

**事實更正一行**：v0.6 檔頭寫「取代 v0.5『固定收齊六份證據再進辯論』架構」——v0.5 §3.2／§3.3／選擇節點③ 已經是自由實驗台、斷言依資料亮牌、隨時可上碼頭。兩版在**方向**上其實同意；v0.6 的貢獻是**深度**，不是轉向。這點記一下，免得後續 CR 誤述沿革。

# 三、兩個必須先解決的問題

## 1. v0.6 刪掉了「相反航向的往返對照」——這推翻了總監的既有裁決

**事實**：v0.6 §3.2 的設定列只有〔船況／放手／船況記錄／位置記錄／重複〕，**沒有航向**；風的處理全部交給封閉船艙（A2）。§13 也只寫「封窗對照只能說甲板風不是共同前行的必要解釋」。

**衝突**：總監在 v0.3 輪明確裁決——

> 「風不能寫成回程吸收且零額外操作；需有相反航向的穩速往返紀錄與相對船風向，並重算趟數及點擊。」
> 「玩家要看見：船換向後，相對風向改變；落點卻沒有跟著風向形成一致變化。」

**物理上兩者不等價**：
- **艙內對照**回答的是「沒有甲板風時，結果還一樣嗎」→ 證明風**不是必要解釋**。
- **往返對照**回答的是「**甲板上真的有風的時候**，落點跟不跟著風走」→ 直接在有風的現場否證風是主因。

槳手的質疑是「**甲板上**有風」，所以在甲板上做的往返是更直接的回答；艙內是繞道（換了裝置、換了場地）。v0.6 少了它，柱三…柱一的風那一釘就只能靠繞道回答。

**我的建議（整合方案）**：
- **A2（艙內）維持為最小過關路徑**（採 v0.6 的經濟性）；
- **把往返對照補回設定列作為「航向」一項**，並新增 **S-wind「相對風向明顯改變，落點沒有跟著偏向同一邊」** 為**補強斷言**；
- 「甲板上有風」這枚質疑釘**兩種答法都接受**：走艙內（A2）或走甲板往返（S-wind）。玩家自己選。

這樣既保住總監的裁決（往返存在、資料是真的兩趟、點擊誠實計入），又不強迫必做，符合 v0.6 「不必收集完整」的精神。**但這條要總監點頭，因為它動的是既有裁決。**

## 2. v0.6 的三柱四拍需要引擎工作——最貴的一項可以砍掉

**查證結果**：

| v0.6 的拍 | 現行引擎 | 判定 |
|---|---|---|
| **追問**（把主張逼成可測預測） | `debatePress` / `debatePressChoice` | ✅ 零改動 |
| **觀念**（選出真正的物理區分） | **不存在**。ch1 的近似物是 FR 的 `explore.steps` | ⚠ 需新增一個階段 |
| **配對**（從卷宗選**兩項**組成論證） | `debatePresent(state0, p)` 只吃**單一** `p.evidence`（＋可選 `p.subitem`） | ❌ 需改引擎 |
| **回應**（接受到哪裡／指出缺口） | `breakReply` / `texts.wrong` | ✅ 零改動 |

另外兩件事實，供成本評估：
- **FR 已經是章節專屬程式碼**：`debateFr`（ch1）與 `debateFr2`（ch2）是兩支不同函式，`debateFr2` 讀 `CH.fr.requires` / `CH.fr.enemy`。所以 ch3 的 FR 本來就要寫第三支（或趁機一般化）——這件事無論採哪版都要做。
- 現行柱結構是**每柱三條證詞**（`d.idx >= 3` → 「支柱已盡」）；v0.6 的四拍不用證詞列，是另一種形狀。

**我的降階方案（保留推理感、砍掉最貴的）**：

> **追問** → 沿用 `press`（零改動）
> **觀念** → 新增一個 choice 階段（可比照 ch2 `debateFr2` 的 `enemy.slope/classify` 兩步選擇模式，是既有寫法）
> **配對** → **改成「出示一項 ＋ 選適用範圍」**，沿用單項 `debatePresent`（零改動）
> **回應** → 沿用 `breakReply`

理由：**v0.6 已經在斷言環節做了「選適用範圍」**（§二-2 的三選一）。在辯論裡再要求「兩項配對」，等於把同一個判斷做兩次，而它是四拍裡唯一需要動引擎核心的一項。砍掉它，四拍的推理感仍在（追問→物理區分→出示→回應），成本從「改辯論核心」降到「加一個 choice 階段」。

**若總監仍想要兩項配對**：那它應該用 **ch2 FR 的組鏈 UI（三槽降為兩槽）**，而不是擴充 `debatePresent`——組鏈已經存在，只是目前綁在 FR 路徑上。

# 四、去蕪：回答 v0.6 §16 第 3 題「哪些補強斷言沒價值，可以刪？」

**建議 S1–S5 收成 3 條：**

| 原 | 處置 | 理由 |
|---|---|---|
| **S1** 手放會混入方向不一的額外推動 | **保留** | 真正的方法學發現，也是探索型玩家的獎勵 |
| **S2** 一回不足以判斷散布與重複性 | **刪掉，降為質疑釘** | 它沒有對自然說任何話——它是**對玩家程序的提醒**。§二-3 的「重複性」釘已經是它，做成「斷言」會稀釋斷言的意義 |
| **S3** 減速組出現前偏 | **併入 S4** | S4 需要 S3 的資料才成立，兩條並存等於同一件事拆兩張卡 |
| **S4** 三種船況指紋 | **保留**（吸收 S3） | 強路徑的核心；讓艦長少一次追問 |
| **S5** 舊紙與加速組同型但不能反證 | **併入 A6 的適用範圍選項** | 它本質是 A6 的「範圍三選一」正解，不是另一條斷言 |
| — | **新增 S-wind**（見 §三-1） | 補回往返對照 |

→ **補強斷言 = S1（手放）、S4（三態指紋）、S-wind（往返）**。三條，各自對應一種不同的方法學能力：控制、外推、現場否證。

# 六、選答 v0.6 §16 的幾題（挑最有價值的）

**Q1 自由實驗台會不會變成參數海？** 不會，但**臨界點在第五個設定列**。目前五列（船況／放手／船況記錄／位置記錄／重複）已是上限；補回「航向」是第六列，因此**建議航向只在「已取得一組乾淨穩速」後才出現**（條件式揭露，比照 GB-ADR-011 的分段亮牌），否則首次進場就六個下拉會勸退人。

**Q5 提早辯論的失敗是否都能回傳不洩答的缺口？** §2-3 的六枚釘都合格（它們描述**缺什麼判斷**，不指定設定）。唯一要小心的是「甲板上有風；你還沒證明風不是共同前行的必要解釋」——這句已經很接近告訴玩家「去做艙內」。建議改成：**「甲板上有風。你怎麼知道石頭不是被它推回桅腳的？」** 保留問題、不指向裝置（這樣兩種答法 A2／S-wind 都還開著）。

**Q8 是否存在以弱斷言意外通關的漏洞？** 有一個：**A6 是文件判讀，不需實驗**。若柱二的最小配對是 A3＋A6，而玩家用一回（非三回）的加速資料換到 A3 的弱版本，就可能在沒有 A1 的情況下推進。v0.6 §7 柱二已注意到並補「若沒有 A1，艦長仍會追問」——建議把它**寫成硬條件**：柱二的改寫需 A1 已被接受（或當場出示），不能只靠追問提醒。

**Q11 伽桑狄還有替玩家總結答案的地方嗎？** 有兩處：§10 的 `C1-M1`「下面是發生過的事；上面是你准備拿它說的話」與 `C1-M2`「門閂排除了手，岸標證明走穩，三回排除了單次巧合」。**後者是替玩家把三個推論一次講完**——建議砍成「門閂、岸標、三回。甲板上的風還在。」把因果留給玩家自己接。

**Q13 若要減少點擊，優先合併哪個判斷？** 合併**雙紙帶的兩個判斷**（同拍對齊 → 逐拍扣除）為一條「先對齊、再拉尺」的連續操作，中間不必各自確認一次。它是全章唯一必做卻與主線（船況分類）無關的支線，壓縮它不損失實驗設計權。
