## 〇、結論與比較基準

**第三章沒有第四章 D1-1/ok2 那一類的因果斷裂。** 這不是印象評語，有結構性的原因：**第三章的敘事鷹架有三層，第四章只有一層。**

| 層 | 第三章 | 第四章 |
|---|---|---|
| **場景框架** | `scenes3.json` 交代動機與交棒（C0-2 舊紙缺什麼 → C0-3 卷宗交給你） | `scenes4.json` 交代動機 ✅ 有 |
| **任務卡**（進實驗前常駐） | ✅ 每輪有 `dialogue`（上一輪留下什麼）＋`goal`（這次要做到什麼，含進度計數）＋`hint`（本輪檢核） | ❌ **沒有**。玩家只有 embed 的一行 hint |
| **過場橋段**（每站之間） | ✅ `ship3SayMissionBridge` 五段由 NPC 演出的因果橋 | ❌ **沒有**。站與站之間直接切換 |

**第四章 `D1-1/ok2` 那句懸空的「每一拍加上什麼」之所以會出現，正是因為它必須靠一句台詞獨力承擔「銜接下一站」的工作。第三章把這件事交給任務卡與過場橋，所以單句台詞不必超載。**

第三章確實比第四章好，而且好在架構，不是好在文筆。

**但第三章有一個問題比第四章任何一處都嚴重：第三柱把一個鋪陳了三次的問題，在玩家要回答的那一刻收走了。** 詳見第三節。

## 一、runtime 的實際敘事結構（先釐清，因為與規格書不同）

功能規格書 v0.1 列了 17 個場景（C0-1…C3-4），但它自己在檔頭標明「**舊基線保留供審計；玩家迴路已由 `CH3-CR-016` 與 v0.3.1 重構稿取代**」。

現行 runtime 的實際結構是：

```
scenes3.json（11 場，只提供框架）
  C0-1 馬賽港・遇見伽桑狄 → S5
  C0-2 借船・舊紙・維達爾的規矩        ← 立起「舊紙缺哪一欄」
  INT-C1 幕間：半天
  C0-3 先看舊紙能說什麼                ← 交出卷宗、交出設計權
  C1-1 同一份卷宗 → 【embed: ship / phase: dossier】 ← 整章實驗全在這裡
  INT-C2 幕間：三輪質詢的最後一句      ← 辯論已結束
  C3-1 少寫的不是答案，是一欄
  C3-2 替卷宗取名
  CE-1／CE-2／SC3-R1
```

**九個實驗站全部在 `C1-1/e1` 這一個 embed 節點裡面。** 所以本次審查的「玩家讀到的文字順序」，主要來自三處：

1. `ship3DossierMissionState(d)` → 任務卡（`dialogue` / `goal` / `hint`）
2. `ship3SayMissionBridge(before, after)` → 站與站之間的演出橋段
3. 辯論的 `lastPlayerLine` / `lastReply` 鏈

## 二、逐站檢查

### 站 1｜重現舊紙（mission `reproduce`）✅ 鋪陳完整

**上一步留下什麼問題**——在 `scenes3.json` 就講清楚了：

> `C0-2/n9` 維達爾：「這張紙只記了落點。船當時是走穩、變快，還是變慢，沒寫；也沒有鼓點、岸標，連第二回都沒有。」
> `C0-2/x21a` 旅人：「這張紙缺的那一欄，明天我們可以真的記出來。」
> `C0-2/x21b` 維達爾：「先把你說的那一欄真的記出來，再談配哪一趟。」
> `C0-3/x5a` 伽桑狄：「放手怎麼放、船速誰記、落點誰畫——你排。」

**任務卡接得上**：
> dialogue：「舊紙只寫『解纜後第一段，石頭落在桅後』。今天重做同一種操作階段，並把舊紙漏掉的船速欄補進新原紙。」
> goal：「船況固定為解纜後第一段；**你要決定的是怎麼放手、怎麼記船速**。留下可判讀船速的原紙，同一做法重現三回。目前合格重現 N／3 張。」

**「你要決定的是什麼」寫得非常明確，而且與 `C0-3/x5a` 伽桑狄那句逐字對應。** 這正是第四章 D1-1 缺的。

#### ⭐ 特別值得記：「鼓點」的引入順序，正好是第四章「拍」的反例

| | 第四章「拍」 | 第三章「鼓點」 |
|---|---|---|
| 首次出現 | `D1-1/ok2` **直接當成已知使用**（「每一拍加上什麼」） | `C0-2/n9` 出現在**「舊紙缺什麼」的清單裡**（「也沒有鼓點、岸標」） |
| 定義 | 三場之後的 `D2-1/n23` | 不需要定義——它是一面聽得見的鼓 |
| 玩家第一次要用它 | 定義之前 | 定義之後（任務 1 的「船速怎麼記」選項：「水手等拍敲鼓」） |

**先在「缺什麼」的脈絡裡讓玩家認識這個東西，再在「你要決定」的脈絡裡要他使用——這是第四章「拍」該有而沒有的作法，建議直接把它當成修 `D1-1/ok2` 的參照。**

### 站 2｜走穩三回（mission `steady`）✅ 過場橋做得極好

`reproduce > steady` 橋段（`chapter-ui.js:1866`）：

> （旁白）三張新紙並排在舊紙旁邊。一樣的後偏。
> 維達爾船長（沒有伸手去拿）：「八年。」
> 維達爾船長：「八年來畫過這條線的只有我一個。現在有四張了。」
> 旅人：「當時他們怎麼說？」
> 維達爾船長：「船在走，石頭當然落後。」
> 維達爾船長（停）：「**我反駁不了。我只做過這一種。**」
> 旅人：「哪一種？」
> 維達爾船長（朝防波堤抬了抬下巴）：「**解纜。出了那道堤以後，我從來沒扔過。**」

**這一段用八句話同時完成四件事**：確認上一站的結果、給維達爾一個情感重量、指出舊紙的真正缺陷（只做過一種船況）、並且**由 NPC 自己說出下一站的必要性**。玩家不需要被告知「接下來做走穩」——他會自己想到。

任務卡再補上單變因原則：
> goal：「留下三張可確認近似走穩的原紙」／hint：「把第一輪和這一輪的條件欄逐項對照；**除了船的狀態，其餘欄位應維持相同**。」

### 站 3｜兩輪並排比較（mission `speed`）✅ 且有一個聰明的設計

`steady > speed` 橋段：
> 馬蒂厄：「走穩三回，桅腳。起步三回，桅後。」
> 維達爾船長（看了很久）：「兩疊都是我的船。」
> 旅人：「高度一樣，放手的人也一樣。那幾欄我們鎖住了。」
> 維達爾船長（把筆抽出來，這次沒插回去）：「……那不一樣的，是這兩趟各自在做什麼。」
> （旁白）他在舊紙那個空白的船速欄上，敲了兩下。

**「敲了兩下」把整章的核心（船速欄）用一個動作收束**，而且不說破。

任務卡：
> dialogue：「**不用再跑一趟。** 第一輪的解纜起步紙與第二輪的走穩紙已經在卷宗裡，現在由你決定哪些能放在一起比較。」

**「不用再跑一趟」這一句很重要**——它明確告訴玩家這一站的動詞不是「做實驗」而是「挑資料」。第四章的 D1-2 沒有這種「這一站你要做的是哪一類動作」的提示。

### 站 4｜封閉船艙（mission `cabin`）✅ 動機由 NPC 提出，不是系統交辦

`speed > cabin` 橋段：
> （旁白）一陣側風把攤在桶上的紙掀起一角。馬蒂厄用封蠟壓住。
> 馬蒂厄：「風從解纜就沒停過。」
> 維達爾船長：「風怎麼了。」
> 馬蒂厄（沒有立刻回答，看著那張被壓住的紙）：「**石頭是跟著船走的，還是被風推著走的。這兩件事，我們的紙分不出來。**」

**這是全章鋪陳最漂亮的一站，也是「玩家清楚自己在判斷什麼」做得最好的一處。**

### 站 8｜🔴 第三柱・對時與換算——**鋪陳了三次的問題，玩家從來沒被允許回答**

這是本次盤點的主要發現，也是我在程式盤點裡標為 F2 的那個問題的敘事面。**從敘事角度看，它比程式角度看嚴重得多**，因為鋪陳做得太完整了。

#### 問題被立起來三次

| # | 位置 | 文字 |
|---|---|---|
| 1 | `cabin>dual` 過場橋，伽桑狄收尾 | 「那就讓它們**回到同一個時刻**，再看一次。」 |
| 2 | `dual` 任務卡 goal | 「**怎麼對上同一時刻、怎麼改成從桅杆量**，留到碼頭上當眾做。」 |
| 3 | P3 選完來源後，維達爾的回應 | 「兩張都收。同一趟、同一鼓點；岸上從碼頭量，船上從桅杆量。**現在先把同號鼓點對上。**」 |

#### 然後玩家做了什麼

按一個「對鼓點」按鈕，再按一個「換原點」按鈕。

**「為什麼必須先確定同一時刻」與「兩張紙到底差在哪」這兩個問題，從來沒有被問過。**

#### 引擎裡那兩題其實寫好了，只是 UI 不呈現、引擎還預先給了通過

`setDossierP3Premise` 在玩家**只選了來源**時就設定：
```js
p3.question = true;   // 自動
p3.concept  = true;   // 自動
```
而 `chapter-ui.js:4718` 的分支鏈只有 `source → aligned → transform`，沒有 question／concept。

被埋掉的內容（全部已寫好）：

**question 拍**——「比較兩張紙之前，該先確定什麼？」
- ✓「先確定兩張紙記的是同一事件、同一時刻，再比較位置。」
- ✗「先決定岸上和船上哪一個人比較可靠。」→ 維達爾：「別先挑誰可靠。先證明兩張紙記的是同一時刻。」
- ✗「先選看起來比較平順的那條路。」

**concept 拍**——「兩張紙為什麼不一樣？」
- ✓「兩張紙量的是同一顆石頭；不同的是各自拿碼頭或桅杆當起點。」
- ✗「兩張紙只是擺放角度不同。」
- ✗「兩張紙上的石頭受了不同的力。」→ 商人（指著兩張條件欄）：「石頭、放手和船況都相同。你說的差別，記在哪一欄？」

**注意那個「✗ 先決定誰比較可靠」選項——它正是過場橋裡維達爾親口說的那句「你們兩個，誰站錯地方了？」** 劇本刻意讓對手先犯這個錯，好讓玩家有機會糾正他。**現在對手犯了錯，玩家卻沒有麥克風。**

而 `lastReply` 的接續台詞是照三步寫的，中間兩句在 runtime 永遠不會出現：
> （question 之後應接）「同一時刻先對上。現在告訴我：岸上和船上的人，各從哪裡開始量？」
> （concept 之後應接）「好。現在當著我們的面，把它們對上。」

#### 還有一層：A4 是全章唯一沒有「選適用範圍」的斷言

第三章的核心儀式是**「取得資料 → 選一句沒有超出資料的範圍 → 斷言才成立」**。A1、A2、A3、S1、S4 全部走 `setDossierScope`，錯選過強版本會留下刪改痕跡再回選。

**只有 A4 和 A5 是由 `alignDossierPapers` / `transformDossierPapers` 直接發的。**

而劇本架構 §五 明文要求 A4 要有自己的限定句：
> 正確後，A4 候選浮出。玩家點擊並選定限定句：
> 「**同號鼓點只證明兩張紙記的是同一事件與時刻；尚未說明如何互換位置。**」

**這句限定句在 runtime 不存在。** 於是第三柱在概念高潮處，脫離了全章一以貫之的儀式——玩家做完最抽象的一步，反而是唯一不用說明「這一步只能支持到哪裡」的一步。

#### 建議（P1）

引擎端 3 行、UI 端約 20 行，**不需要寫任何新內容**：

1. `setDossierP3Premise` 的 `step === "source"` 分支：`p3.question = false; p3.concept = false;`
2. `alignDossierPapers` 開頭加 `if (!p3.question || !p3.concept) return err(state0, "dossier-p3-premise-required");`，並刪掉它自己那兩行 `= true`
3. UI 補兩個分支：
```js
if (!db.p3.source)        { /* 既有 */ }
else if (!db.p3.question) { /* 新增：三選一 */ }
else if (!db.p3.concept)  { /* 新增：三選一 */ }
else if (!db.p3.aligned)  { /* 既有 */ }
```
4. （較大，可延後）替 A4 補一個 `setDossierScope` 拍，限定句直接用劇本架構 §五 的原文。

## 三、其他發現

### 🟡 N2｜規格書要求的「逐拍讀懂兩張紙」前置消失了

功能規格 §四 R-REF3：
> 「UI 起始把兩張紙**上下分開，不透明疊合**……玩家**須依序讀 0–3 號鼓點**，同一拍在上下兩張紙同時亮起。」

R-SHIP3-02 動作契約：
> `inspectRecordBeat()`｜前置：G3｜「依序亮起 0→1→2→3 號鼓點；**讀完四拍才可進時間配對**」
> `alignRecords(pair)`｜前置：**G3 且四拍已讀完**

舊 API（`inspectRecordBeat` / `alignRecords`）還留在 engine3，但**新的 dossier 流程沒有等價的前置**。`alignDossierPapers` 只要求 `p3.source`。

**敘事後果**：玩家在還沒真的看懂「岸紙每一拍記兩個東西（石頭與桅杆），船紙只記一個」之前，就被要求把它們對齊。**換算因此變成一個沒有前提的操作**——這與 N1 是同一個病灶的兩面。

規格書還特別設計了錯誤演出：
> 「錯把終點或不同號鼓點當成同一時刻時，**先顯示 `2 ≠ 3` 的可見後果**，再提示時間不一致。」

runtime 的錯誤回應是純文字（維達爾：「最後一點不是同一時刻。你看，中間的鼓號全對不上。」）——**話說了，但沒有讓玩家看見那個錯配**。而同一章的彗星式「錯誤留下可見痕跡」在別處是有做的（第四章的彗星折角、第三章的錯紙保留）。

**建議（P2）**：在 align 的錯誤回饋裡，把被錯配的兩個鼓號在兩張紙上同時高亮（例如岸紙 2 號 ↔ 船紙 3 號連一條紅線）。純 UI，成本低，而且規格書已經指定了。

### 🟡 N3｜最有意思的取捨全部鎖在 `explore` 模式

`chapter-ui.js` 的設定列是逐任務條件式渲染的（**這點做得對**，不會出現第四章那種「提供了不該有的選項再偷偷覆寫」）。但結果是：

| 設定 | 何時可選 |
|---|---|
| 怎麼放手 | `reproduce`、`explore` |
| 船速怎麼記 | `reproduce`、`explore` |
| 位置由誰記 | `reproduce`（只有 deck/shore）、`explore` |
| **鼓打多快** | **只有 `explore`** |
| **怎麼加槳／收槳（力度）** | **只有 `explore`** |
| **換哪一艘船** | **只有 `explore`** |

`explore` 是**五輪引導任務全部完成之後**才會進入的狀態。

所以我在程式盤點裡評為「全章最好的取捨設計」的那一項——**快鼓 → 讀值誤差 0.12 → 必然未分類 → 白花天數**——絕大多數玩家不會遇到，因為進入 explore 時他已經拿到所有需要的斷言了。同理，「換船→桅高→偏移量」那個由玩家資料長出來的誘答，也要玩家主動多花天數借船才會出現。

**這不是 bug，是節奏取捨**（引導期先教單變因是對的）。但敘事上有點可惜：**整章最能讓玩家感覺「我的工具選擇會影響資料品質」的那一課，被放在課程結束之後。**

**建議（P2）**：在 `steady` 或 `speed` 任務開放 `beatBand`（這兩輪本來就要求 `speedRecord === "beats"`）。任務卡的 hint 已經寫好對應文案（「不是時間不等，而是觀察者來不及每次都把位置點得準」）。讓玩家在引導期至少踩一次「工具選錯 → 紙變成未分類 → 白花一天」，`explore` 的自由度才會有意義。

### 🟢 N4｜抽象概念全部錨在實物上——這一點明顯優於第四章

第四章的落差之一是「距離平方」在 D1-2 要用、生活類比（磁鐵）在 D4-1 才來。第三章沒有這個問題，因為**它的抽象概念全部綁在看得見的東西上**：

| 抽象概念 | 錨點 | 出現位置 |
|---|---|---|
| 共同運動 | 石頭離手前就跟著船走 | `C0-2/n3` 伽桑狄直接講 |
| 對時 | **一面聽得見的鼓**，同一號＝同一時刻 | `C0-2/n9` 先當「舊紙缺什麼」出現 |
| 參考物 | 「我沒有離開過岸」／「我沒有離開過船」 | `cabin>dual` 過場橋 |
| 換尺 | 岸上從**繫船柱**量、船上從**桅腳**量 | 設定列的選項說明 |
| 證據邊界 | 舊紙上那個**空白的船速欄** | 貫穿全章，`steady>speed` 用「敲了兩下」收束 |

**沒有一個概念是先丟抽象再補類比的。** 唯一沒有實物錨的是「未分類」這個狀態本身，但它是認識論狀態不是物理量，而且 `C0-2/n9` 已經用「沒寫」「連第二回都沒有」鋪過。

### 🟢 N5｜沒有第四章那種「順序顛倒」

我特別檢查了第四章 `D0-2/c0` 那種「選項引用了尚未出現的道具」的模式：

- `reproduce` 任務的位置記錄選項是 `["deck","shore"]`，**不提供 `dual`**——因為雙紙要到站 5 才登場。引擎裡雖然有 `if (draft.positionRecord === "dual") draft.positionRecord = "shore";` 的保險，但 UI 根本不給這個選項，所以玩家不會遇到「我選了卻被偷改」。
- `speed` 任務不提供實驗按鈕（`runDossierExperiment` 直接回 `dossier-use-existing-comparison`），任務卡也明說「不用再跑一趟」。
- 每個鎖定的任務都有一段明文說明（例如 `speed`：「這一輪只改船的狀態。船、石頭、放手方法、鼓拍和記錄方式都不變」）。

**「不給不該有的選項，並說明為什麼這一輪被鎖住」——這是第四章 `D4-1` 順序問題的正解，第三章已經做到了。**

## 四、優先順序

| 優先 | 項目 | 性質 | 成本 |
|---|---|---|---|
| **P1-A** | **恢復第三柱的 question／concept 兩個判斷拍**（N1） | 鋪陳三次的問題沒有被問 | engine 3 行 + UI ~20 行，**內容全都寫好了** |
| **P1-B** | 替 A4 補上劇本架構 §五 指定的限定句（`setDossierScope` 拍） | 全章唯一脫離「選範圍」儀式的斷言 | engine ~25 行 + UI ~15 行 |
| **P2-C** | align 錯誤時把錯配的鼓號在兩張紙上高亮（規格 §四已指定的「可見後果」）（N2） | 錯誤有話說、沒有畫面 | UI ~15 行 |
| **P2-D** | 在 `steady` 或 `speed` 開放 `beatBand`（N3） | 讓最好的取捨在引導期就被遇到 | UI 1 個條件 + 引擎解鎖 |

**若只做一件事：P1-A。** 它的成本最低、內容已經存在、而且它修的是第三章目前唯一一處真正的敘事斷裂——**一個被三段台詞慎重立起來的問題，在玩家要開口的那一刻被系統自己回答掉了。**

## 五、給第四章的一條建議（反向借用）

第四章 `D1-1/ok2` 的修法，第三章有現成範本：

1. **概念的引入順序**：讓「拍」先在「這張紙缺什麼／這件事還不能算」的脈絡裡出現一次，再在「你要決定」的脈絡裡使用——就像第三章的「鼓點」在 `C0-2/n9` 先當缺項出現。
2. **站與站之間補一段 NPC 演出的因果橋**：第三章的五段 `ship3SayMissionBridge` 平均八句話，就完成了「上一站結果 → 對手的反應 → 下一站為什麼必要」。第四章目前完全沒有這一層，所有銜接壓在單句台詞上，`ok2` 的懸空就是這樣來的。
3. **任務卡的三欄式**（`dialogue` 上一輪留下什麼／`goal` 這次要做到什麼＋進度／`hint` 本輪檢核）：第四章的 embed 只有一行 hint，把三件事擠在一句 55 字的公文裡（見《第四章實驗台程式設計盤點》A-5）。**這一層直接照抄第三章即可。**
