# 《發現之前》第三章實驗台程式設計盤點——三方交叉驗證彙整報告

**日期**：2026-08-03
**性質**：唯讀程式與互動設計審查，均未修改 runtime。
**方法**：claude、codex 各自獨立通讀 `engine3.js`、`chapter-ui.js` 第三章段落及兩份 spike；codex 並以 Node 直接重跑引擎驗證。
**訂正**：第三章實際內容是 1640 馬賽・伽桑狄與維達爾船長的船上落石實驗，不是伽利略比薩斜塔（那是第一章）。

**總裁決（claude／codex 高度一致）**：**第三章的物理模型、證據閘門與狀態完整性明顯優於第四章，第四章的兩個病灶（操作被丟棄改查表、封存開獎同函式完成）這裡都沒有。** 但存在另一種問題：**「第三柱」（雙紙對時／換尺）的判斷被壓縮成選答案名稱，玩家沒有真的逐拍操作**，加上兩處潛伏的資料/狀態風險。

## 一、claude 與 codex 交叉confirm的核心問題：第三柱（G4／P3）判斷被繞過

**兩人各自獨立盯上同一個系統的不同層面，合起來是完整的問題全貌：**

### claude 的角度（F2）：兩個判斷步驟寫好了但從未顯示給玩家
`setDossierP3Premise` 在玩家**只選了來源**時，就把後兩步 `p3.question` 與 `p3.concept` 直接設為 `true`；UI 只走「選來源→對鼓點→換原點」，**這兩題在 runtime 永遠不會出現**。但選項、玩家台詞、NPC 反駁全都已經寫好躺在 engine3.js 裡（例如「先確定兩張紙記的是同一時刻」✓ vs「先決定誰比較可靠」✗，維達爾船長的反駁台詞也寫好了）。**修復成本極低（引擎3行+UI約20行），不需要寫任何新內容。**

### codex 的角度（P0-1/P0-2）：即使顯示出來的步驟，也只是選答案名稱
codex 用 Node 實際重跑確認：UI 只給三個按鈕（「整張紙只平移一次／每拍扣掉桅杆當拍的位置／旋轉紙」），選中正確答案後，`transformDossierPapers` 直接呼叫 `dossierDualTransformData` 一次算完全部點、容差與殘差——**玩家沒有逐拍操作，只是點對了名字**。而且**選錯也不會產生錯誤預覽圖**（`alignDossierPapers`／`transformDossierPapers` 選錯時只寫 attempts，overlay 畫面不變），違反設計文件明確要求的「錯誤要留下可讀爛圖」。

**合起來看**：第三柱從「先確認同一時刻」到「逐拍換算」整條判斷鏈，**在 UI 層要嘛整段隱藏（claude發現）、要嘛壓縮成單選題且錯了也看不出哪裡錯（codex發現）**。這是本輪跨兩位獨立審查者交叉confirm、且都標為最高優先（claude:P1最高優先／codex:P0）的問題。

**codex 建議修法**：保留 `dossierDualTransformData` 作最終驗證，但 UI 改成「移動尺」或兩欄紙帶，玩家逐拍把岸紙桅杆點拖到0（或用減法槽），每完成一拍才畫出該拍換算點；四種典型錯法（終點誤配、同高度交叉、只平移一次、旋轉紙）都要各自產生可辨識的錯誤預覽圖。

## 二、兩處潛伏狀態風險（各自獨立發現，不同機制）

### claude F1：`judgeDossierBlind` 會刪掉玩家六張船艙紙（潛伏，UI目前碰不到）
```js
d.blind.records = clone(DOSSIER_CABIN_RECORDS);   // 只有2筆，id是"C-dock"/"C-steady"
```
但驗證要求 ≥6筆、id需符合 `/^C\d+$/`——`"C-dock"` 不符合該 regex，**一旦被呼叫，玩家做過的六趟紀錄全部消失且永久無法驗證成立**。claude 已 grep 確認 `chapter-ui.js` 目前完全沒有呼叫它，正常遊玩碰不到，故評為 P1（潛伏）而非 P0（線上壞掉）——但這是本次唯一會「刪玩家資料」的東西，存檔遷移／未來UI接線都可能踩到。

### codex P1-1：雙視角設計承諾只存在 UI 記憶體變數，引擎未強制
`ship3DualDesignReady` 只是 `chapter-ui.js` 的模組變數，`engine3.js` 的 `designCommitments` 沒有 dual 欄位；合法引擎流程可以在完全沒有這個「設計判斷」的情況下直接生成正式雙紙紀錄。**codex 精確標示風險層級**：正常 UI 目前仍會要求玩家作答，一般玩家不會直接碰到這個漏洞，**風險在契約與存檔層**（重整頁面會讓這個純UI旗標遺失，且未來測試/遷移無法證明這個設計判斷真的發生過）。

兩者都指向同一類根因：**關鍵判斷用臨時記憶體/簡化驗證代替正式狀態機**，建議一併處理、以此為戒防止未來第四類似案例。

## 三、其他確認問題

| 站 | 問題 | 發現者 |

| 走穩三回 | 導引鎖會覆寫玩家草稿設定（例如玩家選 `brake`，引擎強制改回 `steady`），連做三回直接收卷——codex：「這是後期CR為保證物理鏈的有意收斂，不建議整個移除，但應改成玩家親手完成『複製上一組，只改一項』」 | codex（claude 也提到船艙站配置零作用是同類問題） |

## 四、做對的地方（重構時不要動，優先參考給第四章用）

- **`dossierMotion` 是全系列最完整的可組態物理模型**：船隻→桅高→√(2h/g)＋硬加速度、力度帶、放手法Δv序列、鼓速→dt與讀值誤差，零RNG可重現（claude）
- **快鼓是有標示的真取捨**：`error 0.12 > 0.08` 必然未分類、白花天數，但 `quality` 字串事先寫明並顯示在原紙上——claude：「這正是第四章缺的『失敗有資訊、有代價、但事先講清楚』」
- **範圍誘答由玩家自己的資料生成**：「桅高決定偏移」只在玩家真的測過≥2艘船、且資料呈現單調趨勢時才出現，誘答從玩家自己的資料裡長出來（claude：「比第四章任何誘答都高明」）
- **岸上/船上雙視角動畫的物理尺度控制**：船上視角固定約8公尺甲板尺度，避免把0.7公尺偏移誇張成飛出船外（codex）
- **動畫與量測誤差分離**：理想運動用動畫呈現，人為讀值誤差只留在原紙，沒有把誤差演成物體轉彎（codex）
- **原紙不清空、質疑釘可帶回船**：失敗是下一輪實驗設計的輸入，不是扣血重來（codex）

**claude 給第四章的建議**：「第三章的 `dossierMotion`（真運算）+ `dossierSelectedSourcesCheck`（設計檢查）這一組，就是第四章 D2-1/D3-1 要修回來時的現成內部範本，不必外求。」

## 七、驗證邊界

- codex 已用 Node 直接重跑主流程驗證上述所有發現；`npm test` 142/0 全過，但兩人一致強調**這只證明狀態契約與存檔一致，不能證明操作有趣或代理權已完成**。
- 兩方均未做真人瀏覽器/手機實機驗收。
- codex 特別指出：第三章的分段引導式流程「不是偶然退化或bug，而是後期CR為保證物理鏈與舊存檔相容的有意收斂」——**修法方向應是「交還每站一個關鍵判斷」，不是推翻整個分段設計**。
