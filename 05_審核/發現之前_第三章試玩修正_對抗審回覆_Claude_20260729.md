## A 級(1 條)

### A-1|全證據桌讓 p3 出現「玩家沒說話,NPC 卻在回應」+ 回錯對象

**位置**:`src/engine3.js` `setDossierP3Premise()`,`step === "source"` 的 `lastPlayerLine` 查表。

**可重現證據**(node 實跑,把狀態推到 p3 進行中後逐一選證據):

| 玩家選 | 玩家說出口 | NPC 回應 |
|---|---|---|
| **A1 走穩三回岸紙** | **★ 空白 ★** | 艾蒂安:「**舊紙和船艙紙**都不是這一趟的兩個觀察位置。」 |
| **S1 徒手放石散布** | **★ 空白 ★** | 同上 |
| cabin-pair | 「我先出示封閉船艙…六張對照紙。」 | 同上 ✅ |
| old-paper | 「我先出示船長八年前那張只有落點的舊紙。」 | 同上 ✅ |
| dual-papers | 「我先出示同一趟…兩張原紙。」 | (正解路徑) |

**因果風險**:本輪把證據桌從「三個設計者挑好的選項」改成**攤開所有已取得證據**(A1/A2/A3/A6/S1/S4 + dual-papers:N),但 `lastPlayerLine` 的查表仍只有 `dual-papers / old-paper / cabin-pair` **三個鍵**。新開放的選項落到 `|| ""`。

後果有兩層,**第二層才是真正嚴重的**:

1. 玩家點了證據卡,**對話框裡他沒說任何話**,NPC 卻開口反駁——玩家代理權被抽掉,這正是 Sol 第 3 問要防的。
2. NPC 的固定台詞是「**舊紙和船艙紙**都不是這一趟的兩個觀察位置」。玩家明明遞的是**走穩三回岸紙**,NPC 卻說「舊紙和船艙紙」——**答非所問的變成 NPC**。玩家會合理認為遊戲讀錯了他的操作。

這也讓交接報告第四節的宣稱「**全證據桌的非正解選擇也能留下玩家發言與 NPC 回應**」在 A1/A2/A3/S1/S4 五個選項上不成立。

**直接修法**:`lastPlayerLine` 改為**由 catalog 生成**,不再用固定查表——每張證據卡本來就有 `title`/`condition`,可組成「我先出示〈title〉:〈condition〉。」;NPC 的 `dossierMissing` 台詞也改為引用玩家實際遞出的那張(「〈title〉不是這一趟的兩個觀察位置」)。**同一個修法同時解掉兩層。**

**會失敗的驗證條件**:
- 對 catalog 中**每一個** owned packet 跑 `setDossierP3Premise(s,"source",id)`,`lastPlayerLine` 一律非空;
- 選 A1 時 NPC 回應必須含「走穩」或該卡 title,不得出現「舊紙和船艙紙」;
- 新增契約測試,拔掉生成邏輯要轉紅。

## B 級(1 條)

### B-1|`ship3DossierRecordsForQuestion` 的 fallback 會顯示「不是這一題」的紙

**位置**:`src/chapter-ui.js` `ship3DossierRecordsForQuestion()`:

```js
return records.length ? records : (d.records || []).filter(function (record) {
  return record.filed && record.stage === stage;   // ← fallback:忽略 assertion 綁定
});
```

**因果風險**:本輪新增的「現在判讀的紙」立意正確,但當該 assertion 的 `sourceIds` 尚未建立(或被 sanitizer 清掉)時,fallback 會列出**該 stage 的全部已歸檔原紙**。玩家會在「現在判讀的紙」底下看到**不屬於這一題**的原紙——而這個區塊的全部價值就在於「這一題正在看哪張」。這與 A-1 同源:呈現層擴大了,但綁定層沒跟上。

**直接修法**:fallback 改為顯示明確狀態(「這一題的原紙尚未綁定,請先在卷宗選紙」)而不是塞全部;或至少加視覺標記「未綁定,僅供參考」。
**會失敗的驗證條件**:清空某 assertion 的 sourceIds 後,該區塊不得列出 >0 張紙且不加註記。
