## 一、總裁決

第二章的主因果鏈已成立，而且 B2-4「先押木籌、一次扳閂、逐列看結果」與 B2-5「挑出未實做的紙、寫下邊界、封蠟」是目前全章最成熟的互動敘事：玩家的判斷先留下痕跡，結果可見，錯誤不被抹掉，下一場又會重新使用前一場的紙。這兩場可以作為後續章節範本。

真正的缺口不在「為什麼要做下一個實驗」，而在**玩家做完核心判斷後，故事沒有完整接住那個判斷**：B2-3 的平方根斷言由 system 節點代為歸檔，伽利略只作一般性總結；換球比較則由 UI 與伽利略直接說出結論。B3 辯論雖要求玩家拿證據配對，但 F1 船桅預測在高潮主要作為錯誤選項／跨章債務，缺少一次明確的「這張現在不能用，但正因如此必須留下」的公開支付。

**優先判定**：P0 0 項；P1 3 項；P2 3 項。沒有發現正常玩家路徑會提前看見 H=25 結果的順序顛倒，也沒有發現整場核心判斷被程式完全繞過；但底層引擎允許超前操作，應加一道防禦性守衛。

## 二、審查方法與判準

逐場以同一條鏈檢查：

> 上一場留下的缺口 → 玩家為何現在要判斷 → 玩家實際決定什麼 → 結果如何可見 → 哪個人因此改變／反駁 → 下一步為何非做不可

另用兩條專案既有契約驗收：

1. **玩家責任**：系統可計算讀值，但資料選擇、解讀、主張範圍必須由玩家完成（第二章功能規格 1.1、R-LAB2-04；共用規格 §六）。
2. **斷言接球**：玩家提出斷言後，工作台應收起；玩家把所選資料與有限主張說出口；NPC 必須針對該筆資料回應，再由新矛盾引出下一個實驗（共用規格 §6-1、§6-3）。

本輪不評台詞是否白話，也不重做物理／史實校對；只評敘事因果與玩家判斷是否有戲劇後果。

## 四、主要問題與修法

### P1-1｜B2-3 e2：玩家完成最重要的手動斷言，故事卻由 system 代為收件

**位置與證據**

- `scenes2.json` B2-3/e2（約 870–877）：玩家必須先押 H=25，再選一組紀錄與概念。
- `scenes2.json` B2-3/s1（約 880–892）：只有 system 說「你挑出的那組紀錄與那句話，已經一併記進筆記」。
- `scenes2.json` B2-3/n4（約 895–899）：伽利略回應一般關係，但沒有指出玩家引用的是哪組紀錄、哪兩個倍率，也沒有讓旅人把有限斷言說出口。
- `chapter-ui.js` 約 1605–1634 已正確要求玩家親選完整紀錄與概念；這是有價值的真判斷。
- 共用規格 §6-1、§6-3 明訂：斷言後應離台、玩家說出口、NPC 指名核對資料與範圍、再提出下一問題。

**因果問題**

玩家在程式上完成了全章最重要的資料解讀，但在敘事上只得到資料庫通知。於是「我剛才選的第幾組資料」沒有改變人物對話；刪掉玩家所選引用編號，n4 仍完全成立。這不算核心判斷被程式代做，但算**判斷沒有被故事承認**。

**建議修法**

不改物理流程，只補一個動態簽收拍。若可新增對話佇列，應由 UI 讀 `lawSource` 與該 series 的 4／16／25 讀值：

> 旅人：「我引用第 {lawSource} 組。高度從四格變成十六格，射程大約從 {r4} 變成 {r16}；二十五格的落點也落在我先押的 {prediction} 附近。這張紙只支持：高度放大四倍，射程約放大兩倍。」
> 伽利略：「好，射程這一筆站住了。可它還沒回答另一件事：球往前飛，會不會因此晚一點才往下掉？」

若不能新增節點，至少把 s1 改為玩家出聲，n4 改成針對「第幾組＋四到十六」回應；不要只寫「掉得久，飛得遠」。

**驗收**

1. 玩家所選 `lawSource` 不同，回到故事後顯示的引用編號也不同。
2. 刪掉所選資料後，NPC 台詞會失去指涉，不再是可放諸任何 run 的通用句。
3. 斷言後工作台收起，再由台詞提出「只換球」的新缺口。

### P1-2｜B2-3 e3：換球的資料選擇屬於玩家，物理解讀仍由 UI 與伽利略直接代說

**位置與證據**

- `chapter-ui.js` 約 1636–1665：玩家選一銅一木；成功 callback 直接顯示「同一副骨架——與球重無關，成立。」
- `scenes2.json` B2-3/n6（約 919–923）：伽利略直接總結「銅球這樣彎，木球也這樣彎。重量換了，路沒有換。」
- 玩家確實決定了哪兩組可比較，系統也會拒絕同球、不同裝置指紋、未完成或誤差超限資料；因此不是整段被代做。

**因果問題**

這裡最值得玩家說出口的不是「平方根」第二次，而是控制變因：**哪裡相同、唯一換了什麼、因此能把差異歸給什麼**。現行玩家只配對，系統和 NPC 代替他完成這三步語句。對學習而言判斷仍在；對戲劇而言旅人失去主體。

**建議修法**

比較成功後不要先顯示完整結論，只顯示可觀察結果：

> 「兩組裝置指紋相同；銅球與木球四個落點的最大差異為 {diff}% 。」

回故事後讓旅人完成一句有限判斷：

> 旅人：「兩組只換了球，四個落點仍疊在一起。至少在同球形、同球徑、同一套裝置下，重量沒有改變這條射程關係。」
> 伽利略：「那就別再問哪顆球比較會飛。下一件事更直接：往前飛，會不會讓它晚一點才掉？」

若維持「斷言句只有一個正確選項」的共用規格，可讓玩家只選來源兩組，不另加誘答；但玩家角色必須把由這兩組支持的有限句說出來。

**驗收**

1. 比較成功訊息只陳列差異與固定條件，不先替玩家說「與重量無關」。
2. 劇情台詞明列「同球形、同球徑、同裝置」的範圍。
3. NPC 的下一問明確由這次比較仍未回答的缺口生出。

### P1-3｜B2-5 到 B3-D：船桅 F1 被封存得很好，但公開高潮沒有真正支付這張債務紙

**位置與證據**

- `scenes2.json` B1-2/s1（約 585–593）：F1 明列為待驗預測，不是實驗紀錄。
- B2-5/q1–n5（約 1140–1306）：玩家親手挑出、標記並封蠟，是一個完整認識論動作。
- 功能規格 R-DEB2-01 明定 P3×F3；F1 不得冒充紀錄，可參與複盤與跨章接棒。
- `debate2.json` 的前三柱正解使用 F4、F3、F3；終局三張紙是桌上、遠砲、天空。F1 是進場必需品，也可能成為錯誤配對，但沒有一個必要成功動作要求玩家公開說明它為何不能支付當前主張。

**因果問題**

B2-5 把封蠟做成強烈承諾，玩家自然預期它會在講堂被重新使用。現行高潮真正改變辛普里奧的是三張重排紙；F1 的主要用途留到第三章。這在知識樹上合理，卻讓第二章內的「高潮再用」少一拍：玩家若從未誤選 F1，封袋可能只像通關門票。

**建議修法**

不改 P3 正解，不把 F1 升格成證據；反而應在 P3 或 FR 前增加一次**公開拒用**：

> 辛普里奧：「你們不是還封著一張船桅圖？為何不用？」
> 旅人：（把蠟袋放在桌邊，不拆）「因為袋面寫的是『待驗』。它能提出下一個問題，不能替今天這一柱作證。這一柱我用的是三層門閂留下的三列聲響。」

這是把 F1 當成「欠條」而非「牌」，同時支付 B2-5 與第三章交棒。可用既有 playerCorrect 動態加入，不必改證據配對規則。

**驗收**

1. 玩家必須看見封蠟袋在講堂桌上。
2. 成功路徑至少一次明說 F1 不能支付哪個主張，以及 F3 為何可以。
3. F1 仍保留，不被消耗、不被標成完成船上實驗。

### P2-1｜B2-3 三階段的因果順序在 UI 成立，但底層引擎允許超前完成 H=25

**實測**

以 `Narrative._factory(scenes2, engine2, {})` 建立第二章狀態，停在 B2-3/e1，完成乾淨裝配、雙校準及 H=4／9／16 後：

- `embedReady(state) === true`；
- 直接呼叫 `predictSeries(5)`、`runHeight(25)` 仍成功；
- `embedComplete` 後才進 q1「你看出什麼？」與 n3「二十五格你說多少？」；此時 H=25 已經被看過。

但正常玩家介面不會發生：`chapter-ui.js` 約 1555–1558 在 `stageReady` 為真時隱藏所有額外操作，顯示「額外操作暫停」；約 1366–1368 也明說 25 格會在玩家先說出規律後才開放。因此這是**底層契約缺口，不是現行正常 UI 的敘事 bug**。

**建議修法**

讓 engine／narrative 也知道 embed phase，或在 `labAction` 對 B2-3/e1 阻擋 `predictSeries` 與 `runHeight(25)`。舊存檔若已超前完成，仍允許離開 e1，但 q1／n3 應改呈現為「回看你當時怎麼押」，不能假裝結果尚未發生。

**驗收**

新增負向測試：cursor=B2-3/e1 時，H=4／9／16 後直接呼叫 `predictSeries` 必須得到 phase 錯誤；cursor 進 e2 後同一動作才成功。瀏覽器走正常路徑仍維持 4／9／16 → q1 → n3 → H=25。

### P2-2｜B2-3 q1 的兩個答案物理上近義，但其敘事身分沒有明說

**位置**：B2-3/q1（約 837–860）。

「高度翻四倍，射程翻兩倍」是資料層觀察；「射程像下落高度的開方」是模型層命名。兩者都進 n3，只有後者先揭露 `sqrt`。這不是錯，也刻意容許玩家先用白話看規律；但伽利略的下一句「是嗎？」沒有區分玩家是在報數據，還是在提出模型。

**建議修法**

維持兩項都可走，但使用分支化回應：

- r1 後：「你先看見了倍率。那就用二十五格看看，這個倍率能不能押中下一筆。」
- r2 後：「你給它取了規矩。那就別只靠三筆長得像——用二十五格押一次。」

兩路仍匯流 e2，不必改科學內容。

### P2-3｜B3-D 的入口 hint 一次洩露完整程序，會把公開對決壓回操作清單

**位置**：B3-D/e1 hint（`scenes2.json` 約 1384–1393）。

現行 hint 一次說完「先追問→找破口→放證據→最後三張都留下」。作為救援提示內容正確，但若首次進場就全顯示，它會削弱辛普里奧帶著數據反攻的戲劇性，也讓終局重排的形式提前曝光。

**建議修法**

首次只顯示目的，不顯示流程：

> 「他會把你的證據反過來用。先聽完每一句，再決定哪張紙能回答。」

玩家第一次錯配或主動展開提示後，再顯示目前的完整操作說明。最後三張紙應由敵方數據與前兩柱自然長出，而不是入口先宣布。

## 五、沒有判成問題的疑點

### 1. B1-2 在實驗前先談「保留前行」

這是思想實驗，不是完成證據；runtime 隨即明說「船上的紀錄一筆也沒有」，B2-5 又要求玩家把它封為待驗。它沒有偷換成已證明結論，反而建立第三章債務，應保留。

### 2. B2-1 已說「看見曲線」，會不會洩漏 B2-2？

B2-2 真正要求判斷的是「彎曲從哪一寸開始」，不是「有沒有曲線」。舊抄頁只提供待讀原紙，尺與漏光才完成判斷，因果成立。

### 3. B2-4 的三個單選確認是不是空點擊？

每按一次才揭露低／中／高下一列結果，玩家每次取得新觀察；三列不是同一畫面的重複確認。這符合「一次決策執行總門閂、逐筆讀結果」的共用規格。若實機動畫確實分三拍，應保留。

### 4. B2-5 兩步選擇是否像複習題？

第一步分類「做過／未做」，第二步限制袋面主張，兩步回答不同問題；錯答會回到具名原紙，不只標紅。它是實物化的封存行動，不是同義重問。

### 5. H=25 是否會在 q1 前被正常玩家看見？

不會。雖然底層函式允許，現行 UI 在 e1 三高達標後直接停手。這輪不把它列為玩家體驗 P0，但建議補引擎守衛，避免未來替代 UI 或匯入狀態破壞順序。

## 七、建議驗收案例

1. **正常黃金路徑**：B2-3/e1 只能做到 4／9／16；回故事選 q1 後，e2 才可鎖定 H=25。
2. **斷言來源可見**：選不同 accepted copper series，故事台詞顯示對應引用編號與讀值。
3. **換球主體性**：比較成功後，先看原始差異，再由旅人說出有限結論；伽利略不得搶先下判斷。
4. **F1 邊界**：在 P3 故意拿 F1 配對，回饋必須指出「這是待驗預測」；正確路徑也必須公開說明為何改用 F3。
5. **B2-4 預判完整性**：三個預判都不改結果、不扣信譽，原句保留；三列逐列顯示。
6. **B2-5 封存完整性**：完成紙不能被封成待驗；船桅紙不能被升格為完成紀錄；錯誤痕跡保留。
7. **辯論提示漸進**：首次不預告終局三紙排法；第一次失敗後才顯示操作級提示。

## 八、值得保留的設計

1. **B1-3 對手吃掉上一章勝招**：辛普里奧承認同落，卻指出「你答的是落，我問的是飛」，是跨章對手升級的有效範本。
2. **B2-2 尺與漏光**：錯答不是扣分，而是物件本身留下可讀反證。
3. **B2-4 單次總門閂＋三列逐拍**：先承諾，再一次啟動，最後逐筆讀結果；操作與認知節拍一致。
4. **B2-5 蠟封**：把證據狀態做成可見實物，玩家親手承認「不知道」。
5. **B3-6 劃掉但仍看得見**：改掉的是推論，不是抹掉對手或資料；辛普里奧仍有尊嚴。
