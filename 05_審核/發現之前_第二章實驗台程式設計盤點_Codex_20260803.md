## 一、總裁決

第二章目前最接近「完整探究遊戲」的是彈射工坊：裝置快照、連結測量、先押 H=25、兩道資料門檻、不可刪紀錄、換球比較與辯論再利用都已存在。它不是只有滑桿與答題，球、桌沿、門閂、沙盤、射程與失敗散布確實形成一套可讀物理系統。

但正式程式仍有一個會直接教錯證據規則的 **P0**：`compareBalls()` 沒有檢查兩組 series 的 `accepted`／預測誤差。玩家可故意把木球 H=25 預測填成 100，得到 `accepted=false`，介面卻仍可用該木球組與銅球組比較，取得「與球重無關」並合成 F2。Node 已重現，且這是正常 UI 可走到的路徑，不是只有改存檔才辦得到。

另有四項高槓桿 P1：

1. 換球比較自動替玩家選好第一組銅球與第一組木球，按鈕一按就由系統完成核心證據選擇，違反「學者自由選資料」與「玩家親自選資料」的分工。
2. `compareBalls()` 只比 fingerprint，不比 `apparatusRevision`；玩家把桌沿拆換再裝回原件，兩組 revision 不同仍可宣稱「只換球」。
3. open series 期間 UI 仍可校準；即時裝置顯示已校準，當前 series 卻繼續使用開始時鎖住的舊 profile／fingerprint，畫面與資料真值互相矛盾。
4. `sanitizeImport2()` 不重算 F2，也不核對 F2 的 series／事件來源；零筆 series、游標還在 B0-1 的存檔，只要自稱 `law=true`、`ball=true`、`evidence.F2=true` 就會被接受。

其他底層缺口包括：預測可覆寫、H=25 可在對話提問前超前完成、`labAction` 可在任意場景取得 F2，且這些狀態仍可通過匯入。正常 UI 已擋住其中大部分，故不應誤報成一般玩家必遇 bug；但它們證明目前「劇情相位」只藏按鈕，沒有形成可信的狀態契約。

遊戲性方面，B2-2 的「持尺」仍是一個二選一文字題，B2-4 的三層門閂中間兩拍是逐列確認按鈕，B2-5 的封蠟是文字選單；它們各有清楚概念，但沒有把尺、木籌、門閂、三列墨點與蠟袋變成玩家親手操作的持續物件。三支柱辯論和三紙重排反而比這幾站更有參與感，因為錯配會留痕、支柱會破、錯排會保留並要求整版修正。

**建議裁決**：可形成性試玩，但 F2 換球守衛必須先修。若要宣稱第二章已達「玩家出判斷、系統出結果」，還需取消比較預選、封住 mid-series 校準與相位繞過，並把 B2-2／B2-4／B2-5 從文字選項升為低成本物件操作。

### 2.2 Node 實測

本輪直接呼叫正式匯出的純函式 API，未手改 source：

1. 正常完成銅球系列；木球前三點乾淨但把 H=25 預測填 100，使 `accepted=false`；再呼叫 `compareBalls()`。
2. 銅球完成後，把打磨桌沿換成毛邊、再換回打磨桌沿，完成木球系列；比較不同 `apparatusRevision` 的兩組資料。
3. 在 series 已開始且已有 H=4 後才校準 `releaseZero`，比較 live apparatus 與 locked series 的 profile／fingerprint。
4. 對同一 open series 連續呼叫兩次 `predict()`，確認預測能否改寫。
5. 在 B2-3/e1 的三個高度完成後，直接預測並跑 H=25，確認底層能否越過 q1／n3 的劇情提問。
6. 從 B0-1 初始游標直接完成整套彈射 lab actions，確認能否提前取得 F2，並送進 sanitizer。
7. 建立零筆 series、游標仍在 B0-1、但自稱持有 F2 的存檔，送入 `sanitizeImport2()`。

## 三、法源分工是否落地

法源要求三件事：系統留下可追溯資料、玩家親自選資料與限制主張、NPC 對玩家實際提出的主張作具體反應。現況如下：

| 層次 | 現況 | 判定 |
|---|---|---|
| 資料生成 | fixture、profile、fingerprint、series、預測與失敗紀錄完整 | 強 |
| 玩家承諾 | H=25 先押後看成立；B2-4 也先押木籌 | 中上 |
| 玩家選資料 | F2a 有空白 placeholder；F2b 卻自動選好第一銅／第一木 | 不一致 |
| 玩家形成主張 | F2a 選資料＋概念；F2b 一按即由系統宣告「與球重無關」 | 中偏弱 |
| 可見後果 | 彈射軌跡、沙痕數字、誤差雙門檻、辯論破柱清楚 | 中上 |
| 狀態真值 | F2b 漏 accepted/revision；匯入可憑空自稱 F2 | 弱，需先修 |
| NPC 具體反應 | 辯論很強；工坊成功後多是固定結論，未引用玩家選的實際 series | 中 |

核心不是「系統不能算」。系統應該算誤差、軌跡與比例；不能代做的是**哪張紙能被引用、兩張紙是否真的只差一個變因、以及玩家願意把話說到哪裡**。

## 五、P0/P1：會改變證據真值的問題

## 5.1 P0-1｜不可用的木球系列仍可取得 F2b

### 程式原因

`engine2.js:211-236` 的 `compareBalls()` 檢查：

- 一銅一木；
- fingerprint 相同；
- status complete；
- 前三點是單值；
- `shapeError <= 0.12`；
- 兩球前三點差異 <=3%。

它**沒有檢查 `a.accepted`／`b.accepted`，也沒有檢查 predictionError**。這與規格 R-LAB2-05「雙模式都必須完成 copper accepted series 與 wood accepted series」直接衝突。

### Node 重現

```text
copperAccepted = true
woodPrediction = 100
woodAccepted = false
woodPredictionError = 18.96007984031936
compareOk = true
ballGranted = true
diffs = []
```

這不是只有 raw API 才能觸發：UI 紀錄簿會把 complete 但不可用的木球組放進比較下拉；又會自動選好第一組木球，因此一般玩家只要按「比較兩組・提出斷言」就能拿到錯誤證據。

### 玩家錯誤理解

前一刻介面說「這組紀錄不可用：預測偏差 ✕」，下一刻又用同一組資料宣告「與球重無關，成立」。玩家學到的是：預測承諾其實不重要，只要前三點看起來像就能引用。

### 建議修法

在 `compareBalls()` 先加：

```text
if (!a.accepted || !b.accepted) diffs.push("至少一組未通過完整認證");
```

UI 對應回饋：

> 這兩組裡有一組沒有同時通過形狀與預測門檻。先重做或改選兩組「可用」紀錄。

比較下拉仍可顯示不可用組，讓錯誤資料可見；但標示「不可用」，且送出必須被引擎拒絕。不要只在 UI filter 掉，否則底層真值仍破。

### 驗收

1. accepted copper + rejected wood → `ok=false`、F2b 不變。
2. rejected copper + accepted wood → 同上。
3. 兩組 shape 通過但任一 predictionError >12% → 同上。
4. 兩組 accepted 且其餘五守衛成立 → 才授予 F2b。
5. 正常 UI 顯示拒絕原因，不出現「與球重無關，成立」。

## 5.2 P1-1｜裝置拆過再裝回，revision 不同仍被算成「只換球」

規格要求兩組裝置快照相同，包含 apparatusRevision 對應。現在 fingerprint 只含五個 partId 與兩個 calibration boolean；`compareBalls()` 不比 `apparatusRevision`。

### Node 重現

1. revision 3 完成銅球。
2. 打磨桌沿 → 毛邊 → 打磨桌沿，revision 變成 5。
3. 完成木球；兩組 fingerprint 字串重新相同。

```text
copperRevision = 3
woodRevision = 5
fingerprintsEqual = true
compareOk = true
diffs = []
```

### 影響

玩家實際動過裝置，卻能用兩組資料聲稱唯一差異是球重。確定性 fixture 恰好給同值，所以目前不會數字爆炸；但證據設計的「只改一件事」被偷換成「最後看起來裝回一樣」。

### 建議

- 若法源維持嚴格同一次裝置快照：比較 `apparatusRevision`，不同就拒絕。
- 若設計者認為「拆裝後重新校準也可比較」，則必須修規格與 UI 措辭，改成「零件與校準狀態相同」，不能再說「只換球」。本作目前的教學目標明顯偏前者。

驗收：revision 不同時，即使 fingerprint 相同，也回「兩組中間動過裝置；請找同一版裝置只換球的紀錄」。

## 5.3 P1-2｜open series 期間可校準，live 裝置與 locked series 分裂

`replacePart()` 會拒絕 open series；`calibrate()` 不會。UI 左頁校準鈕在 series 進行中照常存在。

### Node 重現

在 releaseZero 尚未校準時開銅球 series、先跑 H=4，再校準：

```text
calibrate error = null
liveCalibration = true
lockedProfileBefore = speedDrift
lockedProfileAfter = speedDrift
lockedFingerprintAfter = ...#z0s1
liveFingerprint = ...#z1s1
```

畫面左頁會顯示「已校準」，右頁同一 series 後續卻繼續跑 `speedDrift` 舊 fixture。玩家沒有任何可見提示說「這次校準只對下一組生效」。

### 建議

採與換件一致的單一規則：open series 期間，校準也回 `series-open`；玩家先完成或放棄本組。這比允許「校準只影響下一組」更清楚，也符合 snapshot 的認知模型。

驗收：open series 呼叫 calibrate 不改 state、不耗天；UI 按鈕 disabled 並顯示「先完成或放棄這組」。

## 5.4 P1-3｜存檔可憑空自稱 F2，sanitizer 不驗實驗來源

`sanitizeImport2()` 的註解說 fixture 成敗要由 Engine2 重算，但實際只驗 series 欄位型別，沒有重算 profile、fingerprint、readings、accepted、F2a/F2b，也沒有核對證據事件。

### Node 重現

初始存檔保持：

```text
cursor = B0-1/n0
series = []
lab.evidence.f2 = { law:true, lawSource:99, lawConcept:"sqrtScale", ball:true }
evidence.F2 = true
```

送入 `sanitizeImport2()`：

```text
ok = true
reason = null
```

另一條實測：從 B0-1 直接用 `labAction()` 完成 F2，游標完全沒進 B2-3，產生的 state 同樣通過 sanitizer。

### 建議

P1 最小修復：

1. 以 Engine2 重算每一完整 series 的 profile、fingerprint、讀值／judge 結果；不信匯入檔自稱 accepted。
2. `law=true` 必須找到 `lawSource`，且該 series 是 accepted copper、concept=sqrtScale。
3. `ball=true` 必須能從至少一對符合修正後 `compareBalls()` 的 accepted copper／wood series 重建。
4. `evidence.F2=true` 必須等於 `law && ball`，且有唯一 runtime evidence event。
5. cursor 尚未到合法里程碑卻已有 F2 時拒絕或退回，而不是替玩家補故事。

若要避免把 sanitizer 變成第二套引擎，應在 Engine2 暴露 `_auditSeries()`／`auditF2()` 純函式，runtime 與 sanitizer 共用。

## 六、P2：正常 UI 已擋，但底層契約仍可繞過

## 6.1 預測可覆寫

Node 對同一 open series：

```text
predict(5)   → prediction = 5
predict(100) → prediction = 100, error = null
```

正常 UI 在 prediction 已存在後只顯示「放球・25 格」，沒有改寫入口，所以一般玩家目前無法作弊。但 API 沒有「預測已鎖」守衛，替代 UI、舊頁面或未來重構都可能把漏洞重新露出來。

建議：`predict()` 若 prediction 已是有限數，回 `prediction-locked`。若要讓玩家修正輸入錯字，應在送出前改，送出後不得改。

## 6.2 H=25 可在劇情 q1／n3 前超前完成

已知且本輪重現：e1 完成 H=4/9/16 後，raw API 可立即 `predict(5)`、`runHeight(25)`，series 變 complete accepted。正常 UI 因 `stageReady` 暫停額外操作，要求先回故事回答 q1，再由 n3 問 H=25，因此一般玩家不會遇到。

問題在於 Engine2 不知道本輪是「只收前三點」還是「開放預測」。建議由 narrative 增加第二章相位守衛，而不是把場景知識塞進物理引擎：

- e1 只允許 place／replace／calibrate／begin copper／H4-16／abandon。
- e2 才允許 predict／H25／assertLaw。
- e3 才允許 begin wood／完整 series／compareBalls。
- SC-R1 只允許指定的修復動作。

## 6.3 `labAction()` 可在任意場景取得 F2

從初始 B0-1/n0 直接呼叫完整彈射動作：

```text
cursor 仍為 B0-1/n0
lab.evidence.f2.law = true
lab.evidence.f2.ball = true
evidence.F2 = true
eventLog 也寫入 evidence F2
sanitizeImport2 = ok
```

正常 UI 不提供按鈕，因此這是邊界防禦缺口，不是當前玩家路徑 bug。修法同 6.2：在 narrative 對 ch2 action×scene/node 建白名單；sanitizer 再核對里程碑。

## 七、逐站玩法與改善

## 7.1 B1-2 船桅思想實驗：保留低顆粒，不必硬做模擬

這一站沒有資料，作用是把「球離手後仍保留原前行」變成一筆待驗預測。探索模式選落點，學者模式再說岸上會看到彎路。它不是證據，後面也會封進「待驗」蠟袋，分工正確。

風險是錯答回饋容易變蘇格拉底式概念題，而非物件推理；但另有台詞審查處理，不需為了遊戲感另造一套船模擬，第三章才是付這筆帳的地方。

**建議 P3**：讓船與桅杆的示意圖持續留在紙上，玩家移動「落點問號」而非按文字選項；結果仍不得被畫成實驗紀錄。成本低、邊界清楚。

## 7.2 B2-2 墨跡尺線：文字說「持尺」，程式沒有尺

現況只有一張墨跡圖與 choice：從第一寸就彎／前段直後段彎。錯答後伽利略替玩家把尺貼上去，再回同題。物理判斷清楚，但最關鍵的量測動作由 NPC 在錯答後代做。

**建議 P2**：在現有 focus visual 上疊一把可拖／可旋直尺：

1. 玩家把尺貼到軌跡起點。
2. 程式只回「尺與墨線哪裡開始漏光」，不亮正誤。
3. 玩家再選「有直段／從起點就彎」。
4. 保留玩家最後一次尺的位置作為可見紀錄；錯位會留下「只貼到中段」的爛圖。

驗收：刪掉伽利略結論台詞，玩家仍能從尺與漏光看出核心差異。

## 7.3 B2-3 器材踏查與裝配：條件映射好，解法太容易背

### 做對的事

- 器材亮點先說每件控制什麼，不直接顯示內部 profile。
- 固定骨架不假裝成選項；只有 release／edge／rangeBed 真能換。
- 故障 profile 有可辨識失敗：區間太寬、落點散、速度漂移。
- 所有錯誤 series 永久留在紀錄簿，沒有「重來洗掉」。

### 遊戲性限制

- 零件名「門閂／手放」「打磨／毛邊」「耙平／目測」與 detail 已強烈標出優劣；首輪仍有理解，重玩很快退化成選乾淨名詞。
- fixture 完全確定；知道正配後沒有新的判斷。
- 失敗要花完整 series 才看清，若玩家先選多重故障，支配序只顯示最前一個，修一項後才冒出下一項，容易感覺被連續收過路費。

**建議 P2**：不要隨機化答案，也不要把零件名稱故意藏成 A/B。新增一次不耗天的「試放三球」只顯示可觀察症狀，不產生正式數據：

- release：三次離桌速度是否重疊；
- edge：方向扇形是否散；
- rangeBed：落點是一點還是一段區間。

玩家仍要選零件與校準，正式 series 才能認證；但第一次錯誤不必付四天才知道器材根本不適合。

## 7.4 連結測量與 H=25：核心循環應保留

這是本章最成功的程式設計：H 順序鎖定、前三點先出、預測先封、H25 後才看到形狀與預測雙門檻。動畫同時顯示軌跡、H、射程與沙痕，資料與物件有對應。

需修的是契約而非玩法：預測鎖、相位鎖、mid-series 校準鎖。另建議把成功訊息從純百分比改成「你押 5.0，沙痕 5.0；前三點也在同一條骨架上」，先說物理，再把誤差百分比留給展開詳情。

## 7.5 F2a 平方根斷言：資料選擇成立，概念選項仍可試錯

F2a 做到規格最重要的一點：series 與 concept 都有 placeholder，不替玩家預選。錯概念不扣資源，回饋要求比較 4→16 與 2→4，屬資料導向。

但乾淨首輪通常只有一組 accepted copper，資料來源選擇近乎形式；概念是三選一且可無限試。成功後完整主張由 UI/NPC 代說。

**建議 P2**：不必加算式輸入。讓玩家從所選 series 親手框兩列，例如 H4/R2 與 H16/R4，再把兩個「×」籤拖到 4 與 2；系統據此生成一句主張。這會把「選概念」從文句辨認變成資料操作，也符合「玩家選資料，系統可幫忙算」。

## 7.6 F2b 換球比較：目前玩家只按確認

除了 P0/P1 守衛，UI `firstCopper`／`firstWood` 會直接替兩個下拉選好第一對。若只有黃金路徑兩組資料，玩家不需讀紀錄，畫面已顯示「✓ 只換了球」，按下即由系統說「與球重無關，成立」。

這違反規格「學者自由選資料」；也削弱全章最重要的控制變因判斷。

**建議 P1**：

1. 兩個下拉都加入空白 placeholder，任何模式都不預選 series。
2. 探索模式可以預選「下一組使用木球」，不能預選最後要引用哪一組木球資料。
3. 玩家選好後，先顯示差異清單：球種／零件／校準／revision／資料門檻。
4. 玩家再勾「我主張這兩組只改了球」，送入引擎。
5. 成功畫面用共尺疊圖顯示銅／木四個沙痕，讓兩組軌跡與落點同時出現；不要只回一句成立。

## 7.7 B2-4 三層門閂：有預測與限界，缺真正的事件手感

### 做對的事

- q1 先壓木籌，結果後揭露。
- 三個高度逐列出現，避免系統一次吐完整答案。
- q4 要把「分不開」寫成有限主張；虛構延遲會扣信譽且留痕。
- focus visual 在高層與結論時出現，可協助看等時位置。

### 問題

1. q1 的第三項「沒有紀錄，現在不能押結果」讓玩家可以拒絕作預測，卻仍進入 q2；下注鎖被自己開了一個逃生門。
2. q2 只有「扳下總門閂」一個選項；np1、q3 又各只有確認按鈕。程式沒有真正的雙球運動、聲響時序或木籌與結果對照。
3. 玩家選過哪個預判只留 generic choice event，後續沒有把原木籌移到三列旁讓他自己比。

**建議 P1/P2**：

- q1 必須是三個可判斷結果，不含拒押；若要保留認識論慎重，改成「兩聲差小到這套裝置分不出來」，這仍是可驗預測。
- 用一個低成本 SVG 同時播放兩球；三層不是三次完整動畫，而是同一機關依序點亮低／中／高列。
- 原木籌固定留在左側；每列落地後在同一時間軸打兩個聲點，讓玩家看差距是否超過解析度帶。
- q4 由玩家把三列圈進一句有限主張；虛構的「晚」保留在紙上，不只扣信譽。

## 7.8 B2-5 證據牆與蠟袋：概念很強，仍像選單

這站要求玩家把三份做過的紀錄與一份船桅待驗預測分開，是第二章最重要的研究誠信操作。錯封已做紀錄會被具體反問；越界袋面會扣信譽；最後留下能跨章交棒的蠟袋。設計內容應保留。

程式上卻只是 q1／q2 文字選項。背景圖與 focus visual 展示四張紙，但紙、袋、封蠟不是真正的 UI 狀態；玩家無法把錯紙拖進袋、看到袋面仍留錯字、再取出修正。

**建議 P2**：把現有三張 completed paper＋一張 ship paper 變成可拖卡片：

1. 拖一張進袋；錯紙不自動彈回，由伽利略指向紙上的日期／墨點。
2. 玩家親手取出，錯痕留在袋口或 eventLog。
3. 選袋面文字後壓封蠟；越界文字被劃線但不消失。
4. 成功蠟袋成為第三章可見敘事物件；此輪不必新增跨章條件分支，因只有一個合法封存結果。

## 7.9 B3-D 三支柱：好玩，但「問到底」與「說出論證」可再收斂

### 做對的事

- 每柱三句的顯示位置會變，不能靠固定中間卡猜題。
- 玩家要選一句證詞與一張證據；錯配有免費首發，之後扣論證對位。
- 支柱破裂、NPC 反應與三紙終局都有可見後果。
- 三紙重排沒有預選，錯版會完整留在桌上；玩家必須改動後整版重送。這是全章最符合「錯誤留痕」的互動。

### 限制

- ch2 的 pillar 沒有 `requirePress`；玩家可完全不按「問到底」，直接用正確證據破柱。這不是證據繞過，因仍需自己配對，但追問系統成了可略過的輔助層。
- 探索模式追問正確弱句後會顯示「此句有隙」，加上 evidence summary，幾乎只剩選對證據。
- 配對成功後 `playerCorrect` 是系統自動替旅人說的完整論證；玩家沒有親自限制語句。

**建議 P2**：

- 不必強迫每句都追問，否則會退回清單感；每柱只要求「至少問清你要打的那一句」。
- 探索模式可保留洞見，但把「此句有隙」改成描述性痕跡，例如「這句已押了一個可測後果」，避免直接標目標。
- 配對後讓玩家再選一個短理由：「這張紙量到了什麼？」；選項應從資料範圍而非修辭德性區分。系統再把短理由組成完整台詞。

## 7.10 SC-R1：短修復可接受，不要誤稱完整認證

`repairRun` 只要求 clean series 的 reading 數超過進場基線，所以開始一組並跑 H=4 就可完成。這看似弱守衛，但本場台詞只要求「重新做一次乾淨的紀錄」「新增一筆乾淨沙痕」，沒有宣稱完成整組規律認證，因此與第一章「任意 run 被稱乾淨實驗」不同。

建議 P3：UI 明寫「補交一筆乾淨沙痕（不是重新認證整條規律）」；完成後顯示新增的 H4 紀錄與裝置快照。若未來台詞改成「重做完整實驗」，守衛才必須升成 complete accepted series。

## 八、修復優先順序

### P0｜試玩前必修

1. **修 `compareBalls()`：兩組都必須 `accepted=true`。**
2. 加 rejected wood／rejected copper 的負向測試，確認不授予 F2b／F2。

### P1｜下一版核心完整性

3. **比較 apparatusRevision**，或由總監明確改寫法源；不可默默維持兩套定義。
4. open series 禁止校準，與換件共用 `series-open` 守衛。
5. 換球兩個 series 下拉取消預選，玩家親自選資料；成功前顯示差異清單。
6. `sanitizeImport2()` 重建／核對 series、F2a、F2b、F2 event 與里程碑，不接受零 series 自稱 F2。
7. B2-4 移除「拒絕預測卻照常啟動」的逃生選項；原木籌需在結果後可見。

### P2｜遊戲感與防回歸

8. narrative 增加第二章 scene/node×labAction 白名單；封住早跑 H25、任意場景取 F2。
9. `predict()` 加一次性鎖，避免替代 UI／未來重構重新暴露改答案。
10. B2-2 加可拖直尺與漏光；B2-4 加雙球同時播放與三列聲點；B2-5 加紙張拖入蠟袋。
11. F2a 以框資料／倍率籤替代純概念下拉；F2b 成功後用共尺疊圖，而非只回成立。
12. 三支柱要求打哪句就先問清哪句；成功配對後由玩家選短理由，系統再組完整論證。

### P3｜可留形成性試玩後

13. 船桅思想實驗改成移動落點問號，但仍明標待驗。
14. SC-R1 明示只補一筆沙痕，不是假裝完整認證。

## 九、建議新增的自動測試

1. `compareBalls`：任一 series `accepted=false` 必拒絕。
2. `compareBalls`：fingerprint 相同但 apparatusRevision 不同必拒絕。
3. `calibrate`：open series 時深等不變、天數不增。
4. `predict`：第二次提交回 `prediction-locked`、原值保留。
5. narrative phase：e1 不得 predict/run25/assert/compare；e2 不得 begin wood/compare；e3 不得新授 law。
6. sanitizer：零 series 自稱 law／ball／F2 必拒絕。
7. sanitizer：lawSource 不存在、不是 accepted copper、concept 不符必拒絕。
8. sanitizer：ball 找不到合法 accepted pair 必拒絕。
9. sanitizer：F2 event 與 `law && ball` 不一致必拒絕。
10. UI contract：F2a 與 F2b 的資料 select 初始值皆為空；只允許 e3 預選「開始木球」，不得預選證據來源。
11. B2-4：每個預測選項都形成可揭曉的結果承諾；不得有無承諾直通 q2。
12. 重播／動畫只讀：觀看既有 series 不改 days、eventLog、evidence 或 prediction。

## 十、最值得保留的五項

1. **連結測量的 4→9→16→押注→25 結構**：第二章最完整的先承諾、再揭曉。
2. **失敗 series 永久留存**：錯誤不是扣血，而是可回看、可比較的爛資料。
3. **裝置故障的可觀察症狀映射**：量程太寬、方向散、速度漂移各有不同資料形狀。
4. **B2-5 把待驗預測封存而非硬算證據**：認識論操作與第三章交棒都成立。
5. **三紙重排終局**：錯版保留、三張都要親手定位、同一批證據在高潮重新使用，是全章最成熟的互動。

## 十一、最終判定與驗收邊界

第二章已有一套值得保留的物理引擎骨架，但現況不能只用 `144/0` 宣稱「玩家判斷沒有被繞過」。正常 UI 已可用 rejected 木球取得 F2，換球資料又由介面預選；這兩點直接碰到本章的核心頓悟與玩家主體性。

**試玩前最低門檻**：修 F2b accepted 守衛，補負向測試。
**可稱核心互動完成的門檻**：再修 revision、mid-series calibration、比較預選與 sanitizer。
**可稱遊戲感完成的門檻**：B2-2／B2-4／B2-5 至少各有一個物件化操作，且結果後能看見玩家原先的承諾與錯誤留下的圖。

本輪未做瀏覽器與真人試玩，因此動畫手感、聲響辨識、觸控遮擋與學生是否能零說明完成，仍應由下一層驗收處理；不應由靜態程式審查替代。
