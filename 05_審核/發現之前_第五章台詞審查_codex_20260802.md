## B 級（明確錯誤但不阻斷）

### B1｜工作台提示仍把玩家當成在執行規格（3 處）

**位置**：E1-2/lab1（JSON 515）、E2-2/lab2（719）、E2-3/lab3（802）
**原句**：

- 「兩種碰法各留下三筆同速紀錄，勾選後提出斷言一。」
- 「不要再撞；勾回第一輪同一批紀錄重算，再完成 4／8 油灰追一筆。」
- 「三種落下速度各留一筆，勾選後提出斷言三。」

**因果問題**：「勾選／勾回」「斷言一／三」「4／8 油灰追一筆」是介面與測試規格語，不是玩家眼前的實驗動作；尤其「斷言一／三」沒有世界內所指。
**建議修改句**：

- lab1：「用兩種碰法各留下三筆同速紀錄，再從中挑出能放在一起比較的一組。」
- lab2：「別再碰球；把第一輪那批紀錄翻回來，換一本帳重算。接著換成一輕一重的油灰碰撞，再追一筆新紀錄。」
- lab3：「讓同一顆球從三種高度落下，每種留一筆，再比較坑深怎麼變。」

**是否動到節點結構**：否，只改 hint。
**驗證條件**：active hint 不再含「勾選／勾回／斷言一／斷言三／4／8 油灰追一筆」；不看 UI 規格也知道下一個實驗動作。

### B2｜兩份不同來源的紙被說成量了「同一場」碰撞

**位置**：E0-2/x8（JSON 287）
**原句**：「那就是兩件事。可是它們量的是同一場撞。」
**因果問題**：杜佩的三十年帳本與萊頓報告不是同一次實驗的兩份紀錄。這句把後面「同一批資料換帳重算」的嚴格來源設計，提前套到兩份不同來源上。
**建議修改句**：「那就是兩件事。可兩份紙，都是從碰撞留下的痕跡量起。」
**是否動到節點結構**：否。
**驗證條件**：台詞不再宣稱兩份來源記錄同一次 run，同時仍保留「同一類事件能留下兩種可量結果」的衝突。

### B3｜把不同量綱的兩本帳說成「若是同一件事，數字就會一樣」

**位置**：E2-2/reuse_1（JSON 689）
**原句**：「對。而且如果兩本帳講的是同一件事，它們算出來就會一樣。」
**因果問題**：`mv` 與 `mv²` 即使來自同一組資料，數值與量綱也不應彼此相等。真正可檢驗的是兩本帳會不會「同時閉合／同時短少」，不是算出同一個數字。
**建議修改句**：「對。如果真是同一件事的兩種寫法，它們在同一場撞裡，就該一起對平、一起短少。」
**是否動到節點結構**：否。
**驗證條件**：朗讀後不會讓玩家以為 `mv` 應等於 `mv²`；後續一本閉合、一本短少能直接反駁前述假設。

### B4｜反襯警句超額，角色開始共用作者句型

**位置**：至少 E0-1/x6、E0-2/x7、E1-2/x3、E2-1/x3、E2-2/missing_depth_2、E3-1/x2→x4、E3-2/x7
**原句（代表）**：

- 「不是翻字……我要讓它在法文裡也能算。」
- 「同一種速度，各做三回——不是為了保險，是為了讓你自己看見……」
- 「他不是看不見那個坑。他是沒有地方放它。」
- 「她在防的不是院士。她在防我。」
- 「你等一下不是要贏他。」→「讓兩本帳都留在桌上。」
- 「他不是輸了。他是把位置讓出來……」

**因果問題**：本章至少七次用「不是 X／是 Y」或跨句等價反襯，超過同章 ≤3 的硬配額。杜夏特萊、旅人心聲與收尾旁白因此共享同一種作者腔。
**建議修改句**：保留最有角色價值的三處（E0-1/x6、E2-1/x3、E3-2/x7），其餘改為：

- E0-2/x7：「坑深只屬黏土，不能直接算進我的運動之量。」
- E1-2/x3：「同一種速度，各做三回。我要你親眼看見，每回的結果是不是近得足以放在一起。」
- E2-2/missing_depth_2：「她是在防我重做資料，免得院士說我只挑自己要的結果。」
- E3-1/x2：「等一下，別只顧著贏他。」

**是否動到節點結構**：否。
**驗證條件**：同章等價反襯句型 ≤3、同場 ≤1；把角色名遮掉後，保留的三句仍分得出杜夏特萊、旅人與收尾聲音。

### B5｜「第四次有人決定不問」沒有三次可核對的前文事件

**位置**：EE-1/emilie_notebook_6（JSON 1176）
**原句**：「這是第四次有人決定不問。我開始覺得，不問才是這個時代最體面的事。」
**因果問題**：前四章可直接核對的明確事件只有牛頓的「那就先不解釋」；其餘人物雖容忍旅人的異常，沒有三次被寫成「看出異常後決定不問」。精確序數讓章際回呼變成憑空計數。
**建議修改句**：「又有人看出了不對，卻沒有追問。這份情，我記下了。」
**是否動到節點結構**：否。
**驗證條件**：刪去序數後仍保留杜夏特萊有意克制的情感，不再要求玩家回想不存在的三個明確事件。

### B6｜章號進入世界內心聲

**位置**：EE-2/x2（JSON 1223）
**原句**：「空框。第四章那個問號還在抽屜裡待了二十年。這個要多久？」
**因果問題**：「第四章」是製作端分章，不是旅人世界內能指稱的物件；違反章號只可出現在章名卡與存檔提示的規則。
**建議修改句**：「空框。劍橋那個問號曾在抽屜裡待了二十年。這個要多久？」
**是否動到節點結構**：否。
**驗證條件**：角色與心聲不再說「第幾章」；1665 到 1687 的約二十年等待意象仍成立。

### B7｜章末把尚未證明的去向直接寫成坑與溫度

**位置**：EE-2/c_next 選項、x7（JSON 1262、1271）
**原句**：

- 「那一截短少的，沒有消失。它去了哪裡？」
- 「那一截短少的，沒有消失。它變成了油灰上的坑、變成兩顆球摸起來的溫度、變成我還沒有辦法量的東西。它去了哪裡？」

**因果問題**：J3/J4 與本章高潮都刻意只到「壓陷提供尺度，完整去向未對平」。章末卻斷言短少「沒有消失」且「變成」坑與溫度，等於讓旅人用未來能量觀替本章資料簽收，推翻整章邊界。
**建議修改句**：

- 選項：「活力帳少了一截，油灰留下了一個坑。這兩件事要怎麼接起來？」
- x7：「旅人親手寫下：『活力帳少了一截，油灰留下了坑，球也微微發熱。這些是不是同一筆帳，今天還沒有證據。下一張紙，要怎麼把它們接起來？』」

**是否動到節點結構**：否；須同時改選項與 x7，避免選項先越界。
**驗證條件**：章末只並列觀察與問題，不再宣稱轉化機制或完整守恆已證成；能自然交棒下一章熱學。

### B8｜明確「落筆」後，書寫內容卻標成出聲台詞

**位置**：EE-2/x6→c_next→x7（JSON 1252、1258、1268–1271）
**原句**：x6「……在那個空框旁邊落筆。」；c_next「寫下這一章留下的問題。」；x7 speaker=`旅人(你)`。
**因果問題**：場景已明定為書寫，依心聲規則不應標成出聲對話。
**建議修改句**：將 x7 speaker 改為 `stage`，文字併用 B7 的「旅人親手寫下：『……』」。
**是否動到節點結構**：否，只改 speaker 與文字。
**驗證條件**：書寫內容不再以角色對話氣泡朗讀；選項、stage 與下一句心聲連接自然。

### B9｜劇本稿與 runtime 的分數契約互相矛盾

**位置**：`04_劇本/第五章可操作小說稿_兩本帳_v0.1-draft.md:451`；對照 scenes5 E1-1/q1、E3-1/init/debate/reenter、E3-2/j4、SC5-R1/c1
**原句（劇本稿）**：「信譽（起 3；本章全程靜止，失敗一律退回、不扣分）」
**因果問題**：canonical runtime 明確有 `rep:-1`、多處 `rep:+1`、信譽歸零修復場，並於 E3-1 啟用 `debate:init`。`debate5.json` 另以 `persuasion:5` 起始，三個錯項扣說服力，兩個還同步扣信譽；UI 也有第五章專用說服力顯示。這不是死碼，而是實際雙軌。
**建議修改句（劇本稿狀態欄）**：「全域狀態：信譽可因越界主張升降；E3 辯論另啟用 5 點說服力，失手會降低，歸零時暫離複盤後重入；既有證據與已站住的論證保留。」
**是否動到節點結構**：否；這是文件契約修正。若設計者其實要移除雙軌，則需另立機制決策，不能只改台詞。
**驗證條件**：劇本稿、scenes5、debate5、chapter-ui 對「信譽／說服力」是否存在及何時扣分說法一致。

## C 級（可改進）

### C1｜杜佩開場資訊密度高，朗讀像一次講完立場摘要

**位置**：E0-2/n1
**原句**：「運動之量，就是質量乘速度——帶著方向記。撞前多少，撞後就多少。萊布尼茲那個速度還要自乘的『活力』，只是多出來的玄想。」

**是否動到節點結構**：否。

### C3｜跨章回望把三段經驗壓成一句泛化警句

### C4｜立問句的錯答回饋幾乎代寫正確問法

**位置**：E1-1/bad1、bad2

## 特別確認：第五章「說服力」不是死碼

結論：**第五章真的使用「信譽＋說服力」雙軌，不是 chapter-ui／narrative 遺留死碼。**

證據鏈：

1. `scenes5.json:890` 在 E3-1/init 執行 `{ "debate": "init" }`。
2. `scenes5.json:923–929` 有 active `embed system="debate"`，且須 `debateWon:true` 才前進。
3. `scenes5.json:939–946` 有 active `debate:"reenter"` 迴路。
4. `debate5.json:2` 設 `persuasion:5`；其 126、134、142 行的錯項會扣說服力，其中兩項也扣信譽。
5. `chapter-ui.js:431–433` 有第五章專用「說服力 X/5」顯示。

因此，若產品決策認為第三章起不再使用說服力，現行第五章與該決策不一致；但就現行程式與資料而言，它是可達且被 UI 顯示的正式機制。
