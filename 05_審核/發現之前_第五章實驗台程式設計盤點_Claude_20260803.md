## 〇、先裁定分歧：**codex 是對的，我先前的判斷錯了**

我在《第五章互動劇情設計盤點》裡寫「第五章沒有核心判斷被代做的問題」。**這個結論不成立。** 程式碼在三個地方都站在 codex 那一邊：

### 證據一：`engine5.js` 的三個斷言函式**根本沒有 concept 參數**

```js
function assertJ1(state0, ids) { ... }   // engine5.js:117
function assertJ2(state0, ids) { ... }   // engine5.js:136
function assertJ3(state0, ids) { ... }   // engine5.js:180
```

**對照三、四章——這是決定性的：**

| 章 | 斷言函式簽章 | 是否驗證概念 |
|---|---|---|
| 第三章 | `assertG1(state0, baselineIds, mastIds, **concept**)` | ✅ `concept === "steady-shares-motion"` 才成立 |
| 第四章 | `assertK1(state0, records, **concept**)` | ✅ `concept === "forward-plus-inward-turn"` 才成立 |
| **第五章** | **`assertJ1(state0, ids)`** | ❌ **沒有這個參數** |

第三、四章都要求玩家**另外選一句「這些紀錄支持什麼」**，而且錯的概念會讓斷言失敗。**第五章只驗資料選得對不對，選對了就直接發證據。**

### 證據二：那三句結論是**寫死在 UI 陣列裡的**

`chapter-ui.js:7270-7286`（codex 指的位置，完全正確）：

而按鈕（`chapter-ui.js:7470-7485`）只有一顆，成功訊息也是寫死的字串：

**直接回答交辦的第 3 題**：玩家勾完資料之後，「這批資料代表什麼結論」這句話——**是程式生成的固定文字，不是玩家從選項裡選出來的。** 整個第五章工作台沒有任何一處讓玩家選概念。

### 證據三：辯論的核心論證由系統替玩家講出

`narrative.js:325`（codex 指的 303-338 區間內）：

```js
if (isCorrect) {
  say(state, "旅人(你)", pillarDef(pid).playerCorrect);   // ← 系統用玩家的名義講完整論證
  say(state, opponentSpeaker(), pillarDef(pid).breakReply);
```

玩家的輸入只有 `{ evidence, target }`——**把哪張證據推到哪一句話前面**。判定是一次查表：

```js
var isCorrect = weak && weak.evidence === p.evidence && ...
```

配對正確之後，整段論證由 `debate5.json` 的 `playerCorrect` 播出。以第三柱為例，玩家「說」的是：

> 「同一件事，會在同一次碰撞裡，一本對平、一本短少嗎？（把兩本帳並排壓在桌上，指油灰那幾列）同一次撞擊，這邊對平，這邊短少；換了砝碼再撞，短少的份量還會變。記同一件事的兩本帳，不會這樣吵架。」

**這是整根柱子的全部推理，而玩家的操作是「選 J2、指 p3s3」。**

## 二、但有兩點要替第五章補回來（codex 的診斷可再精確）

### 2.1 `narrative.js` 的 `playerCorrect` **是全系列共用的辯論引擎，不是第五章的退化**

`narrative.js` 由 ch1／ch2／ch5 共用，`debate.json`／`debate2.json`／`debate5.json` 都有 `playerCorrect` 欄位，走同一條 `say(state, "旅人(你)", pillarDef(pid).playerCorrect)`。

**所以「系統替玩家講論證」是系列級的既有行為，不是第五章新引入的問題。** 這不表示它不是問題，但它改變了修法的層級與成本估算——動它會同時影響三章。

**真正屬於第五章自己的退化，是工作台那一層**：ch3 的 `assertG*` 與 ch4 的 `assertK*` 都有 concept 參數，**只有 ch5 的 `assertJ*` 沒有**。這一條 codex 抓得準，而且我認為它比 `playerCorrect` 更該優先修——因為它是同一個專案內部前後不一致，而不是全系列的設計慣例。

### 3.1 ✅ 資料層做得好的部分（不要動）

**黏土是真運算，不是查表**（`engine5.js:156-179`）：
```js
var ideal = massFactor * def.v * def.v / 8;      // v=2→0.5, v=4→2.0, v=6→4.5
var readingError = ERRORS[s.claySeq % ERRORS.length];   // [0, +0.1, -0.1] 交替
depth: Math.round((ideal + readingError) * 10) / 10
```
與規格 §7-3／§7-4 逐項吻合（量到 0.5／2.1／4.4，比例 1:4.2:8.8），誤差是交替不是單向漂移。**這是第四章 `canonicalOrbitShape` 該有而沒有的克制。**

**碰撞 fixture 也是算的**（`totals()` 從 `mA, mB, before, after` 實算兩本帳），不是硬表。`4/8・鋼頭` 的 A 車被彈回（−2）由 `followupFixture` 的 `-speed/3` 產生，與規格 §7-2 一致。

**斷言的資料檢查與 ch3 同級**：J1 要求兩種碰撞頭各 ≥3、砝碼一致、速度一致；J3 要求球質量一致、≥3 種速度。玩家湊不出斷言。

**線性閘門無捷徑**：`assertJ2` 要 `evidence.j1`、`runClay` 要 `evidence.followup`、`setDraft` 的 `4/8` 要 `evidence.j2`。我逐條追過，**沒有繞過路徑**。

### 3.2 🔴 輪二是本章最空的一站，而且規格設計的兩個提示不可能出現

`assertJ2` 要求勾選的 id 集合與 J1 **完全相同**：
```js
if (wanted.length !== original.length ||
    wanted.some(function (id, i) { return id !== original[i]; }))
  return err(state0, "same-records-required");
```

於是輪二的玩家動作是：**把剛才勾過的那六格，一模一樣再勾一次，按按鈕。** 沒有變因、沒有概念、沒有任何可能的偏離——任何偏離都回同一個錯誤碼。

**而規格 §2-2 設計了兩個教學提示，兩個都不可能觸發**：

| 規格設計的錯 | 規格設計的提示 | 實際會發生什麼 |
|---|---|---|
| 只勾了鋼頭那幾筆 | 「都平。可你只重記了彈開的那幾次——**黏成一團的呢？**」 | `wanted.length(3) !== original.length(6)` → 回 `same-records-required`，**通用錯誤碼，提示永不出現** |
| 又去做了新實驗才回來 | 「新的也可以算。但院士會問：你是不是換了紀錄才湊出短少的？」（**不擋，只留下這句**） | `runCollision` 直接回 `round2-no-new-experiment` → **擋掉了，規格明說「不擋」** |

第二條特別值得注意：**規格明文要求「不擋，只留下這句」，程式卻是硬擋。** 那句話正是本章方法論的核心（不能換資料湊結果），現在玩家永遠不會聽到。

### 3.3 🟡 `momentum-not-closed` 是死檢查

```js
if (rows.some(function (r) { return r.momentum.before !== r.momentum.after; }))
  return err(state0, "momentum-not-closed");
```

四種 fixture 的動量在建構上全部閉合（鋼頭 `0 + v`、油灰 `v/2 + v/2`、4/8 鋼頭 `-v/3 + 2v/3`、4/8 油灰 `v/3 + v/3`，乘上質量後恆等於 `4v`）。**這個檢查永遠不會觸發。**

不是 bug，但它意味著「動量帳每次都平」這件事，玩家**不可能**用錯誤的資料選擇去證偽——而柱二的整個戲劇前提是「你必須親手驗證對手是對的」。目前玩家驗的是一個不可能失敗的東西。

## 四、改善建議

### 🔴 P1-A｜替 J1／J2／J3 補上概念選擇（對齊 ch3／ch4）

**引擎**（`engine5.js`，約 15 行）：

```js
var J_CONCEPTS = {
  j1: "signed-mv-closes-both-heads",
  j2: "vv-closes-elastic-short-inelastic",
  j3: "depth-tracks-speed-squared"
};
function assertJ1(state0, ids, concept) {
  ...既有的資料檢查全部保留...
  if (concept !== J_CONCEPTS.j1)
    return err(state0, "concept-mismatch", { expected: null });
  ...
}
```
（J2／J3 同型。`concept-mismatch` **不清除勾選、不耗天**，與 ch3 的 `claim-mismatch` 一致。）

**UI**（`chapter-ui.js`，把單一按鈕換成三選一）。誘答建議用本章真實的迷思：

| 輪 | ✓ 正解 | ✗ 誘答一 | ✗ 誘答二 |
|---|---|---|---|
| J1 | 帶方向的 mv，撞前撞後總和不變 | 撞完以後，運動的總量一定會少一些 | 只有彈開的那幾次對得平 |
| J2 | mv² 在彈性閉合、非彈性短少 | mv² 也是每次都對得平 | **非彈性碰撞裡，mv² 少掉一半** |
| J3 | 坑深跟著速度的平方走 | 坑深跟著速度走 | 坑深證明活力才是真正的運動之量 |

**⭐ J2 的第二個誘答（「少掉一半」）特別值得放**：規格 §2-2b 的整個存在理由就是殺掉這個歸納。目前 4／8 追一筆做完之後沒有任何機制承接它；把「少一半」做成一個**在追一筆之前選會過、之後選會被擋**的誘答，這一步才真的有落點。

同理 J3 的第二個誘答與 `E2-3/c_scale` 的越界選項同型——**同一個盲點在工作台見一次、在故事層再見一次**，正好複製規格 §1-1 稱讚的「同一個盲點見兩次」設計。

### 🟡 P1-B｜讓規格 §2-2 的兩個提示可以觸發

1. **區分「J1 的子集」與「完全不同的集合」**：
```js
var isSubset = wanted.every(function (id) { return original.indexOf(id) >= 0; });
if (isSubset && wanted.length < original.length) {
  var picked = selectedCollision(state0, wanted);
  if (!picked.some(function (r) { return r.head === "putty"; }))
    return err(state0, "steel-only-subset");     // → UI 印規格那句「黏成一團的呢？」
  return err(state0, "same-records-required");
}
```
2. **輪二不要硬擋新實驗**：把 `round2-no-new-experiment` 從錯誤改成**允許但標記**——新紀錄照樣入表，但打上 `afterJ1: true`，UI 在斷言區印規格那句「新的也可以算。但院士會問：你是不是換了紀錄才湊出短少的？」。**規格明文寫「不擋」，目前的硬擋違反設計。**

### 🟡 P2-C｜`playerCorrect`：至少讓玩家收尾（系列級，需總監裁）

`narrative.js` 共用，動它會影響 ch1／ch2／ch5，所以我不建議全改。**低成本的折衷**：把 `playerCorrect` 拆成「鋪陳」與「收尾句」兩段，系統播鋪陳，**收尾那一句由玩家從三個選項挑**。

以第五章 P3 為例：
> 系統（旅人）：「同一件事，會在同一次碰撞裡，一本對平、一本短少嗎？（把兩本帳並排壓在桌上，指油灰那幾列）同一次撞擊，這邊對平，這邊短少；換了砝碼再撞，短少的份量還會變。」
> **玩家選收尾**：
> - ✓「記同一件事的兩本帳，不會這樣吵架。」
> - ✗「所以活力帳才是對的那一本。」
> - ✗「所以這兩本帳只是寫法不同。」（← 與 FR 的鏡像誘答同型）

資料層只要在 `debate5.json` 的 pillar 加一個 `closingOptions` 陣列；`narrative.js` 加一個「有 closingOptions 就先問」的分支。**三章可以逐章導入，不必一次全改。**

### 🟢 P3-D｜`momentum-not-closed` 改成有用的東西
兩條路：①刪掉（誠實承認四種 fixture 都閉合）；②**讓它變得可能失敗**——若之後開放「不帶方向的舊笛卡兒版本」作為一個可選的結算方式（規格 §7-2 提到 `4／8・鋼頭` 的 A 車被彈回正是為了這個），這個檢查就會真的擋人，柱二「親手驗證對手是對的」也才有份量。

### 🟢 P3-E｜`c_scale` 移到 J3 之前
目前 `lab3` 的 `until: {collision:"j3"}` 讓 J3 先發，`c_scale` 才問邊界。若 P1-A 落地（J3 有了概念選擇），`c_scale` 可以改成 J3 的**範圍句**（對齊 ch3 的 `setDossierScope` 儀式），或至少把 `until` 改成 `clay-records-ready`，讓邊界選擇成為發證據的最後一關。
