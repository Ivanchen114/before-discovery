# 《發現之前》第六章互動劇情設計盤點——三方交叉驗證彙整報告

**日期**：2026-08-03
**性質**：唯讀敘事因果審查，均未修改runtime。claude與codex均以Node直接驗證多項發現。

---

## 一、總裁決：敘事因果是六章裡最紮實的一次，但引擎/UI落後於`operationContract`寫下的承諾

**claude的定調**：「敘事因果是六章裡最紮實的，但`operationContract`寫下的互動承諾有四處沒有對應的引擎狀態——問題不是設計錯，是實作落後於規格，而規格就寫在同一個資料檔裡、逐條可核。」

**codex的定調**：「章的宏觀因果是成立的，但十一座互動台只有約一半真正把判斷交給玩家。」

**gemini的整體評價最正面**：多數環節的鋪陳都做對了，只找到一處明確問題。三方的分歧不是矛盾，是深入程度不同——gemini做的是敘事表層掃描，claude/codex用Node實測挖到了具體的引擎層落差。

## 二、🔴 最嚴重的招牌機制問題：H2-3長時段觀察的三個操作鍵是假的（claude+codex雙重confirm）

**codex的Node實測**：連續按三種不同按鈕（續鑽/校準/修漏），溫度序列完全相同：`31°→47°→65°→83°→96°→100°`，不管怎麼選都一樣。

**claude獨立重跑，結果一致**：
```
全程亂按：31/continue 47/calibrate 65/continue 83/calibrate 96/continue 100/calibrate
全按續鑽：31/continue 47/continue  65/continue 83/continue  96/continue 100/continue
```
**兩種操作策略得到完全相同的溫度序列。** `action`被記錄下來，但不影響任何數值；`horsePace`/`pressure`是字面常數，原紙永遠聲稱「條件穩定」。

**這正是三方定案認定的本章「新動詞」**（管理一個不會自己停下來的持續過程），**目前只是按六次任意鍵**。契約承諾的「盲目續鑽會讓曲線折斷、變斜或失去水量基準」不存在，劇本寫好的失敗反應（H2-3/w1-w3：漏水、換馬漏記、兩個不能補寫的洞）在正常操作下完全不可達。

**claude評為「投報率最高的修項，因為它是招牌機制」**。

## 三、🔴 稽核板（H3-1）把正確答案印在按鈕標籤上（claude獨立發現，比codex的類似發現更嚴重）

claude發現H3-1（本章高潮）的UI直接這樣寫：
```js
[["chips","T1","碎屑來源 ← T1"], ["air","T3","空氣來源 ← T3"], ["cannon","T4","炮身有限存量 ← T4"], ...]
```
**每顆按鈕的文字本身就是那格的正確答案。** 引擎明明有`audit-placement-mismatch`錯誤碼和對照表可以處理配對錯誤，但UI從不提供能觸發它的操作路徑。

**這不是「系統代玩家講結論」，是「系統把結論當按鈕標籤直接發給玩家」**——比其他章找到的「選項被繞過」問題更直白。**改法成本低**（引擎不用動，錯誤文案已現成）。claude並建議拿掉T2的專屬格，因為契約要的正是「T2不能獨自處決任何來源」這個陷阱，現在的UI設計反而先幫玩家排除了這個陷阱。

## 四、系統性問題：H1-1/H1-2/H1-3三座工作台都是「UI先判結論，劇情再問一次同題」（claude+codex雙重confirm）

**codex的表格**：三座embed的gate都綁在`judged`/evidence——H1-1的UI必須先選「碎屑並沒有顯著較低的熱容量」，離開後劇情的c1再問一次「這組紙最多支持到哪裡？」；H1-2、H1-3同型。**玩家第一次的判斷留在沒有角色反應的UI按鈕上，第二次只是在對NPC重填一次已經選過的答案。**

**codex的修法（一次修三場）**：embed只負責取得乾淨原紙，gate改成`record-ready`，不在UI判結論；回到故事後讓c1成為唯一的結論選擇；正解選項的`effects`才呼叫對應判定函式。**這正好恢復「選資料」與「資料代表什麼」兩個獨立步驟，不需要新增故事節點。**

## 五、claude發現的新洩題模式：五個判斷的正解全部是「比較謹慎的那個」

**B-5**：四個工作台是「1正解+1明顯過度宣稱」二選一，**本章自己的教學修辭洩了答案**——五個判斷的正解全部都是兩者中較謹慎、語氣較小的那個（誤答是「碎屑一定製造了更多熱」「主張永遠都會以同斜率升溫」這類過度宣稱）。整章每句駁回都在教「不要說超過你的紙」，**玩到第三台，玩家會學會一條不必碰物理的規則：挑語氣小的那個。**

**這跟其他章發現的「正解比誘答書面化」洩題是不同類型，但同樣有效——建議每台補第三個「收得太窄」的選項，讓這條捷徑失效。**

## 八、值得保留的設計（三方一致公認）

- **H0-3的「來源封條」結構**（claude評為六章最強鋪陳）：開場就要玩家把四個來源掛到實物位置，逐一寫下「如果熱真從這裡來，哪裡會先變」，後面每個工作台自動帶著「我在查誰、我預期看到什麼」的框架
- **H0-2的期限與署名**：炮頭、馬班、空印章同時建立「誰在等/失敗會怎樣/何時到期」
- **潛熱卡不是高潮空降**：H0-3先公開伏筆，H3-1才反擊；每個概念都先給現象後給名字（潛熱用「冰一邊融一邊收熱」出場，「潛熱」這個詞要到H3-1才真正出現）
- **H3-2個人論文/共同頁分離**：玩家不改寫Rumford，只拒絕替越界宣稱署名
- **HE-1/c3**：全章唯一完全符合「先看資料→玩家提出下一個可分辨實驗→最後一句交棒」的設計，可反向作為H1/H2修訂範本
- **場景層的18個choice全部都有`refutedBy`指回具體節點**：最好的示範是H0-3/c1選錯時，凱斯勒回「我也預測炮頭會熱。你把共同預測當成自己的戰利品了。」

## 九、建議實作順序（綜合三方，依investment/return排序）

1. **稽核板不要把答案印在按鈕上**（H3-1，成本低，消掉本章高潮的判斷代做問題）
2. **長時段觀察補真實擾動與壞紙機制**（H2-3，招牌機制，投報率最高）
3. **修正no-endpoint的判讀矛盾**（成本低）
4. **H1-1曲線隨配置真的變化**+初值不預設乾淨對照（成本低）
5. **水箱台補炮頭初溫的實際控制項**（成本中）
6. **H1-1/H1-2/H1-3補第三選項+概念白名單**，消除「工作台判一次、劇情判第二次」的重複結構（成本中）
7. T2授予時點修正到正確的工作台
8. 空氣預測改成單一封存動作（不重複封兩次）
9. 5組工作台的失敗故事節點接上engine的failure kind路由

## 統計

第六章的敘事設計品質是六章之中最好的（來源封條結構、伏筆節奏、失敗回應的`refutedBy`覆蓋率都是最佳範本），但因為還在動工階段，**engine/UI層的落差反而集中且容易框定**——四個P0級問題（稽核板洩題、長時段假操作、三工作台判斷重複、開場承諾未重用）修完後，第六章有機會成為全案「劇本先審、動工前品質關卡」流程下敘事與程式都最紮實的一章。
