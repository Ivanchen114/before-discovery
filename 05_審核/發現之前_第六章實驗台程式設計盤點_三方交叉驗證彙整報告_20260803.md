## 三、兩方各自用Node實測confirm的核心問題

### H2-3長時段觀察：三個操作鍵結果完全相同（本輪最嚴重、兩方獨立驗證數次都一致）
```
續鑽→31° 校準→47° 修漏→65° 續鑽→83° 校準→96° 修漏→100°
（不論怎麼混按，溫度序列完全相同）
```
劇本寫好的失敗反應完全不可達。**codex給兩條修法路徑必須擇一**：低成本誠實版（刪三選一改成單鍵「記下一格」，3-5小時）或完整玩法版（每格先揭示現場事件如鼓點漂移/漏水，正確處置才產生可用資料，16-24小時）。**兩方都同意：沒資源做完整版時，寧可用誠實的單鍵，也不要留著假選擇。**

### H0-3來源追債台：只驗非空字串，且後續完全不重用（兩方confirm）
```
四來源position=同一位置、consequence=同一後果，兩模型填任意字串
→ sealModels()仍回傳ok=true
```
claude進一步確認：`placements`/`consequences`/`modelPredictions`的**內容從此不再被任何函式讀取**，全檔搜尋只找到「是否非空字串」的驗證。**這個開場承諾只是一張表單，不是後面會被打臉或驗證的因果變數。**

### H1-1碎屑量熱：髒/淨曲線完全相同，且極端值也能通過（codex額外測出）
```
codex實測：chipMass=plateMass=-10、初溫=500、水量=999 → 仍clean=true，仍產生固定26/31/34°C曲線
```
這比「防作弊」層面更嚴重——**是物理映射本身的缺陷**：玩家故意做壞比較後，看不到壞資料造成的任何數值後果。

### 有限來源判讀：`no-endpoint`（目前無法判斷）被錯誤判定為「未兌現」（兩方confirm，codex追加測出炮身/水一樣可以這樣做）
```
四來源全押no-endpoint（引擎允許，即使UI只對碎屑/空氣顯示這個選項）
六格跑完，四次提交not-fulfilled
→ 四封全裂，T4=true
```
一個沒有終點的預測，邏輯上不可能被判定為「未兌現」，但引擎目前的完成條件就是「四來源都要回答同一個字」。

### 空氣密合對照：三種預測方向全部導向相同結果，押錯完全沒有代價（兩方confirm）
```
slower-when-sealed / any-change / faster-when-sealed → 三條路都能取得T3，開放/密合兩條曲線完全相同
```

### codex獨立測出、claude未涵蓋的新問題：水箱可無限重複封存
```
prepareWaterBox()第一次→ok=true；同一state再按一次→ok=true，records變成2，天數再+1
```
玩家可以重複「封存乾淨起點」無限次，每次都成功，沒有任何守衛。

### claude獨立測出、codex報告框架外的兩個新捷徑
1. **空氣密合的「乾淨」判定由呼叫方自己宣告**（十一站裡唯一一站不是自己推導乾淨與否），且押錯預測方向完全沒有代價
2. **本章最終判定「熱是運動」完全沒有前置條件檢查**——全新存檔、任何證據都沒看過，直接就能被判定通過。**這是三方定案認定的「主擊」、唯一計入勝負的動作，修法只要1行程式碼。**

## 四、claude獨立發現：規格文件本身有一處明確違反自己訂的契約

claude把237個節點按執行順序排列後逐條核對「錯誤選項只能引用作答前已見證據」這條規則，發現`H2-2/c1`的兩個誤答選項引用的依據節點，**其實排在玩家作答之後才出現**——這違反了規格`R-CH6-04`。**修法只要改2個字**（把引用目標從後面的節點改成前面已存在的節點）。

**claude也建議把「全域節點順序+refutedBy前向性」直接寫成一條資料契約測試**：純資料檢查，成本極低，一次寫好可以永久防守這類「事後引用」錯誤——這正是人眼最容易漏掉的一類bug。

## 五、⚠️ claude發現的重大文件衝突：四份文件對「該不該有拖曳」互相打架

| 來源 | 立場 |
|---|---|

| 總監2026-07-28裁示 | 「拖曳已移除」（無障礙與橫屏考量） |
| 全專案實際實作 | pointer handler = 0（五章皆然，第六章也是：34個按鈕+6個下拉選單，0個拖曳） |

**目前實作同時違反規格（確實退化成問卷）又符合裁示（確實沒有拖曳），兩份文件無法同時滿足，需要總監裁定。**

claude建議：以裁示為準改寫規格§八與三處operationContract，因為規格真正想守護的是「操作要有空間性與可逆性」，不是字面上的「拖曳」——來源封條可以用第四章既有的轉鍵在掛點間移動、稽核板用兩段點選（點證據再點槽，可取回）、三欄判讀改成三顆都合法可提交的單選鈕，三者都能消掉問卷感，且都落在既有無障礙與橫屏規則覆蓋範圍內。
