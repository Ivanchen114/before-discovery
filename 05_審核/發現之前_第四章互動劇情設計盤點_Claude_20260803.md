## 〇、先回答使用者卡住的那一句

### `D1-1/ok2` 牛頓：「好。沒有拉扯，它就沿這條直線離開。**現在要問的是：每一拍加上什麼，才不會讓它走掉？**」

使用者的反應是「為什麼突然這樣問？每一拍加上什麼？感覺牛頓知道，但這裡的目的是什麼？」——**這個反應完全正確，而且原因有三層，全部是結構問題，不是文字問題。**

#### 落差一：「拍」這個詞在這裡是**未定義前向引用，跨越兩場加一個十四年幕間**

「一拍」的定義在 **`D2-1/n23`**：

> 牛頓：「月亮一路連著走，筆卻不能一路連著算。我把它切成一小段、一小段——每一小段，叫一拍。」

runtime 的實際順序是：

```
D1-1（ok2 使用「每一拍」）
  ↓
D1-2  同一把尺
  ↓
D-INT-1  幕間十四年   ← 玩家中間隔了 14 年的時間跳躍
  ↓
D2-1  虎克的第一封信 → n23 才定義「一拍」
```

**玩家在 `D1-1/ok2` 第一次讀到「每一拍」時，這個詞在遊戲裡還不存在。** 它要到三場之後、跨過一個時代轉場才被解釋。

值得強調的是：**`D2-1` 那一段的鋪陳寫得非常好**——定義（n23）→玩家複述（n24「你把一條不停的路，拆成一拍一拍算？」）→牛頓確認並展開（n25）→玩家推導出自己的任務（n26「所以我要給的規矩是：每一拍，往哪扳、扳多少。」）→補上第二個變數（n27–n28）。這是全章概念鋪陳最完整的一段。

**所以問題不是「拍沒教好」，而是「教得很好，但被提前三場劇透了一個半成品」。**

#### 落差二：這句是**懸空的提問**——問了，但沒有互動承接，也沒有人回答

`D1-1` 的節點流是：

| 順序 | 節點 | 內容 |
|---|---|---|
| 1 | `ok1` | 旁白：旅人畫直線、寫日期、滴蠟封住紙角 |
| 2 | **`ok2`** | **牛頓下結論＋問「每一拍加上什麼」** |
| 3 | `n4` | system：切線預測紙已封存 |
| 4 | `n5` | 旅人：「所以，沒有任何拉扯時，它不會自己沿著圓弧走。」 |
| 5 | `n6` | 牛頓：「這張紙只能說到這裡。我想先知道**一件更小的事**：如果真有那股勁，到月亮那裡，它該剩多少？」 |

- `ok2` 問的問題**沒有選項可以回答**，下一個節點是系統訊息。
- `n5` 旅人講的是**回頭複述 `c1` 的結論**，不是回答 `ok2`。
- `n6` 牛頓**自己又轉了一個題目**，而且說「一件更小的事」——等於承認 `ok2` 那個問題被擱置了，但玩家不知道它會在哪裡被撿回來。

**節奏上的實際結果**：牛頓在五個節點裡問了兩次新問題（`ok2`、`n6`），中間夾了一則系統訊息和一句玩家的回頭複述。玩家讀到 `n6` 時，`ok2` 那個問題已經懸在半空無人處理——「突然」的感覺就是從這裡來的。

#### 落差三：`D1-1` 原本有的**玩家操作被抽掉了**，`ok2` 是那個操作的引導語，操作走了、引導語留在原地

`D1-1/e1` 現在標著 `legacyOnly: true`：

```json
{ "id": "e1", "type": "embed", "system": "orbit",
  "phase": "tangent-seal",
  "hint": "親手封存切線預測紙。它是玩家留下的來源紀錄，不列入本章五份證據。",
  "legacyOnly": true, "next": "n4" }
```

而設計文件 §二 D0 明列產出是「**切線預測紙(封存)**」——封存是玩家動作。現在 `ok1` 用一句旁白（「旅人沿選中的方向畫下一條直線，寫下日期，再滴蠟封住紙角」）把玩家的動作代做掉了。

**同時，設計文件 §二 D1 的定案互動是「玩家三步→封存形狀預測→牛頓續二十七步」——那個作圖 embed 現在在 `D2-1/e1`（`phase: orbit-rule`）。**

也就是說：`D1-1` 原本是「封存切線 → 緊接著進作圖」，`ok2` 是**銜接到作圖的引導語**（「每一拍加上什麼」正是作圖要玩家決定的事）。作圖被搬到 `D2-1` 之後，這句引導語沒有跟著搬，就變成一句指向空處的預告。

### 建議改寫

**核心原則：把 `ok2` 從「提問」改成「陳述」，拿掉未定義的「拍」，讓它只做一件事——把切線結果轉成「所以一定有東西在扳它」的認知，然後交棒給 `n6`。**

同時建議調整節點順序，讓旅人的複述在牛頓下結論之前（玩家先想到、NPC 再確認，符合「玩家出判斷」）：

| 順序 | 節點 | 建議內容 |
|---|---|---|
| 1 | `ok1` | （旁白不動）旅人沿選中的方向畫下一條直線，寫下日期，再滴蠟封住紙角。牛頓等蠟凝固，才把紙拿過去。 |
| 2 | `n4` | （system 不動）切線預測紙已封存⋯⋯ |
| 3 | `n5` | **旅人**：「所以，沒有任何拉扯的話，它不會自己沿著圓弧走。」（不動） |
| 4 | **`ok2`（改寫）** | **牛頓**：「對。沒有拉扯，它就沿這條直線離開。」（把紙轉過來，指著那條直線走出紙外的地方）「**可是月亮沒有走掉。它每一晚都還在。所以一定有東西，一路把它扳回來——一路，不是扳一次。**」 |
| 5 | `n6` | **牛頓**：「這張紙只能說到這裡。（收起）在想那是什麼東西之前，我想先知道一件更小的事：如果真有那股勁，到月亮那裡，它該剩多少？」（微調，補「在想那是什麼東西之前」讓轉題有理由） |

改寫後：
- 「每一拍」消失，`D2-1/n23` 第一次教這個詞時，玩家會是乾淨的。
- 「一路把它扳回來——一路，不是扳一次」**預埋了「連續」這個概念**，等 `D2-1` 說「筆不能一路連著算，所以切成一拍一拍」時，玩家會有「啊，就是那個一路」的接續感——**前向引用改成了前向鋪墊**。
- `ok2` 不再是問句，玩家不會誤以為要回答。
- `n6` 的轉題有了理由（「在想那是什麼東西之前」），不再像跳題。

**另建議**：若工程允許，把 `D1-1/e1`（親手封存）恢復為 active。設計文件明列封存是玩家動作，且第四章「無實驗」的代償正是這些程序性的親手動作；用旁白代做會讓 `D1-1` 只剩一個三選一，是全章互動最單薄的一場。

## 一、落差的五種型態（本章通用診斷）

盤完全章，`D1-1/ok2` 不是孤例。所有鋪陳問題可歸成五型：

| 型態 | 說明 | 出現處 |
|---|---|---|
| **型態 1：前向引用** | 概念在被定義之前就被使用 | `D1-1/ok2`「每一拍」、`D0-2/c0`「這張船紙」 |
| **型態 2：核心裝置只有名字、沒有讀法** | 玩家被要求操作一個從沒被介紹過的東西 | 刻痕帶（`D3-1`）、借條（`D4-1`）、過帳（`D4-1`）、六槽（`D4-2`） |
| **型態 3：類比遲到或缺席** | 違反文字五查⑤「首次出現的概念，必有生活類比或圖」 | 「距離平方」（`D1-2` 用、類比在 `D4-1`）、「均勻球殼」（`D4-2`，零類比） |
| **型態 4：分工原則沒有在台詞裡兌現** | 設計文件 §一.4「牛頓出力氣，玩家出判斷」只寫在 hint，沒進對話 | `D2-1/e1`（三拍／二十七拍） |
| **型態 5：玩家判斷拍被旁白代做** | 設計文件列為玩家動詞的拍，runtime 改成敘述 | `D1-1/e1`（封存）、`D1-2` 的「陷阱抉擇」 |

**一句話總結**：第四章的**每一個互動本身都設計得不錯，問題全部出在互動的「入口」**——玩家被帶到裝置前面，但沒有人告訴他這是什麼、為什麼要動它。這與設計文件 §一.5「國中生可讀」與 D2-3 附註的「**難懂即換**」條款是同一個要求，只是那個要求在轉檔成 runtime 時只落實了一半（換了載體，沒寫讀法）。

### `D0-2` 果園入場考 ⚠️ 型態 1

#### 🔴 落差：`c0` 兩個選項都說「先把這張船紙放上桌」，但船紙要到 `n18` 才被拿出來

runtime 順序：

```
n10–n11  牛頓問「那股勁往上能伸多遠？到雲上呢？到月亮那裡呢？」
c0       兩選項，都以「先把這張船紙放上桌：⋯⋯」開頭   ← 玩家還不知道自己有這張紙

而**設計文件 §七 Phase A 第 2 條寫的順序正好相反**：

> 「序幕 D0 台詞：旅人落地→**出示重畫的第三章船紙**→牛頓入場考（切線三選）→『把那張紙帶上。進來。』」

**設計是先亮紙再考，runtime 是先要玩家用紙答、才亮紙。順序倒了。**

實際體感：玩家在 `c0` 讀到「這張船紙」，會愣一下（哪張紙？），然後才在 `n18` 補上背景——跟 `ok2` 是同一種「先用後教」。

#### 建議
在 `n11` 與 `c0` 之間插入一個旁白節點：

> **stage（新增）**：旅人摸到懷裡那疊紙。最上面那張是他自己重畫的——船、桅杆，還有船上與岸上看見的兩條不一樣的路。馬賽的鹽還沾在紙角。

然後 `n18` 的旁白改為：

> **stage（改寫）**：旅人把那張紙抽出來，追上兩步。

這樣 `c0` 的選項就站得住，`n16` 牛頓問「有紙嗎？」也變成一個玩家已經知道答案的期待拍（更好）。

#### 📌 另記：設計文件的 D0／D1 在 runtime 被重新分配
設計文件 §二 D0 的入場考是「**沒有任何作用改變它的運動，下一刻往哪？**三選（直走✓／圓弧／墜落）」——那是切線題。
runtime 把 `D0-2/c1` 換成第三章複習題（石頭為何落在桅腳），切線三選移到 `D1-1/c1`。

**這個重新分配本身是好的**（先驗證玩家帶著前章成果、再考新概念），但要注意兩個連帶影響：
1. 設計文件寫「D0 產出＝切線預測紙（封存）」，現在產出在 `D1-1`——設計文件此處已過期，建議回填。
2. `D0-2` 因此變成「兩個考題」（`c0` 邊界判斷＋`c1` 前章複習），而 `D1-1` 只剩一個三選一。互動密度前重後輕，這是 `D1-1` 顯得單薄的另一個原因（見型態 5）。

### `D1-2` 同一把尺 ⚠️ 型態 3＋5｜**使用者說的「書桌推演字詞不清楚」主要在這一場**

#### 🔴 落差一：「距離平方」是全章第一個抽象概念，**零生活類比**

> `n10` 牛頓：「把六十秒換成一秒，**再按距離平方把地表那個數縮小**。現在，兩張紙可以用同一把尺讀了。」

設計文件 §一.5 文字五查第⑤條寫得很死：

```

D-INT-1
D2-1
D2-2
D3-1（= runtime D4-1）  磁鐵類比才登場      ← 隔了四場

**類比遲到四場。** 玩家要在完全沒有直覺支撐的情況下，先做一次 3600 倍的換算判斷。

而且磁鐵類比在 `D4-1` 有它自己的戲劇功能（對帳桌上與攪茶類比並列、對照兩個模型），**不宜整個搬走**。

#### 建議：在 `D1-2` 補一個**輕量的、只負責「平方」直覺**的類比

牛頓時代已知的燭光平方反比，國中生也有生活經驗，且與磁鐵不重複（磁鐵管「隔空＋變弱」，燭光管「為什麼是平方」）：

> **`n10` 建議改寫**
> 牛頓：「把六十秒換成一秒。再來，要按距離把地面那個數縮小——不是縮六十倍，是縮六十的平方。」
> **（新增節點）** 牛頓：（把蠟燭往後挪）「你看這片牆。燭火退遠一倍，牆上同一塊地方分到的光，不是少一半，是只剩四分之一。光攤在越來越大的球面上，攤薄的速度就是這樣。」
> **（新增節點）** 旅人：「所以遠六十倍，就只剩三千六百分之一。」
> 牛頓：「現在，兩張紙可以用同一把尺讀了。」

這同時把 `e1` 要玩家做的判斷（「看出 60 和 3600 的關係」）**變成玩家自己推出來的**，而不是 embed 裡的一道換算題——更符合「玩家出判斷」。

#### 🟡 落差二：設計文件的「陷阱抉擇」在 runtime 消失了

設計文件 §二 D2-2 v3 第 1 步：

> 「**陷阱抉擇**：兩張紙都寫 4.9，『一樣＝證明了』被牛頓擋下（『先把時間還清』）。」

runtime 的處理是：`n3` system 直接說明兩張紙**內容不同**（上：牛頓估算 4.9 公尺；下：旅人的 1、3、5、7 比例），然後 `n4` 旅人**自己**說「等一下。這個 4.9，不是我量的。」

**這在證據誠實度上是更好的處理**（旅人的斜面紀錄本來就沒量過垂直落下，`n6` 還回扣了第一章「垂直，你量過嗎」——很漂亮）。
**但代價是：一個玩家判斷拍變成了旅人的自動台詞。** `D1-2` 在 scenes 層可見的玩家判斷，只剩 `c0`（要不要問月距來源）。

這不是必須改的錯誤，但值得記在帳上：**`D1-2` 是全章玩家動詞最少的一場**（設計文件 §一.4 要求「每場設計先清點玩家動詞，無判斷＝打回」）。若上面的燭光類比改寫採用，把「所以遠六十倍，就只剩三千六百分之一」做成玩家選項（三選：60 倍／3600 倍／不變），就能把這一拍還給玩家。

#### ✅ 做得好的部分
`c0`「先問：月亮有多遠，這個數字從哪裡來？」→ `q1`–`q3` 的來源鏈，完整兌現了設計文件的「60R 來源鏈」，而且牛頓那句「**量月亮，不用等我。**」極好——一句話把「這個數字比我老一千八百年」的份量講出來了。

`n22`→`n28` 六個節點完成：**動機（我要一條規矩）→ 定義（切成一小段，叫一拍）→ 玩家複述（你把一條不停的路，拆成一拍一拍算？）→ 確認並展開（一拍之內先直走，走完再扳一點）→ 玩家自己推出任務（所以我要給的規矩是：每一拍，往哪扳、扳多少）→ 補第二個變數（還得配上它跑多快）**。

**這正是 `D1-1/ok2` 該有而沒有的東西。** 建議把這一段當成本章其他概念（借條、刻痕帶、球殼）的改寫範本。

#### ✅ 山頂大砲（`n36`–`n39`）是全章最好的生活類比
「打得慢，砸在山腳；快些，砸得更遠；再快些⋯⋯快到某個份上——它還是一直在落，可地面一直在腳下彎走。」——完全符合文字五查⑤，而且是玩家已經有的生活經驗（丟東西）。

#### 🟡 落差：「三拍／二十七拍」的分工只寫在 hint，沒進對話（型態 4）

`e1` 的 hint：
> 「⋯⋯**前三拍由你親手重對，牛頓再沿同一規則續畫二十七拍**。」

設計文件 §一.4 是全章的**核心分工原則**：

> 「**牛頓出力氣，玩家出判斷**——粗活（幾何、計算、二十七步重複）歸牛頓；判斷（預測、封存、換算選擇、指認、斷言）歸玩家。」

但 scenes 層**沒有任何一句台詞讓牛頓說出這個分工**。玩家只在 UI hint 看到，事後才由旁白 `n29`「第三十拍落下」被動得知。

結果：玩家不知道自己為什麼只畫三拍就結束，也感受不到「我出判斷、他出力氣」這個本章想傳達的合作關係。

#### 建議：在 `n28` 與 `e1` 之間補一句牛頓

> **牛頓（新增）**：「頭三拍你自己扳。方向對不對，紙會告訴你——我不糾正。剩下的二十七拍我來。**同一條規矩重複二十七次，是力氣活，不必兩個人都做。**」

這一句同時做三件事：交代分工、解釋為什麼玩家只做三拍、兌現「幾何自己當裁判」（設計文件 §二 D1「角度不吸附不糾正」）。

（原設計還有一句旅人心聲「我第一次看見有人把耐心用成武器」——那句在 runtime 找不到，若要放回，接在 `n29` 後最合適。）

### `D3-1` 哈雷帶著木匣進來（K3 封存火星木星） ⚠️ 型態 2

#### ✅ 「為什麼要封存」講得極清楚——全章鋪陳最好的動機拍
> `n29` 哈雷：「你們先寫下預測，滴上蠟。我再開包。」
> `n30` 牛頓：「你信不過我？」
> `n31` 哈雷：「**我信不過任何人的記性，包括我自己的。看過答案以後，人都會覺得自己早就知道。**」

玩家在進 embed 之前，完全清楚自己要做什麼（先寫預測再封蠟）以及為什麼（防的不是撒謊，是記憶會自己改寫）。**這一拍不需要任何修改。**

#### 🔴 落差：「刻痕帶」——本章最重要的判讀裝置，**scenes 層零解釋**

設計文件 D2-3 附註把讀法寫得清清楚楚：

> 「**紙帶刻痕版為正案**：行星每回到起跑星位打一刻，預測帶與觀測帶並排；**刻痕對齊＝規則活著，錯開＝死了**；÷距離觀摩＝十年內預測帶打兩刻、觀測帶一刻未到。」
>
> 讀法一句＝「**疊著走＝規則活著，拉開＝規則死了**」

而 runtime 裡「刻痕帶」總共出現三次，全部是當成既有事實被提及：

| 節點 | 原文 |
|---|---|
| `e1` hint | 「**刻痕帶**、兩條看似可行的錯路與錯誤斷言都留在帳上。」 |
| `n37` 旁白 | 「兩個封口、拆包後的觀測與**十年刻痕帶**都留在牆上」 |
| `n41` system | 「木匣、封包、滴蠟與**刻痕帶**仍留在桌上。」 |

**沒有任何一句話說明：刻痕帶是什麼、刻痕怎麼打、對齊代表什麼、錯開代表什麼。**

這一點特別值得提出來，因為**設計文件本身記載這個裝置觸發過「難懂即換」條款**——總監兩度對原本的「對照盤」提問，才把載體換成刻痕帶。**載體換了，但讀法沒有寫進台詞。** 換句話說，換載體想解決的問題並沒有被解決。

#### 建議：在 `n29`（「你們先寫下預測，滴上蠟」）之後、`e1` 之前補兩句

> **哈雷（新增）**：（在木板上釘下兩條紙帶）「行星每繞回同一顆起跑星，就在帶子上打一刻。上面這條照你們的規矩算，下面這條照佛蘭斯蒂德實際看見的。」
> **哈雷（新增）**：「兩排刻痕疊著走，你們的規矩就還活著。哪一天拉開了——**差一格是一格，那就是死了**。火星年短，藏得住；木星要走十一年多才回來一次，藏不住。」

第二句順帶兌現了設計文件的另一個未落地要點：「**木星（路遠年長）能揭穿火星藏得住的誤差**」——這是玩家理解「為什麼要封兩顆行星而不是一顆」的關鍵，runtime 目前也沒說。

### `D4-1` 對帳桌（K4 三天空×兩模型） ⚠️ 型態 2（兩處）

#### ✅ 兩個類比都完整落地，這是全章執行最好的一場
- **攪茶**（`n5`–`n8`）：由**旅人自己講出來**（「像攪一杯茶。水轉，茶葉就跟著轉——不是茶葉自己想轉。」），哈雷回「太陽是湯匙，行星是茶葉。他講得比劍橋一半的人清楚。」——類比＋角色互動＋玩家成就感，一次到位。
- **磁鐵**（`n14`–`n15`）：牛頓放下磁石與鐵針，「像這個：不碰它，也拉它；離得越遠，拉得越弱。**只借這兩件事。別的不借——磁石只吸鐵，這股勁什麼都拉。**」——連設計文件要求的守門句都逐字兌現了。

#### ✅ 蓋章的「無股份的手」名目講得很清楚
> `n25` 哈雷：「牛頓不能蓋——規矩是他的。我不能蓋——書是我要印的。你既不是規矩的作者，也不是出錢印書的人；這桌帳裡，只有你沒有輸贏。」

#### ✅ 三種章的定義清楚
> `n23` 哈雷：「章有三種：對上了——有數字，而且相合；講得通——只有說法，沒有數字可核；對不上——有數字，但不合。」

#### 🔴 落差一：「**借條**」——本章第二核心概念，**scenes 層零解釋**

設計文件把借條寫成整個 K4 的勝負機制：

> 「借條×2（行星：各行星流層另設速度；彗星：可穿透流層＝大借條）」
> 「③核心不對稱：距離律靠**殘差**誠實活著⋯⋯渦旋靠**借條**續命；**解釋成本＝帳上數得出的張數**。」

runtime 裡「借條」出現四次，全部沒有定義：

| 節點 | 原文 |
|---|---|
| `n28` system | 「決定是否留下**不可撕的借條**」 |
| `e1` hint | 「決定是否留下**不可撕的借條**」 |
| `n29` 旁白 | 「哈雷只把真的貼出來的**借條**⋯⋯收進木匣」 |
| `n30` 哈雷 | 「哪一本必須另貼**借條**」 |

**玩家不知道：借條是什麼？為什麼叫借條？貼一張代表什麼？貼多了會怎樣？**

而這正是本章終局判準的全部——「哪一本帳欠得少」。玩家在不懂借條的情況下操作 `e1`，等於在不知道計分規則的情況下比賽。

#### 建議：在 `n23`（三種章）之後補一句哈雷

> **哈雷（新增）**：「還有一樣。有些格子，一本帳非得多加一條特別規定才對得上——比方說『這顆星的流，另外算一個速度』。那種時候，就在格子旁邊貼一張借條。」
> **哈雷（新增）**：「借條撕不掉。意思是：**這一格它不是算對的，是先欠著過去的。** 三份對完，我們數誰欠得多。」

（「借條撕不掉」呼應設計文件的「不可撕」，並讓玩家知道這個決定有後果。）

#### 🟡 落差二：「**過帳**」是會計術語，第一次出現時沒有白話對照

> `n21` 哈雷：「三份都要**過帳**。」

「過帳」對國中生不是日常詞。而且它是整場的動作名稱，出現在 `n21`、`n28`、`e1` hint、`n29`。

**建議**：`n21` 改為
> 哈雷：「三份都要上桌，一格一格對過去。拉力帳的平方規矩不准動，漩渦帳的流速表也不准動。中途改任何一條，整桌帳作廢。」

後續節點沿用「過帳」無妨——首次出現時給過白話對照就夠了。

### `D4-2` 印刷台（K5） ⚠️ 型態 2＋3

#### 🔴 落差一：「**六槽／六處空位**」沒有解釋

> `n5` 旁白：「版框中央留著**六處空位**。最後一處仍寫著二十年前留下的問題：『憑什麼從地心量？』」
> `e1` hint：「接好**六槽證明鏈**⋯⋯」

玩家不知道六個槽分別是什麼、為什麼是六個、為什麼要「接成鏈」。

**建議**：`n5` 改寫，把六槽的意義說出來
> **stage（改寫）**：版框中央留著六處空位——這本書的骨幹是六段證明，一段接一段，缺一段，後面就撐不住。最後一處還空著，上面壓著一張二十年前的紙條：「憑什麼從地心量？」

#### 🔴 落差二：「**均勻球殼**」——全章最抽象的概念，**零類比**（違反文字五查⑤最嚴重的一處）

> `n7` 牛頓：「一個均勻球殼，對殼外物體的拉力，等效於把整個球殼的物質集中在球心。」
> `n8` 牛頓：「把整顆球拆成一層一層的同心球殼，這個結果就能一層層相加。」

這是二十年問號的收束、全章的情感高點，卻用教科書語一次講完，而且沒有任何生活類比承接。國中生讀到這裡會直接失去。

（此處與我在口語自然度審查中的 A-3 是同一個節點，但那份談的是語體，這裡談的是**理解鷹架缺失**——兩者要一起改才有效。）

#### 建議：把 `n7`–`n9` 擴成有鷹架的四拍

> **`n7` 牛頓（改寫）**：「一個厚薄均勻的球殼，拉外面的東西的時候，跟把整個殼的重量全擠在球心一樣。」
> **（新增）旅人**：「怎麼會一樣？近的那半明明比較近。」
> **（新增）牛頓**：「近的那半拉得重，可是它擠在你正前方那一小塊；遠的那半拉得輕，卻攤得又寬又廣。**一邊多一點，一邊少一點，加起來剛好抵成一股從正中心來的拉力。** 我算了二十年，就是算這件事。」
> **`n8` 牛頓（不動）**：「把整顆球拆成一層一層的同心球殼，這個結果就能一層層相加。」
> **`n9` 旅人（不動）**：「所以從地心量，是可以的。」
> **`n10` 牛頓（不動）**：「現在是。二十年前不是——二十年前我只是假設它可以。」

（「我算了二十年，就是算這件事」同時把 `D1-2` 剎車拍的問號、`n10` 的「二十年前我只是假設」串成一條線——這也是被刪掉的 legacy 心聲「那個問號，他補了二十年」原本承擔的工作。）

#### 🟡 落差三：`e1` hint 是全章最複雜的一段操作說明，但寫得最公文
> 「接好六槽證明鏈，放入球殼頁，保持預測早於觀測；精確寫下虎克的兩項貢獻，並把來源接回哈雷、佛蘭斯蒂德與牛頓。最後由你移走旅人的作者名條，留下尚未解明的機制，再壓下印刷機。」

一句 78 字、五個動作、三個規格詞。**這也是本章戲劇份量最重的一拍（旅人親手把自己的名字拿掉）**，說明文字卻讓人讀不下去。

**建議**：
> 「六段證明接起來，把球殼那一頁放進第六槽。預測要排在觀測前面。虎克做過哪兩件事，寫清楚——別多寫，也別少寫。來源接回哈雷、佛蘭斯蒂德和牛頓。最後，把你自己的名條從作者欄拿走；還沒弄清楚的那一格，留白。然後壓下印刷機。」

## 五、一句話結論

**第四章的互動設計本身是好的，五個證據的形式（作圖／對帳／封存／兩本帳／署名）也確實兌現了「書桌章」的定調。落差集中在一件事上：設計文件裡寫得很清楚的「這個裝置怎麼讀」，在轉成 runtime 台詞時被當成已知略過了。**

`D1-1/ok2` 是這個問題最尖銳的表現形式——它甚至不是「略過解釋」，而是「把一個還沒被解釋的詞，提前三場拿出來用」。

修法不需要動任何因果邏輯或機制，只要在每個裝置第一次出現時，補上設計文件裡**已經寫好的那一兩句讀法**。`D2-1` 的「拍」與 `D4-1` 的攪茶／磁鐵證明了：**這個團隊寫得出好的概念鋪陳，只是沒有每一處都寫。**
