## 三、宣稱 5｜81.7 毫米錯紙：數字正確，而且錯在對的地方

**我獨立驗算**：月球在 60 秒內落約 4.9 公尺（與地表 1 秒落 4.9 公尺數值巧合）。換成 1 秒應除以 60²＝3600 得約 1.36 公釐；錯答除以 60 得 **4.9 ÷ 60 ＝ 81.67 公釐**。與文案「約 81.7 毫米」相符。

更重要的是**錯的性質對**：error code 命名為 `time-not-squared`，文案寫

> 紙上會得到約 81.7 毫米，但那只把六十秒平均切開。斜面紙帶顯示落距跟時間的平方一起變；這張退件留下，再換一次。

這是**時間**平方的錯（60 秒→1 秒），不是距離平方的錯，描述沒有混淆；而且回連第一章斜面紙帶的等時段比例（1:3:5:7），把玩家自己量過的東西當成判準。**這一項寫得好。**

## 四、C-1｜81.7 那段文案硬寫兩處，會走針

**位置**：`greybox/src/chapter-ui.js:5717` 與 `6451`。

**實際證據**：兩處逐字相同——

- `5717`：error-code 對應表裡的 `"time-not-squared"` 項。
- `6451`：「除以 60」按鈕 callback 內的 fallback 字串。

**因果問題**：同一句退件說明存在兩份真相。改一處漏一處時，玩家在不同觸發路徑會看到不一致的說明，而測試不會紅（兩處都還是合法字串）。這與本專案反覆遇到的「雙份真相」是同一類。

**最小修法**：`6451` 改為查 error-code 表，不自帶字串：

```js
doOrbit("convertMoonTime", { choice:"divide-60" }, function (rr) {
  if (rr.ok) return "✓ 已換成一秒。";
  return orbitErrorText(rr.error);   // 單一來源
});
```

**可失敗的驗證條件**：改動 `5717` 的文字後，`6451` 觸發路徑顯示的內容必須跟著變；新增契約可斷言 `chapter-ui.js` 中「81.7 毫米」只出現一次。
