# 《發現之前》第四章實驗台互動設計診斷——三方交叉驗證整合報告

**日期**：2026-08-05
**觸發原因**：總監親自試玩後判斷「劇本邏輯還行，但可能是互動的地方設計得不好」，要求三方深入`chapter-ui.js`的`orbit4`系列渲染函式與`engine4.js`的action邏輯，找出K1-K5互動層的具體問題。
**方法**：claude、codex、gemini三方獨立走查，我對三方最關鍵的技術claim逐一讀原始碼核對（不採信文字描述）。claude因中途連線中斷，先交K1/K2深讀＋全章框架分析，K3-K5由codex的完整走查補齊，三方在重疊部分完全互證。

---

## 一、總裁決：劇本判斷正確，問題確實在互動呈現層——但不是「缺導覽」，是「導覽的每一格都填錯了內容」

三方一致：K1-K5的物理邏輯與狀態機設計是對的（codex：「規則、封存、揭曉、借條全部有真後果，沒有代做認知步驟」），**不需要重寫任何一站的核心邏輯**。但claude提出全篇最精準的框架：**第四章的導覽骨架其實比其他章都完整——有任務卡、有「為什麼現在做這一步」、有「現在只做一件事」、有進度數字、有定位提示、有分區——問題是這些格子裡填的內容經常是錯的或矛盾的**，不是空的。

---

## 二、⭐ 兩個最重要的發現（三方獨立互證，我已讀原始碼確認）

### 發現一｜K2的核心互動圖被放進錯誤的區塊（codex最先發現，claude獨立確認）

```js
chapter-ui.js:6567  if (phase === "scale") orbit4ScaleSheets(visual);   // 左側「I 書桌推演」只拿到兩張靜態氣氛紙
chapter-ui.js:6568  else orbit4Svg(visual, lab, phase);                 // 其他站都在這裡放可判讀的SVG
chapter-ui.js:6766  orbit4ScaleGeometry(work, sc);                      // ★真正的正矢幾何圖，被放進「II 旅人筆記」操作區
```

**K2是六站裡唯一一站，左側視覺區沒有放真正該判讀的圖。** 玩家被要求「從圖上指出向內差距」，但左邊只有靜態氣氛紙，真正的幾何圖藏在右邊操作區裡，跟一堆按鈕擠在一起。玩家自然會往左邊找、找不到、覺得不知道要幹嘛。

### 發現二｜K2階段的定位提示被CSS主動藏起來（gemini與codex分別命中一半，claude確認為全章唯一）

```css
stage.html:2299-2300
#controls.orbitLab[data-phase="scale"] .orbitEvidenceChips .empty,
#controls.orbitLab[data-phase="scale"] .orbitEvidenceChips .todo { display:none; }
```

`.todo`就是「這一輪追：地月紙」這個chip——唯一告訴玩家這一站要拿什麼證據的元素。claude確認**K2是六個相位裡唯一同時把`.todo`和`.empty`都藏起來的一站**，結果玩家在最需要方向感的K2，表頭只剩年代地點跟一個`n/5`數字，沒有任何一句話說這一輪的目標是什麼。

**這兩個發現疊加起來，剛好命中總監原話裡最具體的symptom**——K2（同一把尺／60↔3600那一站）正是總監提到「不知道要幹嘛」最核心的段落。

## 三、claude發現的框架性洞察：導覽格子「填錯內容」對照表

| 導覽位置 | 應該放什麼 | 實際放了什麼 |
|---|---|---|
| 「現在只做一件事」卡片 | 玩家下一個具體動作 | 一整張任務清單（K1有4個下拉+2階段、K4是3列×蓋章、K5是4組任務） |
| 左側視覺區「I」編號 | 暗示先在這裡看 | 玩家誤以為先在這裡操作（但K2完全不可互動） |
| 按鈕/題幹動詞（K2） | 描述玩家實際能做的判斷 | 「圈」「連起」暗示可以在圖上畫，但SVG是`role="img"`不可互動 |
| 開場站（K0/tangent）的定位chip | 這一站要拿什麼證據 | `PHASE_TARGET.tangent = null`，完全沒有；且顯示「還沒有能夾回去的紙」 |
| 下拉選單的placeholder | 你要選什麼 | 「（未預選）」——這是在解釋一條製作端的設計原則（不給預設答案），不是操作提示，claude統計K1五個下拉全部有這個問題（另外還有K2的`結論尚未預選`跟K4的`先選總結範圍`，共7處） |

claude的結論：「玩家看得到目的、看得到範圍、看得到進度，唯一看不到的是『現在，手要點哪裡』」——這句話精準抓住了問題本質，不是「太少說明」，是「說明的內容錯位」，所以單純加更多文字反而會讓問題更嚴重（變得更像使用手冊）。

## 四、K1-K5逐站問題彙整（以codex的完整走查為主幹，補入claude/gemini的獨立發現）

### K1｜逐拍改向
- 四個下拉（方向/初速/箭長/路徑預測）要一次填完才能封存，且玩家還沒看過任何路徑結果，認知負荷偏高（呼應設計文件自己列出的真人風險）
- 左圖橘箭看起來像可操作，實際只能用右側轉鍵，圖與控制沒有hover/focus對應
- claim panel（勾兩張紙、選結論）是完成主線後突然長出的第二份表單，玩家容易誤以為早就做完了
- 回饋訊息在頁面最底部，`orbit4RenderPreserving`刻意保留原本捲動位置，導致按了按鈕常常看不到回饋

### K2｜地月同尺
- 見上方發現一、發現二
- 題幹「圖上的哪一段」沒有指明是哪一張圖（左邊兩張raster還是右邊的幾何SVG）
- 4.9m與1.36mm並排卻沒有可見的單位換算過程，四個倍率選項容易變成盲猜
- 第三步用「兩個60」措辭，但畫面實際是「距離60」跟「倍率3600」，關係更難讀懂

### K3｜封存行星預測
- 「遠、弱、慢、路長」的推理依據在設計文件裡，工作台上只剩距離比與週期下拉，第一次玩容易感覺在猜彩券
- 兩張一起拆封後，任務卡文字沒跟著更新，仍停留在「先押週期」的舊指示

### K4｜兩本帳與借條
- **開場不是對帳，是先跳出一個印刷排程的二選一**（`models`階段開場文字實測為「先處理印刷排程，再逐列對帳」，且明寫「做完才開對帳桌」）——K5性質的決定被塞在K4最前面，玩家容易懷疑自己是不是進錯站
- 「殘差0.8%/1.6%/2.2%」這類數字沒有持續顯示判準，玩家不知道該蓋「對得上」還是「對不上」
- 加借條後，畫面只顯示借條數量，沒有清楚呈現「原本的落差還在＋多借了一個假設」，容易誤解成「借條=補好了」

### K5｜出版校樣
- 全章操作步驟最多的一站，卻沒有局部導航（來源鏈→信用線→作者欄→證明邊界→送樣）
- 「翻出球殼頁」跟「放進第六槽」是兩次意義相同的點擊，中間沒有新判斷
- 送樣/延後按鈕從頭到尾固定在最底部，跟正在處理的斷槽距離很遠，且沒有明講「送樣跟延後都會消耗一個窗口」，只用紅色表達危險不表達成本

## 五、實測驗證的技術細節（我親自核對，非採信文字）

- `.orbitLab .orbitAction { min-height:42px }`與`.orbitRuleDesigner .shipSelect { min-height:42px }`——按鈕與選單確實是42px，未達44px無障礙觸控標準（codex發現，我已核對）
- `orbit4Mission`表裡vectors/models/proof三站的mission[1]確實是多件事清單而非單一動作（claude發現，我已讀完整表格核對）
- 「（未預選）」/「尚未預選」佔位字樣共7處，不是claude原本列的5處（我核對時多找到2處：`結論尚未預選`與`先選總結範圍（尚未預選）`）
- `.orbitVisual { align-self:start }`（不捲動）／`.orbitWork { overflow:auto }`（唯一的工作區）——確認pane I（書桌推演）與pane II（旅人筆記）在版面上的捲動行為不對稱

## 六、修法優先順序（三方一致同意的順序）

**若只做三處（投報率最高，合計不到30行程式碼）**：
1. 拿掉`stage.html:2299-2300`那條CSS，讓K2階段恢復顯示「這一輪追」提示
2. 把「現在只做一件事」的內容從「整站任務清單」改成「當前狀態下的下一個具體動作」（需要依state分歧，不是純文案）
3. K2的按鈕/題幹動詞改成跟實際操作一致的判斷語（不再用「圈」「連起」這種暗示可畫圖的詞）

**其餘依優先序**：
4. 把K2的`orbit4ScaleGeometry`真正移回左側視覺區，讓圖與判讀真正對上（這項claude、gemini都建議，但涉及調整渲染呼叫位置，工程量比純文案修法略高，codex估0.5-1日）
5. 操作後的結果訊息搬到操作點旁邊，並在新表單出現時把焦點/捲動位置帶過去（不要固定捲動在原位）
6. K4把印刷排程決定明確標成「進桌前的一次性決定」，做完後才顯示「K4對帳桌」標題；並在蓋章格旁固定顯示判準說明
7. K5加局部步驟導航，並把「翻出球殼頁」與「放進第六槽」合併成一個有意義的動作
8. 按鈕/選單觸控尺寸從42px補到44px
9. 開場站（K0/tangent）補上定位chip，不要用null
10. 下拉選單移除「（未預選）」這類製作端語言的佔位字

**不建議做**：K1-K5做成一條全章五格進度條——codex指出K編號是證據ID不是嚴格遊玩順序（實際可達順序是K2→K1→K3→K4→K5），硬做進度條反而會製造「倒退」的錯覺，應該顯示「目前拿的是哪張紙、這張紙第幾步」，不是全章進度。

---

## 七、直接回答總監原話「實驗台互動區有點不知道要幹嘛」

三方收斂到同一個結論：**不是缺說明，是說明的內容放錯了位置。** 目的卡、任務卡、進度數字、分區標籤、定位提示——這些導覽元件全部都在，但內容經常跟玩家實際該做的下一步對不上（一張卡裝了六件事、編號暗示先看不可互動的那一半、按鈕動詞承諾了不存在的操作、K2最需要提示的時候提示被藏起來）。修法不是加更多文字說明（那只會更像使用手冊），是把每個既有欄位裡的內容換成真正對的東西。

## 八、未能驗證

三方一致：本輪均為靜態程式碼走查與action/state追蹤，未做瀏覽器逐站實玩，未判斷美術與圖像品質。claude有一項待驗未完成：表頭`?`鈕呼叫的`window.BD_showLabIntro()`是否有針對第四章I/II雙欄結構的專屬說明，若只是通用實驗台說明，則玩家卡住時唯一的求助管道對本章可能沒有實際作用——這點留待下一輪確認。
