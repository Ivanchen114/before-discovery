# 《發現之前》第四章實驗台程式設計盤點

**審查者**：Codex
**日期**：2026-08-03
**性質**：唯讀程式與互動設計審查；未修改 runtime、資料、遷移或測試檔

## 一、總裁決

第四章的**狀態完整性明顯強於遊戲性**。引擎很認真地保留封存順序、錯誤嘗試、借條、錯稿與舊存檔邊界，但玩家實際操作的品質落差很大：

- **K1 牛頓作圖法**有本章最強的物理操作骨架，但目前存在兩個會掏空主體性的問題：固定三次同方向轉鍵即可逐拍過關；玩家畫的前三拍也沒有真的接進牛頓後續軌道。
- **K2 同一把尺**概念正確，卻主要是四題連續選擇題，較像換算學習單。
- **K3 火星／木星封存**是 runtime 與 canonical spike 落差最大的一站；原型裡真正有戲的「先想、滴蠟、拆包、刻痕帶」被壓成單次點擊。
- **K4 對帳桌**最接近「牛頓出力氣，玩家出判斷」：系統算，玩家判讀模型與承擔補丁。但錯章只彈回、借條只改文字，後果仍可更具體。
- **K5 印刷台**有真正的風險與永久錯稿，是本章最有遊戲性的後果系統；但流程過長，免費預覽又會逐項報答案，容易退回核對清單。

因此我的結論不是「第四章互動不好玩」，而是：**有兩座好系統被實作細節削弱，兩座仍停在習題／清單層，只有對帳桌與錯稿送印已接近可保留的最終形態。**

## 四、逐站盤點

## 4.1 K1 牛頓作圖法

### 已經做對的部分

1. 玩家先封存方向、初速、箭長與路徑預測，才可落第一拍。`sealOrbitRule()` 沒有預設值，契約清楚。
2. 慢×短、中×中、快×長都可形成近圓，不把「中間選項」偷偷設成唯一答案。`run-node.mjs:6490-6548` 也鎖住九宮格結果。
3. 錯拍會留下 `manualAttempts` 幽靈紙；重置不會洗掉錯線。這符合本作「失敗留痕」。
4. UI 保留鍵盤與 44px 轉鍵，canonical spike 明確說明移除拖曳是為了橫屏與無障礙，不應為了表面直覺就把 pointer drag 強塞回來。
5. `orbit4CaptureViewport()` 與焦點恢復避免每次重繪把手機玩家甩回頁首，這是紮實的互動工程。

### P0-1：固定三次轉鍵可取代逐拍判斷

`sealOrbitRule()` 與每次 `commitOrbitBeat()` 後，都把下一支箭固定設為：

```text
當下正確方向 + 0.6 rad（約 34.4°）
```

UI 每次轉 6°，而有效容差是 18°。因此玩家每一拍只要固定按三次逆時針，就會留下約 16.4° 的誤差，三拍全部通過。

我直接重跑引擎得到：

| 拍 | 固定操作 | 誤差 | 結果 |
|---|---|---:|---|
| 1 | 逆時針 3 次 | 16.4° | 通過 |
| 2 | 逆時針 3 次 | 16.4° | 通過 |
| 3 | 逆時針 3 次 | 16.4° | 通過 |

`manualComplete=true`。也就是 UI 雖寫「重新判斷現在的中心」，實際最有效策略是記住按鍵次數，不必看地球位置。

**物理損失**：玩家沒有學到「位置改變後，向內方向也要重算」，只學到一個固定節奏。

**具體修法**：

- 抽出可重播的 `orbitAimOffset(attempt, step)`，讓三拍的偏角方向與幅度不同，例如正、負、正，且不是 6° 的固定整數倍。
- 引擎與 audit 都用同一個 deterministic 函式，不用隨機數，避免存檔不可重算。
- 對既有 schema 2 半成品存檔保留舊 `+0.6` audit 相容分支；新封存的規則附 `aimPatternVersion:2`。不要直接改常數後讓舊半成品被 sanitizer 當偽造。
- 新增契約：連續三拍使用同方向、同次數轉鍵，至少一拍不得通過；改變月亮位置後，下一拍的合格方向必須真的改變。

### P0-2：玩家前三拍沒有真的交給牛頓續畫

這是比按鍵捷徑更核心的問題。

`commitOrbitBeat()` 確實更新玩家紙上的 `position`、`velocity` 與 `path`；但 `continueOrbitRule()` 接手時，直接呼叫：

```js
simulateOrbitRule(seal.target, seal.speed, seal.strength)
```

它從標準起點重跑整條 canonical 軌道，沒有把玩家第三拍留下的 `o.position`、`o.velocity`、`o.path` 當續畫起點。最後 `o.path` 還被 canonical `sim.path` 整筆覆蓋。

因此玩家前三拍目前只是**資格門檻**，不是結果的一部分。只要三箭落在 18° 容差內，精確方向如何不同，牛頓都畫出同一條標準路徑。

**這直接違反本章最好的分工承諾**：「規矩是你的，前三步你自己來；剩下的他接著畫。」

**具體修法**：

1. 新增 `continueOrbitFromPlayerState()`，以玩家第三拍後的 `position`、`velocity`、`path` 為起點，牛頓只續畫後面的拍數。
2. `run.path` 必須保留玩家三拍作為 prefix；第四個點必須由第三拍狀態算出，而非重新從初始狀態生成。
3. `orbitRunAudit()` 同樣先 replay 玩家三拍，再 replay 牛頓續畫，逐點驗證。
4. 新 run 加 `continuationMode:"player-state"`。既有已完成存檔沒有該欄時，走 legacy canonical audit，避免舊存檔全毀。
5. 重新檢查九宮格分類。玩家容許的小角度誤差應讓近圓變成窄帶，而不是把三個配對的物理分類變成運氣。

### 次要問題

- 玩家一開始同時選四項，抽象負荷偏高。可先選「每拍朝哪裡」，再讓速度與箭長以兩條可比較的視覺帶呈現，最後封存形狀預測。
- 目前表格會顯示每拍角度誤差。這適合教師／學者模式；探索模式應優先讓玩家看箭頭與地心線疊合，數字可折疊。
- 三拍後的「請牛頓續畫二十七拍」是好交棒，應保留。

### 本站結論

**概念骨架最好，但目前不能算真正完成。** 修完 P0-1、P0-2 後，K1 才會從「帶動畫的三次校準」變成全章招牌互動。

## 4.2 K2 同一把尺

### 已經做對的部分

1. 先封存量級預測，再換算與揭露，錯押注留在紀錄中。
2. 牛頓負責月距與幾何來源，玩家只需判斷「60 秒如何換成 1 秒」以及兩張紙能否同尺比較，方向上符合角色分工。
3. `ch4-migration.js:603-635` 只在舊紀錄足以驗證時重建 canonical K2，沒有把舊自由欄位冒充成新操作。

### 問題：四步操作仍是算術學習單

目前流程是：

1. 猜剩多少。
2. 選除以 60 或 60×60。
3. 選 4.9 m 與 1.4 mm 差幾倍。
4. 選 60 與 3600 是相加還是相乘。

第 2 步成功回饋已說出「時間平方、除以 60×60」；第 3 步又確認 3600；第 4 步再問「60 與 3600 的關係」。玩家不是用紙做判斷，而是在連做三題彼此提示答案的小測驗。

**一句話替代測試**：把整站換成「牛頓算出月球一秒偏 1.4 mm，與地表差 3600 倍」後，後續劇情幾乎不變。這表示目前互動還沒有產生不可替代的證據形狀。

### 低成本改法

不必先改 engine schema，可只重做 UI 表現並沿用四個 action：

1. 把兩張紙做成可見的「60 秒紙」與「1 秒紙」。玩家不是選除數，而是把時間尺折一次或折兩次；錯折後月球紙仍大到無法與地表紙疊合。
2. `convertMoonTime` 仍接收 `divide-60`／`divide-3600`，只是操作物件改成紙尺，不再是裸按鈕。
3. 把倍率與關係合成一拍視覺判斷：60 格距離尺疊到 3600 格弱化帶，玩家選「一層」或「兩層」折疊。底層仍可依序呼叫 `judgeScaleRatio`、`judgeScaleRelation`，但畫面只呈現一次完成操作。
4. 錯誤不要只顯示紅字；讓兩張紙實際對不齊，並保留上一張錯折的淡影。
5. 探索模式先不顯示「第 1-4 步」；教師模式可保留逐步數字。

### 本站結論

**物理正確，但不夠像操作。** 這站不需要更複雜的引擎，而需要把算術答案變成紙張對不齊／對得上的可見後果。

## 4.3 K3 火星、木星封存預測

### runtime 的核心落差

`predictPlanet()` 在一次函式呼叫內依序：

1. 計算預測。
2. `tick()` 記 `sealedAt`。
3. 再 `tick()` 記 `openedAt`。
4. 立即填入 actual、residual、pass。
5. UI 只有一顆「封存預測，再揭露觀測」按鈕。

資料上確實滿足 `openedAt > sealedAt`，但對玩家而言，封蠟與拆包是同一次點擊。這是**程式有時序、玩家沒有時序**。

更重要的是，數值預測由引擎直接算好。玩家沒有先判斷火星會快／慢、木星是否會放大誤差；唯一真正的判斷延後到兩筆完成後的文字 claim panel。

### canonical spike 已經給出更好的答案

`spike_ch4_D3-1_sealing_v2_CANONICAL.html` 原本包含：

- 火星先選快／慢／一樣。
- 「滴蠟」與「拆包」分成兩個動作。
- 火星對上後，玩家可嘗試改規矩或提前宣布結案，哈雷會以仍封住的木星反制。
- 木星先判斷小誤差會更明顯或更藏得住。
- 預測帶與觀測帶走十年，刻痕是否錯開是可見結果。
- 可觀摩錯誤距離律如何在木星上累積成兩刻對零刻。

這些不是裝飾，而是 K3 的遊戲性本體。runtime 目前只保留了最終資料格式，沒有保留玩家的承諾、誘惑與動態比較。

### 建議修法

**P1 正式修法，不建議用假動畫掩飾：**

1. 拆成 `sealPlanetPrediction()` 與 `openPlanetObservation()`。
2. 封存時 row 只含 prediction、sealedAt；不能先把 actual 寫進 state 再用 CSS 隱藏。
3. 開封時才寫入 actual、residual、openedAt、revealed。
4. `planetLab` 增加火星「快／慢／一樣」與木星「誤差更明顯／更藏得住」的玩家判斷紀錄。
5. 把 canonical spike 的刻痕帶移植為 SVG runtime；`prefers-reduced-motion` 時直接畫完，不取消比較本身。
6. 保留舊 `predictPlanet()` 作為完成態相容 wrapper，或讓 sanitizer 同時接受 legacy 完成 row 與新版 partial-sealed row。
7. 增加「封存後重載頁面，仍只能拆包、不能改預測」測試。

**不建議的低成本假修法**：先播滴蠟動畫，500ms 後自動拆包。它只把一次系統代做拖長，沒有增加玩家判斷。

### 本站結論

**目前是本章最弱站，canonical spike 反而比 runtime 成熟。** 最有效率的方向不是重新發明，而是把已定案 spike 的關鍵互動搬回正式引擎。

## 4.4 K4 三天空 × 兩模型對帳桌

### 為什麼這站最接近成品

1. `beginLedgerRow()` 負責跑兩套模型，玩家不用手算。
2. 玩家要判斷每一格是「對得上／只有說法／對不上」。
3. 行星與彗星失配後，玩家親自選擇是否留下一張不可刪借條。
4. 最終總結依實際借條動態生成，不會用固定成功文字洗掉玩家決定。
5. 彗星硬接會留下可辨認折角，這是全站最好的物理失敗。

這正是「牛頓出力氣，玩家出判斷」：系統提供結果，玩家決定結果可以支持哪個模型、修補的代價是否值得留下。

### 仍然削弱趣味性的地方

#### 1. 錯章只是彈回

`stampLedgerCell()` 會把錯誤寫進 `stampAttempts`，但不把錯章留在格子上；UI 只說「錯章會彈回」。玩家看不到自己把哪張帳蓋壞，只看到驗證器拒絕。

**低成本修法**：利用既有 `stampAttempts`，在格子上畫淡紅、斜線劃掉的舊章，直到玩家補蓋正確章。無需改 engine schema。

#### 2. 借條改變總結，卻沒有造成後續負擔

加借條或拒絕借條都可完成該列；差異主要出現在 K4 總結文字。這是倫理選擇，但還不像遊戲後果。

**低成本修法**：每張借條在桌側增加一格「額外假設負擔」，並一路帶到 K5 校樣頁的附註區。它不扣分、不阻斷，也不把渦旋說寫成愚蠢；只是讓玩家看見「說得通」與「付出多少補丁」是兩件事。現有 `modelLab.loans` 已足以渲染，無需改狀態。

#### 3. 六次蓋章後會重複

兩模型 × 三列都是同一組三選一。月亮的「兩邊一度都能活」是好轉折，但行星、彗星後面操作語法完全相同。

**改法**：保留月亮雙蓋章；行星用數值條對齊後蓋一次「哪本帳先裂」；彗星用方向圖直接選可否通過，再決定借條。底層仍可寫入同一兩格 stamp state，畫面動詞不必三列複製。

#### 4. 開列順序是假選擇

玩家可以任選月亮、行星、彗星順序，但結果表完全固定，順序沒有策略後果，反而可能破壞「先看兩套都能活，再逐步分開」的戲劇曲線。

**建議**：若不打算讓順序影響敘事，就固定月亮起手；行星／彗星可自由。不要把行政順序包裝成策略自由。

### 本站結論

**本章最值得保留的核心互動。** 需要的是把已記錄的錯章與借條變成可見重量，不需要重寫引擎。

## 4.5 K5 出版校樣／印刷台

### 已經做對的部分

1. `submitProof()` 允許玩家在有缺口時真的送印，產生 `wrong-proof`，消耗窗口並保留錯稿。這是本章少數「判斷會改變局勢」的硬後果。
2. 延後也消耗窗口並留下理由，不是免費撤回。
3. 六槽、來源歸屬、虎克範圍、作者欄與結論邊界都存入 state；錯誤不只存在文案。
4. `placeProofLink()` 與 `assignCredit()` 會保留錯配嘗試，來源倫理與出版物件高度一致。

### 問題：真正有風險的送印，被前面的清單工作稀釋

玩家要依序：

1. 填五個來源槽。
2. 翻出球殼頁。
3. 再把球殼頁放入第六槽。
4. 判虎克範圍。
5. 分配四種貢獻。
6. 親手退出作者欄。
7. 選證明邊界。
8. 預覽。
9. 送印或延後。

其中「翻頁」後再「放頁」、「退出作者欄」都只有一個合法動作，主要是在證明玩家有點過，不是判斷。測試確實鎖住了玩家必須親手做，但**親手做不等於有趣**。

### 問題：免費預覽逐項報出缺口

`previewProof()` 本身只回 audit，問題在 UI 把缺槽、錯槽、虎克、署名、球殼頁、作者欄與最後一句逐項列出。玩家可反覆按免費預覽，照清單修完。

這使送印風險從「我敢不敢押這張校樣」退化成「我有沒有漏看驗證器訊息」。

### 低成本修法

1. **免費預覽只顯示物理後果，不報欄位答案**：斷鏈處在版面上裂開、錯名字的來源線脫落、缺球殼頁就讓外層天體那一段懸空。
2. 保留可及性用的詳細文字，但放在「請印刷工逐項念出問題」的明確輔助按鈕；不要默認把答案清單推到所有玩家面前。可記錄提示使用，不必扣分。
3. 合併「翻出球殼頁」與「放入第六槽」為一次真正判斷：玩家先看三個可能缺口，再把頁放到能補上外部天體處理的槽。若因節點／測試鎖不宜改 action，可讓第一次按鈕改成開抽屜，第二步在同一畫面拖放，不再像兩頁表單。
4. 來源槽與四條信用線改成同一張可重排版框，錯配留在紙上；目前每次只顯示下一個 open slot，太像逐題作答。
5. 把三個校樣窗口畫成三張實體紙籤。送錯稿或延後時，當場撕掉／壓掉一張，讓成本不只出現在 `2/3` 數字。
6. 短稿路線若已選，應真的留下可翻看的短稿物件；否則分支只改一行狀態文字。

### 本站結論

**保留送錯稿與窗口成本，壓縮保證正確的程序點擊。** 玩家應把精力放在來源、信用與結論邊界三種真正判斷，而不是證明自己逐項按完。

## 五、與 canonical spike 的落差

| 項目 | canonical spike | runtime | 判斷 |
|---|---|---|---|
| K1 三拍 | 玩家畫三拍，牛頓接手同一紙 | 三拍驗證後重跑標準軌道 | runtime 失去直接因果 |
| K1 起始偏角 | 每拍固定 +0.6 | 同樣固定 +0.6 | spike 的既有缺陷被帶入正式版 |
| K2 同尺 | 四判斷一封蠟 | 基本保留 | 仍是選擇題鏈，未完成物件化 |
| K3 火星／木星 | 先想、封蠟、拆包、刻痕帶、誘惑 | 一鍵封存並揭露 | runtime 大幅退化 |
| K4/K5 | 未由指定 spike 完整覆蓋 | 引擎自行發展出蓋章、借條、錯稿 | K4/K5 的狀態設計反而較成熟 |

最重要的結論是：**spike 被標成 CANONICAL，不代表 runtime 已保留它的玩家動詞。** 契約測試目前偏向驗證時序欄位與 append-only 紀錄，沒有驗證「封存與揭露是不是兩次玩家動作」或「牛頓是否從玩家第三拍真的接著畫」。

## 六、優先修改順序

### P0：不修就會破壞玩家主體性

1. **K1 從玩家第三拍真實狀態續畫**，不再重跑 canonical 路徑。
2. **K1 打掉固定三次轉鍵捷徑**，偏角須逐拍變化且可重播。

### P1：把系統代做改回玩家承諾

3. **K3 分拆封存與開封**，重建火星／木星質化判斷與刻痕帶。
4. **K2 將四題換算改成紙尺折疊與疊合後果**，可沿用現有 engine actions。

### P2：讓既有紀錄變成可見重量

5. **K4 把錯章與借條永久畫在桌上**；借條帶進 K5 附註負擔。
6. **K5 免費預覽改成視覺缺口，不逐欄報答案**；合併保證正確的程序點擊。

### P3：之後再做的表現層

7. 紙籤、封蠟、錯稿壓印動畫。
8. 模型殘差與刻痕的動態轉場。
9. 手機橫屏細部排版與音效。

不要先做 P3。現在最大的問題不是演出不足，而是部分操作沒有進入結果因果鏈。

## 七、建議新增的驗收契約

### K1

- 同方向、同次數轉鍵連做三拍，不得保證三拍全過。
- 玩家第三拍位置／速度改變時，牛頓續畫的第四點必須跟著改變。
- run path 的前三段必須逐點等於玩家 path，不得被 canonical 路徑覆蓋。
- 舊 schema 2 partial/completed run 仍可載入，並明確標 legacy continuation。

### K2

- 錯折紙留下可見殘影，不能只留 engine attempt。
- 成功前不在 UI 直接顯示下一題所需的完整關係。

### K3

- 封存後、開封前重載頁面，預測仍在且觀測不可見。
- 一次 click 不得同時產生 sealedAt 與 openedAt。
- 火星、木星的質化判斷各自入狀態；開封後不能回改。
- 刻痕帶的預測與觀測由 state 數值生成，不用烤死圖片。

### K4

- 錯章在 UI 上留痕，重繪／重載後仍可見。
- 有借條與無借條的校樣摘要必須有可見差異。

### K5

- 免費預覽不直接輸出內部 slot ID 或逐項正解。
- 送出缺口校樣必須消耗窗口並留下可回看的錯稿。
- 輔助模式逐項念出缺口時須標記為提示使用，不能偽裝成玩家自行判斷。

## 八、最終判斷

第四章已經有一套很強的「證據不能被洗白」引擎，但還沒有完全變成「玩家的判斷改變紙上世界」的遊戲。

最值得保留的是：

1. K1 的四項封存、三拍交棒與幽靈紙。
2. K4 的雙模型、逐列蓋章與不可刪借條。
3. K5 的送錯稿、延後與窗口成本。

最需要重做的是：

1. K1 的真實續畫因果。
2. K3 的先封再揭玩家時序。
3. K2 與 K5 的選擇題／核對清單外觀。

若只准改一件事，先修 K1 的真續畫；若能改兩件，再把 K3 canonical spike 搬回 runtime。這兩項會比增加任何美術動畫更直接提升「我親手和牛頓做出這條證明」的成就感。
