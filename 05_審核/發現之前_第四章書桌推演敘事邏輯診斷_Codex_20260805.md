# 《發現之前》第四章「書桌推演」敘事邏輯診斷

**審查者**：Codex
**日期**：2026-08-05
**性質**：唯讀診斷，不修改 runtime
**正本**：`greybox/data/scenes4.json`、`greybox/src/chapter-ui.js`、`greybox/src/engine4.js`
**設計法源**：`02_設計/發現之前_第四章書桌探究現行設計定案_v1.0.md`

## 一、總裁決

第四章 K1–K5 的底層推理鏈是成立的，不需要改回器材實驗，也不需要搬動整場：

> 作出可運算的路徑（K1）→用另一尺度獨立檢查（K2）→先封存、再揭曉天文資料（K3）→讓兩套模型讀同一批資料並留下修補成本（K4）→把有限結論、來源與署名送進公共世界（K5）。

總監的五個困惑大多不是核心設計錯誤，而是**故事沒有把工作目的、證據身分與角色認知狀態說在操作之前**。現行介面其實有逐站目的卡（`chapter-ui.js:6067-6101`），但章首故事沒有先建立「這一章的實驗就是書桌上的可反駁預測與獨立觀測」，部分過場又把「參考圖」「觀測」「模型類比」連續放上桌，玩家自然會混淆它們各自算不算證據。

真正需要處理的不是增加解說量，而是補四個短橋：

1. 章首先宣告本章的查案方法。
2. 繩球演示開始前先交代它只比較「持續改向／停止改向」。
3. 山頂大砲明標為 K1 的整體縮圖，不是新證據。
4. 對帳前明說「類比只負責把模型講清楚；同一批天空紀錄才負責裁決；借條記錄臨時新增的假設」。

## 二、現行 runtime 的重要事實

1. `D3-1/n13`「那顆七十六年回來一次的彗星……」目前是 `legacyOnly: true`（`scenes4.json:1446-1451`），玩家不會看見。現行 active runtime 並沒有先把七十六年週期告訴玩家。
2. 哈雷在 `D3-1/n25` 明說佛蘭斯蒂德資料「我沒拆過」，並在 `n28-n31` 要求先封預測、再開包；`n38` 只承認火星與木星兩筆相合，`n40` 仍要求同一規矩接受整片天空檢驗（`scenes4.json:1532-1652`）。他不是知道答案等玩家追上。
3. 彗星在實際模型帳裡比較的是「逐夜星位」：拉力帳留下 2.2% 殘差，簡化渦旋帳留下高傾角、逆向路徑與固定流面衝突（`engine4.js:1553-1569`），不是直接把七十六年週期餵給玩家。
4. 現行 K4 UI 的借條確實有狀態後果：行星可借「木星那一層另設流速」，彗星可借「彗星可以穿過流（未量過）」；借或不借都會進封存總結（`chapter-ui.js:7073-7133`）。問題不是假互動，而是故事對這個動作的意義交代得太晚。
5. 目前測試基線為 159 通過、0 失敗。這只證明結構與狀態契約通過，不反駁真人試玩已暴露的理解缺口。

## 三、五個困惑逐點診斷

### 1. 繩球演示不知道要做什麼

**分類**：設計意圖正確，鋪陳與局部措辭有缺口。

**現況**

- 虎克信先提出「直行＋持續中央吸引」（`D2-1/n3-n7`）。
- 牛頓接著只說「這樣就畫得出來了」「路。先看這個」（`n11-n13`），便開始轉繩球。
- 玩家先回答繩子把球拉向手，牛頓鬆手讓球沿切線走；直到結果已發生，`n20` 才說繩子不是月亮的答案，只借幾何（`scenes4.json:1020-1076`）。

演示本身有用：它把 K0 的切線紙重新叫回來，讓玩家看見「拉著時持續改向；一鬆手就沿當下方向離開」。問題是 `n13` 沒有先說要比較這兩種狀態；`n20` 的「有東西一直在改月亮的路，而且不會斷」也容易讓人把「不會斷的東西」誤聽成未知實體，而不是「每一刻都在發生的改向」。

**最小修法**

`D2-1/n13` 原句：

> 路。先看這個。

建議：

> 先別猜月亮靠什麼轉彎。我只想把信上的兩種走法分開：拉著時怎麼走，拉一停又怎麼走。

`D2-1/n20` 原句：

> 繩子不是月亮的答案，月亮上也沒有繩。這個演示只指出一件事：有東西一直在改月亮的路，而且不會斷。這是他寫給我的。

建議：

> 繩子不是月亮的答案，月亮上也沒有繩。它只讓我們看清兩件事：拉著時，球一路向手邊轉；一鬆手，球就沿當下的方向直走。虎克要我合起來算的，就是這兩種走法。

`D2-1/n21` 建議同步收窄：

> 取得參考卡「繩球演示」：只比較「持續改向」與「停止改向」，不把繩子當成天上的機制。

**工程判斷**：三處文字替換即可，不動場序、embed 或狀態。

### 2. 山頂大砲不順，是否該當證據圖

**分類**：位置正確；缺少橋接與證據身分標示。不是證據圖。

**現況**

K1 完成後，牛頓與旅人先看三十拍路徑及各種錯紙（`n29-n34`），接著在 `n35` 沉默，`n36` 突然說「想像一件事：最高的山頂上，架一門砲」，三句後便下結論「月亮，就是打得夠快的那顆砲彈」（`scenes4.json:1185-1217`）。直到 `n42` 才補「畫得出來，不等於證得出來」，`n43` 才稱它為圖卡（`scenes4.json:1235-1245`）。

這個位置其實合理：

1. 放在 K1 之前會先洩漏「持續落下卻繞住」的整體答案。
2. 放在哈雷帶資料之後，容易誤以為大砲圖是哈雷的觀測證據。
3. 現在放在 K1 後、虎克第二封信與哈雷獨立資料前，正好可把三十拍細圖縮成一眼能讀的整體假說。

不順的原因是，`n35→n36` 沒有說明「我現在只是換一種畫法，把剛才的三十拍看成一整條路」。而 `n39` 語氣太像已證實的結論，會讓後面的 `n42` 邊界補得太晚。

**大砲圖的正確身分**

- 是思想實驗／K1 綜合圖／後來的教學重建。
- 不是新的觀測。
- 不能單獨證明引力機制或平方反比。
- 若使用《原理》的經典圖像，圖卡應明標它是後來的綜合呈現，不能假裝成 1679 年已完成的歷史原紙。

**最小修法**

`D2-1/n35-n36` 改成：

> 牛頓把三十拍的細圖推到一旁，另畫一個圓地球。
> 牛頓：三十拍太細。換一個一眼就看得懂的問法：假想最高的山頂架一門砲。

`D2-1/n39` 改成保留假說語氣：

> 如果這張圖站得住，月亮就像一顆一直落下、卻一路錯過地面的砲彈。

`D2-1/n43` 改成：

> 取得對照圖卡「山頂大砲（後來的綜合圖）」：它把 K1 的三種路徑縮成一張總覽；不是新觀測，也不能單獨證明引力機制。

**工程判斷**：不搬場，只改三個既有節點；若圖卡標題由資產表產生，再同步一處圖說。

### 3. 整章是書桌推演，還是少了實驗

**分類**：設計選擇成立；章首框架缺口。

**現況**

`D0-1` 很清楚地交棒案件：「放手不會清除原有運動，月亮為什麼沒有沿直線離開？」（`scenes4.json:36`）。`D0-2` 也很清楚地建立證據邊界：船紙只能支持放手後前進仍在，不能直接替月亮作答（`scenes4.json:103` 起）。但兩場都沒有告訴玩家：這一章無法把月亮搬進實驗室，接下來要用「先寫死預測→作圖與換尺→拆天文資料→模型對帳」取代器材實驗。

介面逐站目的卡其實已存在，並分別寫出 K1–K5 的目的（`chapter-ui.js:6067-6101`）。然而目的卡只在進站後回答局部操作，不能取代章首的整體方法框架。總監玩完仍問「是不是少一個實驗」，正是這層缺口的真人證據。

**建議新增的唯一章框句**

位置：`D0-2/s1` 合作成立後、進第一座紙桌前，或第一座紙桌目的卡的最上方；不必另開場。

> 月亮搬不進屋。這一次，只能把地上的紀錄、天文數字和紙上作圖分開留下：先寫下預測，再看不同來源的紙會不會在同一條規矩上碰面。

若希望由牛頓說，則用：

> 我們不能把月亮搬上桌。先把每個猜法寫死，再拿天文數字來查。紙若對不上，就改猜法，不能改觀測。

這句必須在第一次書桌操作前出現，而不是等玩家做完一站才由 UI 解釋。

**是否應新增器材實驗**：不建議。天文觀測資料就是本章的外部經驗來源；再塞一個器材關卡只會讓 K1–K5 的證據層級更混亂。真正欠缺的是方法宣告，不是量杯。

### 4. 哈雷是在觀測，還是已經知道週期

**分類**：哈雷的 active 台詞前後一致；彗星資料封面的文字有實質歧義，屬局部敘事資訊設計缺口。

**現況結論**

哈雷在當下不知道七十六年週期，也不是拿答案等玩家追上：

- `D3-1/n25`：「這是佛蘭斯蒂德那邊抄來的觀測。我沒拆過。」
- `n28-n31`：他把封蠟推給旅人，要求先押火星、木星週期再拆包，理由是看過答案會重寫記憶。
- `n38`：只承認火星、木星兩筆比牛頓保證有用，仍不能替整片天空作保。
- `n40`：他要追的是一本敢碰整片天空的書（`scenes4.json:1532-1652`）。

提示中提到的「七十六年回來一次、以後跟他姓」在 `D3-1/n13` 已退役，`legacyOnly: true`；不能拿來解釋現行玩家困惑。

**總監困惑的真正根因不是退役旁白，而是 active 場間接縫。** `D3-1` 清楚演出哈雷保管、封存並在揭曉後查讀火星／木星觀測；進入 `D4-1` 時，劇本卻省略「第三份彗星資料目前究竟包含什麼」的交接，直接把它和已有週期資料的月亮、行星並列。哈雷在此既不是親自在望遠鏡旁觀測，也不是已知彗星週期的出題者；他的角色是把佛蘭斯蒂德留下、尚待續算的日期與星位帶進來，要求牛頓的規矩接受獨立檢驗。現行 active 台詞沒有把這個中間身分說清楚。

真正的歧義出在 `D4-1/n20`：

> 三份觀測封面：月亮、火星與木星、彗星。每一份都把可核對的距離、週期、日期與星位寫在紙邊。

「每一份」會讓人以為彗星紙也已附完整週期。可是實際引擎的彗星欄比較的是逐夜星位與路徑方向，不是已知七十六年週期（`engine4.js:1553-1569`）。這一句應改，否則角色狀態再一致，資料標籤仍會誤導玩家。

**最小修法**

`D4-1/n20` 改成：

> 三份觀測封面：月亮紙列距離與週期；火星、木星紙列各自的距離與週期；彗星紙只有不同日期的星位，還沒有寫好的週期答案。

可在 `D3-1/n40` 後補一句哈雷的工作狀態，但非必要：

> 火星和木星先對上了。彗星還只是一疊不同日期的星位；接下來得看同一條規矩能不能把那些點接成一條路。

**工程判斷**：優先只改 `D4-1/n20`，一個節點即可解除最大歧義；若真人仍不清楚，再加第二句。

### 5. 借條機制看不懂跟「穿越解謎」的關聯

**分類**：K4 的模型比較與借條後果設計成立；敘事包裝沒有在操作前把任務與穿越者困境接起來。

**現況**

`D4-1/n2-n18` 先用攪茶與磁石把兩套說法講清楚，且公平承認渦旋說能解釋行星同向運動。這是可敬對手設計，不應刪。`n20-n25` 再交代三份資料、固定規矩、三種章與旅人作為蓋章者。這些步驟各自合理。

但三個關鍵身分沒有及時分開：

1. 攪茶、磁石是**模型類比**，不是裁決證據。
2. 月亮、行星、彗星才是兩套模型共同讀取的**同一批資料**。
3. 借條是模型遇到失配後臨時增加的**未量過假設**，不是提示券，也不是把錯誤洗成正確。

現行「借條」第一次被要求理解時，`n28` 只說「借條只有你自己貼得上」，embed hint 才補「若有人想補新說法，借條要留在帳上」（`scenes4.json:1867-1881`）。UI 要等玩家真的蓋出失配，才顯示具體借條內容（`chapter-ui.js:7073-7090`）。因此玩家知道按鈕怎麼按，卻未必知道這跟穿越查案有什麼關係。

**最小修法 A：在資料登場前切開類比與證據**

位置：`D4-1/n18` 後、`n20` 前。

> 哈雷：茶和磁石只是把兩套說法講清楚，不是證據。現在讓它們讀同一批天空紀錄。哪一套算不過，卻要臨時多補一句，那一句就寫成借條，留在原來的失配旁。

若不得新增節點，可併入 `n18` 後半。

**最小修法 B：把穿越者的限制寫進進站提示**

`D4-1/n28` 建議改成：

> 你知道後來課本留下哪個名字，但這張桌只認 1686 年攤得出的紙。先讓兩套規矩讀同一份觀測，再依結果蓋章。若某套要加一個沒量過的新假設才說得通，就把它寫成借條；借條能保住一個解釋，不能抹掉原先的失配。

接著保留現有操作資訊：

> 三份資料先過哪一份，由你決定。蓋錯不罰，桌上的數字會把錯章頂回來。

這會直接回答「穿越回去到底在解什麼」：玩家不是替未來正解按確認，而是判斷 1686 年現有紙張最多支持到哪裡，並留下當時模型為了存活付出的成本。

**補充小修**

`D4-1/n25` 的「只有你沒有輸贏」說得太絕對。旅人其實知道未來結局，也有破案動機。可改成：

> 規矩是牛頓的，書是我要印的，我們都押了東西。你不靠任何一本帳署名；這一輪，只准照桌上的紙蓋章。

**工程判斷**：一個過渡句＋一個 system 提示重寫即可。借條狀態、模型結果與 K5 都不用改。

## 四、大砲位置與哈雷認知狀態的關聯

兩者有關，但答案不是把大砲搬到哈雷之後。

最清楚的鏈應是：

1. 虎克第一封信提供「直行＋持續向內改向」。
2. K1 把這兩件事逐拍畫成可運算路徑。
3. 山頂大砲把 K1 的細部路徑縮成一張整體思想圖。
4. 牛頓主動收窄：「畫得出來，不等於證得出來。」
5. 虎克第二封信再提出平方反比的距離關係。
6. 哈雷帶來封存資料與公開證明壓力，要求漂亮圖像接受獨立觀測。

因此大砲應留在哈雷之前。它負責把「怎麼可能一直落又不撞地」看懂；哈雷負責把「可能」推進到「拿什麼查」。若把大砲移到哈雷之後，它反而會像哈雷帶來的證據，並模糊他當時並不知道彗星週期的狀態。

需要改的只有兩件事：在大砲前說它是 K1 的縮圖，在大砲後說它仍是假說；不要搬場。

## 五、章首是否已有框架句

**沒有完整框架句。**

- `D0-1` 有清楚案件問題。
- `D0-2` 有清楚證據邊界與合作成立。
- `chapter-ui.js` 有逐站目的卡。
- 但沒有任何一句在玩家第一次進紙桌前告訴他：本章的「實驗」是把預測、計算、天文觀測與競爭模型放在同一張桌上互查。

最適合的位置是 `D0-2/s1` 合作成立後、第一次工作台出現前。推薦唯一版本：

> 月亮搬不進屋。這一次，只能把地上的紀錄、天文數字和紙上作圖分開留下：先寫下預測，再看不同來源的紙會不會在同一條規矩上碰面。

這句只框方法，不預告 K1–K5 答案，也不把故事說成操作手冊。

## 六、K1–K5 整體結構是否需重做

| 證據站 | 敘事功能 | 現況 | 裁決 |

| K1 | 把直行與向內改向做成可反覆運算的路徑 | 主操作成立；繩球入口目的太晚 | 保留，補橋 |
