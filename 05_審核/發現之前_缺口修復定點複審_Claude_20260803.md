**繞過雙封閘門的路徑真的關掉了** ✓——因為函式不在，不是因為契約擋住。

### C-1｜未知或打錯字的 `labAction` 會靜默 no-op，而第六章已有正確做法

**位置**：`greybox/src/narrative.js:1068-1246`（`labAction` 的 else-if 派送鏈）。

**實測證據**：如上——包含一個**真實 action 的打字錯誤**（`sealPlanetPredictionTYPO`）在內，全部靜默回傳未變更的 state，不報錯、不改 state、測試不紅。

**而正確做法就在同一個檔案裡**。`narrative.js:1242-1246` 第六章用的是明列白名單：

```js
/* 第六章：只開放明列的來源追債 action；Engine 上其他方法不可由資料任意呼叫。 */
else if (CHAPTER_ID === "ch6" && ["setSourceLedger", "sealModels", …].includes(action))
```

第一到五章仍是長串 else-if，落空即靜默。

**因果問題**：資料層若寫錯一個 action 名（或重構時漏改一處），玩家按下按鈕**什麼都不會發生**，畫面沒有錯誤、state 沒有變化、測試全綠。這與我前四輪抓到的是同一型——**護欄看不見的那條路徑**，這次是第五次。

**判 C 不判 B**：現行資料對 `predictPlanet` 與任何不存在的 action 命中 0，眼下無害。

**最小修法**：把 ch1–ch5 比照 ch6 改成白名單，落空即 `return err(state0, "unknown-lab-action:" + action)`。**可失敗的驗證條件**：在任一 `scenes*.json` 掛一個不存在的 `labAction.action`，測試必須轉紅（現況不會）。
