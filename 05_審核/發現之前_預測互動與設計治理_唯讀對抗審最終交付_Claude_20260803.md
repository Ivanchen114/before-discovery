## 二、Layer A｜B=2、C=1

### A-B1｜「形狀不得退回設定查表」無契約可擋，而唯一能區分的結果是玩家可押的選項

**位置**：`greybox/src/engine4.js:520-546`。

把 `orbitShapeForRun` 改成永遠 `return canonicalOrbitShape(...)` → **149/0 完全不轉紅**。

**先排除空變異**，逐組態實算值域：

| 函式 | earth-center 九組態輸出 |
|---|---|
| `canonicalOrbitShape` | `circle`、`ellipse`、`away` —— 僅此三種 |
| `orbitShapeFromSimulation` | 同上 ＋ **`crash`**（`sim.minRadius < 0.28`） |

`ORBIT_SHAPES` 宣告六種，**canonical 永遠無法產生 `crash`**——那是兩者唯一語意差。而 `crash` 在 `tests/run-node.mjs` 出現 **0 次**（對照 `circle` 14、`line` 5、`away` 2、`ellipse` 1）。

**`crash` 是玩家可押的選項**：`chapter-ui.js:6631` 把 `["crash", shapeLabels.crash]` 列進押注清單，`6609` 標籤「切入地球」，`5978` 文案「它切得太深，撞進地球。」。

**玩家後果**：分類器一退回查表，實際撞進地球的路徑會被命名成 circle／ellipse／away——**押對的玩家被判成押錯，那句文案永遠不出現**。正面違反 A4「形狀名稱不得退回設定查表」與 A3。

**最小修法**：加正向斷言（`_orbitShapeFromSimulation("earth-center",{minRadius:0.1,maxRadius:1.0}) === "crash"`）＋負向斷言（canonical 值域不得含 crash）＋一條走完會 crash 的完整 run 斷言 `run.actualShape === "crash"`。**驗證條件**：把 `orbitShapeForRun` 改成永遠用 canonical，必須轉紅。

## 三、Layer B｜B=1、C=2

### B-B1｜「40 筆 ADR 均有 CURRENT 落點」是形式合規，而文件裡有一行明文的機器索引

**位置**：`greybox/tests/run-design-governance.mjs:81-91`；`03_規格/發現之前_跨章runtime與治理規格_v1.0.md:70`。

契約判準是 `active.filter(id => !concatenated.includes(id))`——**八份 CURRENT 全文串接後的單一子字串存在檢查**。不問出現在哪一份、不問章別、不問語意。

**決定性證據**：跨章規格第 70 行是一行明文標示

```
**機器覆蓋索引**：`GB-ADR-001`、`GB-ADR-002`、…、`GB-ADR-041`。
```

**這不是意外副作用，是刻意放來讓契約通過的一行。** 40 筆 active ADR 全部命中它，其中 **19 筆只出現在該份文件**；另 21 筆有兩份以上落點，刪任一份都不會轉紅。

**反向控制（任務書 B 第 2 組）**：從第四章功能規格書移除 `GB-ADR-040` → **全綠 exit 0**，照樣印「40 筆均有 CURRENT 規格落點」。

**章別落點本身也是列舉**：`GB-ADR-040` 在第一、三、四、五章的落點全是「**現行裁決**：`GB-ADR-…`、…」形式——同一編號在四章都被列為現行裁決，**沒有任何一處說明它在該章做什麼**。這同時使**跨層第 1 項（GB-ADR-040 須有語意性落點，不只列出 ID）不成立**。

**最小修法**：契約從「全文串接」改為「章別歸屬 + 語意鄰近」——每筆 active ADR 須出現在 registry 指定的歸屬 CURRENT 文件；且該落點所在行不得同時出現三個以上 ADR 編號。同時刪除第 70 行機器索引。**驗證條件**：移除任一章的 ADR 落點必須轉紅；把某語意段落換成列舉行也必須轉紅。**注意：第二項條件套上去會立刻紅**，所以這條 B 同時包含文件補語意段落，不只改測試。

### B-C1｜`active` 判定使 partially-superseded 無法區分

`if (!/^\*\*狀態\*\*：superseded\b/m.test(section)) active.push(row.id)`——非字面 `superseded` 即算 active，`partially-superseded` 併入同池。契約名稱已誠實揭露，不構成誤導；但 B5 要求的「被取代的部分不能藉 CURRENT 重新生效」無法由這條分辨。**修法**：拆成獨立集合，要求其落點須同時出現 `supersededBy` 指向的接手 ADR 編號。

### B-C2｜「現行設計定案」沒有任何風險／取捨／未驗欄位

`02_設計/發現之前_第四章書桌探究現行設計定案_v1.0.md` 全文搜「風險／取捨／未驗／限制／尚未／待」——只有一行講舊句處理，**沒有任何取捨或未驗風險記載**。任務書 §九-4 本身就預期需要這個欄位（「A 層若抓到 K1 四項先封過早，B 層文件應把它列成取捨／未驗風險」）。一份零記載取捨的「定案」文件，結構上無處安放已知限制。**修法**：CURRENT 設計文件加固定的「已知取捨與未驗風險」段落，並納入治理測試（八份 CURRENT 皆須具備該段落）。

## 六、判定與建議

**整體不放行**：Layer A B=2、Layer B B=1。

三條 B 的共同型態值得訂成跨章通則：

> **每條護欄都要同時有正向存在斷言與負向旁路斷言；負向斷言的探針不得取自被檢驗對象自身的欄位。**

這已是連續四輪同型（前兩輪的 ch4 選項層、ch3 洩題單格、第一二章 term 錯字）。訂成通則比逐條修更省。
