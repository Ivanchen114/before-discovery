# 《發現之前》預測機制「敘事動機」全五章三方交叉驗證——最終報告

**日期**：2026-08-03
**觸發原因**：使用者實機遊玩第四章K1（軌道形狀預測）時感到「不知道為什麼要預測，這邊的物理概念是要解謎什麼」。經三方確認這是敘事/劇本層問題後，使用者要求把同一檢查角度套用到一到五章「所有」預測環節。
**性質**：唯讀敘事分析，均未修改runtime。
**方法**：claude、codex、gemini各自獨立檢查五章所有已知預測點，用統一四項判準逐一評分。

**本報告可直接交給實作端使用**——每個問題點都附有具體的最小改寫台詞。

---

## 一、判準（沿用K1盤點時建立的四項檢查）

1. **疑問先立**：互動前，敘事有沒有先講清楚「這個預測在回答上一步留下的什麼疑問」？
2. **有依據**：玩家有沒有足夠的資訊/線索去做有根據的猜測，還是純粹瞎猜？
3. **直覺在前**：建立直覺用的類比/思想實驗，有沒有在互動之前出現？
4. **故事收尾**：猜錯之後，故事層面（不只是UI內部訊息）有沒有把「你猜的是什麼、實際是什麼」講出來？

**codex提出的驗收硬測試，建議正式採用**：把互動UI的標題與提示全部遮住，只讀互動前最後四句，玩家仍應能回答「我在押什麼、憑什麼押、翻開後能排除哪一種說法」。

## 三、最高優先：第三章第三柱（codex評為全五章最嚴重）

**問題**：玩家先被要求安排雙觀測者、同鼓號、對齊紙帶，**但劇情沒有先演出「岸紙彎、船紙直，兩位具名觀測者都堅持自己沒畫錯」的矛盾**。兩個零點、同一拍等概念也沒有先用兩把尺承接，操作像程序不像在解一宗衝突。

**這與程式/敘事審查階段發現的「第三柱判斷被繞過」是同一個機制的不同切面**——那次發現的是「判斷被系統代做」，這次發現的是「連判斷需要解決什麼衝突都沒講清楚」，兩者疊加使第三柱成為全案最需要優先處理的單一環節。

**codex建議的互動前橋接台詞**：
> 艾蒂安：「我從碼頭量，石頭一路往前。」
> 馬蒂厄：「我從桅杆量，它直直落。我的鼓號跟你一樣。」
> 船長：「同一顆石頭、同一趟、同一拍，兩張紙怎麼會都是真的？」
> 伽桑狄把兩把木尺分別壓在碼頭與桅杆：「先別改線。先問兩張紙各從哪裡算零。」

**三種錯圖需要進故事**（不只是UI顯示錯誤）：
- 錯拍：艾蒂安指出「你把我的第三拍接到他的第四拍」
- 固定平移：只一拍貼合，其餘仍鼓出
- 直接拉直：原觀測點離開紙帶，馬蒂厄拒簽

## 四、其他需要修的問題點（依優先順序）

### 1. 第一章A2-2/e1 第五段預測（中度同型）
**問題**：e1只說「先寫下第五段會走多遠」，沒交代「為何第五段能檢驗規律」；1、3、5、7的讀法要到互動**後**才由角色整理。

**改寫**（放在互動前）：
> 伽利略：前四段先露著，第五段先蓋住。別猜總長；先看每一段比上一段多走多少，再押第五段。翻開後，才知道這條規矩能不能預先說中。

**收尾**：
> 伽利略把押記與第五段刻痕並排，沒有擦掉：「差多少先留著。回頭只讀五段各自增加多少。」

### 2. 第四章K2距離預測（與K1同型，需修）
**問題**：`D1-2/n1-n8`完全沒有一句說「你先猜猜月亮那裡一秒掉多少」，押注只存在於e1的hint裡；沒有類比；收尾也完全沒提押注。

**改寫**（放在互動前）：
> 牛頓：「先別算。你猜——月亮那裡，一秒掉多少？跟地上一樣多？少六十倍？還是少到幾乎看不見？」
> 牛頓：「猜完蓋起來。算完我們再翻。我要看的是你有沒有先想過，不是你算得快。」

**收尾**：
> 牛頓（翻開蠟封）：「你猜的是＿＿。算出來是一點四公釐。」

### 3. 第三章加速/減速方向預測（部分同型）
**問題**：疑問已立好（舊紙缺船速，須分辨穩速與變速），但沒有把「石頭保留放手瞬間前行、船後來改速」轉成可操作直覺，玩家主要靠既有物理知識猜，不是靠遊戲給的線索。

**建議補小物件類比**（互動前）：
> 馬蒂厄把墨水瓶放在木板上，先猛推、再猛收：「瓶子相對木板往哪滑？船變速時，我們要查的是同一件事。先把兩種方向封起來。」

**收尾**：
> 船長：「你押的方向沒對上，但先別改紙。把兩趟並排，看清楚後來改速度的是船，還是已經離手的石頭。」

### 4. 第四章K3行星預測（⚠️預警型——目前不是問題，修復後會變成問題）
**現況**：目前`predictPlanet(id)`是假動作（引擎自動算好），所以「有沒有依據」尚未成為問題。**但根據總清單建議，K3即將被改成真押注（押火星/木星週期落在哪個區間）**。

**claude與codex一致警告**：玩家手上有K2（力隨距離平方變弱），但從那推到「週期∝距離^1.5」需要一步數學，目前`D3-1`完全沒有台詞鋪陳這一步。**如果只修好程式（真封存+真開獎）而不同步補上這段鋪陳，會直接製造出第二個K1。**

**建議在改K3的同一張工單裡，於`n29`（「你們先寫下預測，滴上蠟」）之前補一句**：
> 牛頓：「離得遠，拉得弱；拉得弱，走得慢，路又更長。兩件事疊起來——遠一倍，一年就不只長一倍。火星比我們遠一半多一點，你猜它一年有多長？」

**收尾**：
> 哈雷把押偏的紙也釘回牆上：「這不是罪證。它告訴我們，同一條律到了哪個尺度開始露出差距。」

### 5. 全案通用缺口：錯押的故事層收尾普遍缺席
**這是三方在多個「範本級」預測點（第二章H=25、第五章4/8）裡都提到的唯一共同缺口**：邏輯、依據、直覺鋪陳都做對了，但「猜錯之後」的故事收尾普遍只停在UI訊息，沒有回到對話。建議統一補一句「把押錯的紙留下，NPC指出哪裡沒接上」的收尾句型，範例已附在上面各章節。

## 五、做對的範本（三方一致公認，可作為其他章節修改的參照）

### 第二章H=25：全五章最佳
```
n2 伽利略：「先讓發射器閉嘴……它穩了，才輪得到真正的問題——掉得愈深，飛得愈遠——遠多少？」← 立起本輪問題
e1  做 4/9/16
q1 「你看出什麼?」二選一（翻兩倍／開方）← 玩家先提出主張
n3 伽利略：「是嗎?（把沙盤又降下一段，新釘一格）二十五格——射程，你說多少？」← ⭐關鍵
e2  押注 + 放球
p1 旅人：「……二十五格的預測也接上了。」← 故事層收尾
```
**⭐關鍵設計原則（claude提煉）**：「`n3`的『是嗎?』是關鍵——預測不是憑空要求，是對玩家自己剛講出口的那句規律的檢驗。」**這個「預測=檢驗玩家剛講出口的主張」的模式，是全案最值得複製的敘事範本。**

### 第五章4/8追一筆：三個既有缺口已全部補好
```
x11 杜夏特萊：「你現在只看見等重油灰少一半——『一半』是規矩，還是碰巧？」← 立起問題
x12 stage：「她把『一半』圈起來……等旅人先落筆。」← 封存動作
lab2b hint：「先封存你的預測……猜錯不擋進度，原預測會和結果一起留下。」
x13 旅人：「不是固定一半。等重時少一半，換成4／8，少的是三分之二。」← 收尾
x14 杜夏特萊：「那就不能把『一半』寫成定律……」← 接到黏土
```

### 第四章K0切線：同一章裡的正面對照
`D1-1/n2`「先拿掉所有拉扯……別替它畫完一圈」→`n3`「只告訴我，它下一步往哪裡」→三選一（錯選有駁：「你把要證明的圓，先塞進答案裡了」）→`n5`旅人收尾句。**目的清楚、預先擋掉最常見的直覺錯誤、故事層有收尾。同一章裡K0做對、K1做錯，是最直接的內部對照組。**
