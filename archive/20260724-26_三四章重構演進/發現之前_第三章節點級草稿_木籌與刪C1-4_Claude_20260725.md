# 修正一｜C0-2 木籌：從「旅人代填」改成「玩家選理由」

## 問題（逐字證據）

現行 `C0-2` 的木籌儀式，最後一步是**旅人自己寫**：

- `n3e` 艦長：「（把另一枚木籌推給旅人）那你呢？別等石頭落地，才決定自己原本相信什麼。」
- `n3f` **旅人(你)**：「（寫下「桅腳」）我知道書上怎麼回答。我還沒看過海怎麼回答。」（型別＝`line`）
- `s0` system：effects `[{"flag":["initialPrediction","foot"]}]`

木籌是本章「先承諾、後揭曉」的核心儀式，卻是 NPC 幫玩家完成的。

**而且我查了全 repo：`initialPrediction` 這個 flag 只有這一處在寫，`src/`、`tests/`、其他 `data/*.json` 都沒有任何地方讀它。** 也就是說，本章第一個承諾目前**零機制後果**——這正是它感覺不到重量的原因。

## 設計界線：守 CH3-CR-014，但把決定還給玩家

CR-014 裁定「旅人既已讀過《對話》，不再由玩家假裝未知而自由猜落點」——這個誠實邊界正確，**不動**。

所以玩家選的**不是落點**（三個選項都寫「桅腳」），而是**憑什麼這樣押**。三種理由對應三種不同的知識來源，而艦長會分別回敬——他要的不是答案，是你打算怎麼讓他看見。

## 節點級草稿（替換 `n3f`，其餘不動）


**實作註**
- `s0` 的 `tokenReason` 需依分支寫入不同值。若既有效果系統不支援「同一節點依來路寫不同值」，請改成**三個 s0 變體**（`s0_book`／`s0_carried`／`s0_seen`，各自 `flag` 值不同、`next` 同為 `n3g`），r_*2 各自指向對應的 s0。
- `initialPrediction=foot` **保留不動**（舊存檔相容；雖然目前無人讀，別在這一批順手拿掉）。
- 新 flag `tokenReason` 請確認 `src/sanitize.js` 的匯入淨化是否有 flag 白名單；若有，一併登錄。

## 選配（第二階段）：讓理由在終局被回收

`C3-3`（最後的誘惑／證據邊界）是本章高潮。若要讓開場那句理由真的有重量，可在 `n3`（旅人說出邊界）之後插一句 require 分支——**沿用 ch4 `n4p`／`n4d` 的既有寫法**：

```json
{"id":"n3r1","type":"line","speaker":"艦長","text":"你一開始說書上這麼寫。今天我簽的不是那本書，是這六筆紀錄。","require":{"flag":["tokenReason","book"]},"next":"n3r2"},
{"id":"n3r2","type":"line","speaker":"艦長","text":"你一開始說它本來就跟著船走。你把「本來」量出來了，我才簽。","require":{"flag":["tokenReason","carried"]},"next":"n3r3"},
{"id":"n3r3","type":"line","speaker":"艦長","text":"你一開始說你見過類似的事。今天你讓我也見到了，而且寫得比你當時清楚。","require":{"flag":["tokenReason","seen"]},"next":"n4"}
```

（三句互斥、依 flag 落一句，最後都接原本的 `n4`。舊存檔沒有 `tokenReason` 時三句皆不成立，直接到 `n4`，安全。）

# 修正二｜刪掉 C1-4，把「先查哪一條」交給玩家在對話裡決定

## 問題（逐字證據：同一訊息講三次）

1. `C1-3/n3` 艦長：「我承認穩速三筆站得住。但甲板有風；我的舊紀錄也還在船尾。**你們先查哪一個？**」
2. `C1-4`（整場 4 節點）
   - `n1` stage：「艦長把「變速」與「風」寫在兩塊木牌上。兩塊都沒有翻面。」
   - `n2` 伽桑狄：「變速能解釋方向，風也可能造成偏移。**先後由你決定**，但不能因為先看到一個好解釋，就把另一塊牌丟進海裡。」
   - `n3` 艦長：「**先查哪一條**，就先承受那條資料還不完整的時候。」
3. `C2-1/n2` 艦長：「**你可以先查風，也可以先查變速。**但若一筆資料還沒有分類依據，就老實寫『未分類』，別先替它取一個方便的名字。」

問完之後，玩家還要**進工作台再選一次**——同一個決定做兩遍，中間夾 7 個節點。這是「亂」與「點擊多」最具體的一段。

## 改法

### (1) `C1-3`：折入 C1-4 的關鍵一句，並就地做決定

```json

{"id":"n3a","type":"line","speaker":"伽桑狄","text":"（把「變速」與「風」兩塊木牌並排放下，都沒有翻面）先後由你決定。但不能因為先看到一個好解釋，就把另一塊牌丟進海裡。","next":"n3b"},

{"id":"s1","type":"system","speaker":"system","text":"調查順序已記下。兩塊木牌都留在桌上；先查的那一條，資料會先完整。","effects":[{"flag":["probeOrder","<選項 id>"]}],"next":"g1"},
```

（`n1`／`n2` 馬蒂厄與伽桑狄那兩句不動。`s1` 同樣可依實作需要拆成 `s1_speed`／`s1_wind` 兩個變體。）

### (2) 刪掉 `C1-4` 整場（4 節點）

其唯一不可失的內容（伽桑狄「不能把另一塊牌丟進海裡」＋艦長「先承受資料不完整」）已折進上面的 `n3a`／`n3b`。

### (3) `C2-1/n2` 縮短，改成呼應你剛才的決定

```json
{"id":"n2","type":"line","speaker":"艦長","text":"照你說的順序。但若一筆資料還沒有分類依據，就老實寫「未分類」，別先替它取一個方便的名字。","next":"e1"}
```

（刪掉「你可以先查風，也可以先查變速」——那句現在已由玩家的選擇取代。`n1` 的器材描述保留，它是踏查所需。）

## 這不是假選擇（設計說明）

三個理由：

1. **順序真的會改變資料何時能被分類**——這是 CR-016／GB-ADR-029 既有的物理設定（「先查風／先查變速必須改變資料何時能被分類，不能只有敘事順序不同」），本改動只是把這個既有後果的**決定權從工作台前移到對話裡**，不是新加一個空選項。
2. **承諾被記下**（`probeOrder`），而且艦長當場翻牌、指出資源在哪（風向旗／加減槳號令）——選擇立刻改變畫面上的東西。
3. **另一塊牌明文留在桌上**，避免玩家誤以為選了就不用查另一條（守伽桑狄那句紀律）。

**選配加強（不需改引擎）**：工作台已經知道玩家實際先做了哪一項（`evidence.g2`／`g3` 的完成序）。若 UI 比對「宣告的 `probeOrder`」與「實際先做的」不一致，可在工作台訊息列補一句艦長：「你剛才說先查風。」——只讀狀態、不改引擎，就讓「改口」留下痕跡，與本章木籌母題同源。
