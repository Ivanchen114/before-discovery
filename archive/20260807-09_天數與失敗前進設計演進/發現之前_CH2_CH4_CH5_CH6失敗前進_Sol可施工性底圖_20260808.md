## 一、先把「六章完成」定義清楚

六章完成，不等於六章都要新增同樣長的錯路；而是每章至少有一個玩家能感到世界接住其選擇的承重點，並符合：

1. 當場已有足夠證據者，人物可立即反駁，不故意拖延。
2. 當場證據不足者，選擇先成為世界中的承諾，等資料、裝置或對手在後文裁決。
3. 誠實猜錯、實驗失敗不扣信譽；把未證明說成已證明、抹除來源或以權威代替證據，才處理資格代價。
4. 路線是有後果的繞路，不是六章各做多結局；仍匯回歷史主線，但不洗掉錯紙、撤回、借條或人物記憶。
5. 每章以 **1 個主岔口＋0–2 個短讀回** 為上限。把每個錯項都擴成八至二十節點，會讓成本爆炸，也會讓玩家覺得每題都在等「錯誤動畫」。

目前 CH1、CH3 已施工並通過 Fable conformance；本文件只處理 CH2、CH4、CH5、CH6。

### 3.3 建議演出結構

1. q1 選擇立即寫入具名狀態，例如 `ch2DropPrediction = late | unresolved | abstain`；不得只用裸計數。

4. 第三列揭曉後，依 q1 讀回：

   - `unresolved`：押中本裝置的可見結果，但仍要說清楚「分不開」不等於數學上絕對同時。
   - `abstain`：不羞辱玩家；人物指出他保住了資格，但也沒有冒險留下可被檢驗的預測。
5. B2-5 或 B3-D 只需一個條件讀回，不新增另一條主弧。

## 四、第四章：不要再造玩法，讓封存錯紙被後文記得

### 4.1 主岔口推薦：D1-1/c1

現行三個選項都已呼叫 `sealTangentPrediction`：

### 4.2 ADR-016 四欄起稿

| 欄位 | 技術事實起稿（Fable 必須改寫成戲） |
|---|---|
| 當下誰知道什麼 | 畫面已給月亮此刻的位置與運動方向；在理想化幾何題內，切線方向可當場由圖反駁。 |
| 現在最多能反駁到哪 | 牛頓可立即指出「拿掉拉力後的下一步方向」；不能因此宣稱完整軌道理論、平方反比或出版證明已成立。 |

這是一個「立即反應＋延後裁決」的混合型，不應硬把明明能由圖判斷的錯誤拖到章末。

### 4.3 現有世界內後果，必須保留

第四章其實已是四章中最接近目標者：

- K4 每格章都由資料裁決；錯章記入 `stampAttempts` 並彈回，原始結果不被改寫。
- 行星／彗星失配後，玩家可親手加「借條」，且不可刪。
- 第一輪印刷位置可選誠實短稿或延後；`priorityRecord` 讓署名爭議提早或延後出現。
- 錯校樣會留下 `printed-broken-proof` 與印刷窗口代價。

所以本輪不應另造「時間裂口」、回溯或第二套印刷災難。最佳投資是把已有痕跡送回人物嘴裡。

### 4.4 建議演出結構

1. D1-1 保留當場幾何反駁，但錯紙不擦。
2. 在 D4-1 的 K4 進場或 D4-2 印刷台，依 `tangentPrediction.choice` 加一個條件讀回：玩家曾把「原有前進」畫成什麼。
3. DE-1 封存時讓錯紙與後來證據並存；不要只在 UI 顯示狀態。
4. 若 Fable 想把「短稿／延後」再戲劇化，可只加人物差異反應；現行兩路已有真狀態，不需再加第三結局。

### 4.5 不動條款

- 不改 K1/K2/K3/K4/K5 的數值、證據門檻、借條 append-only 性與印刷窗口。
- 不復活舊 K1 三拍、舊固定常數或舊 hearing 流程；以現行 runtime 與 GB-ADR-050 等後法為準。

## 五、第五章：讓過度斷言活進辯論，輸一個回合

### 5.1 主岔口推薦：E2-3/c_scale

現行三個選項：

- `overclaim-vital-force`：「坑深跟著速度的平方走。這證明活力才是真的運動之量。」
- `momentum-wrong`：「坑深跟著速度的平方走——所以動量帳是錯的。」
- `measurement-only`：「油灰上的坑讓我們量得出那一截短少。可它還沒說那一截去了哪裡。」

目前兩個錯項只走同場反應，沒有狀態；正確項才寫 `ch5ScaleBoundary=measurement-only`。這使玩家不必承擔自己已公開說出的理論立場。

| 欄位 | 技術事實起稿（Fable 必須改寫成戲） |
|---|---|
| 當下誰知道什麼 | 坑深與速度平方的測量關係已可見；同一碰撞的兩本帳與短少也已留下。 |
| 現在最多能反駁到哪 | 可立即反駁「一張尺度紙已證明完整本體論」；不能僅靠這張紙宣布動量帳或活力帳在所有問題上出局。 |

| 錯誤在哪一場揭曉 | 資格越界可在 E2-3 當場指出；實際代價在 E3-1 對手引用玩家原句時揭曉。 |

### 5.3 建議演出結構

1. 三個選項都寫入具名立場，例如 `ch5ScaleClaim = vis-viva-wins | momentum-false | measurement-only`。
2. 夏特萊或杜普雷當場只劃主張邊界，不強迫重選；玩家帶著原句進 E3-1。
3. 辯論對手拿同一批 J1/J2/J3 資料反擊玩家原句，讓錯路真的輸一回合：
   - `vis-viva-wins`：被追問坑深量到的是哪一種效應，憑什麼替所有運動之量裁決。
   - `momentum-false`：被指出碰撞總帳仍有守恆用途，玩家把「用途不同」說成「整本錯」。
4. 玩家必須自行縮句到測量邊界，才匯回主線；原斷言留在辯論紀錄或筆記。
5. 誠實理論押注本身不扣 rep；若沿用「明知來源不足仍宣稱已證明」的資格罰，Fable 與 Sol 必須把懲罰理由寫成越界，而非猜錯。

### 5.4 不動條款

- 不改 collision 引擎的數據、J1/J2/J3 取得條件與 debate5 的證據資格。
- E1-1 的權威替代是當場可知的程序錯誤，維持立即反駁與既有 rep；不升格為主枝。
- 不把兩本帳改成二選一真理；章的成熟處正是兩套量在不同問題上有不同用途。
- 不讓 NPC 直接說出修正版，修復句必須保留玩家行動或選擇。

### 5.5 Fable 交件需求

- E2-3 三種立場的承諾拍與不重選匯流。
- E3-1 對手的出手、玩家受阻、換手與修復拍。

- 明列 debate5 是否需要新 move／predicate；若只用 scenes5 前後包裹，請直接說明。

## 六、第六章：已有失敗弧，不要再證明一次

### 6.1 主弧認定：H2-1 已成立

H2-1 現行已有完整結構：

1. 玩家封存「密合後升溫應較慢」的空氣來源預測。
2. 工作台比較開放／密合曲線。
3. 封條裂開，原預測仍保留。
4. 玩家可選擇「保留封條，劃掉這一版」，或試圖刪除／硬保空氣說。

這就是 ADR-014 要的失敗前進：誠實預測、自然反駁、玩家撤回、痕跡保留。它不需要另一套回溯，也不需要因猜錯扣分。

### 6.2 補強候選：H1-3 → H3-1

H1-3 的 `heat-is-motion` 現行台詞是：「升溫證明熱就是運動，這一班已分出勝負。」它已因要求共同原紙背書超出範圍而扣 rep、設 `ch6DryOverreachTried=1`，但後面沒有充分讓此斷言反咬玩家。

建議把既有 flag 在 H3-1 讀回：S8「升溫最後停住」出現時，凱斯勒拿玩家早先的勝負宣言反擊。玩家必須把它移到「機制未決」，承認有限來源版本退下不等於運動說已完成。

## 七、四章共同 state 與相容性原則

1. 使用具名事件／枚舉，不使用 `wrongCount`、`loopCount` 等裸計數。
2. 舊存檔缺新欄位時一律走 neutral legacy 路徑，不得偽造玩家曾經犯錯。
3. 分支狀態寫入後不可因匯流被清空；封存章與跨章匯出只投影必要摘要。
4. 每個具名後果必須防重播：同一 claim／事件只能 yield 一次。
5. 新 `require`、`flagEquals` 或 lab predicate 必須先對照 runner 白名單；不得假定 JSON 寫了就會生效。
6. scenes JSON 是 canonical；施工後重建 JS mirrors 與 stage bundle，不直接手改 generated mirror。
7. 每章一張 CR：CH2、CH4、CH5、CH6 分開。可以同批 Design Gate，但不能做一張跨四章大 CR，否則回歸與回退範圍失控。

## 八、建議的實際流水線

使用者已裁定「六章完成後再一起玩」，因此取消逐章實玩，但不取消設計權限與雙向審查：

1. **本文件交 Fable**：Fable 依四章候選各寫 branch map＋實際台詞；可挑戰候選，但必須說明戲劇理由與技術代價。
2. **Sol 可施工性複核**：只審狀態、存檔、引擎事實、成本與保護條款，不改 Fable 的戲劇目的。
3. **總監同批裁決四章 Design Gate**：一次裁 CH2／CH4／CH5／CH6，不要求先玩。
4. **Sol 分章施工**：四張 CR、四個可獨立回退的修改包；每章施工後即跑定點與全套測試，但不要求使用者中途試玩。
5. **Fable 分章 conformance**：核對台詞、揭曉時機、保護段與玩家看到的戲。
6. **Sol 六章整合驗證**：mirrors、stage bundle、存檔相容、鍵盤／讀屏 smoke、全套測試與瀏覽器六章路徑。
