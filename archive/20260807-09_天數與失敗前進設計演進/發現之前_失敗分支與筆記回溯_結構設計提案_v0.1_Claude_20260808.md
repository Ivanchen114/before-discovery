# 失敗分支與筆記回溯 結構設計提案 v0.1

**日期**：2026-08-08
**作者**：Claude（供總監裁決；本文件是 Design Gate 前的結構提案，不是實作規格——凍結節點、fixture 與台詞均不在本文件內定案）

## 一、問題陳述

現況是單線主劇情＋選項節點：選對推進，選錯由 NPC 一拍糾正後原地重選。錯誤是牆，不是路。後果：(a) 玩家沒有「賭」的感覺——反正錯了就重選，選擇沒有重量；(b) 沒有意外——所有結局都是「終於選對」；(c) 科學史最有教育力的素材（錯誤路線的真實下場）完全沒被玩到。

## 二、現況雛形盤點（全部回檔核實）

本提案不是新發明，是把四個已存在的雛形統一成正式結構：

1. **SC-R 修復場**（narrative.js:23-24 掛鍵、redirectIfLocked:1369）——信譽歸零後的強制失敗劇情，已是「錯到底→走一段戲→回主線」的最小實例，但只有 7 節點且多數玩家看不到。
2. **辯論 suspend→debrief→reenter**（narrative.js:165/260-273/418/447）——辯論輸了離席複盤再入，已是微型迴圈；再入時保留已破支柱＝「保留進度的回溯」先例。
3. **死路 A／死路 B＋hadFailure**（narrative.js:1325、scenes.json:1192）——劇本層已有「失敗路徑」概念與旗標，死路 B 回述已條件化。
4. **生產性失敗原則**（run-node.mjs:5781 常駐測試）——「提早辯論會退回實驗，資料與已完成幾何不清空」。**回溯時什麼保留的答案，專案已經寫下：紙留下來。**
5. **憲章級法源（衝突掃描時發現）**：架構計劃書 v0.3 第 97/99/115 行——「主線……包含歷史上真實走過的死路」「**設計過的死路**：刻意引導玩家與科學家一起追錯、一起撞牆（**憲章五保證撞牆有產出**）」。現行死路 A/B 只兌現了一半（玩家旁觀 NPC 撞牆）；本提案是把「玩家親自撞、撞完有產出」補回憲章原意。**壞紙＝憲章五「撞牆有產出」的機制化。**

## 三、提案結構：三個新概念

### 3.1 岔口（值得失敗的選擇）

不是每個 choice 都長失敗分支。岔口的入選判準（三項全過才立案）：

- **賭注可見**：選擇當下玩家知道自己在賭什麼（工期、信譽、一張紙、一個人的信任）；
- **錯法有戲**：錯誤路線在歷史上真有人走過，或走到底會產生「當眾落空」的場面（不是走兩步就自知理虧）；
- **後果可記錄**：失敗會產生一張具體的紀錄（壞紙），而不只是情緒。

密度上限：**每章至多 2 個岔口**。四律紀律「拍數增加＝閱讀量，不得順勢增加點擊判斷數」照舊適用——岔口不新增判斷點，它把既有選擇的錯項從「牆」改建成「路」。

### 3.2 失敗劇情段

錯項不再一拍糾正，而是繼續走 8–20 節點，直到後果自己現身：預測當眾落空、被對手拿去引用、裝置打臉、資助人收回信任。設計鐵則：

- **NPC 不搶戲**：失敗段中 NPC 不得提前點破（原則 61「不得代玩家診斷」照舊）；讓現實打臉，不讓角色說教。
- **失敗段有自己的完整三拍**（四律 63 適用）：誰先發現異常→別人怎麼回應→現場怎麼確認。
- **終點是一張紙**：失敗段的最後一個動作是玩家（或見證 NPC）寫下這條路的紀錄——壞紙誕生。

### 3.3 筆記回溯（錨點規則）

失敗段終點後，旅人筆記自動翻回某一頁——回到錨點。

- **意象**：沿用 C0-1/x1 既有文本「頁面自己動了。一頁。又一頁。越翻越快。」的書頁＝時間裝置暗示；回溯＝「筆記翻回上一頁」，一個固定短儀式拍（2–3 節點，逐字機不重播長段）。**不使用「重新穿越」一詞**——理由見 §五。
- **錨點位置**：岔口所在**場**的開頭或岔口前最近的工作台出口，不回章開頭。錨點在岔口立案時一併凍結，寫進章 mechanics contract。
- **重走防痛**：錨點到岔口之間已完成的工作台以 `until` 條件門直接跳過；重走段落的旅人 OS 換變化文本（一句即可，例：「這一頁我讀過了。這次我看的是另一欄。」）；逐字機對已讀 line 提供既有 ack 快進。

## 四、保留／重置清單（回溯語意，本提案最重要的一節）

| 項目 | 回溯後 | 依據／理由 |
|---|---|---|
| 壞紙 | **保留**，進證據欄獨立分區 | 生產性失敗原則的推廣；失敗＝一次已付費的實驗 |
| 旅人筆記記錄 | **保留**（含失敗段的筆記行） | 筆記是玩家的跨線記憶體，也是回溯的敘事載體 |
| 信譽變化 | **保留**（失敗段內至多 −1，岔口本身不另扣） | 代價是真的，否則失敗段變免費觀光；上限防死鎖，見下 |
| 死鎖保險 | 壞紙可作為 SC-R 修復場的合格證據 | 「用證據道歉」——壞紙就是證據；低信譽玩家不會被迴圈鎖死 |
| 場景進度 | 重置到錨點 | 定義本身 |
| NPC 對話狀態 | 重置（NPC 不記得失敗線） | 世界線乾淨；記憶只屬於旅人與他的筆記 |
| 工作台狀態 | 錨點前已完成者保留；岔口後產生者併入壞紙或丟棄（逐案凍結） | 沿用 debrief 再入「保留已破支柱」先例 |
| loopCount | 存檔內部欄位，**永不上 HUD、不進章末結算、不跨章加總** | GB-ADR-054：不做第二條資源血條、不用裸數字評價研究風格 |

## 五、壞紙的證據資格邊界（憲章四相容性）

1. **壞紙記的是操作，不是結論**：欄位＝當時的條件、做了什麼、現場看到什麼、誰在場。它是「這條路我走過」的憑據，不是任何物理主張的正面證據。
2. **辯論中的合法用法**：僅可支付於「排除」與「回應質疑」語步（「你怎麼知道不是Ｘ？」——「我試過Ｘ，這是紀錄」）；不可支付於正面主張的證據槽。這與 conclusionLint 及 R-DEB ownsEvidence 的既有紀律一致。
3. **防洩答**：壞紙文本只記「發生了什麼」，不記「所以正解是什麼」；失敗段本身也不得由 NPC 說出正解方向（原則 61）。
4. **UI 呈現**：證據欄獨立分區，暫名「**未走通的紀錄**」；卡面標註取得場與失敗條件，視覺降一階（如墨色偏灰），不與正式證據混排。
5. **敘事上的正當性**：C3-2 x4「你不會回來替它辯護」的單向時間性**不受損**——回溯發生在「這一次停留」之內，旅人離開此章後依然永不回來；筆記翻頁是停留期間的反芻，不是跨章重生。§三的意象選擇正是為了保護這句台詞與「紀錄比人久」的主題。

## 六、與現有系統的接縫

- **存檔**：新增 `badPapers[]`（含取得場、岔口 id、條件摘要）、`anchorReturn`（最近錨點）、`loopCount`（internal）。各章 schema 各自擁有（ch1 現=3），試點章 bump 一版並附遷移表；舊存檔 `badPapers` 缺省＝空陣列，向後相容。→ **R4，需獨立 Design Gate 條目**。
- **辯論引擎**：壞紙作為新證據 kind 進 debate 資料，僅掛「排除／回應」語步槽位；weakTo 照常可設（壞紙也能被拆——「你那一趟根本沒控制船速」）。
- **check-mechanics**：岔口屬 `evidence_judgment` 可否證結構的自然延伸——失敗後果、留痕、錯項引用來源欄位本就是 contract 必填；失敗段納入 dominance 檢查（不得成為不可達裝飾）。
- **story-audit**：失敗段節點以 `branchRole: "failure-arc"` 標註（具體欄位名施工時定），三軌報表單列，不與主線 LINE_RUN 混計。

## 七、試點提案（二選一或 A/B 並做）

### 候選甲：ch3 解纜打賭（推薦）

- **岔口**：C0-3 舊紙定界（現有 choice `c1` 的越界項「所有船上落石都會落在桅後」改建為岔口）。
- **失敗段梗概**：玩家帶著越界結論上碼頭→維達爾不阻止（「算一張紙。拿去。」的冷眼延伸）→公開演示第一趟解纜起步（depart 窗、v0=2a 條件下落點明顯偏移）→預測當眾落空→圍觀者散去，艾蒂安把那張寫壞的岸紙推過來：「這張，要不要留？」→壞紙誕生，筆記翻頁。
- **錨點**：C0-3 場開頭。
- **壞紙回收**：ship public 質詢段，被問「你憑什麼說只在走穩時成立？」時可打出壞紙——「解纜那一趟我押錯過，這是那張紙。」
- **推薦理由**：打賭意象是該章 DNA（04_劇本/第三章_艦長打賭提案）；depart 物理修正（CH3-CR-021）剛好提供「起步窗會露餡」的機制基礎；且 ch3 是互動密度最低的章，失敗段同時緩解該章節點流空曠的問題——一箭雙鵰。

### 候選乙：ch1 斜面錯讀存活

- **岔口**：A2-2 斜面規律判讀（現有答題走廊的錯項「距離跟時間成正比」改建）。
- **失敗段梗概**：伽利略不糾正，照玩家的錯規律一起做第五段預測→裝置當眾打臉（球早到／晚到一個明顯格數）→付一天工期重測，錯讀紀錄成壞紙。
- **錨點**：A2-2 場內、第一次判讀前。
- **壞紙回收**：A3-D 辯論被辛普里奧逼問「你怎麼知道不是量錯」時打出：「我量錯過一次，這是那張紙。錯的規律在第五段就會露餡——這條規律撐過了八段。」
- **風險**：ch1 已凍結上線，動它是 R4 級回改；建議若選乙，先做 spike 不動 canonical。

**建議路徑**：照四律先例——試點做 A/B 原型（spike_workshop 零依賴單檔，不動 greybox），總監實玩後裁決是否全系列鋪開與批次順序。

## 八、成本與風險

- **內容量**：每個岔口約 +15–25 節點（失敗段）＋2 錨點儀式拍＋1 壞紙定義＋1 辯論回收掛點。六章滿配（每章 2 個）約 +250 節點，選擇性配置（試點先行）可控。
- **測試面**：每岔口至少 4 條契約——失敗段可達、壞紙必產、回溯後狀態符合 §四清單、壞紙辯論槽位合法性。
- **三顆地雷**（四律裁決檔既列）照抄適用：存檔遷移（R4 流程）、演出節奏（回溯儀式不得自動連播長段）、不為文字加 lint。
- **最大風險仍是重走體感**——原型階段必測「從失敗段終點回到岔口再選對」的真人時間與煩躁度；若超過 90 秒或試玩者皺眉，錨點再往後挪。

## 九、開放問題（供總監裁決）

1. **意象定案**：筆記翻頁（本提案推薦）／重新穿越／不解釋直接回溯——三選一。
2. **試點章**：甲（ch3 打賭）／乙（ch1 斜面）／甲乙並做 A/B。
3. **信譽保留規則**：§四的「保留但上限 −1」是否接受，或失敗段完全不動信譽。
4. **壞紙辯論資格**：§五的「僅排除／回應語步」邊界是否接受，或更嚴（僅場外筆記可見、辯論不可用）。
5. **每章岔口上限**：2 個（本提案）或更保守（全系列共 3–4 個）。
6. **凍結章政策**：ch1/ch2 岔口是否納入四律展開批次同車，或永久豁免。
