## 一、總裁決

這次靈感成立，而且比繼續逐句潤稿更接近目前的核心體驗問題。

《發現之前》的主要缺口不是「劇本不夠好」，而是許多玩家選擇只有**判定回饋**，
沒有**後果劇情**：

```text
目前常見：玩家選錯 → NPC 指出缺口 → 回同一題 → 選對 → 主線繼續

建議目標：玩家承諾 → 世界依這句話行動 → 錯誤造成可見後果
          → 玩家補做、撤回、失去資格或承擔公開代價
          → 帶著痕跡匯回主線；極少數重大失敗才局部回捲
```

這不是要求六章改成多結局，也不是替每個按鈕另寫一章。建議採用：

> **折返式分支（foldback branching）＋失敗前進（fail forward）＋少量局部時間錨點。**

分支可以回到共同主線，但玩家說過的話、留下的壞紙、失去的署名、人物態度、
補做的工作或旅人記得的時間折痕，至少一項不能消失。

## 三、AS-IS：現在不是完全沒有失敗，而是失敗壽命太短

### 3.1 已有的好骨架

現行系統已具備四項重要基礎：

1. 《架構計劃書》憲章五已要求「失敗產生新資訊，不得只是扣分或原地重試」。
2. 跨章證據法源要求錯誤只打掉主張，原紙、數據與進度保留。
3. 六章都有章別修復場：`SC-R1`、`SC3-R1`、`SC4-R1`、`SC5-R1`、`SC6-R1`。
4. 共用 narrative 已能保存 `returnScene／returnNode`，把信譽歸零的玩家送去修復再返回。

因此本案不是從零增加「失敗系統」，而是把現有失敗從**規則正確**推進到
**戲劇上有生命**。

### 3.2 真正缺口

多數錯項目前只有一至兩個節點的生命：

```text
錯誤主張
→ NPC 說出問題
→ 回同一個 choice
```

這種結構可以避免玩家帶錯答案通關，卻造成四個體感問題：

- 世界沒有真的相信或採用玩家剛說的話；
- 玩家還沒感受到代價，答案就被系統收回；
- NPC 比較像提示器，不像會因玩家行動改變計畫的人；
- 主線只像「玩家全選對」的唯一劇本，錯路沒有故事記憶。

第六章已比前章進一步：人物會針對原紙、署名與未決範圍質詢；但錯項多半仍在
同一 choice 內折返。第三章 `C3-1/x1` 也已有三種完整主張，兩個錯項仍是一句人物
回應後立即重選。它們正是本案最適合的低成本試點。

## 四、設計目標與非目標

### 4.1 設計目標

1. **玩家的話會使世界行動**：人物先相信、拒絕、記錄、署名、停工或改變計畫。
2. **錯誤有產物**：壞紙、裂封、撤回線、失去的資格、新問題或人物記憶可回查。
3. **修復與錯因一致**：錯在來源就補來源；錯在範圍就重寫範圍；錯在誠信才走信譽修復。
4. **分支最終可匯流**：歷史主線維持，但匯流後的台詞與狀態能讀回玩家走過的路。
5. **穿越從背景升為稀有機制**：只在真正不可逆的公開失敗出現，不取代一般科學失敗。

### 4.2 非目標

- 不替每個選項建立永久平行世界。
- 不讓每章都固定配置一次時間回捲。
- 不把普通計算錯誤、預測失準或選錯原紙變成 Game Over。
- 不建立生命值、總天數、重來次數排名或懲罰型資源血條。
- 不讓 NPC 在失敗分支直接朗讀正解。
- 不讓玩家靠上一輪的未發生資料，在回捲後冒充公開證據。
- 不改寫史實人物的已知生死、著作、發現歸屬與公開歷史結果。

## 五、失敗的五級分類

不同錯誤不應共用同一種「紅字＋重選」。

| 級別 | 類型 | 例子 | 戲劇處理 | 是否扣信譽 | 是否回捲 |
|---|---|---|---|---|---|
| F0 | 操作未成立 | 未選資料、空欄、無效數值、前置未完成 | 介面短提示 | 否 | 否 |
| F1 | 認知誤判 | 選錯資料、混淆一次方／平方、範圍判錯 | 人物針對原紙回應；保留錯誤主張 | 否 | 否 |
| F2 | 生產性失敗 | 實驗設計不乾淨、錯誤模型撐過一輪、公開答辯被擊中 | 一個短失敗弧線；新增分辨任務或代價 | 否 | 原則否 |
| F3 | 研究誠信違約 | 隱瞞原紙、冒領署名、把未量得寫成已證明 | 信譽事件＋同因果修復場 | 是 | 通常否 |
| F4 | 不可逆公開破裂 | 強迫他人替理論簽名、把錯誤稿送印、反覆拒絕更正 | 完整失敗場景；可觸發局部時間錨點 | 是或已歸零 | 候選 |

最重要的不變量：

> **F1／F2 不得偷算成 F3。猜錯與實驗失敗不是不誠實。**

只有玩家已看見來源與界線，仍選擇隱瞞、補寫、冒領或拒絕必要更正，才升為 F3／F4。

## 六、三種分支尺寸

### 6.1 反應枝：每個有意義選項都要支付

長度約一至三拍。最低包含：

```text
玩家實際說出／做出不同內容
→ 對方針對該內容回應
→ 世界留下至少一個差異
```

差異可以是人物態度、筆記句、先後順序或稱呼，不必全部改狀態。但若之後完全不被
讀回，就不能只靠隱藏 flag 宣稱選擇有意義。

### 6.2 失敗弧線：只給承重選擇

長度約一個短場或一段「離台→人物反應→新任務→再入」。建議每章只挑少數真正
承擔核心認知或公開責任的節點，不設定硬配額。

最低結構：

```text
承諾錯誤主張
→ 世界暫時依它行動
→ 後果在另一拍或另一場出現
→ 玩家看見原本忽略的欄位／反例／人物代價
→ 玩家選擇撤回、縮窄或補做
→ 分支帶著痕跡匯回主線
```

### 6.3 時間裂口：全系列稀有事件

只用於 F4。玩家已把事情推到無法靠正常補正挽回，例如錯誤稿已開印、共同署名被
強迫成立、歷史人物因此中止合作。

時間裂口不是失敗畫面後的「重新開始」按鈕，而是一場完整戲：

1. 玩家看見錯誤造成的世界結果；
2. 旅人筆記無法封頁，紙張、墨跡或既有穿越意象開始回捲；
3. 回到最近的時間錨點，不回章首；
4. 世界狀態回復，旅人的時間折痕保留；
5. 第二輪不原樣重播，新增一個只來自親歷失敗的問句或行動；
6. 旅人記憶只能改變提問與程序，不能成為 NPC 可引用的未來證據。

## 七、局部穿越的世界觀邊界

本案最大的上游爭點不是程式，而是系列設定。

現行系列聖經只確立旅人被穿越、不會老、穿越原因不解釋；沒有授權旅人主動倒轉
時間。如果直接加入「玩家按鈕控制回溯」，會把旅人從被動異常改成有可操作超能力，
屬系列級設定變更。

### 7.1 三種解釋方案

| 方案 | 描述 | 優點 | 風險 |
|---|---|---|---|
| A．字面時間倒轉 | 旅人知道自己真的重走同一段歷史 | 機制最清楚 | 改變核心世界觀；為何不濫用很難回答 |
| B．筆記推演 | 玩家看到的是送印／署名以前的一次可能後果 | 不改時間設定 | 失敗可能像預告片，不像真的發生 |
| C．曖昧的時間裂口 | 世界演到不可逆後果，筆記與畫面回捲；不解釋是時間、記憶或書頁拒絕封存 | 保留神祕與情緒；不授予主動超能力 | 必須讓玩家仍相信後果有重量 |

**本提案推薦 C。**第一次垂直切片只演一次，不建立可自由呼叫的「回溯能力」。若真人
試玩普遍理解為普通讀檔，或覺得後果被抹消，再由總監決定是否退回純失敗弧線。

### 7.2 歷史誠實不變量

- 回捲只能發生在遊戲已明示的合理重建或史料空隙內。
- 已知史實結果是外框，不以錯誤選項產生「牛頓沒有出版」「伽利略改信另一套物理」等
  alternate canon。
- 回捲後保留的是旅人私人的失敗記憶；已被回復的世界紀錄不能進公開證據鏈。
- 不以穿越替玩家免除原紙、比較、署名與有限主張的正常支付。

## 八、時間錨點與狀態契約

### 8.1 錨點位置

時間錨點必須同時滿足：

1. 位於一個不可逆公開動作之前；
2. 玩家在錨點前取得的合法原紙與證據已穩定；
3. 回捲後不必重做整章工作台；
4. 錨點後沒有跨越已知史實的長時間跳躍；
5. 可用一句世界內語言命名，例如「印刷台前」「共同頁落印前」，不顯示 node ID。

### 8.2 什麼保留、什麼回復

| 層 | 回捲後 |
|---|---|
| 錨點前合法證據、原紙與已完成工作 | 保留 |
| 錨點後錯誤署名、送印、授證或人物決定 | 回復 |
| 旅人的失敗記憶與時間折痕 | 保留，但只屬私人記憶 |
| 錨點後新取得、現已不曾發生的資料 | 不得保留為證據 |
| 信譽 | 不可草率決定；世界人物若不記得，章內信譽是否回復須另裁 |
| 事件帳 | 同時保留「上一輪發生過」與「本輪世界已回復」的可區分記錄 |

### 8.3 兩種未裁實作方向

**方向一｜章別白名單回復**  
每個時間錨點明列哪些 world fields 回復，旅人記憶與跨錨點紀錄另存。優點是可精確
守住證據；缺點是每章維護成本高，新增欄位容易漏回復。

**方向二｜獨立 checkpoint envelope**  
抵達錨點時保存一份不含自身快照的乾淨狀態；失敗後恢復 checkpoint，再合併旅人
記憶帳。優點是通用；缺點是匯出／匯入、sanitize、舊存檔與不可逆事件的風險較大。

本檔不裁實作。現行專案尚缺獨立的跨章存檔相容與遷移正式法源；未先補該法源、
章別遷移表與負向 fixture，不得進真正回捲施工。

### 9.1 為什麼先做第三章

- 節點已存在三個完整主張，不必重寫整個 ship 工作台。
- 錯誤正好位於全章有限主張的總結點，戲劇價值高。
- 可先驗證「後果劇情是否改善體感」，不必先承擔 checkpoint 與存檔風險。
- 若第三章加長分支仍只像教學重試，表示問題不只在分支長度，不能急著做穿越。

### 9.2 為什麼第四章適合第二階段

印刷、署名與來源本來就是不可逆公共動作；「校樣已開始印」比一般物理答錯更有資格
觸發時間裂口。錨點也能放在 K5 入口，不必讓玩家重做 K1–K4。

## 十、第一階段：不做真正回捲的垂直切片

### 10.1 範圍

只施工第三章 `C3-1/x1` 的兩條錯誤分支：

- `earth-moves`：過度宣稱；
- `nothing-learned`：抹去有限結果。

### 10.2 每條分支至少要有

1. 官員或現場人物真的依錯誤內容採取一個動作；
2. 一個人物承受或指出具體代價，而不是只報正誤；
3. 玩家翻回一張自己取得的原紙；
4. 玩家親自撤回或縮窄，NPC 不代寫正解；
5. 章末至少有一句依失敗歷程變體，但不額外授予證據或信譽；
6. 重整／讀檔不重播已看過的完整失敗演出。

### 10.3 本階段不做

- 不做 checkpoint；
- 不升 save schema；
- 不新增跨章分數；
- 不改 ship engine 的物理、原紙、證據與辯論門檻；
- 不改第四、五、六章；
- 不把兩個錯項寫成稻草人。

## 十一、第二階段：第四章時間裂口切片

只有第一階段真人試玩證明「錯誤被世界接住」確實改善體驗，才進本階段 Design Gate。

最低前置：

1. 總監裁決採 A／B／C 哪一種時間解釋；
2. 更新系列聖經的穿越能力邊界；
3. 建立跨章存檔與遷移正式法源；
4. 固定 K5 的唯一時間錨點與回復不變量；
5. 建立舊存檔、錨點前、錨點後、重複回捲、匯出／匯入負向 fixture；
6. Claude 做狀態機與歷史邊界 CONFORMANCE；
7. 總監做無提示真人試玩，確認它不是普通讀檔換皮。

## 十二、驗收條件

### 12.1 結構與狀態

- 每個受管選項都能指出不同的第一個世界反應。
- 承重錯項至少有一個後果活到下一拍以外，不在同一句被取消。
- 所有分支均有明示匯流點；不得依賴不存在的 node 或隱藏跳轉。
- 錯誤主張、原紙與修復動作可在事件帳回查。
- F1／F2 不扣信譽；F3／F4 才能依現行合法 `sourceId` 與 reason 記帳。
- 失敗不刪原紙、不偷發證據、不重置已完成工作台。

### 12.2 時間裂口專用

- 回到精確錨點，不回章首，也不讓玩家重讀無關長段。
- 錨點後的錯誤授證、署名、送印與人物決定確實回復。
- 旅人時間折痕保留，但不能被 NPC 當成來源。
- 重複回捲不複製證據、事件、信譽或完章狀態。
- 舊存檔與匯出／匯入 fail closed；不能猜測不存在的錨點。
- 降低動態模式可略過回捲動畫，但保留相同語意與可讀提示。

### 12.3 真人試玩

對不熟悉設計稿的玩家至少追問：

1. 「你剛才在哪裡失敗？」
2. 「那個失敗讓誰做了不同的事？」
3. 「你後來為什麼改變做法？」
4. 「回到錨點後，什麼被抹掉、什麼還留著？」
5. 「你覺得自己是在理解資料，還是在猜設計者要的句子？」

玩家若只能回答「按錯了，所以再按一次」，本案失敗；節點再多也不算後果劇情。

## 十三、主要風險與對策

| 風險 | 因果 | 對策 |
|---|---|---|
| 分支爆炸 | 每個選項都永久分岔 | 反應枝普遍、失敗弧線少量、主線折返；只讓狀態差異被後文讀回 |
| 失敗被當成考試懲罰 | 普通錯答也扣信譽或回捲 | 嚴守 F1／F2 與 F3 分界 |
| 玩家故意看完所有錯路 | 失敗內容變成收藏清單 | 不提供完成率；錯路的價值是理解與代價，不是全蒐集獎勵 |
| 回捲抹掉重量 | NPC 不記得、世界全復原 | 保留時間折痕與不同第二輪行動；普通失敗優先留在世界內，不回捲 |
| 回捲偷渡未來答案 | 玩家用上一輪資料直接說服古人 | 記憶只開問題／程序，不進證據鏈 |
| 史實被改寫 | 分支產生 alternate history | 分支只在合理重建縫隙；已知史實是不可突破外框 |
| 存檔污染 | checkpoint、eventLog 與不可逆狀態不同步 | 第二階段前補正式存檔法源與遷移表；正反 fixture 後才施工 |
| 重玩疲勞 | 每次失敗重播長演出 | 局部錨點、已播去重、第二輪變體與可跳動畫 |

## 十四、方向成立後，正式文件與開發 skill 要補什麼

這一輪只立候選，不直接改法源或 skill。若第三章試點獲准，至少要分四層補齊：

### 14.1 正式設計文件

1. **互動敘事規範**：新增「承重選擇的後果契約」，至少記錄 `commit／world_action／
   delayed_consequence／repair／converge／readback`，並標 F0–F4。匯流不等於失效，但
   匯流後必須有一項可見痕跡被讀回。
2. **系列聖經**：只有採時間裂口時才補穿越能力邊界；明定不可主動呼叫、是否為字面
   時間倒轉，以及私人記憶不得充當歷史證據。
3. **存檔與遷移法源**：定義 checkpoint envelope、世界狀態與旅人記憶的分層、舊版
   save fail-closed 規則、匯出／匯入與重複回捲不變量。
4. **章別功能規格**：每章只列獲准承重節點、失敗級別、後果產物、唯一匯流點與禁止
   改動的史實／證據邊界；不能把本表六個候選直接當施工清單。

### 14.2 `before-discovery-dev` skill 候選補強

現行 `check-narrative --story-audit` 已能列 choice 拓撲，並提醒人工查 NPC 回應與後文
讀回；它還不能量出「錯項活多久」。建議經 skill Design Gate 後增加：

- **Branch lifetime 診斷**：由每個 option 的 `next` 追到首次匯流，列出獨有可見節點數、
  跨場與否、是否立即回原 choice；只報結構，不自動宣稱真假選擇。
- **Failure-consequence contract**：只要求獲准的承重 choice 登錄上述六拍、F 級與後果
  產物；普通語氣選擇不硬塞契約。
- **人工四問**：世界是否依玩家的錯誤行動？後果是否晚於同一句？玩家是否親自修復？
  匯流後是否仍讀得到痕跡？四問不能以 flag 存在代替可見演出。
- **R4 路由**：一旦任務出現 rewind／checkpoint／跨章失敗記憶，強制加入
  `serialized-state-change`、存檔法源、遷移表與負向 fixture，不得以敘事 R2 施工。
- **反向 fixture**：把承重錯項改回「NPC 一句否定→同題重選」，檢查必須失敗；刪掉
  readback、重複合併證據或讓 F1 扣信譽，也要各有一個可失敗樣本。

不建議新增「每章至少幾條分支」或以分支節點數打品質分。那會把目前的選項灌水，
換成另一種分支灌水；skill 應守住已裁決契約，戲劇判斷仍由逐節點審查與真人試玩完成。

## 十五、交 Claude 的獨立對抗審任務

請 Claude **唯讀審查本檔，不修改 runtime 或正式法源**，依 A／B／C 分級回答。

### A 級必查

1. 「曖昧時間裂口」是否仍實質改變現行旅人世界觀？需要先改哪份上游法源？
2. F1／F2／F3／F4 是否有混類，尤其普通錯答是否被偷算成研究誠信問題？
3. 回捲保留／回復表是否可能偷留不存在的證據、署名、信譽或不可逆操作？
4. 六章候選是否違反物理、史實、證據所有權或既有章別狀態契約？
5. 第三章試點是否真的能驗證假說，或仍只是把「立即重試」拉長？

### B 級結構建議

1. 是否同意「第三章先做後果弧線、第四章再試時間裂口」的順序？
2. 哪些候選節點應撤回、替換或調整匯流點？
3. 章別白名單回復與 checkpoint envelope，哪個更適合現有存檔架構？是否有第三方案？
4. 時間裂口若不成立，如何用純世界內後果達到同等張力？
5. 哪些自動測試與真人試玩問題仍缺少可失敗條件？
6. 第十四節提出的正式文件與 skill 補強，哪些過度設計、哪些仍不足？

### C 級

- 名詞、視覺意象、分支長度與具體台詞品味。

審查者每條 A 級須附法源條號、狀態反例或可重現失敗路徑；不得只以「分支很有趣」
或「時間旅行很適合」作結論。
