## 二、核心發現：隱形變異繞過測試（三方獨立驗證）

> **這是本次審查最有價值的發現，也是三方對抗機制真正發揮作用的證明。**

### 2.1 問題的形狀

六條旅人筆記契約**全部是對 `chapter-ui.js` 原始碼做 `includes()` 字串比對與出現順序比對**，沒有任何一條建構 state、執行 handler 或檢查渲染結果。

因此存在一整類**契約看不見的改動**：只要修改後保留原本那些字串，契約就全綠，而行為已經壞掉。本報告稱之為**隱形變異**。

### 2.2 三方各自獨立跑出同一結果

三方在**未互相討論**的前提下，各自設計變異、各自執行，結論一致：

| 方 | 進路 | 結果 |
|---|---|---|
| **C｜codex** | 獨立設計變異並執行主契約 | 確認契約無法偵測隱形變異；另抓到**別名規避正則**（A-2 同源） |
| **A｜claude** | 抽出六個 handler 本體＋最小 DOM shim，以引擎產生的 state 實際執行，斷言渲染文字 | 三章（ch4／ch5／ch6）隱形變異**契約全綠、行為轉紅**；A-2 別名規避**契約全綠** |
| **B｜gemini** | 以**基礎變異 vs 隱形變異對照**設計 | 基礎變異（刪字串）會轉紅；隱形變異（保留字串）不轉紅——對照組本身就是證明 |

**三種完全不同的攻擊設計得到同一結論，這比任一方單獨報告的可信度高得多。** 這也是本次採「三方各自完整攻擊 A–F」而非分鏡頭的直接收穫：分鏡頭會讓這個缺口只落在其中一人視野裡。

### 2.3 A 鏡頭的實證明細

**檔案**：`greybox/src/chapter-ui.js`（ch4 `:4030`、ch5 `:4118`、ch6 `:4226`）／`greybox/tests/run-node.mjs:10648–10775`

| 變異 | 內容 | 六條筆記契約 | 行為探針 |
|---|---|---|---|
| **M2** | ch5 `if (true \|\| (lab.evidence && lab.evidence.j1))` | **全綠** | ★轉紅：J1 前原紙行出現「第二本帳」與「短少」 |
| **M3c** | ch6 `((air.judged \|\| true) ? "揭曉：" …)` | **全綠** | ★轉紅：未 judge 就出現「揭曉：」 |
| **M5** | ch4 `var opened = true \|\| (row.revealedAfterSeal === true && …)` | **全綠** | ★轉紅：「火星押記：約 1.9 年；**觀測 1.88 年，殘差 1.06%**」 |
| **M4b** | ch5 `var evx = lab["evidence"]; evx.j1 = true;` | **全綠** | ★轉紅：J1 前出現第二本帳 |

**差別只在字串在不在，不在行為對不對。**

### 2.4 玩家可見後果

任何人日後為了修版面、合併衝突或由 AI 代改而動到閘門條件，三章的封存值會直接出現在筆記裡，而 `npm test` 全綠、沒有人會知道。這正是「先承諾、後揭曉」整個設計要防的事。

### 3.2 根因的精確版本（採 C 的修正）

> **不是「讀錯欄位而失敗」，而是「靜默空狀態」。**

A 原本的結構推論列出兩種可能：ch7 落回通用路徑後，若 `renderLabTables()`（`chapter-ui.js:795`）被觸及，它讀的是 `state.lab.inference.claims` 與 `state.lab.evidence.runs`——**第一章的 lab 形狀**，而 Engine7 的 lab 沒有 `inference`，可能拋錯。

**C 的瀏覽器實測排除了拋錯這一支**：ch7 時 `custom.handled` 保持 false → `09-notebook.part.js:14-30` 的通用路徑去克隆 `#labRunsBody`／`#labClaimsBody`，而這兩個 tbody 在 ch7 從未被填充，於是通用路徑找不到任何列，直接輸出「(尚無研究紀錄)」。**沒有錯誤、沒有警告、沒有任何訊號。**

**這個修正很重要**：靜默失敗比拋錯嚴重。拋錯會被 console、監控或玩家回報抓到；靜默空狀態只會讓玩家以為自己什麼都沒做過。

- **分級**：**A**（依交付範圍：含第七章時為 NO-GO 的唯一阻斷）

### 3.4 驗收條件（C 鏡頭原文，逐字保留）

> 以下 7 項為 C 鏡頭（codex）提出的**最低驗收條件**，逐字轉錄。

1. 新增 Ch7 專屬 `bd:notebook-snapshot` handler，必須 `handled=true`，從 `state.lab` 投影而非 clone DOM。
2. 至少呈現：
   - append-only records（配置、觀測、重做版本）
   - matrix 六格與 tested scope
   - replication／exclusive／next-config commitments
   - mid／final verdict attempts
   - integrity incident、離桌狀態與 repair history
3. 封存／誠信邊界：
   - active withholding 的原紙內容不可由筆記旁路看見；
   - 可顯示「此格離桌、待修復」與事故存在；
