# 《發現之前》旅人筆記系統施工後三方回審任務書

狀態：**待三方獨立對抗審**  
施工基線：`d0527512fcb03d516eaa687a356b8aaba25337b4`  
施工依據：`05_審核/2026-08-11_旅人筆記系統三方對抗審查報告.md`  
審查原則：不得以施工者的測試全綠代替獨立驗證；請從玩家可見行為、存檔狀態與旁路變異三面攻擊。

## 一、這輪實作主張

1. `bd:notebook-snapshot` 已由第一至第七章正式 runtime 全數接管；第七章不再恆空。
2. 筆記本只投影既有 state，不會因開啟、切頁或關閉而改寫存檔。
3. 封存前的原紙、答案與延後揭曉資料不會旁路洩漏；合法揭曉或修復後才可見。
4. 第四章被取代的行星預測與舊版證明不再消失，改以摺疊歷史保留並標示「舊版／作廢／已取代」。
5. 第二至第六章補齊裝置版本、逐次嘗試、質量、條件、判讀狀態與人類可讀標籤；玩家不應再看到 `steel-only` 等原始代號。
6. 第七章筆記包含矩陣六格、測試範圍、承諾、判詞嘗試、完整性事件、離桌／修復歷程；主動扣留時不得顯示被扣留原紙，修復後原紙恢復但事件史不得消失。
7. 正式章清單改由 registry 驅動；新增正式章卻缺筆記 handler 或恆空時，測試必須失敗。
8. 展開與重播控制的最小高度為 44px；844×390 橫屏初始筆記頁不得水平溢出。
9. 現行法源升為 `旅人筆記系統_跨章規格_v0.2`，舊 v0.1 標為 superseded，並以 `GB-ADR-056`／`ADR-018` 留下治理紀錄。

## 二、指定對抗路徑

### A. 接管與唯讀

- 在保留所有關鍵字的前提下，將任一正式章 handler 改成 `handled=false`；契約應轉紅。
- 令第七章 handler 永遠回傳空畫面；契約應轉紅。
- 對同一合法 state 連續開啟三次筆記並切頁、關閉；前後 state 必須深度相等。
- 第三章缺卷宗的舊存檔仍須由第三章 handler 接管，顯示「未留存」，不得落回別章或空白。

### B. 延後揭曉與防旁路

- 第一至六章各取一組「封存前／合法揭曉後」state，實際執行 renderer；前者不得出現答案，後者必須出現。
- 把第五章隱藏條件改成恆真；行為測試應轉紅。
- 第七章手工製造 `away` 狀態：被扣留原紙內容不得出現；完成合法 repair 後內容應恢復，incident 與 repair history 仍須保留。
- 第七章 1794 年史料只能經 `Engine7.visibleArchival1794` 顯示，不得直接讀 raw state 旁路。

### C. 追加歷史與可驗證性

- 第四章同一行星先封一張預測、再重做第二張：兩版都須存在，舊版摺疊且有明確狀態標籤。
- 第二章同一系列留下兩個裝置版本：須能辨識版本、fingerprint、profile 與拒絕原因。
- 第三章留下錯誤再正確的 scope／source 嘗試：兩次都須可展開，不能只留最後成功結果。
- 第五章黏土紀錄須同時顯示球的質量與坑深；所有錯誤碼須轉成人類可讀中文。
- 第六章須顯示每筆條件、工作台已判／待判與模型預測中文標籤；只有 airBench 紀錄時也不得顯示「尚無研究紀錄」。

### D. 治理與可及性

- registry 新增一個正式章、但不新增 handler；總契約應轉紅，且不得靠修改測試硬編章號放行。
- 移除 v0.2 的 CURRENT 路由或 `GB-ADR-056` 語意落點；治理測試應轉紅。
- 把 `44px !important` 降回 36px；旅人筆記可及性測試應轉紅。
- 以 844×390 橫屏檢查長資料、鍵盤 Tab／Enter、焦點返回與捲動位置；不得只驗空白初始頁。
