# 《發現之前》旅人筆記／證據圖第二輪三方對抗審任務書

狀態：**唯讀審查，不得直接改 runtime 或生圖**  
本輪目的：判定第一至七章哪些資料需要補圖、哪些現有圖只是背景／器材代用品、哪些應列為「歷史參考」而非正式證據，以及圖像是否在錯誤時點洩漏答案。

## 一、審查方式

請 Claude、Codex、Gemini **先各自獨立審查**，不得先看另外兩人的結論；三份到齊後再交叉驗證。每一位都必須讀實際資料、資產映射與 runtime，不得只看截圖或施工者摘要。

請把發現分成：

- **A**：缺圖／錯圖會洩題、冒充史料、讓玩家無法驗證證據或使取得狀態失真。
- **B**：正式證據雖有映射，但只是背景、器材或通用圖，無法辨認這張證據真正記錄了什麼；或宣稱「取得參考卡」卻無法回看。
- **C**：一致性、來源母版、圖說、替代文字、手機可讀性或視覺品質問題，不阻斷理解。

每一條需附：章別／證據碼或節點、現行資產、玩家可見後果、建議分類、揭曉門檻、驗收條件。請明列「已實攻」與「只讀碼／未驗」。

## 二、不得混淆的四層

1. **正式證據**：只有引擎真的授予的 `evidenceNames` 項目；可進辯論。
2. **研究紀錄**：操作條件、原紙、錯誤、重做與判讀歷程；不可因有漂亮圖就自動升格。
3. **歷史參考**：原典、後世刊本或明示為重建的圖；可供理解，不替玩家授證。
4. **完整記錄**：劇情逐字紀錄；不等於取得證據或參考卡。

審查者不得用「看起來重要」把研究紙或歷史圖升格成正式證據。若遊戲明說「取得參考卡」，卻只留在逐字紀錄，請判斷是否違反旅人筆記的可回看承諾。

## 四、核心攻擊問題

### A. 有映射不等於有合格證據圖

- 每張卡能否一眼回答「這是什麼來源／做了什麼／看到什麼／最多能說到哪裡」？
- 若只顯示工作室背景或器材，玩家能否把它與另一張使用同器材的證據區分？
- 合成證據（例如 F5）是否真的呈現三份來源與邊界，還是單純把三張舊圖拼在一起？
- CG／raster 是不是把玩家尚未做出的軌跡、結果或判決提前烤進圖片？

### B. 圖像必須服從封存／揭曉

- 封存預測、未揭曉實測、被暫扣原紙與 superseded 版本，圖像層是否與文字層同樣守門？
- 取得動畫、筆記卡與放大閱讀器是否共用同一個 resolver 和同一個 `visualKey`？
- K4 四種借條世界線、ch7 暫扣／修復、ch5 J1／第三球等狀態，是否可能被 fallback 圖旁路洩漏或誤表現？

### C. 歷史圖與遊戲重建的身分

- 原典掃描、後世刊本、史料意象與遊戲重建是否在卡面或圖說明確區分？
- 山頂大砲需維持：「依 1728 年刊本原典重建；不是牛頓親筆手稿，也不是原典掃描」。
- 生圖不得生成看似可讀的假古文、假數據或假公式。可驗證數字、刻度、表格、玩家軌跡與判決應由 deterministic HTML／SVG 疊層負責。

### D. 是否真的需要補新圖

每一個候選請四選一，不得只回答「可美化」：

1. **現圖合格，不補**。
2. **補 dedicated raster 底板**：只承載紙張、器材、手部、蠟封、墨痕與時代質感；資料另疊。
3. **維持／新增 deterministic SVG 或 HTML**：因內容取決於玩家數據或需要精準可驗證。
4. **改列歷史參考並接入筆記回看**：不成為正式證據。

若建議補圖，請同時交付一段可直接生圖的中文提示詞，必須包含：

- 年代、地點、器材與構圖；
- 與現行《發現之前》寫實歷史插畫風格一致；
- 保留可放 HTML／SVG 資料的乾淨區；
- 不含任何文字、數字、公式、表格判決、UI 邊框或浮水印；
- 圖片身分（史料意象／遊戲重建／實驗底板）；
- 負面條件（不得現代器材、不得奇幻光效、不得偽造手稿文字）。

## 五、工程契約必查

現行 `greybox/tests/run-node.mjs` 的證據視覺測試仍：

- 手工列出 `scenes` 至 `scenes6`；
- 寫死 `required.length === 37`；
- 第七章由另一份 art test 另外保護。

請判斷這是否違反「由 chapter registry 與所有 `evidenceNames` 自動推導」的現行法源。指定反向控制：在 registry 新增一個正式章及一個 evidence code，但不補 `evidenceVisual`；全章契約必須轉紅。把 ch7 任一 mapping 刪掉，也必須由同一總契約轉紅，不能只靠章別特例。

另請檢查：

- 每個 raster／SVG 是否有可解析 runtime 路徑、明確 `sourceMaster`、alt、caption。
- `sourceMaster` 不得只是「可用」「新繪」等人類備忘字串；需能指向實際檔案或明確標示歷史債。
- E2 的 dynamic exception 是否仍有必要；若 `card_E2.webp` 已存在，為何 resolver 仍走 `evidence:E2` 特例？

## 六、手機與無障礙

- 844×390 下，每張卡第一層只顯示圖、短標題、情境與一句支持範圍；細節進放大閱讀器。
- 放大圖的 alt 與 `accessibleText` 必須能傳達圖中的比較關係，不能只說「一張古紙」。
- 純顏色、細線或小字不得是唯一資訊來源。
- 圖片本身有字時，需檢查手機可讀性；更優先的修法通常是把字移回 HTML。

1. A／B／C 數量與 GO／CONDITIONAL GO／NO-GO。
2. 44 項正式證據逐章盤點表，另列所有「取得參考卡／史料」但未進正式 evidence 的項目。

4. 每張必補圖的 imagegen 提示詞與 deterministic overlay 欄位。
5. 至少五組反向控制及實際結果。
6. 已實攻、只讀碼、未驗三欄清單。
