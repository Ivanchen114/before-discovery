## 二、核心發現：預製答案冒充玩家成果（跨章根因）

> **這是本輪最重要的整合結果，也是三方從六張不同的卡各自撞上的同一件事。**

### 2.1 兩個架構事實（A 鏡頭實攻確認）

1. **全 runtime 只有一個 state-driven visual key。** `chapter-ui.js:323-344` 的 `evidenceVisualKeyForState` 第一行就是 `if (CHAPTER_ID !== "ch4" || code !== "K4") return null;`——**除了 ch4 的 K4，其餘 43 個證據碼的圖像一律與玩家狀態無關。**
2. **全 runtime 只有一個疊層機制，而且是特例。** 掃過 `09-notebook.part.js` 與 `03-focus-visual.part.js`，唯一的 HTML／SVG 疊層是 E2 的 `e2DiagramMarkup()`。沒有任何通用疊層管線。

**所以「卡面反映玩家做了什麼」在現行架構下對 42／44 張是不可能的。** 個別卡的問題都是這一件事的表現。

### 2.2 同一根因的兩種表現形態

| 形態 | 卡面有什麼 | 案例 | 誰抓到 |
|---|---|---|---|
| **(a) 烤死具體數值** | 有數字，但不是玩家的 | **K3**（Mars 1.874／觀測 1.88／殘差 0.32%）、**K1**（固定三條路徑）、K4 base SVG（殘差 0.36%／45.8%）、K2（教學基準，**已誠實標示**） | K3＝A；K1＝C；K4/K2＝雙方 |
| **(b) 烤死結論或留白** | 沒有玩家資料，卻宣稱可追查 | **GRID_STATE**（六格全空白）、**T4**、ch6 T1–T5／S8（結論句寫死）、**G1–G5**（船景／艙景／空白紙帶） | GRID_STATE＝A；T4／G1-G5＝C；G1-G5＝B 獨立命中 |

### 2.3 最尖銳的單一案例：K3 與玩家紀錄互相矛盾

`ch04_card_K3_sealed_predictions_v01.svg` 的靜態文字寫「先封存預測 Mars **1.874**／再翻觀測紙 殘差 **0.32%** ✓」。

而玩家的押記是三選一的帶（`_PLANET_BANDS` mars：1.5／1.9／2.3）。選「約 1.9 年」者，旅人筆記的研究紀錄會顯示「火星押記：約 1.9 年；觀測 1.88 年，**殘差 1.06%**」。

> **同一個筆記畫面上，證據卡寫 0.32%、研究紀錄寫 1.06%；卡上的「預測」1.874 是玩家從來沒寫過的數字。**
> 而 K3 這一章要教的正是「順序就是證據的一部分：鎖規則 → 寫預測 → 封存 → 才揭露觀測」。

### 2.4 為什麼獨立成節

與上一輪的「隱形變異」同理：**六張卡分開看是六個美術問題，合起來看是一個架構問題。** 若逐張補圖而不建疊層管線，只會把資料問題烤得更牢——這也是 C 在結論裡寫的那句話。

**修法順序因此是：先建 deterministic overlay 管線與 state projection，再補底板。** 反過來做會返工。
