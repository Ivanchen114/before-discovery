## GB-ADR-001|資料載入策略:.js 全域賦值 + .json 規範鏡像

**背景**:R-ENV-01 要求雙擊 `index.html` 可玩;R-DATA-02 要求機器可讀 JSON 於 `/data`。file:// 之 opaque origin 使 fetch/XHR/ES module 載入一律被現代瀏覽器阻擋(Sol 審稿 #3)。
**選項**:①改用 localhost 指令啟動;②建置時 bundle;③資料以傳統 script 全域賦值載入,JSON 為規範鏡像。
**裁決**:採③。`/data/*.js` 為執行載體,`/data/*.json` 為規範鏡像,兩者深度相等性入自動測試(R-DATA-05)。
**理由**:①違反「雙擊可玩」對非技術試玩者的意義;②違反「無建置步驟」;③零依賴、零指令,漂移風險由測試封殺。

## GB-ADR-002|fixture 全面重校準與誤差語義修正

**背景**:v0.1 附錄 A 經枚舉驗算有 12+ 處矩陣違規(Claude 審核 A-1;Sol 審核 #2 同時指出)。根因:樣式為絕對偏移、容差為相對百分比——傾角越陡基準越大,相對衝擊縮水,一切變得可判定。另 v0.1「水鐘=對稱抖動」與矩陣「陡+水鐘三次平均不通過」邏輯矛盾:零均值抖動經平均必然收斂通過。
**裁決**:各樣式按「嚴重度×樣式÷基準」之相對衝擊重校;水鐘誤差改為「首段系統性偏高+微抖」(平均不可消除);脈搏改為「大幅抖動+輕偏移」(平均可大幅消除=廉價工具×多次路徑);原木後段流失遞增且三 run 形狀相異;木球突刺逐 run 游走。
**理由**:憲章四(不得製造錯誤的物理模型或虛假歷史因果)+R-EXP-04(矩陣為規範)。驗證:54 配置×216 判定點全符,與 12% 線最小距離 0.5pp,測試常駐 `/tests`。
**修訂(2026-07-19,依 Sol 第 2 輪審稿 A-1)**:撤除原裁決文中「此即伽利略需要緩斜面的史實原因」之宣稱。計時誤差樣式定位為**表現短時測量不確定性的教學代理**,非伽利略水鐘實測誤差之重建——本模型無操作程序與量測方程,無從導出該歷史因果;伽利略之實際程序(全程/指定距離集水稱重)與本切片逐段增量讀值不同。規格 v0.1.2 R-EXP-06 已同步代理聲明;史實頁揭露義務入 `docs/debt.md`。數值與矩陣不受影響。

## GB-ADR-009|試玩修正:診斷回饋、連續工作階段與辯論複盤(2026-07-20)

**背景**:總監實玩發現三個同源問題:①「選集內部不一致」會讓人誤以為多跑幾次即可救陡坡水鐘,但引擎實際判定的是平均形狀對奇數律的偏差;②A2-2/A2-3 三個 embed 被演成反覆進出實驗室;③辯論「追問」沒有可見產物,說服力歸零又把已持有全部證據的玩家送回實驗台做無效工作。
**裁決**:①判定回饋拆為「前四段形狀偏差」與「第五段預測偏差」兩道 12% 門檻;公開計時器性格,連續失敗第 2 次給中性觀察、第 3 次探索模式給診斷問句(學者模式按需索取),不替玩家宣判答案。②A2-2→A2-3 視為一次連續工作階段,僅首次進實驗台設確認閘;SC-R1 仍獨立進場。③追問改為可持久的 `pressed+insight`;介面採證詞卡、證據手牌與自然語言行動句。④**說服力歸零**=證據—證詞錯配,進 A3-F 與伽利略複盤後再入;**信譽歸零**=行為失格,仍進 SC-R1 做一筆乾淨紀錄。兩種資源不得共用同一修復動詞。
**不變邊界**:實驗 fixture、12% 判定線、證據取得條件、支柱弱點、說服力/信譽扣值與凍結劇情結論均不變;本次改動屬表現、回饋與失敗迴路修正。
**驗證**:資料鏡像、自動通關、追問狀態、失敗分流、雙歸零、UI 靜態契約與瀏覽器 G7 人工清單常駐。

## GB-ADR-017|證據隨台詞入鏡＋角色語氣可讀性(2026-07-21)

**背景**:總監實玩第二章砲術圖場景時,角色正指著圖辯論,畫面卻只剩工作室背景;玩家被要求判讀自己看不見的證據。同輪又發現第二章把 ADR-005「老派書面語」做成半文言,連伽利略也受感染,使物理謎題多疊一層語文解碼。
**裁決**:①`lineFocusVisual` 為跨章資料契約:只在角色實際拿起、指向、比較圖像/器材時自動入鏡,同場景保留、下一個特寫取代、換場清除;選項與對話 z 層永遠高於特寫。第一章補 S1/S2/E1–E5 與器材關鍵時刻,第二章補 S3/S4/F2–F4 與證據牆。E2 綁縛悖論沿用程式 SVG,不另造可能畫錯物理資訊的點陣圖。②第二章 CH2-CR-002 僅調語氣、不動情節與判定:辛普里奧保留「老夫」與古派修辭,但不用「爾等／此乃／焉知」作理解門檻;伽利略、旅人與玩家選項採自然白話。唯一半文言例外=B2-3 伽利略刻意模仿,須有明確表演框架。
**理由**:遊戲若要求玩家讀圖,圖就必須在同一注意焦點內;謎題的難度應來自證據配對與物理推理,不應來自解碼文言。角色風格由節奏、立場、慣用詞與動作建立,不是靠提高閱讀門檻。
**驗證**:雙章關鍵場景/資產/替代文字/換場清除契約;E2 SVG 單一來源;第二章半文言禁詞掃描(刻意模仿節點唯一豁免);完整回歸常駐。

## GB-ADR-016|直向自動橫置(2026-07-21)

**背景**:玩家回報安卓「進不去」;總監截圖定位根因——直向時 16:9 舞台成 219px 高帶,標題卡上下溢出被裁,繼續/開始按鈕不可見;rotateHint 被關閉後即卡死。總監問「一進去可以直接是橫屏嗎」。
**裁決**:網頁無法命令裝置轉向(iOS 無鎖向 API;Android 需全螢幕手勢),採遊戲業標準解:**portrait+coarse 時整座 #stage 旋轉 90°(translate 置中+rotate)畫滿螢幕**,寬高公式=原式 vw/vh 對調(dvh 優先,vh 回退);實體轉向即由真橫屏 media 接手。rotateHint 於此模式退場(GB-ADR-014 的攔截職責被本案取代;原則 38 的層級要求仍適用於其餘 overlay)。已知代價:直向下鍵盤輸入(押注值/回顧/書信碼)為側向打字,可接受;字級 clamp 之 vw 縮小由 px 下限兜底。
**驗證**:契約測試(media 條件+rotate+rotateHint 退場);真機=總監 Android/iPhone 直拿實測,見標題全貌並可開局。
**補記(2026-07-21,總監授權 Claude 代修,Sol 事後複驗)**:系列首頁 v2 驗證揭露整合縫——media query 依視窗非旋轉舞台,直拿手機命中「窄高」分支跑出直版單欄。修法=**旋轉手機視同 844×390 低高度橫屏**:全部 13 個 `(max-height:520px)` 系列區塊追加替代式 `(orientation:portrait) and (pointer:coarse) and (max-width:520px)`(max-width 限定=視覺高度<520,iPad 直拿不誤吃手機壓縮版);全部 5 個窄高/窄寬區塊加 `(pointer:fine)` 鎖桌機。真橫屏手機規則零改動。契約測試鎖兩式。

## GB-ADR-014|行動裝置橫屏全螢幕(2026-07-20)

**背景**:總監:手機玩要橫屏全螢幕,瀏覽器網址列擋畫面。
**裁決**:三件套——①HUD「全螢幕」鈕(手勢內 requestFullscreen+`screen.orientation.lock("landscape")`,Android Chrome 有效);②直向+觸控裝置顯示轉橫提示(可進全螢幕/可婉拒,sessionStorage 記憶);③PWA manifest(fullscreen+landscape+圖示自標題主視覺裁切,Sol 可換專圖)。**誠實邊界:iPhone Safari 不支援元素全螢幕與鎖向**——藏全螢幕鈕,提示改導「加入主畫面」(manifest 生效=全螢幕開啟)。
**驗證**:契約測試(按鈕/提示/manifest 欄位/圖示實檔/灰盒不長舞台件);真機行為=G 系列人工簽核。
**補記(2026-08-02，總監要求開場提示)**:WebKit 新版本已在 iOS 提供／修正 `Element.requestFullscreen`，因此改為**能力偵測優先**，不再用 iPhone 名稱一律判定無全螢幕。標題頁內嵌非 modal、可略過的「遊玩體驗建議」：有 Fullscreen API 時給真按鈕；Apple 行動裝置在 HTTP(S)、無 API、非 standalone 時，才顯示「分享 → 加入主畫面 → 從桌面開啟」。文案只承諾減少 Safari 工具列，不宣稱必然全螢幕；請求失敗時保留建議並以 `aria-live` 回報，不阻擋開始遊戲。舊 `rotateHint` 因置於尚未顯示的遊戲畫面且又被 GB-ADR-016 隱藏，屬不可達死路，正式退役。

## GB-ADR-041｜玩家可見「說服力」改名為「論證對位」（2026-08-03）

**背景**：舊名「說服力」容易被讀成口才、魅力或另一種全域聲望，並與 `state.rep` 的「信譽」混用。現行機制實際衡量的是：玩家挑出的證據是否咬住當前主張，而不是角色有多會說話。runtime 與常駐測試已使用「論證對位」，但章規格與治理文件尚未形成正式裁決。

**裁決**：玩家可見名稱固定為「論證對位」。狀態列、辯論介面、讀屏文字、提示、現行規格與測試使用新名；內部欄位 `persuasion`、事件名稱、存檔 schema 與既有 fixture 保持不變，以避免無必要的存檔遷移。歷史 ADR、凍結劇本與審查紀錄不做機械回寫，只由現行文件標明名詞演進。

**語意邊界**：論證對位是單場證據—主張配對的容錯；信譽是整章研究誠實與操作授權。配錯證據可以降低論證對位，但普通錯答、計算錯或預測失準不扣信譽。兩者歸零時分別進入配對複盤與章別研究誠實修復，不得共用修復動詞。

**驗證**：五章玩家可見 runtime 不得出現舊名；現行規格須使用新名並明載內部 `persuasion` 相容邊界；匯入與存檔往返不得因改名改變資料；治理測試鎖定本 ADR、`GOV-ADR-001` 與現行規格之間的引用關係。

## GB-ADR-043｜第四章 K2：一秒真實正矢先行，六十秒只作事後顯影（2026-08-05）

**背景**：GB-ADR-039 雖修正了 `1.4 mm` 的顯示精度，runtime 仍把「月球六十秒偏折 4.9 公尺」寫成與地表答案相同的固定常數，再除以 3600 產生一秒值。畫面因此看似由兩張獨立來源相遇，實際答案早已被引擎塞入；也倒置了「為什麼選六十秒」的發現順序。

**驗證**：契約必須用改動 fixture 的負向變異證明正矢不是固定常數；鎖定一秒值、六十秒事後值、約 3600 容差、揭曉順序與舊存檔正規化。另以桌機與 844×390 實玩確認切線端點、實際端點與向內差距的 SVG 可讀，且合作焦點圖不遮蔽選項。

## GB-ADR-044｜共同探究雙鏡頭：關係側視與紙面閱讀分工（2026-08-05）

**背景**：現行焦點圖多以側視或三分之四構圖呈現旅人與科學家共同工作，人物關係與時代氛圍成立，紙面內容卻因透視而不可讀。若反過來把完整推導、數值與判決一次燒進同一張圖，又會形成數學牆、提前洩答，並使畫面無法回應玩家當前進度。兩種需求不是二選一，而是兩個先後鏡頭。

**裁決**：①一至六章各選一個共同探究拍點，依序配置「關係鏡頭→閱讀鏡頭」。關係鏡頭以側視／三分之四視角呈現兩人正在一起看、算、對齊或爭論，紙面可失焦，不負責傳遞精確內容；閱讀鏰頭改為正視或俯視完整紙面，讓玩家看見角色此刻正在看的材料。②「完整紙面」不等於「同時揭露全部」：每個閱讀鏡頭只強調當下的一項比較，其餘欄位可保持未填、低對比或摺起；更多推導另置可選展開，不得把閱讀門檻變成一面公式牆。③生成影像只可承載少量、穩定且已在該拍之前揭曉的短標記、單一箭頭或一個既知值；任何會隨玩家選擇改變、需要精確判讀、仍待揭曉、含多步公式或構成正確判決的資訊，仍由 HTML／SVG／Canvas 呈現。判準先看洩答與狀態依賴，再看文字數量。④圖片不是唯一資訊來源；正文、圖說與替代文字須保留同一層意思。閱讀鏡頭可以讓玩家略過數學細節，但不能略過主線所需的白話判斷。

**實作邊界**：本條只新增資產、`lineFocusVisual`／`viewFocusVisual` 映射與漸進揭露表現，不改場景節點、證據 ID、存檔 schema、引擎 action 或任何正確判定。圖片內的少量文字須在提示詞、資產台帳與人工驗收中逐字記錄；OCR 或生成品質未通過時，改用無字圖加程式疊字，不得以「大致看得懂」放行。

**驗證**：契約鎖定六章各有一組不同資產的關係／閱讀鏡頭、觸發順序與既有節點可達；閱讀圖不得出現在對應內容揭曉以前，且每張都有圖說與 alt。另逐張人工檢查構圖、手部、紙面方向、允許文字與未洩答內容；最後以桌機與 844×390 實機確認圖片不遮選項、閱讀圖可看清當前重點、略過細節仍能沿正文前進。

## GB-ADR-048｜互動不等於工作台：第四章依認知工作分層（2026-08-06）

**背景**：第四章把切線判讀、同尺換算、逐拍作圖、封存預測、模型對帳與出版組頁都包進同一種大型書桌工作台。K2 實際只要求三個有先後的一次性判讀，玩家卻要離開人物對話、進入左右雙欄介面，造成「知道要比較什麼，卻不知道為何要操作這座台」的斷裂。總監實玩另確認，圖面順序應先顯示月亮已走過的短圓弧，再由當下方向畫切線；實際下一點與端點短差只能在預測後揭露。

**裁決**：①跨章互動分成對話判讀、精簡操作板、完整工作台；一次性的指出、比較、命名或限制主張留在對話舞台。②分層採兩道門檻：反覆改變條件且結果不同、錯誤留可診斷產物、存在可續玩中間狀態、或玩家能決定操作順序／協定，任一成立才離開純對話；要再升為完整工作台，還必須額外具備「同時攤開多來源、跨兩次以上判斷反覆回查條件後才能提主張」或「組裝需署名、送印、對外負責的公開產物」至少一項。單一封存—揭曉循環中、同批翻開且可一次完成判讀的有限卡組，不因張數多就自動滿足多來源條件。前四項是複雜度訊號，不是完整工作台的充分條件；彼此重疊時也不得重複計分。③第四章 K0 切線與 K2 同尺紙改為「對話推進＋圖面逐步揭露＋玩家選項」；三個判讀仍經 `convertMoonTime`、`judgeScaleRatio`、`judgeScaleRelation` 寫入章別引擎，錯答留痕，最後一判才取得 K2。④K1 保留精簡作圖板，K3 保留封存／揭曉板，K4 模型對帳與 K5 出版組頁保留完整桌面；不得再把所有互動一律稱為實驗台。⑤K3 現行只有「封存直覺押記與理論值→同步揭曉→並讀四張卡」的證據判讀，沒有兩種盲驗方向可選；不得把提案中的未實作分岔寫成 runtime 既有玩法。日後若新增研究路徑選擇，先在對話舞台決定，再進操作板執行。⑥證據狀態可先成立門檻，但若 canonical scene 指定授證掛點，提示音、閃光與焦點卡只能在該玩家發現或具名簽收行觸發；選項回聲與操作板成功訊息不得搶拍。掛點必須為結構化資料，不以台詞關鍵字猜測。

**圖面順序**：第一張紙先畫地球、月亮與已走過的短圓弧；玩家再從月亮當下方向延伸直切線。第二張沿用同一張紙，才補上實際下一點、極淺實際路徑與兩端點短差。生成 raster 負責紙張與墨跡氣氛；精確端點、短差、數值與判決仍由程式／正文提供，圖片不是唯一資訊來源。

**相容與驗證**：不改 K2 fixture、schema 2、舊 `scale` embed 讀檔相容或證據 ID。新局主線不得進入 D1-2 `scale` 大工作台；三個判讀少任一項不得取得 K2，弧長錯答、倍率錯答與關係錯答都須保留。常駐測試鎖定兩道工作台門檻、K2 對話授證的具名簽收與下一問、兩張順序圖、對話選項的章別 action 白名單、K2 最終授證與舊游標續玩；桌機與 844×390 另驗圖片、選項與人物台詞不互相遮擋。

## GB-ADR-049｜短幕時間折疊保留對話，重大跳躍才使用逐拍蒙太奇（2026-08-06）

**背景**：第四章 `D-INT-1` 用六句文字掠過 1665 至 1679，但畫面始終停在同一間亮著燭光的書房，玩家容易把它讀成普通旁白，而不是十四年正在翻過。若再插入一套全畫面多圖蒙太奇，又會打斷「旅人看著同一張紙翻頁」的主觀時間感，並與章首／換科學家的重大交棒重複。

**裁決**：①時間轉場分為兩級：跨章、換地點、換同行者或需要一至三個史實里程碑者，沿用 `sceneFx: montage` 並由玩家逐拍推進；同一敘事場內以數句對話掠過多年、人物與問題仍連續者，使用資料驅動的 `sceneTreatment: time-passage`。②短幕折疊進場時，背景、焦點圖與非必要介面退到近黑；對話框、繼續操作與一個 HTML 年份錨點保留。離場後才淡入下一時代的真實背景。③短幕折疊不新增計時器、不自動換句、不攔截玩家操作，也不修改劇情、證據、引擎或存檔；`prefers-reduced-motion` 只取消淡化動畫，仍保留黑場與逐句閱讀。

**第四章落點**：`D-INT-1` 顯示 `1665 → 1679` 與「十四年，折進一頁」，黑場持續到玩家親手選擇「翻到 1679」並進入 `D2-1`。既有 `timePassage` 音樂與此視覺狀態並行，但兩者由不同資料欄位控制，不得以音樂名稱反推畫面。

**驗證**：常駐契約鎖定 `sceneTreatment` 場景存在、模式與年份短標；同一場景不得同時註冊短幕折疊和重大蒙太奇。舞台層須由共用場景資料切換 class，近黑層位於對話框之後，且程式不得用固定秒數前進。另以桌機與 844×390 實機確認黑場不遮文字、繼續鈕與手機安全區，離開幕間後新背景能正常淡回。

## GB-ADR-050｜K1 先試跑、選紀錄、再斷言；不以盲猜形狀冒充預測（2026-08-06）

**背景**：K1 新局要求玩家在看見任何軌道路徑前，同時選「每拍指向、初速、箭長、三十拍後形狀」。前三項是模型規則，第四項卻沒有足夠經驗可推，實玩時成為名詞密集的盲猜。程式雖能忠實續畫玩家規則，畫面卻容易被讀成現代模擬器替牛頓預測，而不是兩人把紙上小步快速算完。

**裁決**：①前段對話先共同確立「每一小步都朝此刻的地心轉」，K1 新局不再把方向列為可調欄位，也不在結果前要求形狀押注。②精簡操作板只保留兩個白話變因：「月亮原本跑多快」與「每一步往內扳多少」；每次 `runOrbitPaperTrial` 依同一固定算法快速續畫，設定、完整路徑與結果皆 append-only。相同組合不得重跑洗版。③K1 不是觀測實驗，介面與台詞稱「紙上試跑／快速續畫」，並明載結果是模型輸出，不替天空作證。④玩家至少選三張紙才可 `assertK1`：兩張不同快慢、不同向內扳量且都留在近圓窄帶；第三張須與其中一張只差一項、結果不再近圓。只有玩家再選出「原有前進保留；向內扳量必須和快慢相配」才授 K1。⑤切線來源紙仍是斷言的一部分，避免試跑只得到配對規律、卻漏掉原有前進不需另一股力維持。

**取代與相容**：本條取代 GB-ADR-040 的 K1「規則紙＋形狀預測紙」新局流程，以及 GB-ADR-047 的「玩家三拍＋共同續畫」新局流程；K3 與其他章真正具備依據、封存、揭曉的預測不受影響。舊存檔若已有 `ruleSeal`、三拍或 `ruleRuns`，仍沿舊 UI 與原重播稽核走完，不與新 `paperTrials` 混寫。K1、K2、K3–K5 證據 ID 與下游閘門不變。

**驗證**：引擎重算九組快慢／向內扳量，鎖定慢／少、一般／適中、快／多三組近圓；同組重跑必須零變更拒絕。少於三筆、三筆全同結果、不是控制變因、錯誤結論或缺切線紙皆不得取得 K1。sanitizer 必須重算每條路徑、核對玩家操作事件與三紙選集，拒絕偽造座標、混入舊三拍 schema 或先寫成功 claim。另以桌機與 844×390 實機確認兩個選單、結果表、三紙勾選與斷言在精簡板內可讀。

## GB-ADR-051｜K2 地心量距先由玩家試答，合理理由各自保留缺口（2026-08-06）

**背景**：K2 已由玩家接出「距離約六十倍」與「一秒向內偏折約縮為三千六百分之一」，下一句卻只由牛頓說「它們是不是也照這條規矩」並直接宣布「為什麼可以從地心量」尚未證明。玩家容易不知道規矩究竟是數字巧合、距離平方，或已經成立的力學定律；面對地心量距的真正缺口，也只被安排沉默。

**裁決**：①在正式引入力與加速度以前，K2 只把關係說成可見量：「同樣一秒裡，距離放大約六十倍，向內落下的距離縮成約六十平方分之一」；不得把兩點吻合提前命名為普遍定律。②牛頓提出「為什麼能從地心量」後，由玩家在對話舞台選一個理由試答：球形中心、四面對稱或落下方向。三項都不得扣信譽、授證或偽裝成唯一正解；各有專屬回應後匯流。③四面對稱是最接近的部分答案：它能支持合起來的方向朝中心，不能單獨證明大小等同於把整顆地球集中在地心；球形只指出中心位置，落下方向則是以結果倒推理由。④匯流時由旅人親口限縮：「能指出地心，還不能把整顆地球當成縮在那一點」；牛頓只把問號留下，不代答後來才完成的球殼證明。

**相容與驗證**：不改 K2 證據、`judgeScaleRatio`／`judgeScaleRelation`、schema 2、授證掛點或舊游標；選項只新增對話分支與一般 choice 紀錄。常駐測試鎖定三項無 effects、三個專屬回應、對稱只完成方向、三路匯流至旅人限縮，以及 K2 筆記在本段不出現「力」「加速度」或「作用按距離平方變弱」。選項長度與句型須保持對稱，桌機與 844×390 另驗三項可讀且不遮人物。
