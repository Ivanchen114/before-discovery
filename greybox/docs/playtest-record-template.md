# 《發現之前》五章統一試玩紀錄模板

**用途**：把玩家體感轉成可定位、可批次、可驗證的問題；不是通關攻略，也不取代自動測試。

**主持規則**：沿用 [`playtest-protocol.md`](playtest-protocol.md) 的「不主動提示、記玩家原話」；裝置與無障礙檢查引用 [`browser-checklist.md`](browser-checklist.md)，不在本檔複製另一份。

**紀錄位置建議**：`05_審核/試玩紀錄/YYYYMMDD_chN_裝置_測試者.md`。

## 5. 根因分群

一張截圖或一個 OBS **不直接觸發施工**。先把 Issue 放入下列根因之一：

| Root ID | 類型 | 判準 | 典型處理層 |
|---|---|---|---|
| ROOT-MECH | 機制／狀態 | 選擇沒有後果、狀態可偽造、流程卡死 | engine／sanitizer／contract |
| ROOT-EVID | 證據／推理 | 紙沒攤開、來源不明、NPC 代玩家診斷、過度斷言 | data／workbench／debate |
| ROOT-NARR | 故事／動機 | 人物為何合作、旅人為何介入、轉場缺「不得不」 | scene structure／dialogue |
| ROOT-VOICE | 聲線／聲域 | 心聲過多、公開發言辨識失敗、語言檔位漂移 | scenes／presentation |
| ROOT-UI | 呈現／導覽 | 任務不明、當前原紙不明、控制被遮住 | chapter UI／stage |
| ROOT-PHYS | 物理／史實 | fixture、因果、史實歸屬或命題邊界錯 | law／fixture／histfacts |
| ROOT-OPS | 製作／版本 | 正本、鏡像、資產、存檔或法源漂移 | tooling／governance |

## 8. 從試玩到施工的閘門

```text
OBS（原始觀察）
→ ISSUE（可復現問題）
→ ROOT（同型根因）
→ CR／GB-ADR（範圍、不變邊界、驗證條件）
→ 施工
→ 定點復驗
```

- A 級可立即停線，但仍須保存精確狀態與可驗證依據。
- B 級先按根因合併，避免同一病灶分散成多個畫面補丁。
- C 級進文字／一致性批次，不插隊改動共用引擎。
- 自動測試通過、代理瀏覽器走查、真人桌機／手機簽核必須分開記錄。
